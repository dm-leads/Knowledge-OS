# Справочник — Оценка MCP Тильды

## Краткая суть

- **MCP Тильды** — официальный удалённый сервер `https://tilda.ru/api/mcp/`: 279 инструментов, токен из кабинета
  Тильды даёт доступ к одному проекту-сайту.
- 140 инструментов только читают, 37 правят черновик страниц, 102 сразу меняют живой сайт, магазин, блог или внешние
  кабинеты (маркетплейсы, почта).
- Подключается записью в `.mcp.json` проекта и помощником заголовка: токен лежит только в файле секретов.
- **Вердикт: забрать.** Чтение свободно; запись — по «да» владельца на конкретное изменение, со снимком «до», обратным
  чтением и строкой в журнал действий. Правила и скрипты — навык `tilda` в `_Движок\Исходники скиллов\`.

> Для быстрого знакомства человеку может хватить блока выше.
> Ниже начинается полный каноничный текст документа.
> Для агентов, правок, анализа, ревью и разрешения расхождений обязателен полный текст.

## 1. Что это и тип

Официальный http-MCP-сервер конструктора сайтов Тильда («Tilda MCP», версия 1.0.1 на ноябрь 2026). Даёт агенту то же,
что редактор и кабинет: страницы, блоки, Zero Block, публикацию, настройки проекта, SEO-файлы, статистику, магазин,
блог (feeds), коннекторы маркетплейсов. Тип — MCP-сервер, удалённый.

## 2. Как подключается

Ничего не ставится. В `.mcp.json` проекта — сервер `tilda-<сайт>` типа `http` и `headersHelper`, который печатает
заголовок `Authorization: Bearer <токен>` из файла секретов (`scripts/mcp_bearer_header.py` навыка `tilda`). Codex —
через `bearer_token_env_var` в своём конфиге. Подробно — навык `tilda`, раздел 2.

## 3. Требования

- Python для помощника заголовка.
- Токен в файле секретов.
- **Отметка доверия к папке** в Claude Code: без неё новые версии не запускают `headersHelper`, клиент уходит в OAuth и
  падает с «Dynamic Client Registration rejected (HTTP 404)». Случай 02.11.2026: расширение VS Code окно доверия само
  не показало, лечилось отметкой `hasTrustDialogAccepted` у обеих записей папки в `~/.claude.json`.

## 4. Что создаёт / меняет

Локально — только `.mcp.json` проекта. Состояния на машине не хранит. На сайте — всё, что разрешают инструменты
групп 2 и 3 (ниже).

| Группа | Число | Действие |
|---|---|---|
| Только чтение | 140 | страницы, блоки, `page_preview` (вместе с неопубликованными правками), SEO-файлы, 40 инструментов статистики, магазин, блог, подсказки `*_instructions` |
| Черновик | 37 | блоки и страницы; посетитель видит после `publish_page`. ⚠️ проектные CSS, код в `<head>`, шрифты уходят на сайт с публикацией любой страницы |
| Живой сайт и вовне | 102 | публикация, настройки проекта, robots, редиректы, **магазин** (64 инструмента, меняется сразу), блог, синхронизация с Ozon, Wildberries, Яндекс Маркетом, VK, письма |

У 83 инструментов магазина меток `readOnlyHint` нет — граница чтения задана навыком, а не сервером.

## 5. Глобальность влияния

Только проект, в чьём `.mcp.json` прописан сервер. Глобальные серверы и другие проекты не затрагивает. Несколько
сайтов — несколько серверов с разными именами `tilda-<сайт>`.

## 6. Конфликты с нашей средой

- Одинаковые имена серверов перекрывают друг друга молча (локальная > проектная > пользовательская настройка) —
  отсюда правило имени `tilda-<сайт>`.
- Команда `headersHelper` с кириллицей в пути на Windows может не запуститься — путь к помощнику латиницей.
- Лимит частоты сервера (HTTP 429 с `retry_at`): массовые проходы — в фоне, клиент ждёт и повторяет.

## 7. Безопасность

- Наружу уходит только то, что агент сам пишет в Тильду: тексты, цены, настройки.
- Обратно приходят **адреса вебхуков с ключами** (`get_form_integrations`) и **персональные данные покупателей**
  (`store_get_orders*`, `get_payments_history`, `get_profile`) — не печатать, без задачи не читать.
- Ловушки записи, проверенные на живом сайте:
  - `store_save_products` очищает галерею товара, если её не передать;
  - `store_save_products_field` стирает пропущенные поля и подменяет пустой артикул сгенерированным;
  - `update_record` для списков (поля формы, приёмники заявок) заменяет список целиком: пустой список отключает все
    приёмники, и заявки перестают доходить в CRM и аналитику;
  - `toggle_page_block_visibility` переключает, а не ставит состояние — без проверки по `page_preview` легко показать
    скрытый блок.

## 8. Профильность для нас

Высокая для любого проекта на Тильде: акции и цены, плашки, посадочные, SEO-техника (robots, sitemap, редиректы,
мета), проверка устаревших акций обходом страниц, статистика страниц как proxy. Проверено на задаче «акция 20 %»:
альяс-плашки и карточки, 7 товарных страниц, 7 товаров магазина и сноска о доставке в 21 Zero Block — за один день,
каждая запись со снимком и обратным чтением.

## Вердикт

**Забрать.** Чтение — свободно. Запись — только по «да» владельца на конкретное изменение (что, на какой странице,
как было, как станет), малыми шагами, со снимком «до», обратным чтением и строкой в журнал действий проекта.
Публикацию держит владелец, пока не сказал иначе. Правила, механика блоков и скрипты — навык `tilda`.
