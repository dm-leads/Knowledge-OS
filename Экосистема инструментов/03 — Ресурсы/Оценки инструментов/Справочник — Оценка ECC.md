# Справочник — Оценка ECC

## Краткая суть

- **ECC** (Affaan Mustafa, MIT, `github.com/affaan-m/ECC`, сайт ecc.tools) — **мета-харнесс**: готовая система
  работы агента «план → тест → реализация → ревью → проверка → память → улучшение», ставится один раз
  и начинает управлять поведением агента во всех сессиях.
- Состав на 23.09.2026 (v2.2.2): 68 агентов, 292 навыка, 94 команды, 24 хука, 122 файла правил, самообучение
  («instincts»), сканер безопасности AgentShield.
- **Вердикт: целиком не ставим.** Дублирует уже включённый у нас superpowers, добавляет 24 хука на каждое
  действие агента и вторую систему памяти поверх нашей. Профиль — 90% разработка ПО; маркетинговые навыки
  общие и западные (LinkedIn, X, Exa), Яндекса нет ни в одном.
- **Забрано точечно 24.09:** 7 навыков сжаты в 3 наших (`agent-hygiene`, `llm-pipeline-economy`, `brand-voice`),
  ещё несколько — «на примете» под конкретные задачи. См. разделы в конце.

## Что это

- Тип: **мета-харнесс** (плагин Claude Code + установщик для Codex, Cursor и ещё десятка сред).
- Популярность: 266 тыс. звёзд и 40 тыс. форков за 8 месяцев (репо создан 18.01.2026), последний коммит
  22.09.2026. Цифра звёзд аномально высокая для такого срока — по стандарту принимаем со скепсисом.
- Лицензия MIT. Проект живой: 223 открытых задачи, регрессионные тесты, отдельная политика безопасности.

## Как ставится (verbatim)

```bash
npx ecc-universal@2.2.2 setup                     # мастер: плагин ecc@ecc в Claude Code
npx ecc-universal@2.2.2 install --guided          # несколько сред сразу (Claude Code, Codex, Kimi)
npx ecc-universal@2.2.2 install --profile minimal --target claude   # без хуков
```

Внутри Claude Code: `/plugin marketplace add https://github.com/affaan-m/ECC` → `/plugin install ecc@ecc`.
Windows: из PowerShell те же `npx`-команды или `.\install.ps1 --profile minimal --target claude` из клона.
Удаление: `npx ecc-universal@2.2.2 uninstall --dry-run`, затем без `--dry-run`.

## Требования

Node.js 18+, Git, Claude Code 2.1+. Ключей API не требует. Дополнительные модули (AgentShield, InsAIts,
Itô compute) — отдельные пакеты и сервисы.

## Что создаёт / меняет

- Плагин `ecc@ecc` в выбранной области (user / project / local): навыки, агенты, команды — с пространством
  имён `/ecc:...`, поэтому команды одноимённые с нашими технически не перекрываются.
- **24 хука** (`hooks/hooks.json`, грузятся автоматически): 9 на `PreToolUse` (два — на любой инструмент),
  2 на любой `PostToolUse`, 7 на `Stop`, 2 на `SessionStart`, по одному на `PreCompact`, `SessionEnd`,
  `PostToolUseFailure`. Каждый запускает процесс Node.
- `SessionStart` подмешивает в начало сессии до 8000 символов (сводки прошлых сессий и до 6 «инстинктов»).
- Состояние — в `~/.claude`, `~/.codex`, `~/.config`, `~/.local`, `~/.gateguard`; сессии хранятся 30 дней.
- Правила (`rules/`) плагином не ставятся — только ручным копированием в `~/.claude/rules/` или в проект.

## Глобальность влияния

Рекомендованный путь мастера — **Global user**: плагин и хуки включаются во всех проектах машины,
включая Бризекс и Knowledge-OS. Есть область `project`/`local` — влияние только на одну папку.

## Конфликты с нашей средой

Проверено по `~/.claude/settings.json` и кэшу плагинов 23.09.2026:

- **superpowers** (включён) делает ту же работу — план, TDD, ревью, проверка перед завершением — и тоже
  подмешивает текст на `SessionStart`. Две методики, которые одновременно задают агенту порядок работы.
- **code-review**, **feature-dev** (включены) — у ECC команды с тем же назначением.
- **codex** (включён) уже держит свой хук на остановке; ECC добавляет ещё семь.
- **Память:** «инстинкты» и сводки сессий ECC — вторая система памяти поверх нашей (`MEMORY.md` +
  Knowledge-OS). Два источника «что было раньше» в начале каждой сессии.
- **Совпадений имён навыков с нашими `~/.claude/skills` нет** (сверено по списку 292 навыков).
- **Расход токенов.** Плейбук Anthropic для Opus 5.5 (22.09.2026) советует убирать лишние проверки и
  раздутые инструкции — пятые модели проверяют свою работу сами. ECC построен на обратном: обязательная
  проверка на каждом шаге и постоянный контекст на старте. Это наш вывод из сопоставления, а не замер.

## Безопасность

- Сетевых вызовов наружу хуки по умолчанию не делают (проверено по `scripts/hooks/`): `mcp-health-check`
  обращается только к вашим же MCP-серверам, сторонний монитор InsAIts выключен до `ECC_ENABLE_INSAITS=1`.
- «Телеметрия» `skill-run-tracker` — локальный журнал вызовов навыков, не отправка.
- Диагностику, по заявлению README, не выгружает; обратная связь — только публичной задачей на GitHub.
- Плюс: GateGuard перехватывает разрушительные команды (`rm`, `git checkout` с путём и т. п.) до запуска.
- Минус: 24 исполняемых хука — большая поверхность. Проект сам просит считать хуки, MCP и инструкции
  «исполняемой конфигурацией».

## Профильность для нас

Большая часть — разработка ПО: паттерны 20+ языков и фреймворков, TDD, починка сборки, ревью PR.
Близкие нам по названию навыки прочитаны:

| Навык | Что внутри | Для нас |
|---|---|---|
| `seo` | учебный чек-лист технического SEO под Google (краулинг, Core Web Vitals, title 50–60 символов) | ничего сверх нашего `ai-seo` и канона статей |
| `market-research`, `competitive-platform-analysis` | рамки исследования, поиск через Exa, LinkedIn | общие, без Рунета |
| `content-engine`, `brand-voice` | контент под платформы, голос бренда из реальных текстов | у нас свой ToV-канон и критик |
| `lead-intelligence` | поиск контактов через LinkedIn и соцграф | западный B2B, не наш канал |
| `prompt-optimizer` | разбор промпта с подбором компонентов ECC | уже закрыт `claude-brief` |

Что может пригодиться как идея: `context-budget` / `token-budget-advisor` (аудит того, что съедает контекст),
`skill-stocktake` (ревизия библиотеки навыков), AgentShield (`agentshield scan`) — разовая проверка
конфигурации агента на секреты и опасные права.

## Вердикт

**Не ставим** — ни глобально, ни в проекты. Дублирует superpowers, добавляет 24 хука и вторую память, профиль
не наш. **Забрать точечно** — читать отдельный навык в репо и адаптировать в `_Движок\Исходники скиллов\`,
если появится задача (ревизия навыков, аудит расхода контекста).

**Пересмотреть, если:** откажемся от superpowers и понадобится замена; или появится проект, где основная
работа — разработка ПО в команде. Пробовать тогда только с областью `project` и профилем `minimal` (без хуков).

## Что забрали (24.09.2026)

Семь навыков сжаты в три и переписаны под наши правила, исходники — в `_Движок\Исходники скиллов\`:

| Наш навык | Из чего | Что изменено |
|---|---|---|
| `agent-hygiene` | `context-budget`, `config-gc`, `skill-stocktake` | считает только то, что реально грузится; учитывает скрытые навыки, дубли имён и навыки-ссылки; убирает переносом в корзину по номерам |
| `llm-pipeline-economy` | `regex-vs-llm-structured-text`, `cost-aware-llm-pipeline` | добавлены наши уроки: модель находит — код меняет, мышление съедает лимит ответа, пустой результат ≠ успех, цены только со страницы тарифов |
| `brand-voice` | `brand-voice` | русскоязычные источники и каналы, типовые признаки машинного текста, уступает канону ToV |

Первый замер `agent-hygiene` на этом устройстве (24.09): постоянный расход до первого сообщения —
около 17 тыс. токенов без системного промпта самого Claude Code: описания 92 навыков ~10 тыс., индекс
памяти ~5,7 тыс., глобальный CLAUDE.md ~1,2 тыс.

## На примете — не ставим, пока нет задачи

| Навык ECC | Для чего пригодится | Условие |
|---|---|---|
| `competitive-platform-analysis` → `benchmark-methodology` → `competitive-report-structure`, плюс `market-research` | методический слой анализа конкурентов: бриф позиционирования, уровни конкурентов, оценка с доказательством, отчёт о свободной нише | когда вернёмся к выбору инструмента данных для анализа рынка; заточено под креативные студии — переделать под наши рынки |
| `carrier-relationship-management`, `logistics-exception-management`, `customs-trade-compliance`, `returns-reverse-logistics`, `inventory-demand-planning` | исходный материал для курса Учебного центра по логистике | как источник знаний по стандарту извлечения, не как навыки; практика американская — сверять с российской |
| `brand-discovery` | интервью для формулировки бренда с нуля (8 модулей) | новый бренд без позиционирования |
| `video-editing` | конвейер монтажа на FFmpeg | если начнём монтировать ролики сами |
| `data-scraper-agent` | сборщик данных по расписанию с записью в таблицу | если мониторингу демпинга на Авито понадобится свой сборщик |
| AgentShield (`npx ecc-agentshield`) | разовая проверка настроек агента на секреты и опасные права | запуск стороннего кода — только с согласия Дмитрия |
