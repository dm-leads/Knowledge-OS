# Справочник — Оценка Topvisor

## Краткая суть

- **Topvisor** — российский сервис проверки позиций сайта в Яндексе и Google по региону. Хранит позицию каждого
  запроса за все даты, когда запускалась проверка, и отдаёт эту историю по API бесплатно.
- **Вердикт: забрать** — как независимый измеритель позиций для оценки SEO-вмешательств (см.
  [Оценка Keys.so](<Справочник — Оценка Keys.so.md>) — там мониторинг живёт только на время подписки). Клиент —
  навык `topvisor` в `_Движок\Исходники скиллов\`, **только чтение**.
- Главные оговорки: проверка платная и идёт только по запуску или расписанию — истории «между съёмами» нет;
  позиции двух трекеров по уровню не сшиваются.

## 1. Что это и тип

Облачный сервис с веб-интерфейсом и REST API v2 (`https://api.topvisor.com/v2/json/`). Оплата в рублях, с баланса,
за каждую проверку запроса. Единица хранения — проект (сайт) с группами запросов, поисковиками и регионами.

## 2. Как подключается

Ключ API и номер пользователя — в кабинете. У нас — переменные `Topvisor_API_KEY`, `Topvisor_User_Id`,
`Topvisor_ID_Project` в мастер-.env устройства. Заголовки запроса: `User-Id` и `Authorization: bearer <ключ>`.
Работа — через навык `topvisor` (клиент `scripts/topvisor.py`). Ничего не ставится.

## 3. Требования

Python с `python-dotenv`. Установки, демонов и MCP нет.

## 4. Что создаёт / меняет

Клиент ничего не меняет: ходит только в методы чтения (`get/…`), остальное отсекается в коде. Локально — файлы
снимков в папке, которую указали. В самом сервисе проверки, группы и расписания создаёт человек в интерфейсе.

## 5. Глобальность влияния

Навык глобальный, вызывается осознанно; поведение агента не меняет.

## 6. Конфликты с нашей средой

Нет. Дополняет `keysso` (мониторинг позиций на время подписки, в том числе по второму региону) и
`seo-niche-research`.

## 7. Безопасность

- В одном аккаунте могут лежать проекты разных сайтов. Клиент работает только с проектом из
  `Topvisor_ID_Project` и не печатает список остальных.
- Запуск проверки тратит деньги. В клиенте его нет намеренно: цену показывает интерфейс перед запуском, решение —
  за человеком. Метод цены в API (`get/positions_2/checker/price`) требует отбор запросов; на пробном отборе по
  именам он вернул ноль — цену через API считать неподтверждённой.
- Персональных данных в ответах нет.

## 8. Профильность для нас

Высокая для одного вопроса: «как менялась позиция этих запросов в этом регионе». Что даёт и чего нет:

| Даёт | Не даёт |
|---|---|
| позицию запроса по региону на каждую дату проверки, за всё время жизни проекта | позиций между проверками — ряд нерегулярный, если нет расписания |
| историю бесплатно и без срока подписки | визитов, кликов, заявок |
| группы запросов — тест удобно держать отдельной группой | контроля «сам собой»: контрольные запросы надо завести и проверять в те же даты |

Ловушки:

- **Проверяется только то, что запустили.** Если в дату съёма проверяли одну группу, по остальным запросам проекта
  точки нет — и контроля тем же прибором нет. Контрольную группу заводить до старта теста и ставить на то же
  расписание.
- **Три состояния ячейки.** Число — позиция; «--» — проверка была, сайт в глубине проверки не найден; даты нет в
  ответе — проверки не было. В ноль не сводить.
- **Ключ ячейки истории** — «дата:проект:номер региона»; номер региона — внутренний номер проекта (метод
  `project`), а не код региона поисковика.
- **Уровни разных трекеров не сравниваются:** сервисы по-разному считают место в выдаче. Сравнивать изменения
  внутри одного прибора.
- **Позиция «до»** — это дата последней проверки до события, а не день перед ним: смотреть на дату, а не на
  подпись колонки.

## Вердикт

**Забрать** — только чтение. Проверки и расписание — человек в интерфейсе. Перед любым тестом, который оценивается
по позициям: отдельная группа теста, отдельная контрольная группа, одно расписание на обе.
