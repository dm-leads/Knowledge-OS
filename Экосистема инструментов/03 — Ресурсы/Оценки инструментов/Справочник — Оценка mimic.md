# Справочник — Оценка mimic

## Краткая суть

- **mimic** (`github.com/littledivy/mimic`, MIT) — перехватывает сетевой трафик приложения или сайта и
  **генерирует Python-клиент к его API**. Слоган: «Intercept any app, then call it from Python like a library».
- Тип: **пассивная утилита-генератор кода** (CLI), не плагин Claude Code, среду ассистента не трогает.
  Внутри — `mitmproxy` для захвата + **Claude API** для генерации типизированного клиента из пойманных эндпоинтов.
- **🔴 Прямо про нашу боль.** Мы вручную реверсили недокументированный `events_timeline` amoCRM, руками
  разбирали Wappi/sipuni. mimic автоматизирует ровно это: поймал свою авторизованную сессию → получил
  готовый Python-клиент. Инструмент для сборки **read-only коннекторов к сервисам без нормального API**.
- **Вердикт: в песочнице → забрать как локальную утилиту.** Польза реальна и кросс-проектна, но захваченный
  трафик = сырые ПДн клиента, а генерация шлёт структуру эндпоинтов (и примеры ответов) в Claude.
  Применять только на своих сессиях, read-only, с обезличиванием захвата ДО генерации.

## 1. Что это и тип

- **Генератор API-клиентов по перехваченному трафику.** Автор — littledivy (Divy Srivastava, известен по Deno).
  Язык — Python (по README). Лицензия **MIT**.
- Не харнесс и не skill-pack: это отдельная CLI-утилита. В `~/.claude` ничего не ставит, `CLAUDE.md` не правит.
- Ограничения из README: **certificate pinning** (банки, Instagram) и **DPoP-токены** ломают захват/повтор —
  мобильные приложения с пиннингом не возьмёт.

## 2. Как ставится и рабочий цикл (команды из README, 02.08.2026)

```
sh install.sh                        # ставит uv + mimic в изолированное окружение
mimic doctor                         # проверка установки
# захват веб-панели: DevTools → Network → правой кнопкой → «Save all as HAR» → traffic.har
mimic hosts --har traffic.har        # какие API-хосты поймались
mimic learn <host>                   # заглянуть в эндпоинты
mimic gen <host> --har traffic.har   # → клиент client.py (класс + методы, с твоей авторизацией)
```
Пользование результатом:
```python
from client import Сервис
c = Сервис(); данные = c.get_что_нужно()
```
Три источника захвата: **HAR из браузера** (наш основной путь — amoCRM и веб-панели), сохранённый **cURL**
(`Session.from_curl(...)`), поток **mitmproxy** (`mimic record`, для iOS через прокси). Первый прогон —
на безобидном публичном эндпоинте, убедиться что `install.sh`/`doctor` отработали.

## 3. Требования

- Python + **uv** (ставится сам): `sh install.sh` → `mimic doctor`.
- **mitmproxy** — только если ловим мобильный трафик через прокси; для веба достаточно HAR/cURL.
- 🔴 **Своего ключа Claude НЕ нужно** (уточнено по README 02.08.2026): генерация клиента идёт
  **на серверной стороне mimic** — то есть захват отправляется в их сервис. Это не «дешевле», а
  наоборот тревожнее по приватности (см. п.7): данные уходят третьей стороне, не через наш ключ.

## 4. Что создаёт / меняет

- Генерирует файл(ы) Python-клиента в рабочей папке. Среду ассистента и глобальные конфиги не трогает.
- Промежуточные артефакты захвата (HAR / mitmproxy-дампы) — **сырьё с ПДн**, оседает локально.

## 5. Глобальность влияния

- **Нулевая.** Обычная CLI-утилита в своей uv-среде. Не Claude Code плагин → на другие проекты машины
  (включая Breezeks) не влияет, глобальную среду не меняет.

## 6. Конфликты с нашей средой

- Нет: не пересекается с нашими навыками/командами/памятью, ничего не подменяет.

## 7. Безопасность и ПДн (ключевое для нас)

- 🔴 **Захват = живые ПДн.** HAR/поток amoCRM/Wappi содержит телефоны, имена, переписки клиентов.
  Файлы захвата — **строго локально, НИКОГДА в git** (как и `conversations.db`); удалять после генерации.
- 🔴 **Генерация серверная — захват уходит третьей стороне.** `mimic gen` отправляет пойманные
  эндпоинты (и, возможно, примеры ответов) на бэкенд mimic, где они прогоняются через Claude. Мы НЕ
  контролируем, что там логируется. Митигация обязательна: ловить на **тестовой/непдн-сессии** или
  **обезличить HAR до `mimic gen`** (у нас есть `pii.py`). На сырых боевых данных — нельзя.
- ⚠️ **Юридика/ToS.** Только СВОИ авторизованные сессии, read-only — ровно наша посадка по amoCRM
  ([[rule-yandex-mcp-read-only]] в духе). Не для чужих аккаунтов и не для обхода защит.

## 8. Профильность для нас

- ✅ **Высокая и повторяющаяся.** Сборка коннекторов к сервисам без публичного API — сквозная боль всех
  проектов: недокументированные эндпоинты CRM/панелей, новый клиент с личным кабинетом без API,
  выгрузки из SaaS. mimic сокращает «руками реверсить сеть» до «поймал HAR → получил клиент».
- ⚠️ **Не для мобильных с пиннингом** (банки) и не там, где нельзя обезличить захват до генерации.

## Где нам реально пригодится

- **Новый клиент без API.** Личный кабинет CRM/панели без документации → HAR → read-only клиент за минуты
  вместо дней ручного реверса (как было с amoCRM `events_timeline`).
- **Недокументированные эндпоинты** сервисов, которыми уже пользуемся (Промопульт, коллтрекинг, нишевые SaaS).
- **Разовые выгрузки** из веб-панели, где нет экспорта, а данные нужны для аналитики.

## Безопасный рецепт применения

1. Поймать **свою** авторизованную сессию в браузере → сохранить HAR.
2. **Обезличить HAR** (вырезать телефоны/имена/токены) ДО подачи в mimic — или ловить на тестовых данных.
3. Прогнать генерацию → получить Python-клиент; захват удалить.
4. Клиент использовать **только на чтение**, секреты — из `.env`, не в код.
5. Сначала обкатать на непдн-эндпоинте (напр. публичный каталог), потом на боевом.

## Вердикт

**В песочнице → забрать как локальную утилиту.** Пробовать на неПДн-эндпоинте; для боевых сервисов —
обезличенный захват и read-only. Ценность кросс-проектная (быстрая сборка коннекторов), риск управляем
теми же правилами, что и вся наша работа с ПДн. Правила подключения —
