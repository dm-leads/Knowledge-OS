# Справочник — Оценка API Авито

## Краткая суть

- **API Авито** — официальный интерфейс кабинета продавца: объявления, статистика, расходы, баланс, продвижение,
  автозагрузка, сообщения. Адрес — `api.avito.ru`.
- **Вердикт: забрать — чтение.** Запись (цены, ставки, продвижение, сообщения) — только через модуль с белым
  списком методов, журналом и откатом, по команде владельца на каждое изменение.
- Главные оговорки: ключи своего кабинета выдаются при платном тарифе; сайт `avito.ru` — не API, автоматические
  запросы к нему с адреса владельца закрывают этот адрес на дни.

## 1. Что это и тип

Облачный REST API площадки. Не ставится: к нему ходит наш клиент. Условия — «Условия использования Авито API
для бизнеса» на сайте площадки. Отдельный API у кабинета «Авито Реклама» (медийная реклама) — свои ключи.

## 2. Как подключается

Два способа входа, для разных задач:

| Способ | Для чего | Что нужно |
|---|---|---|
| персональная авторизация, `client_credentials` | свой кабинет | пара `client_id` и `client_secret` из личного кабинета |
| авторизация через приложение, `authorization_code` | сервис для чужих кабинетов | регистрация приложения на портале разработчика, Redirect URI, ключи приходят письмом |

Для своего кабинета приложение и Redirect URI не нужны. Ключи — в кабинете, раздел «Для профессионалов» → «API»,
адрес `avito.ru/professionals/api`; ключ берётся с основного аккаунта, не с аккаунта сотрудника. У нас — переменные
`AVITO_CLIENT_ID`, `AVITO_CLIENT_SECRET` в `.env` проекта. Токен: `POST /token`, живёт 24 часа.

Ключи медийной рекламы: вкладка «API» кабинета «Авито Реклама», создаёт администратор, ключи привязаны
к рекламному аккаунту.

## 3. Требования

- **Платный тариф** на аккаунте: «Базовый», «Расширенный» или «Максимальный» — портал разработчика, копия
  от 12.07.2026. **14.10.2026 в кабинете одного из проектов ключи API в услугах предлагались только
  с «Максимальной» подпиской, 6 000 ₽ за 30 дней** — наблюдение владельца по интерфейсу; летом, по его же
  опыту, ключи давали без подписки. Условия меняются — смотреть в кабинете перед покупкой.
- **Вакансии** — свой раздел API: публикация и правка вакансий прямо методом, без файла. Нужны «Максимальная
  подписка в Работе» и пакет размещения или разовое размещение с кошелька (документация, снимок 31.07.2026).
  Тариф в «Услугах» и в «Работе» в одном профиле одновременно не купить.
- Python со стандартной библиотекой. Демонов и MCP нет.

## 4. Что создаёт / меняет

Клиент на чтение ничего не меняет. Методы записи есть и тратят деньги или меняют кабинет: услуги продвижения,
ставки, цена объявления, загрузка файла автозагрузки, отправка сообщений. Они идут только через отдельный модуль
записи с белым списком.

## 5. Глобальность влияния

Локально в проекте: клиент и ключи живут в проекте. Общего навыка и глобальной установки нет.

## 6. Конфликты с нашей средой

Нет. Если клиент нужен второму проекту — не копировать файл, а поднять пакетом канона: копия застывает.

## 7. Безопасность

- **Сайт — не API.** Запросы кодом к `avito.ru` и его поддоменам с адреса владельца площадка считает
  автоматическими и закрывает адрес целиком — сайт перестаёт открываться и в его браузере. Только `api.avito.ru`;
  ответ 429 — стоп, а не повод повторить. Документацию читать по снимку или копии в веб-архиве.
- **Переадресацию в клиенте выключить:** стандартная библиотека идёт по ней сама и несёт заголовок с токеном
  на новый адрес.
- **Личные данные.** Метод «свой аккаунт» отдаёт имя, почту и телефон; сообщения и заказы — данные покупателей.
  В вывод — номер кабинета и числа; наружу — агрегат.
- Ключ и токен в журналы и вывод не попадают.

## 8. Профильность для нас

Высокая, если реклама идёт на Авито: расход, просмотры, контакты, остаток и состояние объявлений снимаются
командой, а не руками из интерфейса.

**Объявления API не создаёт.** В документации (снимок 31.07.2026, 245 методов) метода создания объявления нет:
объявление заводят в кабинете или файлом автозагрузки, прямое создание есть только у вакансий. API читает,
меняет цену, ставки и услуги продвижения, запускает загрузку файла — не чаще раза в час — и отдаёт её отчёт.
Поэтому «объявлений много — значит, нужен API» неверно: массовое создание — это файл автозагрузки, а API лишь
избавляет от ручной загрузки и чтения отчёта. В первый месяц число объявлений к тому же ограничено лимитом
аккаунта, а одинаковое объявление в разных городах в услугах блокируется как повтор.

Ловушки — каждая встречена на живом кабинете:

- **Прокси.** Через прокси из переменных окружения `api.avito.ru` не открывается, напрямую отвечает. Клиент
  ходит без прокси.
- **Неверный ключ — HTTP 200.** Метод токена отвечает кодом 200 и ошибкой в теле. Успех — наличие
  `access_token`, а не код ответа.
- **Статистика — один запрос в минуту на профиль.** Клиент сам выдерживает паузу.
- **429 при листании объявлений** даже с паузами 5–20 секунд — паузы брать длиннее и не повторять в цикле.
- **Метод тарифа** в документации описан для категории «Транспорт»; в других категориях на него не опираться.

## Вердикт

**Забрать — чтение.** Запись — отдельным модулем: белый список методов, сухой прогон, журнал, откат, команда
владельца на каждое изменение и каждую сумму. К сайту площадки код с машины владельца не ходит.
