# Справочник — Оценка JEV (TypeSafe AI)

## Краткая суть

- **JEV** (у разработчика — Jev) — облачная модель компании TypeSafe AI, Inc. Она не генерирует текст. На вход —
  данные (`state`) и список вопросов трёх типов: «да/нет», «выбор из списка», «оценка по шкале». На выход — по
  каждому вопросу значение этого типа и вероятности. Вышла 15.09.2026, текущая версия `jev-1.13.0`.
- **Вердикт: только в песочнице.** Работаем через свой клиент (навык `jev`, черновик) на публичных или
  обезличенных данных. Официальный плагин для Claude Code не ставим. В боевые контуры не подключаем, пока нет
  замера на своих русских текстах.
- Три оговорки, от которых зависит всё остальное:
  1. **Русский язык не заявлен.** Документация называет основным английский, про остальные — «принимаются, но
     хуже». Качество на русском известно только из собственного замера.
  2. **Уверенность — не правильность.** Число уверенности считается из распределения вероятностей по формуле и
     показывает, насколько ответ «собран в одну точку». Гарантирован формат ответа, а не истинность.
  3. **Экономия в деньгах у небольших потоков ничтожна.** Миллион входных токенов стоит 0,042 $; тысяча записей —
     центы и на этой модели, и на дешёвой языковой. Выигрыш, если он есть, — в скорости и в вероятности, по
     которой можно развести «делаю сам» и «отдаю человеку».

Статусы фактов ниже: **документация** — прочитано на официальной странице 05.10.2026; **слова автора видео** — не
проверено, источник — расшифровки в `_исходные-заметки\JEV (TypeSafe AI)\`; **наш замер** — проверено на этом
устройстве; **сторонний источник** — чужой блог или каталог, не разработчик модели.

## 1. Что это и тип

Облачный сервис с HTTP-интерфейсом — не плагин и не библиотека. Разработчик — TypeSafe AI, Inc. (Сан-Франциско).
Модель закрытая, условия использования — договор с клиентом (Master Customer Agreement, редакция 23.09.2026).
Вокруг — открытые компоненты разработчика под лицензией MIT: пакет для Python `typesafe-sdk` (0.7.2 от
26.09.2026), пакет для JavaScript `@typesafe-ai/sdk` (0.6.0), навык для агентов, узел для n8n и
`system-one-adapter-python` — замена клиента, которая задаёт те же вопросы обычной языковой модели (пригодится
как базовая линия при сравнении). Код замеров разработчика `WorkflowEvals` открыт под Apache-2.0.

Запрос — три поля: `model`, `state` (строка, объект или массив — только текст), `questions` (словарь «имя вопроса
→ вопрос»). Вопрос — это `type`, `instructions` и `criteria`:

| Тип | Что спрашиваем | `criteria` | Что возвращает |
|---|---|---|---|
| `noul` | выполняется ли условие | необязательно: `{"true": "...", "false": "..."}` | `noul` — вероятность «да» от 0 до 1 |
| `choice` | один вариант из набора | обязательно: словарь «вариант → описание», до 255 | `choice`, `probabilities`, `confidence` |
| `score` | место на упорядоченной шкале | обязательно: массив описаний уровней, от 2 до 10 | `score` (может быть дробным), `legend`, `probabilities`, `confidence` |

Все вопросы одного запроса считаются по одному `state` параллельно и не видят ответов друг друга. В ответе также
`model` (точная версия) и `usage` (число входных и выходных токенов).

**Как считается уверенность** (документация, `/confidence`):

- `choice`: `(p_max − 1/n) / (1 − 1/n)`, где `n` — число вариантов. Учитывается только вероятность победителя.
- `score`: единица минус средневзвешенное расстояние до самого вероятного уровня, делённое на среднее расстояние
  от среднего уровня при равномерном распределении; не меньше нуля.
- `noul`: поля нет. Если нужна одна шкала с остальными — `|2p − 1|`.

Наш вывод из формулы, не цитата: одно и то же число уверенности соответствует разной вероятности победителя при
разном числе вариантов. При двух вариантах уверенность 0,7 — это вероятность 0,85; при шести — 0,75. Документация
предлагает `confidence` как общую шкалу для старта («on the same 0 to 1 scale for every question»), а про
вероятность победителя пишет прямо: «set its threshold per question». Мы ставим порог на каждый вопрос отдельно и
по вероятности выбранного ответа.

Популярность: шум большой, но мерить им нечего. У репозитория навыка 2 586 звёзд при двух коммитах — к таким
числам относимся со скепсисом, как записано в правилах волта.

## 2. Как подключается

Ключ создаётся в кабинете `console.typesafe.ai` либо берётся ключ OpenRouter. Заголовок —
`Authorization: Bearer <ключ>`.

Официальные команды установки (не выполнялись):

```
pip install typesafe-sdk
npm install @typesafe-ai/sdk
claude plugin marketplace add typesafe-ai/skills
claude plugin install typesafe@typesafe-ai
npx skills add typesafe-ai/skills --skill typesafe-ai      # другие агенты; -g — глобально
```

У нас ничего из этого не ставится: навык `jev` (`_Движок\Исходники скиллов\jev`) ходит в HTTP-интерфейс клиентом на
стандартной библиотеке Python. На этом устройстве системный `curl` открывает эти адреса только с
`--ssl-no-revoke` (наш замер; вероятная причина — проверка отзыва сертификатов в нашей сети, а не свойство
Windows).

## 3. Требования

- Ключ и положительный баланс. Оплата — зарубежной картой (слова авторов видео); способы оплаты и минимальная
  сумма в кабинете TypeSafe в документации не описаны (не найдено). У OpenRouter: минимум 5 $ за пополнение;
  комиссия 5,5 % для карт (не меньше 0,80 $) и 5 % для криптовалюты; принимаются карты, AliPay и USDC; новым
  пользователям даётся небольшой бесплатный остаток (документация OpenRouter).
- Пределы частоты напрямую: 100 тысяч токенов и 80 запросов в секунду, «can change without notice» (документация).
- Пакеты, если понадобятся: Python 3.10+ или Node 20+. Нашему клиенту нужен только Python.

## 4. Что создаёт и меняет

- Сам сервис на устройстве ничего не создаёт.
- Плагин Claude Code — один файл `SKILL.md`; хуков, фоновых процессов, MCP-сервера и правок `CLAUDE.md` в
  репозитории нет (репозиторий разработчика `typesafe-ai/skills` на GitHub; MCP-сервера у TypeSafe не найдено).
  Файлы ложатся в каталог плагинов Claude Code в профиле пользователя — по устройству Claude Code, установкой не
  проверялось. Автообновление включается вручную — тогда текст навыка меняется без нашей проверки.
- Пакет для Python — только код в окружении: скриптов установки и телеметрии в колесе не найдено (прочитано без
  запуска).

## 5. Глобальность влияния

- `claude plugin install` ставит плагин в область `user`, то есть на все проекты устройства. **Наш замер:**
  `claude plugin install --help` → `--scope <scope> ... (default: "user")`. В документации TypeSafe область не
  названа. Это тот самый красный флаг №1 стандарта.
- `npx skills add` по умолчанию ставит в проект, с `-g` — глобально (документация).
- Наш навык живёт как остальные: исходник в каноне, в `~/.claude/skills` — ссылка, которую ставит владелец после
  вердикта. До замеров ссылки нет.

## 6. Конфликты с нашей средой

- Имён `typesafe` и `jev` среди навыков и плагинов устройства нет (наш замер, 05.10.2026).
- У официального навыка открыта жалоба: описание срабатывает на разговоры о «type-safe» коде, то есть может
  включаться без нужды (сторонний источник: issue #2 в `typesafe-ai/skills`).
- Официальный навык расходится с двумя нашими правилами. Он велит агенту читать живую документацию из сети как
  часть задачи — это внешний текст в контексте агента. И документация предлагает дать агенту ключ со словами
  «run some experiments» — у нас платный вызов идёт после названной цены и «да» владельца.
- Смысловое пересечение — с навыком `llm-pipeline-economy`: решатель встаёт в его порядок решений отдельной
  ступенью, см. [Методология — Модели-решатели в конвейере](<../../../Методологии/Методология — Модели-решатели в конвейере.md>).

## 7. Безопасность

**Данные** (документация: политика конфиденциальности от 19.11.2025, соглашение об обработке данных от
24.04.2026, договор от 23.09.2026, страница доверия):

- На запросах клиентов модель не обучают: «We will not train or fine tune any artificial intelligence or machine
  learning models on your prompts or other Input». В договоре мягче — «without Customer's prior consent».
- Запросы хранятся и обрабатываются в AWS, США. Срок хранения числом не назван: «as long as necessary». Режим без
  хранения — только для корпоративных клиентов по запросу.
- Бессрочно разработчик вправе использовать сами запросы и ответы, чтобы выводить из них «телеметрию», отслеживать
  злоупотребления и исполнять закон (договор, §4.1). Телеметрию — «technical logs, hashes, summary statistics and
  classifications, metrics, and learnings related to Customer's use of the Services» — он может обрабатывать «without
  restriction, including to improve the Services» (§4.3).
- Вычислительные подрядчики (Modal, Nebius, CoreWeave) запросы обрабатывают, но не хранят — по заявлению
  разработчика.
- Через OpenRouter добавляется второй обработчик. По умолчанию OpenRouter запросы не хранит, только метаданные;
  провайдер TypeSafe помечен у него как «не обучает, запросы не хранит». Эта метка расходится со страницей доверия
  самого разработчика («stored and processed on databases, caches and compute nodes within AWS»). Считаем, что
  хранит: метка OpenRouter — не гарантия.
- Договор заключает тот, кто принял условия: частное лицо от своего имени либо организация, если кабинет заведён
  от её имени (преамбула договора). От этого зависит, кто отвечает по договору.
- Клиент заверяет, что не числится в списках лиц, с которыми власти США запрещают или ограничивают сделки, не
  находится в стране под эмбарго США и не является её гражданином (§16.12). Условия сайта добавляют: «The Site is
  intended for visitors located within the United States». Россия в текстах не названа; подпадает ли наша
  ситуация — юридический вопрос, здесь он не решён, решает владелец.

**Вывод по данным:** срок хранения неизвестен, сервер в США — по политике канона туда идут только публичные и
обезличенные тексты. Звонки, переписки и заявки клиентов — нет.

**Содержимое как атака.** Документация прямо предупреждает: «Content written to adversarially steer the model...
or text that argues for its own classification, can move the answer». Отзыв, сообщение или объявление — текст
постороннего человека; он может «уговорить» модель. Отсюда правило: необратимое действие по ответу модели без
человека не выполняется.

**Ключ.** В пакете для Python до версии 0.7.1 ключ мог попадать в текст ошибки (документация: журнал изменений,
запись 0.7.1 — «exclude the value from logged exceptions»). В пакете для JavaScript такая жалоба открыта
(сторонний источник: issue #14 в `typesafe-ai/typesafe-sdk-js`). Наш клиент ключ не печатает и в ошибки не
включает.

**Доступность.** Адрес `api.typesafe.ai` с этого устройства достижим (наш замер 05.10.2026: без ключа — код 403 и
текст «Must supply an API key», хотя документация обещает 401; то же расхождение описано в жалобе #8 репозитория
навыка). Обслужит ли сервис запрос с ключом из нашей сети, этот замер не показывает. С сервера не проверяли. Перед сервисом стоит
Cloudflare; есть жалоба, что он отклоняет запрос, если в `state` встречается текст команды `curl` (сторонний
источник).

**Чужие пакеты с похожими именами** — не ставить: в PyPI `typesafe-ai`, `jev`, `system-one`, `typesafe`; в npm
`system-one` и `jev`. Официальные только `typesafe-sdk` и `@typesafe-ai/sdk`.

## 8. Профильность для нас

Подходит узкому классу задач: поток однотипных коротких текстов, по каждому нужно простое решение, критерий можно
записать словами, а после решения есть понятное действие. Для маркетинга и аналитики это разметка отзывов,
объявлений, поисковых запросов, комментариев.

Не подходит и сделает хуже:

- всё, где нужен текст: ответ, черновик, объяснение, цитата-доказательство;
- счёт, арифметика, сравнение дат — «Jev is not a calculator», считать в коде;
- вопросы, где ответ надо вывести, а не узнать в тексте, и вопросы с двойным отрицанием;
- длинный вход с посторонним содержимым — точность падает («context rot»);
- редкие решения: одно в неделю дешевле принять самому;
- задачи, которые закрывает правило в коде.

Особенности, которые надо закладывать в вопросы и проверку (документация, страница известных слабостей от
02.10.2026): читает формулировку буквально; при выборе из списка в части случаев склоняется к первому варианту
(«In some cases, we observed...») — порядок надо переставлять и сверять; вероятности у шкалы не годятся для точных
чисел между уровнями.

**Цена на практике.** Платится весь вход: `state` плюс все вопросы, в каждом запросе заново. В примере
документации короткая фраза и один вопрос дали 296 входных токенов — у запроса есть постоянная часть. Сколько
токенов занимает русский текст, документация не говорит; в стороннем замере норвежский дал около двух символов
на токен. Считать надо по полю `usage` первого же прогона. Порядок величин: тысяча записей по полторы тысячи
токенов — 0,06 $.

**Наш первый замер, 06.10.2026.** Один проверочный запрос через OpenRouter, модель `typesafe/jev-1.13`: русская
фраза и три вопроса, всего 652 символа. Ответила версия `typesafe/jev-1.13-20260917` за 0,64 с; сервис насчитал
619 входных токенов и 0,000026 $ — ровно по прайсу. Это близко к двум символам на токен при постоянной части
около 280 токенов. Ответы на русский текст осмысленные, но один запрос — проверка связи, а не замер качества.

**Наш первый замер качества, 06.10.2026.** Публичные отзывы о компании на русском, 1 301 запись без имён авторов;
вопрос «общий вывод автора отрицательный?», эталон — оценка автора в звёздах (1–2 против 5). Совпало 1 265 из
1 274 (99,3 %); на выборке с равными классами — 138 из 142 (97,2 %, интервал 93,0–98,9 %). Среди ответов с
вероятностью 0,9 и выше верных 1 229 из 1 231. При повторе ответ не изменился ни в одной из 169 записей; при
перестановке вариантов выбор из десяти изменился в 3 из 169. Большая часть расхождений — шум эталона: текст не
соответствует звёздам. Цена — 2 069 запросов за 0,16 $, ровно по прайсу; медиана ответа 0,64 с, один запрос —
63 с. Оговорка: тональность отзыва — лёгкая задача; на коротких поисковых фразах эталона ещё нет. Данные и
подробный отчёт — в проекте, не в каноне.

Карта применимости к конкретному проекту — документ этого проекта, в канон данные компании не попадают.

## Вердикт

**Только в песочнице.**

- Интерфейс модели — пробуем своим клиентом на публичных и обезличенных данных, с эталоном и названной ценой.
- Официальный плагин — **не ставим**: по умолчанию глобальный, тянет в контекст внешнюю документацию, дублирует
  наш навык. Текст прочитан, полезное перенесено в методологию и в навык.
- Официальные пакеты — **позже**: когда понадобится то, чего нет в запросе из трёх полей (асинхронные вызовы,
  готовые типы), и у пакета выйдет версия 1.0 — нынешние меняются с поломками.

Условия перехода в «забрать»: на русских текстах совпадение с человеческим эталоном не ниже порога, принятого для
задачи; вероятности подтверждают себя (среди ответов с 0,9 верных около 90 %); владелец решил вопрос о договоре и
данных. До этого — никакого подключения к боевым потокам и никаких действий без человека.
