# Справочник — Оценка стека Красинского (DuckDB, Parquet, Beads, Syncthing)

## Краткая суть

- Стек автора: данные в Parquet → DuckDB (локально, без развёртывания) → граф Graphify; задачи агентов — Beads;
  синхронизация — git, тяжёлые файлы — Syncthing
  ([Доп8](<../../../Методологии/_Красинский — полный разбор (2026-07)/Доп8 — AI-native компания (воркшоп, как её построить).md>), раздел 1.6).
- **DuckDB — уже используем:** живая база Ядра данных первого инстанса с 14.09.2026. Вердикт `забрать` —
  подтверждён работой, отдельной установки на устройство не нужно (ставится в окружение проекта).
- **Parquet — `забрать` как формат** снимков больших таблиц и выгрузок между системами; пишется самим DuckDB,
  лишних зависимостей не требует. Не вместо Markdown для журналов и баз, которые читает человек.
- **Beads — `позже`, только в песочнице:** `bd init` по умолчанию создаёт и правит `AGENTS.md`, `bd setup claude`
  ставит хуки. У нас ту же работу делают `TASKS.md`, журнал действий и реестр гипотез. Условие пересмотра — на одном
  проекте больше трёх агентов теряют задачи между чатами.
- **Syncthing — `позже`:** полезен, когда появится второе рабочее устройство или понадобится держать тяжёлые
  файлы (базы, записи, выгрузки) синхронно с сервером без ручного копирования.
- Graphify — [отдельная карточка](<Справочник — Оценка graphify.md>): песочница, режим кода, не на ПДн.

> Для быстрого знакомства человеку может хватить блока выше.
> Ниже начинается полный каноничный текст документа.
> Для агентов, правок, анализа, ревью и разрешения расхождений обязателен полный текст.

## Откуда стек

Красинский строит компанию так, чтобы все данные (BI, тикеты, звонки, переписки, события) лежали в одной
связанной системе и агент видел её целиком: сырьё — файлами Parquet, запросы — DuckDB прямо по файлам, связи —
граф Graphify. Задачи агентов ведёт Beads, чтобы агент не застревал в локальном оптимуме; файлы между людьми и
машинами — git, тяжёлое — Syncthing. Названия «Битс» и «SingSync» в расшифровке искажены распознаванием речи;
Beads и Syncthing восстановлены по описанию автора — гипотеза, не цитата.

## DuckDB

| Пункт | Оценка |
|---|---|
| 1. Что это | Встраиваемая аналитическая СУБД (как SQLite, но для аналитики). Открытый код, лицензия MIT |
| 2. Как ставится | Python-пакет `duckdb` в окружение проекта (`uv pip install duckdb`); у первого инстанса — окружение Ядра данных |
| 3. Требования | Python; версия на 14.09.2026 — 1.5.5, ставится на Python 3.14 |
| 4. Что создаёт | Один файл базы (`*.duckdb`) там, где скажешь; серверов и демонов нет |
| 5. Глобальность | Нет: пакет в окружении проекта, в системный Python устройства не ставился (проверено 28.09: `import duckdb` вне окружения — нет модуля) |
| 6. Конфликты | Нет |
| 7. Безопасность | Данные не уходят наружу. Файл базы с ПДн — вне git |
| 8. Профильность | Прямая: аналитика на миллионах строк без сервера |

**Вердикт: `забрать` — уже работает.** Грабли первого инстанса (построчная вставка ≈2,7 мс на строку, `ON CONFLICT
DO UPDATE` при внешнем ключе, откат транзакции) записаны в памяти агента первого инстанса; при переносе Ядра
данных в канон поднимаются в его стандарт.

## Parquet

| Пункт | Оценка |
|---|---|
| 1. Что это | Открытый колоночный формат файлов (Apache). Сжатие, типы колонок, быстрое чтение выборочных колонок |
| 2. Как ставится | Отдельно не ставится: DuckDB пишет и читает Parquet сам (`COPY … TO 'x.parquet'`, `read_parquet('x.parquet')`) |
| 3. Требования | Нет сверх DuckDB. `pyarrow` на устройстве не стоит и не нужен |
| 4–6. Что меняет, глобальность, конфликты | Ничего — это файлы |
| 7. Безопасность | Файл Parquet с ПДн — то же, что таблица с ПДн: вне git, наружу только агрегат |
| 8. Профильность | Снимки больших таблиц «на дату» (известный ответ, заморозка периода), обмен выгрузками между сервером и устройством, архив длинных рядов |

**Вердикт: `забрать` как формат,** когда таблица большая или нужен неизменяемый снимок. Журнал действий и база
инцидентов остаются Markdown: их читает человек и агент без запросов. Автор ведёт журнал инцидентов в Parquet —
у нас это не нужно, пока инцидентов десятки, а не тысячи.

## Beads

| Пункт | Оценка |
|---|---|
| 1. Что это | Распределённый трекер задач для ИИ-агентов с графом зависимостей и памятью (`bd`). Репозиторий `github.com/gastownhall/beads` (прежде у Стива Йегге), лицензия MIT; на 28.09.2026 — около 27,5 тыс. звёзд |
| 2. Как ставится | `npm install -g @beads/bd`; для Windows — скрипт `install.ps1`; есть `brew`, `go install`, MCP-сервер `beads-mcp` (PyPI) |
| 3. Требования | Node (для npm) или Go (сборка); встроенная база Dolt |
| 4. Что создаёт | `bd init` — папка `.beads/` с базой Dolt, **создаёт или обновляет `AGENTS.md` по умолчанию** (выключается `--skip-agents`), git-хуки (выключаются `--stealth`/`--no-git-ops`). `bd setup claude` ставит хуки и настройки Claude Code |
| 5. Глобальность | CLI глобально (npm `-g`); куда пишет `bd setup claude` — в проект или в `~/.claude` — не проверено, по рамке это проверяется в песочнице до вердикта |
| 6. Конфликты | Пересекается с нашими `TASKS.md`, журналом действий, реестром гипотез Движка роста; дописывание `AGENTS.md` и хуки — наложение на канон правил агента |
| 7. Безопасность | Телеметрия в README не описана — не проверено. Синхронизация через git-remote (`refs/dolt/data`) |
| 8. Профильность | Для команд из многих агентов, пишущих код. У нас — владелец и несколько чатов, задачи уже в файлах |

**Вердикт: `позже`, только в песочнице.** Условие пересмотра: на одном проекте больше трёх агентов одновременно, и
задачи теряются между чатами при живых `TASKS.md` и журнале. Пробовать — в изолированной папке с
`bd init --stealth --skip-agents`, без `bd setup claude`.

## Syncthing

| Пункт | Оценка |
|---|---|
| 1. Что это | Открытая программа непрерывной синхронизации папок между устройствами напрямую, без облака. Лицензия MPL-2.0 |
| 2. Как ставится | Установщик или бинарь под Windows/Linux; на сервере — пакет или контейнер |
| 3. Требования | Нет; постоянно работающий процесс на каждом устройстве |
| 4. Что создаёт | Фоновый сервис, веб-интерфейс — по умолчанию только с локального адреса; конфиг в профиле пользователя |
| 5. Глобальность | Устройство целиком (сервис), но проекты и среду агента не трогает |
| 6. Конфликты | Нет с каноном; риск — синхронизировать папку, где работает git или живая база (конфликтные копии файлов) |
| 7. Безопасность | Трафик между устройствами — TLS. Глобальным серверам обнаружения уходят ID устройства и порт, ретранслятору — ID устройства; оба можно выключить. Отчёты об использовании выключены по умолчанию, спрашивает один раз ([документация безопасности](https://docs.syncthing.net/users/security.html), 28.09.2026) |
| 8. Профильность | Тяжёлые файлы вне git: резервные копии баз, записи, выгрузки между сервером и устройством |

**Вердикт: `позже`.** Сейчас одно рабочее устройство, сервер доступен по SSH, копии баз снимаются явно. Условие
пересмотра: второе устройство или регулярная синхронизация больших файлов с сервером. При установке — выключить
глобальное обнаружение и ретрансляторы, если устройства видят друг друга напрямую; папки git и живых баз не
синхронизировать.

## Что не проверено

- Beads: куда именно пишет `bd setup claude` и есть ли телеметрия — README об этом молчит, установку не запускали.
- Число звёзд Beads — снимок страницы на 28.09.2026, популярность — со скепсисом.
- Что Красинский имел в виду именно Beads и Syncthing — восстановлено по описанию, в записи названия искажены.
