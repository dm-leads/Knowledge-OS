# Справочник — Оценка graphify

## Краткая суть

- **graphify** (PyPI `graphifyy`, команда `graphify`; Apache-2.0/MIT) превращает кодовую базу + доки/SQL/PDF в **запрашиваемый граф знаний** (GraphRAG по коду).
- Тип: **CLI + скилл для Claude Code** (и Cursor/Codex/…) + **опциональный MCP-сервер**. 98k★, активно развивается.
- **Исполняемый инструмент, трогает среду:** `graphify install` пишет в `.claude/`, умеет ставить хук `PreToolUse`, режим `--strict` навязывает «сначала спроси граф».
- **Вердикт: в песочнице, код-режим.** ✅ Полезен для наших КОД-репозиториев локально/бесплатно/безопасно. ⚠️ Семантический режим (доки/PDF) шлёт содержимое в бэкенд → **не на ПДн/секреты**. Ставить в project-scope, не глобально.

## Проверка среды (2026-07-28)

- graphify **НЕ установлен**. Python **3.14** есть, **uv** есть, `pipx` нет (не нужен).

## Как ставится / что делает

```
uv tool install graphifyy      # CLI (глобальный бинарь uv-tool — сам по себе поведение ассистента не меняет)
graphify install               # ⚠️ ставит скилл/хук в .claude/ — делать ТОЛЬКО с --project
/graphify .                    # построить граф текущей папки (в Claude Code)
# или напрямую CLI, без установки скилла:
graphify .                     # → graphify-out/
```

Выдаёт в `graphify-out/`: `graph.html` (интерактив), `GRAPH_REPORT.md`, `graph.json`, `cache/`, `cost.json`. Запросы: `graphify query "…"`, `graphify path A B`, `graphify explain "…"`. MCP: `python -m graphify.serve graphify-out/graph.json`.

## Требования

- Python 3.10+ (у нас 3.14), uv или pipx.
- **Код-режим — без API-ключа** (tree-sitter AST, 36 языков, локально).
- **Семантический режим** (доки/PDF/картинки) — нужен API-ключ бэкенда (Anthropic/OpenAI/Gemini/**Ollama** локально/…), тратит кредиты.

## Что создаёт / меняет

- В проекте: `graphify-out/`, `.graphifyignore` (опц.), при `graphify install` — конфиги `.claude/`/`.cursor/` и хук `PreToolUse`.
- Логи запросов — opt-in локально (`~/.cache/graphify-queries.log`). **Телеметрии нет.**

## Глобальность влияния и конфликты

- `graphify install` без `--project` → влезает в среду ассистента (скилл + хук + возможный `--strict`) во всех проектах.
- **Снимается скоупом:** `graphify install --project` в одном репо, либо вообще без `graphify install` — использовать CLI `graphify .` напрямую. Тогда конфликтов с нашей средой нет.

## Данные и приватность (ключевое для нас)

- **Код** — парсится локально, наружу ничего не уходит. Безопасно.
- **Доки/Markdown/PDF/картинки** — при семантическом извлечении **отправляются в выбранный бэкенд**. → Наша Markdown-база (Второй мозг, транскрипты) содержит ПДн/секреты → **на боевом контенте с облачным бэкендом нельзя**. Для графа по знаниям — только локальный бэкенд (Ollama) и без секретов.

## Профильность для нас

- ✅ **КОД-репозитории** (MCP-серверы, скрипты, speech-analytics core, пайплайны Ozon/отзывов) в код-режиме — законная чистая польза: быстро понять/онбордить чужой код, увидеть связи.
- ⚠️ **Контент/знания** — полезный режим утекает данные; на ПДн не применять.

## Как использовать у нас (безопасный рецепт)

1. Один раз: `uv tool install graphifyy` (глобальный CLI-бинарь, безвреден).
2. В нужном **код-репозитории**: `graphify .` (код-режим, без ключа) → смотрим `graphify-out/graph.html` + `GRAPH_REPORT.md`.
3. `graphify install` — **не** глобально. Если нужен слэш `/graphify` в конкретном репо — только `--project` там.
4. Никогда не направлять на сырые транскрипты/`Secrets` с облачным бэкендом.

## Валидация «в поле» (эфир Красинского, 2026)

- Илья Красинский использует graphify как **ядро root-cause аналитики** на клиентах с 2,5 млн пользователей: подцепляет нодами код-базу + все события/параметры + тикеты Jira + обращения → агент по графу за 2-3 вопроса находит корневые причины там, где данные размазаны по 5-7 системам.
- Ключевая мысль: **каждой связи дописывается причинно-следственный тег**, и визуализация нужна **не человеку, а агенту** — он по ней «раскапывает» до корня (в духе Теории ограничений Голдратта).
- Это прямо подтверждает нашу гипотезу применения в **сквозной аналитике** (Roistat↔amoCRM↔МойСклад): graphify — слой понимания поверх описанной модели. Полная дистилляция: `D:\Knowledge-OS\Методологии\Эфиры (разборы)\NOTE-SRC-Prodakt-novogo-vremeni-v-mire-AI-2026-distill.md`.

## Будущее направление: graphify как навык для коллег

- **Где реально ценен:** есть код/артефакты + события/аналитика/тикеты для корреляции, и нужно, чтобы агент быстро нашёл корневую причину. Техническо-аналитические контексты, не универсально.
- **Форма:** обернуть в **исполняемый проектный навык** (как у Красинского): «папка/репо → `graphify .` → graph.json + отчёт → агент отвечает на вопросы о корневых причинах». Коллега указывает проект.
- **Предел:** для сотрудника с одним лендингом — избыточно; семантический режим шлёт данные в бэкенд → на ПДн только локальный бэкенд (Ollama).
- **Рекомендация:** сделать **проектным** навыком (не глобальным), сначала обкатать на нашем кейсе (сквозная аналитика или один репо), потом делиться с коллегами с инструкцией.

## Вердикт

**В песочнице, код-режим.** Пробовать на реальном код-репозитории локально; для графа по знаниям — сначала локальный бэкенд и обезличенный срез. Будущее — проектный навык для аналитики/разработки после обкатки.
