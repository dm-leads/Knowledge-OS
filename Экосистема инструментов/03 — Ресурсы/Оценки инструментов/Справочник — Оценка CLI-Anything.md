# Справочник — Оценка CLI-Anything

## Краткая суть

- **Что это.** Методика из 7 фаз и плагин Claude Code: агент читает исходники программы, строит для неё командную
  утилиту на Python (Click) с выводом JSON, REPL, тестами и файлом навыка `SKILL.md`. К методике прилагается
  каталог из 79 готовых утилит (GIMP, Blender, LibreOffice, Obsidian, n8n, Zotero, браузер и др.) и менеджер `cli-hub`.
- **Где работает.** Программа с открытыми исходниками, своим движком, файловым форматом или API. Закрытый
  веб-сервис без API (конструктор сайта) напрямую не берётся: строить утилиту не из чего.
- **Ценность для нас — методика**, а не установка: как превратить разведанный интерфейс в набор проверяемых
  команд для агента (группы команд, JSON-контракт, «используй настоящую программу, не переписывай её», тесты на
  реальном движке, навык с границами).
- **Риски.** Плагин из маркетплейса ставится глобально (во все проекты машины). `cli-hub` по умолчанию шлёт
  телеметрию в PostHog — отключается только переменной `CLI_HUB_NO_ANALYTICS=1`. Установщик плагина написан под
  Linux.
- **Вердикт:** забрать методику как справочник; плагин и `cli-hub` глобально не ставим; готовую утилиту из
  каталога — только в песочнице и с отключённой телеметрией.

> Для быстрого знакомства человеку может хватить блока выше.
> Ниже начинается полный каноничный текст документа.
> Для агентов, правок, анализа, ревью и разрешения расхождений обязателен полный текст.

## Оценка по рамке

| № | Пункт | Что нашли |
|---|---|---|
| 1 | Что это и тип | Методика (`cli-anything-plugin/HARNESS.md` и `guides/`) + плагин Claude Code с командами `/cli-anything`, `:refine`, `:test`, `:validate`, `:list` + каталог готовых утилит (папка на программу, `agent-harness/`) + менеджер `cli-hub` (PyPI `cli-anything-hub`) + мета-навык `cli-hub-meta-skill`. Есть сборки под Codex, Cursor, OpenCode и другие |
| 2 | Как ставится | Плагин: `/plugin marketplace add HKUDS/CLI-Anything`, затем `/plugin install cli-anything`; вручную — копия `cli-anything-plugin` в `~/.claude/plugins/`. Каталог: `pip install cli-anything-hub`, затем `cli-hub install <имя>`. Навык: `npx skills add HKUDS/CLI-Anything --skill <имя> -g -y`. Под Windows нужен Git Bash с `cygpath` |
| 3 | Требования | Python 3.10+, Click 8+. Каждая утилита требует свою настоящую программу (GIMP, Blender и т. п.). Браузерная утилита — Node.js, Chrome и расширение DOMShell |
| 4 | Что создаёт и меняет | Плагин: только команды и справочные файлы, хуков и MCP нет. Генератор пишет в целевую папку пакет Python, `TEST.md`, `SKILL.md` и `setup.py` и ставит утилиту в PATH (`pip install -e .`). `cli-hub` хранит в профиле пользователя файл `.analytics_id` |
| 5 | Глобальность | Плагин из маркетплейса и `npx skills … -g` — глобально, во все проекты машины, включая рабочие контуры. Утилита через `pip` — в окружение Python |
| 6 | Конфликты | Команда `/cli-anything` и навыки утилит пересекаются только по названиям программ, которых у нас нет. Риск — мета-навык CLI-Hub, который сам ищет и ставит утилиты из каталога: обходит нашу оценку инструментов |
| 7 | Безопасность | `cli-hub/cli_hub/analytics.py`: телеметрия PostHog включена по умолчанию, отключается `CLI_HUB_NO_ANALYTICS=1`. Установщик `setup-cli-anything.sh` ищет методику по пути `/root/cli-anything` (Linux). Утилиты каталога — код сообщества: в новостях репозитория исправления обхода путей и инъекций (Sketch, GIMP) — каждую читать до запуска |
| 8 | Профильность | Методика — общая и полезная: как превратить программу или разведанный веб-интерфейс в набор команд для агента. Готовые утилиты в основном для дизайна, видео, 3D и науки; из близких нам — Obsidian, n8n, Mailchimp, браузер. Маркетинговых сервисов Рунета нет |

## Вердикт

**Забрать методику как справочник.** Плагин и `cli-hub` глобально не ставим. Готовую утилиту из каталога — только в
песочнице, после чтения её кода и с `CLI_HUB_NO_ANALYTICS=1`. Мета-навык CLI-Hub не ставим: он сам устанавливает
инструменты в обход оценки.

## Как применять: закрытый веб-конструктор без MCP

Случай — конструктор сайта, у которого нет MCP и открытого API, а у владельца есть вход в кабинет. CLI-Anything
строит утилиту из исходников, поэтому такой сервис сначала разведывают, а методику берут для оформления итога.

1. **Разведка только чтением.** Браузер агента (Playwright) с входом, который делает владелец. Запрет записи — в
   коде, а не в просьбе: перехват запросов отменяет всё, кроме `GET` и `HEAD`, к домену сервиса. Агент ходит по
   разделам, снимает экраны и журнал сетевых запросов редактора.
2. **Карта внутренних запросов.** Из журнала — какие адреса отдают страницы, блоки, настройки, товары и в каком
   формате. Перехват трафика и сборка клиента к недокументированному API — инструмент
   [mimic](<Справочник — Оценка mimic.md>); захват обезличивать.
3. **Обёртка по методике HARNESS.md.** Если разведка показала стабильные запросы на чтение: группы команд
   («страницы», «блоки», «разметка», «товары»), вывод JSON, тесты на живом кабинете, `SKILL.md` с границами.
   Команды записи в обёртку не входят без отдельного решения владельца и снимка «до».
4. **Граница.** Обёртка над недокументированными запросами ломается при обновлении сервиса и может нарушать его
   условия. Перед постоянным использованием — читать условия сервиса и держать проверку на известных ответах.

## Открытые вопросы

- Насколько браузерная утилита на DOMShell лучше уже стоящего у нас браузера Playwright MCP — не проверено.
- Качество генератора на чужой программе не замерялось: оценка по документации и коду, без прогона.
