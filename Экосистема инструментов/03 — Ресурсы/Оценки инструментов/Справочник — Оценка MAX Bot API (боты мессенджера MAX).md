# Справочник — Оценка MAX Bot API (боты мессенджера MAX)

## Краткая суть

- **MAX Bot API** — HTTP API ботов мессенджера MAX (VK): `https://platform-api2.max.ru/`, токен в заголовке
  `Authorization`. Бот заводит только верифицированная организация, ИП или самозанятый — резидент РФ, через
  платформу «MAX для бизнеса»; бот проходит модерацию до 48 часов по рабочим дням.
- **Что бот умеет:** отвечать в диалоге, принимать диплинк с параметром (`https://max.ru/<бот>?start=<до 128
  знаков>` → событие `bot_started`, поле `payload`), кнопки (ссылка, обратный вызов, запрос контакта с проверкой
  номера), вложения, публикация в канал и группу, где он администратор, назначение других администраторов.
- **Чего не умеет:** создать группу или канал, выдать ссылку-приглашение, отправить сообщение по расписанию.
  Добавление участников в группу (`POST /chats/{chatId}/members`) с 09.09.2026 ограничено, что именно — в
  документации не сказано; в канал этим методом не добавить никого.
- **Вывод для вебинаров:** «новая группа на каждый эфир, человек входит по ссылке, бот шлёт напоминания» в MAX
  делается так: группу и ссылку создаёт человек в мессенджере, бота туда добавляют и назначают администратором
  руками, а напоминания по расписанию шлёт наш сервер через `POST /messages`. Проще и надёжнее — напоминания
  ботом в личный диалог: человек сам нажал «Начать», диплинк принёс номер заявки.
- **Вердикт: забрать.** Для проектов с аудиторией, которая сидит в MAX больше, чем в Телеграме. Статус — по
  документации; рабочие ограничения подтверждаются пробой (раздел «Что проверить пробой»).

> Для быстрого знакомства хватит блока выше. Для агентов и правок обязателен полный текст.

## 1. Что это и тип

Облачный REST API платформы MAX для партнёров. Не ставится: к нему ходит наш сервер или скрипт. Есть
официальная схема OpenAPI ([max-messenger/api-schema](https://github.com/max-messenger/api-schema)) и библиотеки
JS/TS (`@maxhub/max-bot-api`) и Go; официальной библиотеки на Python в документации нет — клиент пишется на
`httpx`/`requests` по схеме или генерируется из неё. Есть навык для агентов от самих MAX —
[max-agents-skill](https://github.com/max-messenger/max-agents-skill), не оценён.

Источник всех фактов ниже, если не сказано иное, — [dev.max.ru](https://dev.max.ru/docs-api), чтение 05.11.2026.

## 2. Как подключается

| Шаг | Как | Ловушка |
|---|---|---|
| Верификация владельца | [business.max.ru/self](https://business.max.ru/self) или мини-приложение «MAX для бизнеса»; организацию подтверждает руководитель или лицо с правом подписи — Госуслуги (роль «Руководитель» / «Администратор»), T-Business ID, Alfa ID | физлица и нерезиденты не проходят; делает человек с правом подписи, не исполнитель |
| Создание бота | раздел «Чат-боты» → «Создать»; лимит — 5 ботов на организацию или ИП, 2 на самозанятого | имя бота генерируется (`id<ИНН>_bot`), выбрать нельзя |
| Модерация | до 48 часов по рабочим дням; статусы «На модерации» → «Опубликован» / «Нужны исправления» | пока бот на модерации, настройки не меняются — закладывать срок в план |
| Токен | «Чат-боты» → ⋮ → «Настройки», или командой «Получить токен» в боте «MAX для бизнеса» | токен могут отозвать за нарушение правил платформы |
| Бот в группах | по умолчанию его нельзя добавить в группу: «Настройки» → «Приватность» | забыть — и бот «не добавляется» без понятной ошибки |
| Сертификат | документация просит добавить в доверенные сертификат Минцифры | без него запросы с сервера падают на TLS |

## 3. Требования

- Адрес — `https://platform-api2.max.ru/` (не `platform-api`), заголовок `Authorization: <токен>`; токен в
  параметрах адреса больше не принимается.
- Лимиты: 30 запросов в секунду на платформу; не больше 2 сообщений в секунду в один диалог, группу или канал.
- События — вебхук (`POST /subscriptions`: HTTPS, порт 443, ответ 200 за 30 секунд, секрет в заголовке
  `X-Max-Bot-Api-Secret`; до 10 повторов, через 8 часов без успеха — отписка) **или** long polling
  (`GET /updates`, документация не советует его для боевого режима). Одновременно — нельзя. С 25.05.2026 вебхук
  по HTTP и самоподписанный сертификат не принимаются.
- Типы событий: `bot_started`, `bot_stopped`, `bot_added`, `bot_removed`, `message_created`, `message_callback`,
  `user_added`, `user_removed`, `chat_title_changed`, `dialog_*`, `message_edited/removed`, `comment_*`,
  `bot_admin_permissions_changed` (последнее — только вебхуком).

## 4. Что создаёт / меняет

| Возможность | Метод или способ | Статус |
|---|---|---|
| Сообщение в диалог, группу, канал | `POST /messages` (`user_id` или `chat_id`), текст до 4 000 знаков, `markdown`/`html`, до 12 вложений | есть |
| Кнопки | `inline_keyboard`: `link`, `callback` (ответ — `POST /answers`), `request_contact` (поле `hash` — проверка, что номер принадлежит аккаунту), `message`, `open_app`, `clipboard`, `request_geo_location`; до 210 кнопок, 30 рядов | есть |
| Диплинк с параметром | `https://max.ru/<бот>?start=<payload>`, до 128 знаков; приходит в `bot_started.payload` | есть |
| Отправка по расписанию | — | **нет**, расписание держит наш сервер |
| Создать группу или канал | — | **нет**, только руками в мессенджере |
| Ссылка-приглашение | — | метода нет; у администратора группы есть право `edit_link`, сама ссылка — в интерфейсе |
| Добавить участников в группу | `POST /chats/{chatId}/members`, до 100 `user_ids`, нужно право `add_remove_members`; ошибки `add.participant.privacy`, `add.participant.not.found` | **ограничен с 09.09.2026**, в канал — нельзя |
| Назначить администраторов | `POST /chats/{chatId}/members/admins`, права `read_all_messages`, `write`, `pin_message`, `add_remove_members`, `add_admins`, `edit_link` и др. | есть; **первого** бота-администратора назначают руками |
| Публикация в канал | `POST /messages` с `chat_id` канала; у бота права `write` + `read_all_messages`; бота сначала добавляют подписчиком руками | есть |
| Список чатов бота | `GET /chats` | **снят с июня 2026**; `chat_id` берётся из событий `bot_added` / `message_created` |

## 5. Глобальность влияния

Ничего не ставит на машину. Бот — объект платформы, привязан к организации; изменения в группах и каналах
делает бот с выданными правами. Отписка вебхука, отзыв токена и удаление бота — в платформе.

## 6. Конфликты с нашей средой

- **Сервер для вебхука** нужен с настоящим сертификатом и портом 443. Расписание напоминаний — таймером
  (например, функция и таймер Yandex Cloud); расписание GitHub Actions для этого ненадёжно (по практике
  проектов — пропуски запусков).
- **Сертификат Минцифры** на машине или сервере, откуда идут запросы.
- **Python**: официальной библиотеки нет — тонкий клиент на `httpx` по схеме OpenAPI.

## 7. Безопасность

- Токен — секрет: в файле секретов проекта под именем вроде `MAX_BOT_TOKEN`, в код и чат — никогда. Секрет
  вебхука — отдельной переменной.
- `user_id`, имя, номер из `request_contact` — персональные данные: хранить минимум, связывать с заявкой по
  номеру из диплинка, а не по телефону; основание — согласие из формы заявки.
- Конфиденциальное в `payload` диплинка не передавать — он виден в ссылке.
- Рассылка — только тем, кто сам начал диалог; правила платформы (`/docs/legal/rules/`) прочитать до запуска.

## 8. Профильность для нас

Высокая там, где аудитория сидит в MAX: напоминания о вебинарах и зумах, выдача ссылок и материалов, приём
контакта с проверкой номера, публикация в свой канал. Для чтения чужих групп и каналов API не предназначен.

## Схема «форма → бот → напоминания о вебинаре» — Телеграм и MAX

| Шаг | Телеграм | MAX |
|---|---|---|
| Человек оставляет заявку на сайте | форма → страница «спасибо» с кнопкой бота | то же |
| Переход в бота с номером заявки | `t.me/<бот>?start=<payload>` | `max.ru/<бот>?start=<payload>` → `bot_started.payload` |
| Группа на конкретный эфир | создаёт человек (Bot API группы не создаёт); ссылку-приглашение бот может выдать сам (`createChatInviteLink`) | создаёт человек; ссылку берёт из интерфейса; бот выдаёт её кнопкой `link` |
| Бот в группе | добавить и сделать администратором | добавить руками, первого бота-администратора — руками; включить «Приватность» |
| Напоминания | наш сервер по расписанию → `sendMessage` | наш сервер по расписанию → `POST /messages` в группу или в личный диалог |
| Отметка в CRM, что подписался | по `payload` → номер заявки | так же |

Простой путь для MAX без ручной группы на каждый эфир: напоминания в **личный диалог** с ботом всем, кто пришёл по
диплинку эфира; группа или канал — по желанию, если нужно общение участников.

## Что проверить пробой

| Вопрос | Почему не ясно |
|---|---|
| Что именно ограничено в `POST /chats/{chatId}/members` с 09.09.2026 | в документации только факт ограничения |
| Может ли бот первым написать человеку, который не нажимал «Начать» | правила в документации не описаны |
| Как бот попадает в закрытую группу или канал и видит ли `user_added` по ссылке | описано частично |
| `GET` и `DELETE /chats/{chatId}/members`, `POST /uploads`, `POST /answers` | страницы не прочитаны |
| Правила платформы и требования к содержанию ботов | не прочитаны |
| Срок модерации на практике | заявлено до 48 часов |

## Вердикт

**Забрать** для напоминаний, выдачи ссылок и публикации в свой канал. Группы и ссылки-приглашения — руками,
расписание — нашим сервером. Перед боевым запуском закрыть таблицу «Что проверить пробой».
