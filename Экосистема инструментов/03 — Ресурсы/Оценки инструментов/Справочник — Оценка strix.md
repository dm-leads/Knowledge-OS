# Справочник — Оценка strix

## Краткая суть

- **Что.** [usestrix/strix](https://github.com/usestrix/strix) — автономный ИИ-агент для проверки
  безопасности. Отличие от обычных сканеров: не просто перечисляет подозрительные места,
  а **пытается воспроизвести уязвимость** и приложить подтверждение.
- **Вердикт: `позже — и только в песочнице`.** Инструмент нам понадобится, но три условия ещё
  не выполнены, и одно из них блокирующее.
- **Блокирует прямо сейчас:** нужен Docker, а на машине его нет — фактическая проверка 14.08.2026.
- **Главное правило при использовании:** запускать только против того, что принадлежит нам,
  и с письменного согласия заказчика. Это не наша осторожность, это требование самого
  репозитория и закон.

---

## 1. Что это и тип

| | |
|---|---|
| Тип | **Исполняемый харнесс**: CLI + песочница в Docker + агенты на LLM |
| Автор | usestrix |
| Лицензия | Apache 2.0 |
| Режимы | Локальный анализ кода · живой веб-сайт · API по OpenAPI/Swagger/Postman · CI/CD |

По водоразделу стандарта это **не пассивный справочник**: он ставится в среду, поднимает
контейнер и обращается наружу. Значит по умолчанию — проектный уровень, не глобальный.

## 2. Как ставится

Дословно из репозитория:

```
curl -sSL https://strix.ai/install | bash          основной способ, нам НЕ подходит
npx skills add usestrix/strix                      навык для агентов — в глобальную среду
```

Есть пакет на PyPI — `strix-agent`.

**Под Windows.** Первая команда выполнится только в Git Bash или WSL, и это тот самый красный
флаг из пункта 7 стандарта: скрипт с внешнего сайта исполняется без чтения. **Ставить надо
из PyPI изолированно:**

```
uv tool install strix-agent          изолированное окружение
uv tool uninstall strix-agent        обратимость одной командой
```

## 3. Требования

| Требование | Состояние на 14.08.2026 |
|---|---|
| **Docker, запущенный** | **не установлен** — проверено `docker --version` |
| Python | есть, 3.14.2 |
| Изолятор пакетов | есть, uv 0.11.18 |
| Ключ LLM-провайдера | нужен отдельный: OpenAI, Anthropic, Google, Bedrock, Azure или локальная модель |
| Ключ Perplexity | опционально |

Docker — блокирующее условие. Без него инструмент не запускается вовсе.

## 4. Что создаёт и меняет

- `~/.strix/cli-config.json` — конфигурация
- `strix_runs/<имя-прогона>` — результаты прогона, в рабочей папке
- При первом запуске **скачивает образ песочницы Docker**
- `strix view` — локальный просмотрщик отчёта: читает файлы с диска, наружу ничего не отправляет

Наш `CLAUDE.md` не правит, хуки не ставит, демонов не поднимает.

## 5. Глобальность влияния

Здесь два разных сценария, и путать их нельзя:

| Способ | Уровень | Допустимо ли |
|---|---|---|
| `uv tool install strix-agent` | CLI в PATH, поведение ассистента не меняет | приемлемо |
| `npx skills add usestrix/strix` | **навык в глобальную среду — включится во ВСЕХ проектах машины** | **нет**, по нашему же правилу |

Второй вариант кладёт исполняемый навык туда же, где живут наши `kos-*` и `lark-*`. Правило
матрицы прямое: исполняемое и «мнящее» в глобальный уровень не идёт.

## 6. Конфликты с нашей средой

Пересечений нет — проверено фактически, а не по памяти:

- В `~/.claude/skills` 32 навыка, `strix` среди них отсутствует
- В `claude mcp list` десять серверов, strix среди них нет
- Имя команды `strix` уникально, наши скрипты его не занимают

Новый компонент среды один — Docker. Он тянет свои требования к диску и правам, но с нашими
инструментами не конфликтует.

## 7. Безопасность

Четыре риска, по убыванию важности.

**Инструмент реально атакует цель.** Это не анализатор, а действующий пентестер: он шлёт запросы,
подбирает, пробует обойти защиту. Репозиторий пишет прямо: *«Authorized use only… only run it
against systems you own or have explicit, written permission to test. Unauthorized testing
is illegal in most jurisdictions»*. Отсюда наше правило: **письменное согласие заказчика
до первого запуска**, даже если сайт делали мы сами.

**Установка скриптом с внешнего домена.** Исполнение непрочитанного кода. Обходится установкой
из PyPI через `uv tool install`.

**Содержимое уходит в LLM-провайдера.** Агент отдаёт модели код и ответы сайта. Значит:
не направлять на страницы с персональными данными студентов, не пускать на боевую базу.
Для проверки — копия сайта на тестовом контуре с обезличенными данными.

**Облачная платформа `app.strix.ai` — опциональна.** Локальный просмотр отчёта ничего
не выгружает. Телеметрии по умолчанию в описании не заявлено; при установке проверить ещё раз.

## 8. Профильность для нас

Для маркетинга, контента и аналитики — **нулевая**. Но контур это перерастает.

**Проекту «Учебный центр» инструмент понадобится, и скоро.** По решению от 13.08 сайт собирается
**кодом**, а не конструктором, и на нём будет: форма заявки, приём онлайн-оплаты, связка
с GetCourse и Битрикс24. То есть свой код, свой сервер и **персональные данные студентов** —
имена, телефоны, оплаты.

Конструктор вроде Tilda берёт безопасность на себя. Код на своём сервере — нет. Это прямое
следствие решения, которое мы приняли осознанно, и strix закрывает возникший разрыв.

Отдельно: обработка персональных данных в России подпадает под 152-ФЗ. Дыра в форме заявки —
не только техническая проблема.

## Вердикт

**`позже — и только в песочнице`.**

Возвращаемся к вопросу, когда выполнены **все четыре** условия:

| № | Условие | Состояние |
|---|---|---|
| 1 | Есть свой сайт с формами и приёмом оплат | в работе, август–сентябрь 2026 |
| 2 | Установлен Docker | нет |
| 3 | Установка из PyPI через `uv tool`, а не скриптом из интернета | правило зафиксировано здесь |
| 4 | Письменное согласие заказчика на проверку его сайта | нет |

**Глобально не ставим ни при каком раскладе** — ни `npx skills add`, ни навык
в `~/.claude/skills`. Проектный уровень, изолированное окружение, обратимая установка.

## Что сделать до strix — и это им не отменяется

Пентест проверяет то, что уже построено. Половина проблем сайта с формой закрывается
на этапе сборки и стоит ноль:

| Мера | Зачем |
|---|---|
| HTTPS и заголовки безопасности | База. Без этого остальное обсуждать рано |
| Ограничение частоты отправки формы | Иначе форму зальют мусором в первый день рекламы |
| Проверка и экранирование того, что ввёл человек | Самый частый вход для взлома |
| Капча или скрытое поле-ловушка | Боты найдут форму раньше людей |
| Никаких ключей и паролей в коде сайта | У нас уже есть правило: папка `Секретные ключи`, вне репозитория |
| Резервная копия заявок отдельно от сайта | Потеря заявок дороже взлома |
| Согласие на обработку персональных данных | Требование 152-ФЗ, а не пожелание |

Strix проверяет, что из этого сделано на самом деле. Он не заменяет ни один пункт.
