# CLAUDE.md — Экосистема инструментов

> Паспорт волта для Claude Code. Агент поддерживает его в актуальности: при новых оценках инструментов,
> решениях «ставим / не ставим», изменениях в экосистеме — дополняет. Контекст между чатами держится здесь.

## Что это за проект

Кросс-проектный волт для **оценки внешних AI-dev инструментов** (Claude Code плагины, skill-паки,
мета-харнессы, MCP-серверы): что это, как ставится, требования, конфликты с нашей средой, профильность,
вердикт «ставим / не ставим / позже». Не привязан к конкретному клиенту — это общая база решений по
инструментарию, чтобы не переисследовать одно и то же и не ломать рабочую среду импульсивной установкой.

## Канон

Волт ведётся по канону Knowledge-OS: [`..\_Движок\Канон\_manifest.md`](<../_Движок/Канон/_manifest.md>).
Документы — строго по типам / именам / метаданным / ссылкам из канона. Память — в `0 — System Docs\` (лениво).

## Структура (PARA)

- `03 — Ресурсы\Оценки инструментов\` — карточки-оценки конкретных инструментов (тип «Справочник»).
- Остальные ветки PARA заводим по мере надобности.

## Направления (области)

- Оценка Claude Code плагинов / skill-паков / мета-харнессов.
- Оценка MCP-серверов.
- Решения об установке в глобальную среду (`~/.claude/skills`, MCP user-scope) и их влиянии на все проекты.

## Ключевые принципы (специфичные для волта)

- **`~/.claude/skills` и MCP user-scope — глобальны на всю машину.** Любой навык/сервер оттуда включается
  во ВСЕХ проектах, включая Breezeks. Установку в глобальную среду проверяем сначала в изолированной папке.
- **Профильность важнее хайпа.** Инструменты для «выпуска ПО» (PR/CI/деплой) слабо применимы к нашей
  маркетинг/контент/аналитике — фиксируем это в вердикте.
- Громкие бенчмарки и звёзды — со скепсисом, проверяем на своей задаче.

## Как со мной работать

- Новая оценка инструмента → скилл `kos-create-doc` (тип «Справочник»). Проверка/починка → `kos-doc-compliance`.
- Возврат после паузы → `kos-memory-check`. Чужую папку к канону → `kos-migrate-to-canon`.
