# Плейбук — Подключить проект к канону

> id: `connect-project`. Идемпотентно: повторный запуск ничего не дублирует. Решение —
> [ADR-0004](<../0 — System Docs/ADR-log/0004-connect-any-project-by-link-and-passport-block.md>).

## Краткая суть

- Запрос владельца в чате проекта — одна строка (см. «Запрос»). Всё остальное лежит здесь, в каноне, поэтому
  запрос не устаревает.
- `kos_connect.py` ставит ссылку `.kos` на `_Движок/Подключение/` и пишет в `CLAUDE.md` проекта блок «Канон
  Knowledge-OS» с импортом правил агента. Новые чаты в папке проекта получают правила сами, без копии.
- Агент дописывает часть паспорта о самом проекте: направления, применимые методологии, системы с кодом.
- Проект заносится в реестр — «Справочник — Карта Knowledge-OS».
- Проверка — свежая сессия без доступа к файлам называет заголовок правил и дату сверки.

> Для быстрого знакомства человеку может хватить блока выше.
> Ниже начинается полный каноничный текст документа.
> Для агентов, правок, анализа, ревью и разрешения расхождений обязателен полный текст.

## Запрос

Владелец пишет в чате, открытом в папке проекта:

```
Подключи этот проект к Knowledge-OS по сценарию D:\Knowledge-OS\_Движок\Сценарии\Плейбук — Подключить проект к канону.md
```

## Шаги (выполняет агент)

1. **Корень проекта** — папка, в которой открыт чат: к её пути привязаны `CLAUDE.md` и память чатов.
   Называю её владельцу одной строкой. Если чат открыт не в корне проекта — спрашиваю, какую папку считать
   корнем.
2. **Состояние.** Папка в git-репозитории — `git status`. Чужие незакоммиченные правки не трогаю.
3. **Подключение:**
   `py -3 "D:\Knowledge-OS\_Движок\Инструменты\kos_connect.py" --project "<корень проекта>"`.
   Результат — строки «ссылка .kos», «исключение из git», «канон сверен». Код возврата 1 — стоп, причина в выводе.
4. **Паспорт о самом проекте.** Если в `CLAUDE.md` вне блока нет описания проекта, дописываю короткий раздел
   по [Шаблону — CLAUDE проекта](<../Шаблоны/Шаблон — CLAUDE проекта.md>):
   - что за проект, для кого и зачем — 1–2 абзаца, со слов владельца или из файлов проекта;
   - направления → какие методологии канона применимы (по [манифесту методологий](<../../Методологии/_manifest.md>)),
     абсолютными путями;
   - системы с кодом, если нужны: ссылкой (`pip install -e`) или выпуском с паспортом
     ([ADR-0003](<../0 — System Docs/ADR-log/0003-code-systems-source-in-canon-releases-in-projects.md>)).
     Выпуск нужен, только если код обязан лежать в репозитории проекта;
   - особенности git проекта: куда публикуется, кто ещё работает в репозитории.

   Чего не знаю — спрашиваю по одному вопросу с вариантом по умолчанию, остальное пишу допущением.
5. **Реестр.** Строка в [Справочник — Карта Knowledge-OS](<../Канон/Справочник — Карта Knowledge-OS.md>):
   проект, абсолютный путь, как подключён, дата сверки. Это запись в канон: `git status` в
   `D:\Knowledge-OS`, коммит только своих путей, push — по команде владельца.
6. **Проверка** — свежая сессия в папке проекта без доступа к файлам:
   ```
   claude -p "Не открывай файлы. Назови дословно заголовок правил работы агента из канона и дату «канон сверен». Чего нет в контексте — НЕТ." --model haiku --disallowedTools "Read,Glob,Grep,Bash,PowerShell,Agent,WebFetch,Edit,Write"
   ```
   Ответ должен содержать «Правила работы агента (канон Knowledge-OS, редакция …)» и дату. «НЕТ» — подключение
   не сработало: проверить ссылку `.kos` и строку `@.kos/agent-rules.md` в блоке.
7. **Итог владельцу:** что подключено, что дописано в паспорт, строка реестра. Уже открытые чаты проекта
   подхватят паспорт после перезапуска: `CLAUDE.md` читается в начале сессии.

## Особые случаи

- **Проект в репозитории компании.** Блок в `CLAUDE.md` коммитится вместе с проектом. Ссылка `.kos` исключена
  из git локально (`.git/info/exclude`) — коллеги без канона просто не получат импорт. Правила агента в
  репозиторий компании не копируются.
- **Правила уже грузятся глобально** (на этом устройстве так с 28.09.2026: `~/.claude/CLAUDE.md` импортирует
  `@kos/agent-rules.md`) — `kos_connect.py` видит это сам и пишет блок без импорта и без ссылки `.kos`, чтобы
  правила не грузились дважды. Проект на устройстве без глобального импорта получает импорт в блоке; заставить —
  ключами `--rules-import` / `--no-rules-import`.
- **Папка `.kos` уже занята обычной папкой** — инструмент её не трогает и останавливается. Переименование —
  решение владельца.
- **Обновить дату сверки** после сверки с каноном: `kos_connect.py --project … --verified <ГГГГ-ММ-ДД>`.

## Результат

В корне проекта: ссылка `.kos` → `D:\Knowledge-OS\_Движок\Подключение\`, `CLAUDE.md` с блоком «Канон
Knowledge-OS» и разделом о проекте. Строка в реестре. Любой новый чат в папке проекта работает по правилам канона
и знает, где методологии, инструменты и системы с кодом.
