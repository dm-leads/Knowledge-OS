# Бутстрап — Настройка движка Knowledge-OS

> id: `bootstrap-knowledge-os`. Запускается один раз на машине (или после обновления движка). Идемпотентно:
> если шаг уже сделан — пропустить.

## Краткая суть

Поставить движок «на ноги»: убедиться, что канон на месте, установить скиллы в Claude Code, проверить
корневой `CLAUDE.md`, при необходимости подключить GitLab. После — всё готово к штамповке/канонизации.

## Когда применять

- Новая машина / первый запуск.
- После обновления исходников скиллов или канона.

## Шаги

1. **Окружение.** Claude Code открыт в `D:\Knowledge-OS\`. Движок на месте: читается
   `_Движок\Канон\_manifest.md`.
2. **Установка скиллов — ссылкой, не копией.** Для каждой папки из `_Движок\Исходники скиллов\`
   создать в `~/.claude/skills\` ссылку-переход (junction) на исходник:
   ```powershell
   $src = 'D:\Knowledge-OS\_Движок\Исходники скиллов'
   Get-ChildItem $src -Directory | ForEach-Object {
     $dst = Join-Path "$HOME\.claude\skills" $_.Name
     if (-not (Test-Path $dst)) { New-Item -ItemType Junction -Path $dst -Target $_.FullName | Out-Null }
   }
   ```
   Почему ссылкой: исходник один, правка сразу видна везде, копии не расходятся. `~/.claude/skills`
   читают и Claude Code, и Cursor (Cursor — для совместимости, по его документации), поэтому второй папки
   не нужно. Junction на Windows работает без прав администратора и между дисками C: и D: одного ПК.
   Если на месте ссылки уже лежит обычная папка-копия — перенести её в резерв и поставить ссылку.
   Перезапустить/обновить Claude Code, чтобы новые скиллы подхватились.
3. **Корневой CLAUDE.md.** Проверить, что `D:\Knowledge-OS\CLAUDE.md` есть и описывает OS (где канон,
   какие скиллы, реестр проектов).
3а. **Правила агента во всех чатах устройства** (ADR-0004): ссылка
   `New-Item -ItemType Junction -Path "$HOME\.claude\kos" -Target "D:\Knowledge-OS\_Движок\Подключение"` и строка
   `@kos/agent-rules.md` в `~/.claude/CLAUDE.md`. В самом `~/.claude/CLAUDE.md` — только особенности устройства (где
   секреты, какие CLI установлены, кто владелец). Проверка — свежая сессия в любой папке называет заголовок правил
   (команда проверки — в «Плейбук — Подключить проект к канону», шаг 7).
3б. **Хуки — ссылкой:** `New-Item -ItemType Junction -Path "$HOME\.claude\hooks" -Target "D:\Knowledge-OS\_Движок\Хуки"`
   (обычная папка на месте — перенести в резерв). Подключение каждого хука в `~/.claude/settings.json` — по
   [манифесту хуков](<../Хуки/_manifest.md>). Проверка — тесты в `_Движок\Хуки\`.
4. **(Опц.) GitLab MCP.** Скопировать `_Движок\Каркас\06 — Инструменты\mcp.template.json` → локальный
   `mcp.json`, вписать URL/токен. **Токен — только локально, не в git, не в чат.**
4а. **Пакеты канона ссылкой** (если нужны системы с кодом): `py -3 -m pip install -e
   "D:\Knowledge-OS\_Движок\Пакеты\<пакет>" --no-deps` ([ADR-0003](<../0 — System Docs/ADR-log/0003-code-systems-source-in-canon-releases-in-projects.md>)).
4б. **Проекты устройства** подключаются к канону по одному:
   [Плейбук — Подключить проект к канону](<Плейбук — Подключить проект к канону.md>).
5. **Smoke-check.** Скиллы из `Исходники скиллов` видны в списке (`kos-*`, `claude-brief` и др.);
   канон читается; `Канон\Справочник — Карта Knowledge-OS` открывается.

## Результат

Движок настроен: можно разворачивать проекты (`stamp-new-project`) или канонизировать папки
(`canonize-existing-folder`).
