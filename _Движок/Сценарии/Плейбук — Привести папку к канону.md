# Плейбук — Привести папку к канону

> id: `canonize-existing-folder`. Главный сценарий переноса проекта: положил папку в `D:\Knowledge-OS\` —
> и привёл её к канону. Запускается в **новом чате** командой вроде «изучи папку `<Имя>` и приведи к канону».

## Краткая суть

Берём папку с произвольными файлами (любые имена/структура/содержимое) и аккуратно раскладываем по
PARA-канону: правильные имена, метаданные, манифесты, ссылки. **Без потери данных. Превью и согласование
перед любыми изменениями. Хаос не копируем — чистим.**

## Предусловия

- Движок собран, скиллы установлены (`bootstrap-knowledge-os` выполнен).
- Папка лежит в `D:\Knowledge-OS\<Имя проекта>\` (или указан её путь).

## Шаги

1. **Указать папку.** Если контур уже живой (есть `0 — System Docs\`) — сначала `kos-memory-check` (брифинг).
2. **Инвентаризация.** Перечислить все файлы и папки; классифицировать: документы / код / медиа / дубли /
   черновики / устаревшее / мусор. Ничего пока не трогать.
3. **Карта-предложение.** Для каждого элемента предложить: контур (`01 — Проекты` / `02 — Области` /
   `03 — Ресурсы` / `06 — Инструменты`) или «в утиль»; каноничное имя (`Тип — Название`) и тип из закрытого
   списка; дубли → консолидация; тяжёлые ассеты → отдельно (вне основного дерева). Сомнительное — помечать.
4. **СОГЛАСОВАНИЕ.** Показать карту целиком и дождаться «ОК». Это обязательный гейт — до него изменений нет.
5. **Миграция (скилл `kos-migrate-to-canon` + `kos-doc-compliance`).** Создать PARA-раскладку; переместить и
   переименовать; проставить YAML-frontmatter; собрать `_manifest.md` контуров; перелинковать (inline +
   футер «Связанные документы»).
6. **Паспорт.** Завести/заполнить `CLAUDE.md` проекта + корневой `_manifest`; первая запись `CHANGELOG`;
   добавить проект в [Карту](<../Канон/Справочник — Карта Knowledge-OS.md>).
7. **Верификация.** Ledger «источник → цель»: все файлы на месте; имена каноничны; метаданные полны; ссылки
   целы; ничего не потеряно. Отчитаться, что осталось ручного.

## Принципы

- **Не копировать хаос:** дубли/мусор/черновики — вычистить до миграции (с согласования).
- **Без потери данных:** перемещение, а не удаление; сомнительное — на согласование.
- **Превью перед изменениями.** Секреты/ПДн — только локально, не в общий git/чат.
- **Переименование под работающим приложением:** процесс продолжит писать по старым путям и пересоздаст старые
  папки. Перед переименованием — остановить приложения и сервисы, которые пишут в папку, после — перезапустить.
  Массовая замена имени задевает вложенные одноимённые папки подприложений: список замен — явный, с превью.

## Готовый промпт для запуска

После переноса папки проекта в `D:\Knowledge-OS\` вставь в новом окне/чате:

```
Изучи папку D:\Knowledge-OS\<имя-проекта> — это новый проект, который нужно привести к канону Knowledge-OS.
1. Сначала прочитай канон: _Движок\Канон\_manifest.md и этот сценарий (Плейбук — Привести папку к канону).
2. Сделай инвентаризацию ВСЕХ файлов и папок (ничего не меняй).
3. Предложи карту раскладки по PARA/канону: что → 01 Проекты / 02 Области / 03 Ресурсы / 06 Инструменты / в утиль;
   каноничные имена и типы; дубли и тяжёлые файлы — отдельно.
4. Покажи карту целиком и дождись моего «ОК» до любых изменений.
5. После согласования — разложи по канону (имена/метаданные/манифесты/ссылки), заполни CLAUDE.md проекта и
   System Docs, добавь проект в карту.
Действуй через скилл kos-migrate-to-canon. Без потери данных, превью перед изменениями.
```
