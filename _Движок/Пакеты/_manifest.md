## Как подключить пакет к проекту

- **Ссылкой** (проект на этом устройстве, код в свой репозиторий не нужен):
  `py -3 -m pip install -e "D:\Knowledge-OS\_Движок\Пакеты\<пакет>"`.
- **Выпуском** (компания хранит код у себя и ставит на свой сервер):
  `py -3 "D:\Knowledge-OS\_Движок\Инструменты\kos_release.py" issue --package "D:\Knowledge-OS\_Движок\Пакеты\<пакет>" --into <каталог кода в проекте>`.
  Проверка выпуска: `kos_release.py check --into … --package …`. `--package` — путь к папке пакета, не имя.

Новая версия, обновление выпуска, новый пакет — сценарий
[Плейбук — Система с кодом: версия, выпуск, новый пакет](<../Сценарии/Плейбук — Система с кодом- версия, выпуск, новый пакет.md>).
Метки версий в git канона — `<пакет>-v<версия>` (первая: `growth_engine-v1.0.0`).

## Тесты пакета

Из папки пакета: `py -3 -m pytest <пакет>/tests`. В каноне тест паспорта выпуска пропускается: паспорта здесь
нет, это исходник.

`datacore` тянет DuckDB, psycopg и движок моделей SQLMesh — его тесты идут в своём окружении: из папки пакета
`uv run pytest` (окружение `.venv` рядом, вне git; `uv.lock` в git). С `DATACORE_REQUIRE_PG=1` каждый тест схемы и
метрик идёт и на переносимом Postgres (ставится сам в ASCII-путь вне репозитория). Метрики проверяются на
синтетическом инстансе `datacore/tests/fixtures/instance.yaml` — кабинеты `b1`, `b2`, системы по ролям.
