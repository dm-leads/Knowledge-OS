# Стандарт — Извлечение знаний из обучающих материалов

## Краткая суть

Курс — это **не для «прочитать»**, а сырьё для трёх артефактов: дистилляции первоисточника,
переносимого ядра методики и проектной дельты «как применяем». Материал считается изученным только
при **доказанном покрытии** — реестр всех файлов со статусом. Пересказ без адресов источника,
чтение «по первым строкам» и дубль вместо дельты — брак, а не результат.

## Когда применяется

Любой внешний обучающий источник: курс, транскрипты видео, вебинар, набор таблиц/шаблонов, книга,
методичка практика. Не применяется к оперативным данным (выгрузки, отчёты систем) — для них свои
плейбуки направления.

## Слои и маршрутизация

| Слой | Что | Куда кладём | Область |
|---|---|---|---|
| 0. Сырьё | Исходники без видео (видео не переносим — вес) | `<Проект>\Большие файлы и выгрузки\Курсы (сырьё)\Для-изучения\<курс> - Только текст\` (вне git) | проект |
| 1. Дистилляция первоисточника | Что источник **реально говорит**: механика, пороги, формулы, чек-листы, анти-паттерны | `<Проект>\03 — Ресурсы\Конспекты курсов\distillations\NOTE-SRC-<курс>-distill.md` | проект |
| 2. Переносимое ядро | Методика, не зависящая от конкретного проекта | `D:\Knowledge-OS\Методологии\` | **кросс-проект** |
| 3. Проектная дельта | Как применяем здесь: наши кабинеты/счётчики/ограничения/цели | направление проекта (`02 — Области\...`), плейбук/стандарт | проект |
| 4. Память | Решение + артефакты | журнал направления + `0 — System Docs\CHANGELOG.md` | проект |

**SSOT:** переносимое ядро пишется **один раз** (слой 2); проект **ссылается**, а не копирует.

## Пайплайн

### Ф0. Инвентаризация источника

Снять фактическую картину до чтения: число файлов, типы, размер, структура модулей; что исключаем
(видео) и почему. Зафиксировать перечень модулей — он станет основой волн и реестра покрытия.

### Ф1. План волн + гейт

Разбить материал на **волны по темам** (не по алфавиту): каждая волна — связный блок, который можно
осмыслить целиком. План волн показать Дмитрию.

> **Гейт:** запуск флота саб-агентов — только после явного подтверждения Дмитрия. Один-два агента
> для узкой задачи — норма; массовый параллельный прогон — с разрешения.

### Ф2. Полное чтение + реестр покрытия

Читать **до конца каждого файла**, а не первые строки. По ходу заполнять реестр покрытия (формат ниже).
Файлы, которые технически не читаются напрямую (PDF/docx/xlsx), извлекать инструментами
(`fitz`/python), а не пропускать.

**Источник считается изученным**, если в реестре: покрытие 100% ЛИБО явный список непрочитанного с
причиной («видео — исключено по решению», «файл повреждён»). Иначе — работа не закрыта.

### Ф3. Дистилляция

**Фиксируем:** механику и последовательности действий; числовые пороги и формулы; чек-листы;
анти-паттерны и «где не работает»; спорные/сильные утверждения автора; готовые шаблоны/таблицы.

**Не фиксируем:** воду, мотивацию, продажу курса, общеизвестное.

**Разметка обязательна:** `[факт: модуль N, файл]` / `[вывод]` / `[гипотеза]`. Любое утверждение,
которое пойдёт в работу, обязано иметь **адрес в источнике**. Цитаты — с указанием модуля/файла.

### Ф4. Сверка с имеющимся

Сопоставить с уже накопленным (другие дистилляции по теме, наши плейбуки/методологии) и разложить на:

- **совпадения** — подтверждает то, что уже знаем (усиливает уверенность);
- **противоречия** — расходится с нашим текущим правилом → требует явного решения, что берём;
- **дельта** — чего у нас не было (главная ценность источника).

Без Ф4 получается четвёртый пересказ вместо приращения.

### Ф5. Применение

- Переносимое → слой 2 (`Методологии`).
- Проектное → слой 3: обновить/создать плейбук направления, внести правки в существующие документы.
- Если источник **меняет действующее правило** — правка правила фиксируется явно (журнал/ADR проекта).

### Ф6. Критик и закрытие

Проверить: покрытие доказано? каждое рабочее утверждение имеет адрес? Ф4 сделана (не дубль)?
переносимое отделено от проектного? Затем — запись в журнал направления и `CHANGELOG`.

## Реестр покрытия (формат)

Таблица/CSV рядом с дистилляцией:

| Файл | Модуль | Тип | Статус | Волна/агент | Что взято |
|---|---|---|---|---|---|
| `03_sbor_klyuchey.txt` | 5. Сбор ключевых слов | транскрипт | прочитан | В1 | механика сбора, пороги частот |
| `matrix.xlsx` | 23. Сбор матриц | таблица | прочитан | В1 | шаблон матрицы |
| `intro.mp4` | 3. Что такое Директ | видео | **исключён** | — | по решению (вес) |

Итоговая строка: **покрытие N/N (100%)** либо список непрочитанного с причинами.

## Definition of Done

- [ ] Ф0 инвентаризация зафиксирована (файлы/типы/модули/исключения).
- [ ] Реестр покрытия заполнен; покрытие 100% или обосновано.
- [ ] `NOTE-SRC-<курс>-distill.md` создан; утверждения размечены и адресованы к источнику.
- [ ] Ф4 сверка выполнена: совпадения / противоречия / дельта выписаны явно.
- [ ] Переносимое ядро вынесено в `Методологии`; проект ссылается, не копирует.
- [ ] Проектная дельта внесена в плейбук/документ направления.
- [ ] Критик пройден; журнал направления и CHANGELOG обновлены.

## Анти-паттерны (ловили на практике)

- **Чтение первых строк + домысел** — главный брак; лечится реестром покрытия.
- **Пересказ вместо дельты** — нет Ф4, знание не прирастает.
- **Выдуманные пороги/цифры** — число без адреса в источнике не берём в работу.
- **Флот агентов без спроса** — нарушение правила проекта.
- **Смешение переносимого и проектного** — ядро загрязняется спецификой одного проекта и перестаёт переноситься.
- **Дистилляция «в никуда»** — материал изучен, но ни один плейбук не изменился ⇒ Ф5 не выполнена.

## Именование артефактов

- Дистилляция первоисточника: `NOTE-SRC-<Курс-слаг>-distill.md`.
- Углублённая тематическая выжимка: `NOTE-<Тема>-DEEP-<YYYY-MM>.md`.
- Документы слоёв 2–3 — по [Стандарт — Конвенция именования](<Стандарт — Конвенция именования.md>)
  (`Тип — Название`). Имена папок-сырья сохраняем близкими к оригиналу (прослеживаемость), с суффиксом
  `- Только текст`, если видео исключено.
