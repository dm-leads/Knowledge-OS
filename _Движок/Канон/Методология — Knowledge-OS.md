# Методология — Knowledge-OS

## Краткая суть

Knowledge-OS — не «папка с файлами», а **управляемая система знаний**: каждый документ имеет тип, имя,
метаданные и место по канону; навигация — через манифесты; изменения и решения — в памяти контура.
Цель — чтобы знание не терялось между чатами, проектами и временем, и чтобы любой новый проект вёлся
**одинаково**.

## Зачем

- **Контекст не теряется.** То, что зафиксировано по канону, переживает смену чата, паузу, новый проект.
- **Однообразие.** Один канон → одинаковые имена/структура во всех проектах. Не «здесь так, там иначе».
- **Найти за секунды.** Тип в имени + манифест-каталог + ссылки = быстрый доступ.
- **Переиспользование.** Движок один, проектов много.

## Каркас PARA

Каждый проект — самостоятельное дерево:

- `01 — Проекты` — временные инициативы с концом.
- `02 — Области` — постоянные направления (операционка функций). Сюда уходит то, что в Бризексе было
  «контент-машиной» и т.п. — у тебя будут **свои** направления.
- `03 — Ресурсы` — переиспользуемые справочники, шаблоны, библиотеки, бренд.
- `04 — Чувствительные области` / `05 — Чувствительные проекты` — закрытое, deny-by-default (пусто, пока
  не решишь, что туда).
- `06 — Инструменты` — скрипты, MCP-конфиги, вспомогательная инфраструктура.
- `0 — System Docs` — память контура (CHANGELOG/ADR/BACKLOG), лениво.

## Три опоры (детали — в стандартах)

1. **Канон документа** — [типы](<Стандарт — Конвенция типов документов.md>) +
   [имена](<Стандарт — Конвенция именования.md>) +
   [метаданные](<Стандарт — Конвенция метаданных и _manifest.md>) +
   [ссылки](<Стандарт — Конвенция ссылок и навигации.md>).
2. **Память** — [изменения и System Docs](<Стандарт — Память изменений и System Docs.md>) (git опционален).
3. **Единственный источник правды** — [SSOT и DRY](<Стандарт — SSOT и DRY.md>): не копировать — ссылаться.

## Как ведётся работа

- Новое знание → скилл `create-doc` (placement → тип → имя → метаданные → шаблон → ссылки).
- Проверка/починка → `doc-compliance`.
- Возврат к работе после паузы → `memory-check` (брифинг по памяти контура).
- Чужая/хаотичная папка → `migrate-to-canon` (разложить по канону).
- Облако (опц.) → [Git и GitLab workflow](<Стандарт — Git и GitLab workflow.md>).
