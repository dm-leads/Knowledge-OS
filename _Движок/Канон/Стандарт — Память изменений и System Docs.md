# Стандарт — Память изменений и System Docs

## Краткая суть

Память контура — три слоя на три разных вопроса. Живут в `0 — System Docs/` (создаётся лениво).
**Git опционален:** CHANGELOG/ADR/BACKLOG ценны и без git; git/GitLab добавляет историю и облако.

## Три слоя

| Вопрос | Инструмент | Когда |
|---|---|---|
| «что изменилось» | git history (если контур в git) | каждая публикация |
| «значимое + когда» | `CHANGELOG.md` | только нарративно важное (лениво) |
| «почему так» | ADR в `ADR-log/` | одно архитектурное/управленческое решение |

Идеи на будущее → `BACKLOG.md`. Задачи с дедлайном/исполнителем — **не сюда** (это трекер задач/PM).

## `0 — System Docs/`

- Папка памяти контура: `CHANGELOG.md`, `BACKLOG.md`, `ADR-log/`. В корне проекта — ещё два рабочих файла агента
  (ADR-0005, [Стандарт — Три файла проекта](<../../Методологии/Стандарт — Три файла проекта (паспорт, журнал действий, база инцидентов).md>)):
  папка `Журнал действий/` с помесячными файлами `Журнал — ГГГГ-ММ.md` и `Справочник — База инцидентов.md`.
- Создаётся **лениво**, когда появляется первый из этих файлов. Сортируется первой (`0 —`).
- `_manifest.md` **всегда в корне** контура, в System Docs не переезжает.

## CHANGELOG

- Триггеры записи: реструктуризация контура, принятие стандарта/ADR, смена владельца, крупная миграция.
- Не для: рутинных правок, опечаток (это git/просто правка).
- Формат — запись сверху (обратная хронология):

```markdown
## YYYY-MM-DD — Краткое описание
- Что изменилось и почему
- [Ссылка на ADR-XXXX] если решение
```

## ADR (decision)

- Одно решение: контекст (силы/проблема), сам выбор, **рассмотренные альтернативы**, последствия.
- Три условия (иначе это не ADR): есть реальный выбор; выбор формирует/ограничивает систему; в будущем
  спросят «почему так».
- Неизменяем после `Accepted`. Переосмысление → **новый** ADR; старому — `status: superseded` +
  `superseded_by:`.
- **Нумерация:** скан `ADR-log/` → номер = max+1, zero-pad 4 (`0001`, `0002`…). Без пропусков и переиспользования.
- Статусы в теле ADR: `Proposed` / `Accepted` / `Deprecated` / `Superseded`.

## Связка

Тяжёлое решение → **и** ADR (полное обоснование) **и** строка в CHANGELOG («Принят ADR-XXXX — …»).
