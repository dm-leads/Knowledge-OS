# Стандарт — Git и GitLab workflow

## Краткая суть

GitLab — облачное хранилище контуров (свой инстанс, свои проекты заводишь сам). Работа описана **четырьмя
человеческими командами**, без терминов git. Git **опционален**: знания и память ценны и локально; git/
GitLab добавляют историю, бэкап и обмен.

## Четыре команды

| Команда | Смысл | Под капотом |
|---|---|---|
| `обнови` | взять свежую версию контура | `git pull` |
| `сохрани черновик` | локально зафиксировать, никому не видно | локальный commit / просто сохранение |
| `опубликуй` | выложить готовое в облако | `git push` с авто-сообщением о сути изменений |
| `откати` | вернуть прошлое состояние / показать историю | `git revert` / `git log` |

## Модель осознанной публикации

- Коллеги/другая машина видят изменения **только после** `опубликуй`. Никаких тихих авто-перезаписей.
- Каждая публикация фиксирует: кто, когда, что именно.
- Порядок: сначала **обновить каноничный документ** → `опубликуй` → потом анонс/сообщение. «Не в системе =
  не существует».

## Границы и безопасность

- **Push-allowlist:** `опубликуй` разрешён только для репозиториев внутри `D:\Knowledge-OS\`. Путь вне —
  СТОП и явное подтверждение конкретного абсолютного пути.
- Контейнер ≠ git-репозиторий: `D:\Knowledge-OS\` — рабочая папка, не репо. `fatal: not a git repository`
  в корне — норма. Границу репо определять по затронутому файлу: `git -C "<путь>" rev-parse --show-toplevel`.
- Запреты: force-push без явной просьбы, массовый push без подтверждения per-repo, коммиты с секретами.
- **Секреты (PAT/токены) — никогда в git и никогда в чат.** Только в локальном конфиге MCP (вне репо).

## Подключение нового репозитория (runbook)

1. Создаёшь пустой проект в **своём** GitLab (имя = латинский слаг контура).
2. Прописываешь URL/токен в `06 — Инструменты/mcp.template.json` → свой локальный `mcp.json` (по образцу,
   с реальным токеном, файл не коммитится).
3. В нужном контуре: `сохрани черновик` → `опубликуй`. Дальше — обычный цикл обнови/опубликуй.
