# Стандарт — SSOT и DRY

## Краткая суть

Каждый управленческий факт живёт в **одном** каноничном документе; остальные **ссылаются**, а не
копируют. Копирование неизбежно расходится в две версии. Это фундамент, на котором держится всё остальное.

## Три вопроса перед созданием документа

1. **Есть ли уже SSOT по теме?** Проверить `_manifest.md` контура, соседние папки, поиск по репо.
   Если да → **СТОП**, поставить ссылку (или дополнить существующий). Если нет → вопрос 2.
2. **Хочу скопировать кусок из другого документа?** Если да → **СТОП**, вместо копии — ссылка.
   Исключение — `soft mirror` (`mirrors:`) только при ограничении доступа. Если нет → вопрос 3.
3. **Мой документ покрывает тот же домен знания, что существующий?** Один **объект** может иметь разные
   **типы** (workflow + instruction + standard) — это нормально. Нарушение — два документа **одного типа**
   об одном и том же. Если да → уточнить разницу охвата, подтвердить намеренность. Если нет → создавать.

## Антипаттерны → лечение

| Антипаттерн | Что будет | Лечение |
|---|---|---|
| Параллельный SSOT | Две копии в разных папках расходятся | Один документ + ссылки из контекстов |
| «Скопировал и подправил» | Оригинал обновили, копия протухла | Inline-ссылка на исходный раздел |
| Суффиксы версий (`… v2`) | Непонятно, что актуально | Править существующий; история — в git; `superseded_by:` при необходимости |
| Дубль между контурами | Каждый владелец правит свою копию | Один SSOT + кросс-ссылка |
