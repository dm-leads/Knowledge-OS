# Стандарт — Конвенция метаданных и _manifest

## Краткая суть

Каждый знаниевый документ начинается с обязательного YAML-frontmatter. Поля едины для всех проектов.
Навигация контура — в `_manifest.md`, а не в README.

## 1. Обязательный frontmatter

```yaml
---
тип-размещения: <slug>      # area | project | resource_kind — для документов проекта; движок-канон опускает
type: <id из закрытого списка>
status: draft | active | deprecated | superseded
description: |
  <1–2 предложения: что это, зачем, для кого>
author: <Имя>
created: YYYY-MM-DD          # неизменна
updated: YYYY-MM-DD          # дата последней содержательной правки
review_cycle: 1m | 3m | 6m | 12m | never
last_reviewed: YYYY-MM-DD    # дата осознанного пересмотра (≠ updated)
gitlab_url: <url>            # ОПЦИОНАЛЬНО — только если контур привязан к GitLab
tags:
  - <тег>
---
```

- Перед закрывающим `---` — **пустая строка** (критично для рендера).
- Брать из шаблона в `Шаблоны/` (`Шаблон — <Тип>.md`), не с белого листа.
- Поле размещения (`area`/`project`/`resource_kind`) обязательно для документов **проекта**; документы
  самого движка (`_Движок/Канон`) его опускают.

## 2. review_cycle ← скорость устаревания темы

Закрытый список `1m / 3m / 6m / 12m / never` ([ADR-0007](<../0 — System Docs/ADR-log/0007-methodbase-check-types-review-cycle.md>)).
Срок выбирается по тому, как быстро устаревает тема, а не по типу:

- **1m** — карты и реестры, которые меняются с каждым новым документом;
- **3m** — закон, правила площадок, стандарты и процессы, которые часто правятся;
- **6m** — методологии, справочники, гайды по умолчанию;
- **12m** — разборы первоисточников и книг, которые сами не меняются;
- **never** — снапшоты: analytics, retrospective, postmortem, audit, research, decision.

При `review_cycle: never` поле `last_reviewed` = `created`.

## 3. Статусы

- `draft` — в работе, ещё не канон.
- `active` — авторитетный источник.
- `deprecated` — устарел, оставлен для истории.
- `superseded` — заменён другим (добавить `superseded_by: <путь>`).
- **Не `archived`** — архивирование делается механизмом хранилища, а не статусом.

## 4. gitlab_url и soft mirror

- `gitlab_url` — опционален; заполняется, когда контур реально лежит в GitLab.
- `mirrors:` — мягкое зеркало при ограничении доступа (канон в источнике, тут — вторичная копия):

```yaml
mirrors:
  - source: <путь-к-источнику>
    sections: [<Раздел>]
    reason: <почему зеркало, а не ссылка>
```

## 5. `_manifest.md` — навигация контура

В корне каждого контура. Содержит: назначение контура, что сюда заходит / что **не** заходит
(кросс-ссылки на соседей), каталог ключевых документов (ссылки), владельца. Frontmatter манифеста:
`type: manifest`, поле `repo_type: area | project | resource | tool | engine`.

Сразу под заголовком манифеста — две строки (с 2026-11-20):

- **`Читать первым:`** — 1–2 ссылки на документ, с которого начинает новый человек или агент, и одна фраза зачем.
  Не `superseded`, не из `Архив/`; для раздела из подпапок — манифест главной подпапки.
- **`Не трогать:`** — что руками не править и почему: файлы, которые собирает скрипт; данные, которые читают
  скрипты; снимки; документы, которые правят на внешнем диске; или «нет».

## 6. Раскладка папок — порядок держит код

Урок проекта, где за полгода в двух папках инструментов набралось 118 и 135 файлов, а 300 файлов снимков лежали
среди рабочих документов: ревизия раз в месяц порядок не держит, держит проверка перед коммитом и в CI.

| № | Правило |
|---|---|
| Р1 | В папке не больше 25 документов (`.md`, кроме `_manifest.md` и `TASKS.md`) — больше — развести по смысловым блокам |
| Р2 | Не больше 40 файлов в папке; код — по папкам систем (одна внешняя система — одна папка), общее — отдельно |
| Р3 | Без порога — папки картинок (картинок не меньше половины, документов и кода нет) и архивы |
| Р4 | Снимки на дату — в папке ресурсов вне git; снимок «до» массовой правки — туда же, скрипт пишет его сам |
| Р5 | В корне — только белый список: вход для агентов, README, манифест, служебные файлы git, папки PARA |
| Р6 | Манифест у каждой папки с документом или скриптом; папку данных упоминает манифест родителя |
| Р7 | В манифесте — «Читать первым:» и «Не трогать:» |
| Р8 | Исключение — только записью «папка, правило, причина, дата» в файле исключений |

- Проверка — `_Движок\Инструменты\kos_layout_check.py` (пороги и белый список — `.kos-layout.json` проекта);
  сначала предупреждения, после разборки куч — ошибки.
- Манифест папки с кодом собирается из описаний в начале скриптов (таблица «скрипт → что делает»): поправили
  описание — пересобрали, манифест не расходится с кодом.
- Перенос скриптов — только инструментом: путь от `__file__` после переноса ведёт туда же (кроме своей папки,
  переехавшего вместе и ещё не созданного), импортёрам — строка пути, деплоям и документам — новые пути, история не
  переписывается, карта переездов; файлы с незакоммиченными правками параллельных чатов не переносятся, в индекс
  — правка поверх HEAD. Перед — репетиция на клоне, после — тесты «до/после» и задачи планировщика по старым путям.
