# Стандарт — Конвенция ссылок и навигации

## Краткая суть

Навигация — три слоя: **каталог** (`_manifest.md`), **inline** на первом упоминании, **футер**
«Связанные документы». Отдельных страниц-списков ссылок не делаем — их роль выполняет манифест.

## Три слоя

| Слой | Где | Роль | Объём |
|---|---|---|---|
| Каталог | `_manifest.md` контура | Полный перечень документов контура | все ключевые |
| Inline | в теле, на первом упоминании | Контекст по месту | естественное число первых упоминаний |
| Футер | раздел `# Связанные документы` в конце | Кураторский список соседей | **3–7**, потолок ~10 |

Машинные связи — только в frontmatter: `superseded_by:`, `mirrors:`.

## Правила

- **Каталог:** навигация живёт в манифесте; отдельных «полезных ссылок»/«навигации по разделу» — нет.
- **Inline:** ставить ссылку на **первом** упоминании другого документа/термина; **одна** ссылка на цель,
  не на каждом повторе.
- **Футер обязателен** для содержательных типов: policy, standard, workflow, methodology, guide,
  reference, runbook, playbook. Не нужен для снапшотов (analytics/retrospective), шаблонов, системных файлов.
- Футер **кураторский** (3–7 прямых соседей), не свалка. Перебор потолка → вынести навигацию в манифест
  или разбить документ.

## Формат

- Обычные Markdown-ссылки: `[Имя](<путь к файлу.md>)`. Пути с пробелами/кириллицей — в `<…>`.
- Только **относительные** пути.
- **Запрещено:** `[[wiki-links]]`, якоря на строки (`#L42`), `cursor://`-ссылки, дублирование контента
  вместо ссылки, поле `related:` в frontmatter.

## Типовые связи

- workflow → instruction, standard, reference.
- instruction → родительский workflow, нужные reference/standard.
- standard / policy → смежные стандарты, опорный ADR.
- methodology → реализующие стандарты, глоссарий, ключевой ADR.
