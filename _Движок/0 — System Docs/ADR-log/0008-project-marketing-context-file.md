# ADR-0008 — Файл контекста маркетинга проекта

- **Статус:** Accepted
- **Дата:** 2026-11-22
- **Решение принял:** Дмитрий («давай дальше по оставшемуся списку», вариант по умолчанию, 22.11.2026)

## Контекст

Разбор `coreyhaines31/marketingskills` 17.11.2026 (`Методологии\_исходные-заметки\GitHub — внешние материалы
(2026-11-17)\`, сверка, топ-10, п. 3) показал приём: один файл контекста продукта, который каждый маркетинговый
навык читает первым. У нас решения по маркетингу проекта лежат в разных местах — паспорт проекта, паспорт оффера
(`offer`), паспорт позиционирования (`positioning`), документ тона, сегменты, карта знаний Движка роста, — и навык
каждый раз заново ищет или спрашивает то, что уже решено. Язык клиента, возражения, доказательства и полномочия
агента в маркетинге своего хозяина в проекте не имеют.

## Решение

1. **Файл.** `Справочник — Контекст маркетинга.md` в проекте, по шаблону `_Движок\Шаблоны\Шаблон — Контекст
   маркетинга.md`. Путь — строкой в паспорте проекта (`CLAUDE.md`, раздел «Направления и методологии»).
2. **Необязательный и одно правило заведения.** Это не четвёртый файл проекта из ADR-0005: `kos_connect.py` его
   не заводит. Нет файла — любой маркетинговый навык предлагает завести его через `marketing`; отказ владельца
   задаче не мешает, навык работает без файла. После согласия `marketing` заводит файл из данных проекта (пустое —
   «нет данных») и в тот же ход дописывает путь в паспорт.
3. **Навигация, а не копия (SSOT).** Решения, у которых есть свой документ (цель и экономика, сегменты,
   позиционирование, оффер, тон, медиаплан, учёт), в файле — только ссылкой на раздел документа и описанием, что
   там лежит, без самих значений. Факты и действующие решения навыки берут из документа по ссылке; при расхождении
   действует документ. Свои разделы — только для того, чему нет хозяина: язык клиента, возражения, доказательства,
   подтверждённые полномочия агента, уроки.
4. **Полномочия.** Шаблон разрешений не даёт. Строка полномочия — действие, границы, источник решения владельца
   (запись в паспорте, журнале, сообщение) и дата. Агент сам полномочия не расширяет; без подтверждённой строки
   действуют правила проекта и канона, файл не отменяет запреты и обязательные согласования (деньги, запись вовне,
   публикации, рассылки).
5. **Персональные данные.** Цитаты клиентов — обезличенными фрагментами, без имён, контактов и обстоятельств, по
   которым человека можно узнать; если обезличить нельзя, не сохраняя смысла, цитату не берут. Источник — ссылкой
   на защищённое хранилище (CRM, речевая аналитика), исходная запись в файл не переносится. Доказательство для
   публикации — со статусом разрешения и основанием; «не подтверждено» — не разрешение.
6. **Уроки** — строка: формулировка, доказательство с выборкой и периодом, где применимо, статус `active` /
   `watch` / `retired`. Урок цикла Движка роста — ссылкой на строку его карты знаний, не пересказом.
7. **Кто читает и обновляет.** Маркетинговые навыки (`marketing`, `offer`, `positioning`, `funnel`, `text-editor`,
   `smm-frameworks`, `brand-voice`, `sales-dept`, `ads-*`) читают файл сразу после паспорта. Навык, который принял,
   заменил или отменил решение, предлагает добавить, заменить или удалить строку; после согласия владельца
   обновляет её и журнал файла. `marketing` при обращении после срока `review_cycle` сверяет ссылки и статусы.

## Рассмотренные альтернативы

- **Всё в паспорт проекта `CLAUDE.md`.** Паспорт грузится в каждую сессию; маркетинговые подробности раздуют его и
  контекст всех задач, не только маркетинговых. Отклонено.
- **Один файл со всеми решениями целиком (как в источнике).** Копия паспортов оффера и позиционирования застывает
  в день копирования и расходится с ними. Отклонено — оставлена навигация по ссылкам.
- **Обязательный файл для любого проекта через `kos_connect.py`.** У проектов без маркетинга он был бы пустым.
  Отклонено.

## Последствия

- Новый шаблон в `_Движок\Шаблоны\`, строка в его манифесте и в шаблоне паспорта проекта; строка в «Стандарт — Три
  файла проекта» о том, что четвёртого обязательного файла нет.
- Навык `marketing` получил шаг заведения и сверки; остальные навыки списка — строку входа и правило обновления.
- Существующие проекты получают файл, когда владелец согласится на предложение навыка; переносить задним числом не
  нужно.
