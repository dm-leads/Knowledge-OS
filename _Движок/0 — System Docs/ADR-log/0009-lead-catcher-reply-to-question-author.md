# ADR-0009 — Ловец лидов: ответ автору вопроса по одобренной очереди

- **Статус:** Accepted
- **Дата:** 2026-11-26
- **Решение принял:** Дмитрий («нужно уже настраивать механизм, чтобы он автоматически… отправить нескольким
  пользователям», «без моего сигнала не делай отправки», 26.11.2026)

## Контекст

Методология ловца лидов (этап 7 «Касание») требовала: человек сам открывает ссылку, пишет вручную, «код ничего не
отправляет». На первом проекте поток нашедшихся вопросов дошёл до десятков, и ручная отправка стала узким местом:
человек ищет автора по ссылке, переписывает текст, держит в голове, кому уже писал и кто ответил. 26.11.2026 проба
показала, что аккаунт через API пишет в личку и читает ответ. Риски остаются прежними: ограничение аккаунта за
сообщения незнакомым, закон о рекламе (первое сообщение без согласия — не реклама), персональные данные.

## Решение

1. Команды `reply` (ответ автору сообщения по ссылке) и `inbox` (ответы на наши сообщения) — в пакете, выключены по
   умолчанию: работают только при `outreach.enabled: true` в профиле экземпляра.
2. Отправляется только строка очереди со статусом «отправить», который ставит человек; без флага `--send` — сухой
   прогон. Текст — ровно из очереди.
3. В коде: обязательная фраза «кто пишет» (`required_phrase`) — без неё не уходит; без ссылок; длина до
   `max_chars`; одному человеку — один раз; стоп-лист по просьбе «не пишите»; вопрос не старше `max_age_days`; окно
   часов; лимит новых людей в сутки; случайная пауза; стоп-сигнал аккаунта — стоп и запись, свежий стоп номера
   (24 ч) — отправка не начинается; неизвестный отказ Telegram — стоп прогона до разбора.
4. Журнал отправок, ответы и стоп-лист — в `private_dir/outreach` (вне git): там номера пользователей Telegram.
   Базы ников не ведётся.
5. Методология, раздел «Касание» и «Чего не делать»: вместо «код ничего не отправляет» — «код отправляет только
   одобренное человеком, по одному сообщению под вопрос»; рассылки по списку остаются запрещены.

## Последствия

- Проекты, где `outreach` нет в профиле, ведут себя как раньше (только чтение).
- Риск аккаунта принимает владелец проекта; номер для отправки задаётся отдельно (`outreach.account`).
- Тесты пакета: выключено по умолчанию, сухой прогон, правила пропуска, один раз на человека, лимит, окно, свежий
  стоп, PeerFlood, закрытая личка, стоп-лист по ответу.
