# ADR-0006 — Контент-машина: пакет не вызывает модели, адаптеры стека — в инстансе

- **Статус:** Accepted
- **Дата:** 2026-10-26
- **Решение принял:** Дмитрий (решения Р11 и Р12 спецификации десяти систем, приняты 26.10.2026)

## Контекст

Волна 2 Контент-машины добавила производство и выпуск статьи: бриф, текст, критику, вычитку, судью спорного,
сборку страницы и публикацию. Здесь два выбора задают устройство пакета на все следующие волны.

1. **Кто вызывает модели.** Модельные шаги можно делать клиентом LLM-API внутри пакета или заданием агенту, который
   работает в Claude Code по подписке. Клиент API даёт запуск без человека, но тратит деньги на каждом шаге, а его
   защита держится на промпте.
2. **Где живёт код конкретного сайта.** Блоки конструктора, вёрстка и поля CMS у каждого проекта свои и содержат
   данные компании. Сборщик и публикатор можно перенести в пакет или оставить в репозитории проекта.

## Решение

- **Пакет моделей не вызывает (Р11).** Модельный шаг — задание агенту файлом `data/briefs/<id>/task_<имя>.md`: роль,
  основная и запасная модель из профиля (`models`), путь и схема результата. Результат проверяет код (например,
  `prepare check`), утверждает человек (`prepare approve`). Модели в профиле — псевдонимы последней версии семейства
  (`claude-opus-latest`), вторая независимая модель — `codex-latest`: проект не привязан к номеру версии. Клиент
  LLM-API остаётся опцией — адаптером через бюджет-гейт (цена до вызова, «да» человека, потолки профиля).
- **Адаптеры стека — в инстансе (Р12).** Ядро задаёт контракты `Assembler` (сборка → пакет с манифестом и суммами
  файлов) и `Publisher` (план действий, снимок «до», применение, чтение обратно, откат). В пакете — общие реализации:
  `html`, `markdown`, `static_repo`, `cms_api`. Сборщик и публикатор конкретного сайта лежат в инстансе проекта и
  подключаются строкой профиля `module:<путь от инстанса>:<класс>`; `assemble contract` и `check` проверяют их на
  синтетической статье.

## Рассмотренные альтернативы

- **Клиент LLM в ядре.** Запуск по расписанию без человека — но расход денег без «да», защита промптом, привязка к
  провайдеру. Отложено до спроса: адаптером через бюджет-гейт.
- **Сборщик первого потребителя в пакете.** Один код для всех — но данные и вёрстка компании в каноне, тест границы
  пакета краснеет, второй проект на другом стеке всё равно пишет своё.

## Последствия

- Цена модельной работы по подписке в учёте расхода — «нет данных», если агент не сообщил токены, а не ноль (Р21);
  задание просит поля `tokens` и `model_used`.
- Каждый проект пишет свой сборщик и, для прямой публикации, свой публикатор, если общих `html`, `markdown`,
  `static_repo`, `cms_api` не хватает. У первого потребителя сборщик блоков конструктора вызывает скрипты маршрута
  как есть и пишет только в рабочую папку темы.
- Запись вовне держат одни и те же механизмы ядра (ступени прав, снимок «до», подтверждение, блокировка, откат) —
  в том числе для адаптеров из инстанса: их действия идут через `core/actions.py`.
