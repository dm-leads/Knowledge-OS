# ADR-0007 — Проверка методобазы скриптом, рабочие типы документов, срок пересмотра по теме

- **Статус:** Accepted
- **Дата:** 2026-11-17
- **Решение принял:** Дмитрий («даю добро на все правки», варианты по умолчанию, 17.11.2026)

## Контекст

Аудит связки методобазы 17.11.2026 (`Методологии\_исходные-заметки\Аудит целостности методобазы (2026-11-17)\`)
показал, что расхождения возникают между документами, а не внутри них: карты ведутся руками и расходятся с
frontmatter, новое подключается в одну сторону. Три правила канона мешали проверять это кодом:

- конвенция типов не знала `plan` и `prompt` (8 документов ядра), а её список рабочих типов расходился со
  словарём префиксов в конвенции именования;
- `review_cycle` у 25 документов стоял не по правилу «срок ← тип», в том числе 1m у карты, которая меняется с
  каждой методологией, и 12m у источников, которые не устаревают;
- проверки перед коммитом не было, а в репозитории работают параллельные чаты — без базы известных нарушений любая
  проверка заблокировала бы чужие коммиты.

## Решение

1. **Рабочие типы.** В закрытый список добавлена группа «рабочие документы цепочки постановки»: `requirements`
   (префикс «Постановка» или «Требования»), `specification` («Спецификация»), `plan` («План»), `prompt` («Промпт»).
   Конвенции типов и именования сведены в один список. Документы в `_исходные-заметки\` (выжимки, сверки, описи)
   проверку «тип ↔ префикс» не проходят: это сырьё, не канон.
2. **Срок пересмотра — по теме.** `review_cycle` из закрытого списка `1m / 3m / 6m / 12m / never`; выбирается по
   тому, как быстро устаревает тема (карта и закон — чаще, первоисточник автора — реже). Снапшоты (`analytics`,
   `audit`, `decision` и др.) — `never`, как раньше.
3. **Скрипт.** `_Движок\Инструменты\kos_methodbase_check.py` проверяет методобазу и навыки по перечню из отчёта
   аудита: ссылки и разделы, frontmatter, ссылки за пределы канона, каталоги и карты, навыки, зрелость в карте.
   Новые нарушения — код 1; известные — в базе `kos_methodbase_baseline.json`, правило «не больше, чем было».
   База пересобирается командой `baseline` только по решению владельца.
4. **Когда запускать.** `check --changed` — перед коммитом в `Методологии\` и `_Движок\Исходники скиллов\`
   (чек-лист стандарта устройства методобазы, раздел 5); целиком — при закрытии волны извлечения и раз в месяц.
   Запуск git-хуком включается отдельной правкой стандарта Git после месяца работы скрипта без ложных срабатываний.

## Рассмотренные альтернативы

- **Привести 25 документов к правилу «срок ← тип».** Карта методобазы получила бы 6 месяцев при ежедневных
  правках, книга-первоисточник — 6 месяцев пересмотра без повода. Правило не отражает риск устаревания. Отклонено.
- **Хук сразу, без базы нарушений.** Заблокировал бы коммиты параллельных чатов по старым нарушениям. Отклонено.
- **Новые типы не вводить, переименовать планы и промпты.** Планы Контент-машины и промпты аудитов — устоявшийся
  рабочий слой цепочки постановки; переименование ломает ссылки без пользы. Отклонено.

## Последствия

- Конвенции типов, именования и метаданных в `_Движок\Канон\` обновлены в том же коммите.
- `Методологии\Стандарт — Устройство методобазы и подключение нового.md` ссылается на это решение.
- 3 документа с `type: task` и выжимки с `type: note` — предупреждения скрипта до следующей правки.
