# ADR-0004 — Подключение любого проекта к канону: ссылка `.kos` и блок в паспорте

- **Статус:** Accepted
- **Дата:** 2026-09-28
- **Запрос:** Дмитрий — «в любой проект заходил, в один чат, задавал запрос, и он сразу на все чаты
  распространял правила»

## Контекст

Проекты владельца лежат не только в `D:\Knowledge-OS`: репозиторий компании на диске C:, клиентские папки,
кодовые репозитории. Сценарии канона умели только разворачивать проект внутри KOS. Проект вне KOS получал правила
работы агента только из `~/.claude/CLAUDE.md` этого устройства (не версионируется) и из памяти чатов. Реестр
проектов и строки «канон сверен» у внешних проектов не было.

Пробы 28.09.2026 (`claude -p` в чистой папке, без инструментов чтения):
- импорт `@путь` с кириллицей в пути не грузится, даже внутри проекта;
- импорт по абсолютному пути вне проекта в режиме без окна подтверждения не грузится;
- импорт через ссылку-переход внутри проекта грузится, в том числе когда ссылка ведёт в папку с кириллицей
  в имени. Условие — латинская строка импорта и латинское имя файла.

## Решение

1. **Правила работы агента — в каноне**, одним файлом `_Движок/Подключение/agent-rules.md`. Файл короткий: он
   грузится в каждую сессию.
2. **Проект подключается ссылкой `.kos`** в своём корне на `_Движок/Подключение/` и строкой
   `@.kos/agent-rules.md` в `CLAUDE.md`. Копий правил в проектах нет.
3. **Блок «Канон Knowledge-OS» в `CLAUDE.md` проекта** — между метками `kos:begin` и `kos:end`. Его пишет
   `_Движок/Инструменты/kos_connect.py`: импорт правил, абсолютные пути к методологиям, реестру инструментов,
   пакетам и сценариям, строка «канон сверен: <дата>». Повторный запуск ничего не дублирует. Текст проекта вне
   блока не трогается.
4. **Исключения из конвенций канона:**
   - файлы `_Движок/Подключение/` называются латиницей, иначе их не импортировать;
   - в блоке подключения пути абсолютные: из проекта на другом диске относительной ссылки на канон нет.
5. **В репозитории компании** ссылка `.kos` исключается из git локально (`.git/info/exclude`), а блок
   коммитится с проектом. Коллеги без канона импорт не получают. Правила в репозиторий компании не копируются.
6. **Запрос владельца — одна строка со ссылкой на сценарий**
   [«Подключить проект к канону»](<../../Сценарии/Плейбук — Подключить проект к канону.md>). Шаги живут в
   каноне, поэтому запрос не устаревает.
7. **Подъём урока в канон из любого проекта разрешён**: обобщённый урок, строка CHANGELOG, коммит своих путей в
   KOS. Это исключение из правила «не менять за пределами проекта».

## Рассмотренные альтернативы

- **Копировать правила в `CLAUDE.md` каждого проекта.** Копия застывает в день копирования. Отклонено.
- **Абсолютный импорт `@D:/Knowledge-OS/...`.** Не грузится: кириллица в пути, внешний импорт требует
  подтверждения. Отклонено по пробе.
- **Держать правила только в `~/.claude/CLAUDE.md` устройства.** Файл не версионируется и не переносится на
  другое устройство. Как источник отклонено. Импортировать правила канона из глобального файла можно:
  тогда проекты подключаются с `--no-rules-import`. Решение за владельцем.

## Последствия

- Любой проект подключается одной командой, проверка — свежей сессией без доступа к файлам (пилот 28.09.2026:
  сессия назвала заголовок правил, дату сверки и лимит субагентов).
- В `~/.claude/CLAUDE.md` пока лежат те же правила текстом, и в подключённых проектах они грузятся дважды.
  Предложено сократить глобальный файл до особенностей устройства; до решения владельца дубль остаётся.
- Правка `agent-rules.md` меняет поведение агента во всех подключённых проектах, поэтому её фиксируют строкой
  CHANGELOG движка.
