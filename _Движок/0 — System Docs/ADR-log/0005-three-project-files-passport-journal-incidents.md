# ADR-0005 — Три файла проекта: паспорт, журнал действий, база инцидентов

- **Статус:** Accepted
- **Дата:** 2026-09-28
- **Решение принял:** Дмитрий («делай», 28.09.2026)

## Контекст

Дмитрий попросил проверить, закреплено ли в каноне, что у каждого проекта есть журнал действий, база инцидентов
и основной документ с особенностями проекта, которые агент ведёт сам. Проверка 28.09.2026: паспорт (`CLAUDE.md`)
был — шаблоном и в каркасе; журнал упоминался мимоходом («закрывая сессию — короткая запись»), без места и
формата; база инцидентов — в петле инцидентов методологии и в справочнике классов ошибок («в проекте ведётся
своя»), без шаблона. Ни один из двух файлов не заводился при подключении проекта, в правилах агента не было,
когда их читать и писать. У первого инстанса оба файла работали с июля 2026 и каждый раз окупались.

## Решение

1. **Стандарт** «Три файла проекта» в `Методологии\`: назначение, место по умолчанию, формат, когда читать и когда
   писать.
2. **Шаблоны** журнала (помесячный файл: действия и выводы из данных) и базы инцидентов в `_Движок\Шаблоны\`;
   в паспорте — раздел «Особенности проекта и правила работы с ним».
3. **Правила агента** (`agent-rules.md`, раздел «Три файла проекта»): журнал — в начале чата и после блока
   работы; база инцидентов — до гипотез о причине сбоя, перед шагом, который уже ломался, и после разбора;
   особенность проекта — в паспорт в тот же ход.
4. **`kos_connect.py`** заводит журнал и базу из шаблонов, если их нет, и пишет пути в блок паспорта. Свои файлы
   проекта указываются ключами `--journal`, `--incidents`, запоминаются в блоке и не трогаются. Похожие файлы в
   проекте без переданных ключей — остановка, а не второй экземпляр.
5. **Имена по умолчанию — по конвенции именования:** `0 — System Docs\Журнал действий\Журнал — ГГГГ-ММ.md`
   (тип `log`) и `0 — System Docs\Справочник — База инцидентов.md` (тип `reference`); стандарт System Docs
   дополнен этими двумя файлами.

## Рассмотренные альтернативы

- **Держать всё в памяти агента.** Память привязана к устройству и папке, её не видят коллеги, другие агенты и
  устройства. Отклонено.
- **Один файл вместо трёх.** Паспорт грузится в каждую сессию и должен быть коротким, журнал растёт каждый день,
  база читается по поводу. Смешение раздувает контекст каждого чата. Отклонено.
- **Журнал одним файлом без деления по месяцам.** Файл растёт без предела, чтение хвоста дорожает. Отклонено;
  единый файл допустим, если проект уже так ведёт журнал.
- **Каркас нового проекта с готовыми файлами без инструмента.** Проекты вне канона не штампуются из каркаса.
  Инструмент подключения покрывает оба случая одним механизмом. Отклонено.

## Последствия

- Любой новый или подключаемый проект получает три файла одной командой; правила чтения и записи действуют во
  всех чатах устройства через глобальный импорт правил.
- Проект с уже заведёнными файлами подключается с ключами, второго экземпляра не появляется.
- Правило публикации канона уточнено в тот же день: push канона — сам после блока изменений, со сканом на секреты
  (разрешение владельца только для этого репозитория); общее правило агента — push по команде, если паспорт
  репозитория прямо не разрешает иное.
