# Спецификация — Архитектура Knowledge-OS

## Краткая суть

Knowledge-OS — переносимый «движок знаний»: форк логики «Второго мозга Бризекс», очищенный от
начинки конкретной компании и переориентированный на работу через **Claude Code**. Даёт каноны
(типы, имена, метаданные, ссылки, память), шаблоны, скиллы и три сценария: развернуть движок,
заштамповать новый проект, привести существующую папку к канону. **Один движок — много проектов.**

## Происхождение и принцип

- **Источник:** «Второй мозг Бризекс» (Cursor-канон: Handbook + скиллы + правила `.mdc`).
- **Что взято (механика):** PARA-каркас, канон документа, память изменений, SSOT/DRY, навигация
  через `_manifest`, онбординг (bootstrap + tour).
- **Что убрано (начинка):** продукты/люди/процессы/инструменты Бризекса (Atmeex, конкретный Lark/
  GitLab, TAIRA/KAIA, направления вроде «контент-машины»).
- **Что переориентировано:** Cursor `.mdc` + `SKILL.md` для агента → нативные **Claude Code скиллы**
  + **`CLAUDE.md`** как корневой «мозг» проекта.

## Раскладка на диске

```
D:\Knowledge-OS\
├─ CLAUDE.md                         ← корневой «мозг» OS: как устроено, где канон, какие скиллы, реестр проектов
├─ _Движок\                          ← переиспользуемый движок (SSOT канона), company-agnostic
│  ├─ Канон\                         ← обобщённый Handbook (методология + стандарты + справочники)
│  ├─ Шаблоны\                       ← по шаблону на каждый тип + манифесты + CLAUDE.md проекта
│  ├─ Каркас\                        ← пустой PARA-каркас (копируется при штамповке проекта)
│  ├─ Сценарии\                      ← три промпта-сценария (bootstrap / stamp / canonize)
│  ├─ Исходники скиллов\             ← исходники скиллов (версионируются; ставятся в ~/.claude/skills)
│  └─ 0 — System Docs\               ← собственная память движка (этот файл, ADR, CHANGELOG, BACKLOG)
│
├─ .claude\                          ← (опц.) проект-скоуп Claude Code для корня OS
│
└─ <Имя проекта>\                    ← каждый новый проект = самостоятельное PARA-дерево
   ├─ CLAUDE.md                      ← паспорт проекта (заполняем вместе, агент поддерживает)
   ├─ 01 — Проекты\  02 — Области\  03 — Ресурсы\
   ├─ 04 — Чувствительные области\   05 — Чувствительные проекты\   (зарезервированы, deny-by-default)
   ├─ 06 — Инструменты\
   └─ 0 — System Docs\               (создаётся лениво)
```

## Модель «движок ↔ проект» (A — ссылка)

- Канон живёт **один раз** в `_Движок\Канон` (SSOT). Проекты **ссылаются**, не копируют.
- Скиллы ставятся в `~/.claude/skills` (user-scope, работают в любом проекте), исходник
  версионируется в `_Движок\Исходники скиллов`.
- Каждый проект — самостоятельное PARA-дерево + свой `CLAUDE.md` (паспорт).
- Переносимость в отрыве от машины — опционально через «вморозить снапшот канона» (см. BACKLOG).

## Канон документа

- **Закрытый список типов** (17 знаниевых + системные `manifest`/`changelog`/`backlog` +
  project-extra `charter`/`requirements`/`specification`/`log`/`artifact` + resource-extra). Стартовый,
  меняется **только через ADR движка**.
- **Имя файла:** `<Префикс типа> — <Короткое название>.md`.
- **Единый русский нейминг** (требование однообразия): префиксы максимально по-русски, по **одной**
  таблице, без разнобоя EN/RU. Машинный `type:` в frontmatter — стабильный английский id.
  Каноничный источник таблицы — `Канон/Стандарт — Конвенция именования`. Рабочая версия:

  | type (id, frontmatter) | Префикс файла (рус) |
  |---|---|
  | policy | Политика |
  | standard | Стандарт |
  | workflow | Процесс |
  | runbook | Ранбук |
  | playbook | Плейбук |
  | instruction | Инструкция |
  | methodology | Методология |
  | reference | Справочник |
  | guide | Гайд |
  | bootstrap | Бутстрап |
  | template | Шаблон |
  | analytics | Аналитика |
  | retrospective | Ретроспектива |
  | postmortem | Постмортем |
  | audit | Аудит |
  | research | Исследование |
  | specification | Спецификация |
  | charter | Устав |
  | requirements | Требования |
  | log | Журнал |
  | artifact | Артефакт |
  | decision | (в `ADR-log/`: `NNNN-kebab.md`, без префикса) |

  > Транслитерации **Ранбук / Плейбук / Бутстрап** приняты как канон (решение 2026-06-28).

- **YAML-frontmatter** обязателен; `gitlab_url` — **опционален** (только для контуров, привязанных к GitLab).
- **Навигация 3 слоя:** `_manifest.md` (каталог) + inline-ссылка на первом упоминании + футер
  «Связанные документы» (3–7, потолок ~10).

## Память изменений (git — опционально)

- `0 — System Docs\`: `CHANGELOG.md` + `BACKLOG.md` + `ADR-log\` (+ git history, если контур в git).
- «Что» → git history; «значимое + когда» → CHANGELOG (лениво); «почему» → ADR (одно решение).
- Работает и без git; git/GitLab — бонус для облака и истории.

## GitLab (механика сохранена, обобщена)

- Роль: облачное хранилище контуров. Конкретный GitLab и проекты заводишь **сам**.
- Движок даёт:
  - `Канон/Стандарт — Git и GitLab workflow` — команды `обнови` / `сохрани черновик` / `опубликуй`,
    модель осознанной публикации, push-allowlist под `D:\Knowledge-OS\`.
  - `Каркас\06 — Инструменты\mcp.template.json` — конфиг GitLab MCP с плейсхолдерами (копируется в проект как `mcp.json`).
  - короткий runbook подключения нового репозитория.
- **Секреты (PAT) — никогда в git/чат**, только в локальном конфиге.

## Скиллы (Claude Code, doc-канон ядро)

- `create-doc` — создать документ по канону (placement → тип → имя → метаданные → шаблон → ссылки).
- `doc-compliance` — привести документ/папку к канону (метаданные, имена, ссылки, футер).
- `memory-check` — брифинг перед работой в живом контуре (tier 0–3).
- `migrate-to-canon` — разложить чужую/хаотичную папку по PARA-канону (ядро сценария «изучи папку»).
- (Доп., следующий этап) лёгкий `publish`/`sync` поверх GitLab-механики.

## Два уровня CLAUDE.md

- `D:\Knowledge-OS\CLAUDE.md` — как устроен OS, где канон, какие скиллы, реестр проектов. Всегда в контексте.
- `D:\Knowledge-OS\<Проект>\CLAUDE.md` — паспорт проекта: что это, направления (замена «контент-машины»),
  глоссарий-дельты, ключевые решения. **Агент поддерживает его в актуальности между чатами.**

## Три сценария (`_Движок\Сценарии`)

1. `bootstrap-knowledge-os` — разовая настройка движка + установка скиллов в `~/.claude/skills`.
2. `stamp-new-project` — копия `Каркас` → новый проект, интервью → заполнение `CLAUDE.md`.
3. `canonize-existing-folder` — навёл на папку → `migrate-to-canon` → канон (превью перед изменениями, без потери данных).

## Что generic, что настраивается под проект

- **Generic:** PARA-каркас, канон документа, память, навигация, скиллы, флоу.
- **Настраивается:** список направлений (areas), глоссарий проекта, какие контуры → GitLab,
  наполнение чувствительных 04/05.
