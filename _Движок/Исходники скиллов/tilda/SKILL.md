# Тильда через MCP

Официальный удалённый MCP-сервер Тильды: 279 инструментов (версия 1.0.1, ноябрь 2026). Токен выпускается в кабинете
Тильды и даёт доступ к одному проекту-сайту. Оценка инструмента и вердикт — в реестре канона:
`Экосистема инструментов/03 — Ресурсы/Оценки инструментов/Справочник — Оценка MCP Тильды.md`. Скрипты — `scripts/`
рядом с этим файлом; запускать из любого проекта абсолютным путём.

## 1. Сайт живой — правила записи

1. **Чтение свободно, запись — по «да» владельца на конкретное изменение**: что, на какой странице, как было, как
   станет. «Да» на одну правку не распространяется на соседние.
2. **Снимок «до» перед каждой записью** (JSON блока, товара, кода страницы) в папку снимков проекта. Скрипты из
   `scripts/` без снимка не пишут.
3. **Малыми шагами**: одна страница → владелец смотрит в редакторе → остальные.
4. **Обратное чтение после записи** и сверка с отправленным; расхождение — стоп, а не «готово».
5. **Каждая запись — строкой в журнал действий проекта**: что, где, номера блоков, где снимки, как проверить и откатить.
6. **Публикацию держит владелец**, пока не сказал иначе: правки страниц делаются в черновике, `publish_page` — только
   по прямой просьбе.
7. Значение токена — никогда в чат, файлы настроек и git. В документах — только имя переменной.

## 2. Подключение в проекте

- Токен — в файле секретов устройства под именем `TILDA_MCP_KEY_<САЙТ>`.
- В `.mcp.json` проекта (не глобально) сервер с уникальным именем `tilda-<сайт>`; заголовок отдаёт помощник:

```json
{"mcpServers": {"tilda-<сайт>": {"type": "http", "url": "https://tilda.ru/api/mcp/",
  "headersHelper": "python \"<путь к навыку>/scripts/mcp_bearer_header.py\" TILDA_MCP_KEY_<САЙТ>"}}}
```

- `mcp_bearer_header.py` берёт значение из окружения, иначе из файла секретов (второй аргумент — когда ключи лежат в
  контуре проекта; иначе `SECRETS_ENV_FILE`, по умолчанию `~/Second Brain Secrets/.env`; путь с кириллицей в
  аргументе под cmd работает, проверено 02.11.2026) и печатает `{"Authorization": "Bearer …"}` — этот вывод читает Claude Code, не чат.
- Имя `tilda-<сайт>` обязательно разное у разных сайтов: одинаковые имена молча перекрывают друг друга (локальная >
  проектная > пользовательская настройка), и агент пойдёт не на тот сайт. Путь к помощнику — без кириллицы, если
  возможно: на Windows команда с кириллицей в пути может не запуститься.
- **«Dynamic Client Registration rejected (HTTP 404)»** = помощник не запустился и клиент ушёл в OAuth. Причина почти
  всегда — у папки проекта нет отметки доверия (`hasTrustDialogAccepted: true` в `~/.claude.json`; на Windows две
  записи папки, `C:/…` и `c:/…`). Новые версии Claude Code без неё `headersHelper` не запускают, а расширение VS Code
  окно доверия само не показывает. Лечится запуском `claude` в терминале этой папки с «да» на доверие или отметкой в
  файле (с копией файла до правки, с разрешения владельца). Лог: `%LOCALAPPDATA%\claude-cli-nodejs\Cache\<папка>\mcp-logs-<сервер>\`.
- **Codex** не читает `.mcp.json`: сервер в `~/.codex/config.toml` с `bearer_token_env_var = "TILDA_MCP_KEY_<САЙТ>"`,
  переменную поднять из файла секретов только для процесса Codex. Ключи конфига сверить с версией Codex.
- Скрипты из `scripts/` ходят в сервер сами: перед запуском `TILDA_MCP_VAR=TILDA_MCP_KEY_<САЙТ>` (имя, не значение).
- Проверка подключения: `python scripts/mcp_tools_inventory.py https://tilda.ru/api/mcp/ TILDA_MCP_KEY_<САЙТ> out.json`
  — опись инструментов с метками; после обновления сервера Тильдой снять заново и сверить.

## 3. Три группы инструментов

| Группа | Что | Примеры |
|---|---|---|
| Только чтение | проекты, страницы, блоки, предпросмотр, SEO-файлы, статистика, магазин, блог | `get_*`, `edit_record` (читает поля блока, несмотря на имя), `get_zero_block`, `page_preview`, `stats_get_*`, `store_get_*`, `feeds_get_*`, `*_instructions`, `describe_tool` |
| Черновик (видно после `publish_page`) | блоки, страницы, библиотека блоков, картинки | `update_record`, `update_zero_block`, `duplicate_record`, `delete_record`, `toggle_page_block_visibility`, `update_page_head_code`, `page_undo` |
| Сразу на живом сайте и вовне | публикация, настройки проекта, robots, редиректы, **магазин**, блог, коннекторы маркетплейсов, письма | `publish_page`, `update_project_*`, `store_save_products`, `feeds_update_post`, `store_run_connectors_*_sync`, `send_test_emails` |

⚠️ Проектные CSS, код в `<head>` проекта и шрифты формально «черновик», но уходят на сайт с первой публикацией
**любой** страницы — согласовывать как живую правку. ⚠️ `get_form_integrations` отдаёт адреса вебхуков с ключами,
`store_get_orders*`, `get_payments_history`, `get_profile` — персональные данные: не печатать, без задачи не читать.

Инструменты-заглушки с подсказкой «Call describe_tool» раскрывает `describe_tool`. Перед задачей на Zero Block —
прочитать `zero_block_instructions` (полная схема JSON блока) — сервер сам это просит.

## 4. Протокол сервера (если ходить в него своим кодом)

- После `initialize` каждый запрос несёт `Mcp-Session-Id` и **`MCP-Protocol-Version`** — без него HTTP 400.
- Лимит частоты: HTTP 429 с `retry_at` в теле — ждать до него и повторить. Массовые проходы по 7–20 блокам идут
  минутами; гнать их в фоне.
- Ответ — JSON или SSE; клиент `scripts/mcp_tools_inventory.py` (класс `Client`) умеет всё это.

## 5. Как устроены страницы и блоки

- Страница — список блоков (`get_page_records`: `recordid`, `tplid`). Zero Block — `tplid` 396; блок-альяс тоже
  числится 396, но `get_zero_block` на нём отвечает «It is not ZeroBlock!» — пропускать.
- **Zero Block** = один JSON: ключи `ab_*` (артборд), элементы под числовыми ключами `"0"`, `"1"`…, `groups`, `meta`,
  `timestamp`. Читать `get_zero_block`, писать `update_zero_block` **целиком**; менять только нужное, остальные ключи
  сохранять как есть.
- **Ширины.** Без `ab_screens` блок свёрстан под 320, 480, 640, 960, 1200: ключ без суффикса — десктоп, остальные —
  `top-res-960`, `-res-640`, `-res-480`, `-res-320`. Ключа нет — берётся значение ближайшей **более широкой** ширины.
  Новый элемент ставить на **каждую** ширину. `container-res-320: window` — на телефоне координаты от края окна.
- **Высота артборда** — `ab_height` и `ab_height-res-<w>` по ширинам; добавил элемент ниже всех — поднять высоту на
  тех ширинах, где он не помещается. Элементы при этом не сдвигаются (координаты от верха).
- **Новый элемент**: `elem_id` — 19 цифр (мс времени + счётчик `000001`), длиннее нельзя; уникальный `zindex`;
  `layer` — имя в редакторе. Высота текста не меряется по JSON: оценка — символов × 0,6 × кегль ÷ ширина строк,
  каждая строка × кегль × межстрочный; следующий элемент — с запасом.
- **Тильда нормализует HTML**: `<br>` сохраняет как `<br />`. При обратном чтении сравнивать с учётом этого (или
  писать сразу `<br />`), иначе ложная тревога. `timestamp` при сверке исключать.
- Логические группы (`type: logical`) — только выделение в редакторе; координаты считаются по элементам.
- Цвет и контраст: на тёмном фоне серая сноска — `#a6a6a6` или около; подписи сайта смотреть в самом блоке.
- Поля обычных (не Zero) блоков: `edit_record` → `update_record` с `only_field`; списки (поля формы, приёмники
  заявок) принимают **весь** список — пропущенный элемент удаляется, пустой список отключает все приёмники заявок.

## 6. Видимость и копии блоков

- `toggle_page_block_visibility` **переключает**, а не ставит состояние; отвечает `y` (скрыт) / `n` (виден).
  `get_page_records` состояние не показывает.
- Текущее состояние черновика — `page_preview` (HTML страницы вместе с неопубликованными правками): есть
  `rec<номер>` — блок виден. Ответ переключателя сверять с ожидаемым; не совпал — переключить обратно и стоп.
- `duplicate_record` ставит копию **сразу после** образца и наследует его видимость. Несколько копий с одного образца
  встают в обратном порядке (последняя — ближе к образцу).
- Черновик и живая страница расходятся до публикации: что видит посетитель — по живому HTML (`id="rec<номер>"`).
- Варианты оформления показывать владельцу копиями блока рядом с образцом (подпись `ab_title`), образец не трогать;
  после выбора лишние копии удалить и перенести вариант в рабочие блоки.

## 7. Альяс-блоки (общие плашки, карточки)

- Оригинал живёт на служебной странице, на других страницах стоят альясы. Правится только оригинал.
- Альяс подхватывает **сохранённый черновик** оригинала в момент публикации **той страницы, где он стоит**.
  Служебную страницу публиковать не нужно, но без переопубликации страниц с альясом сайт не меняется.
- Где стоит альяс — обход опубликованных страниц по `id="rec<номер оригинала>"`. Номер самого альяса на странице
  свой: у блока-альяса (`tplid` 396 или 121, `get_zero_block` — «not ZeroBlock») `edit_record` отдаёт
  `aliasrecord` = номер оригинала — так альясы находятся по всем страницам.
- ⚠️ Альяс выводится в HTML под номером **оригинала**, не своим: по `page_preview` видимость конкретного альяса не
  понять, а на одной странице их бывает два (видимый и давно скрытый). Скрывать по одному: переключить, ответ `y` —
  был виден, теперь скрыт; ответ `n` — был скрыт, сразу переключить обратно. Итог проверять исчезновением
  `rec<номер оригинала>` со страницы (случай 06.11.2026: снятие акции, на главной два альяса одной плашки).
- Снятие акции целиком: прежде чем править, обойти черновики и живые страницы всех страниц сайта (кроме блога) по
  маркерам акции — цены по акции, процент, дата «до …»: кроме ценовых блоков и альясов находятся полоса-анонс и
  всплывающая форма в общем подвале и окна на странице акций; после правки — тот же обход повторно.

## 8. Цены и акции на товарных страницах

Типовая сборка: цена вписана в Zero Block текстом (цена, зачёркнутая старая, кнопка `#order:<Товар>=<цена>:::image=…`
— по ней цена уходит в корзину), а в коде страницы JSON-LD `"price"`. Магазин Тильды хранит цены отдельно, страница
их не читает.

- **На странице виден один ценовой блок, остальные скрыты, не удаляются.** Новая акция — копия блока текущей акции, в
  копии меняются ровно цена и ссылка кнопки, прошлые ценовые блоки скрываются. Конец акции — показать блок без
  акции, скрыть акционный. Прошлые блоки — готовый откат одним переключением.
- JSON-LD `"price"` в коде страницы — цена по акции (`update_page_head_code`).
- Общий элемент первого экрана (сноска о доставке, гарантии) ставить во **все рабочие** ценовые блоки: видимый,
  прошлой акции и без акции — иначе при смене акции он пропадёт. Архив старых акций можно не трогать — сказать
  владельцу.
- Скрипты: `tilda_price_blocks.py` (разведка ценовых блоков и JSON-LD по страницам, только чтение),
  `tilda_promo_price.py` (акционная цена: копия, 2 правки, разметка, один видимый блок),
  `tilda_zero_note_under_buttons.py` (серая сноска под кнопками во всех указанных блоках, место по кнопкам на каждой ширине).

## 9. Магазин и фид

- Магазин меняется **сразу**, без публикации.
- `store_save_products`: большинство полей при пропуске сохраняются, но **галерея при пропуске очищается** — всегда
  передавать `title` и `gallery` из снимка. `store_save_products_field` стирает пропущенные поля и заменяет пустой
  артикул сгенерированным — не использовать для правки цены.
- Акция в магазине: `price` — цена по акции, `priceold` — прежняя. После записи прочитать товар и сверить, что кроме
  цен ничего не поменялось (`tilda_apply_block.py product` делает это и отказывает, если товар менялся после снимка).
- Фид товаров (`/feed-*.csv` и подобные) Тильда пересобирает **с задержкой**, не сразу после правки товара; проверять
  позже, отдельно сказать владельцу.

## 10. Публикация и откат

- `publish_page` — по прямой просьбе владельца; после — проверить живую страницу (HTML, а не только ответ `OK`).
- Откат до публикации — `page_undo` или запись блока из снимка «до» (`tilda_apply_block.py zero <…> <снимок_до> <снимок_до>`);
  после публикации — то же и повторная публикация. Удалённый блок — `recover_record`.

## 11. Скрипты (`scripts/`)

| Скрипт | Что делает | Пишет? |
|---|---|---|
| `mcp_bearer_header.py <ПЕРЕМЕННАЯ>` | заголовок авторизации для `headersHelper` | нет |
| `mcp_tools_inventory.py <URL> <ПЕРЕМЕННАЯ> <out.json>` | опись инструментов; класс `Client` для своих скриптов | нет |
| `mcp_call_readonly.py <URL> <ПЕРЕМЕННАЯ> <инструмент> '<JSON>' <out.json>` | вызов читающего инструмента со снимком в файл; пишущие отсечены белым списком в коде | нет |
| `tilda_price_blocks.py` | ценовые Zero Block страниц, видимость на живой странице, JSON-LD | нет |
| `tilda_apply_block.py zero\|record\|head\|product` | одна запись из подготовленного файла со снимком «до» и сверкой | да, черновик / магазин сразу |
| `tilda_promo_price.py` | акционная цена на странице по механике п. 8 | да, черновик |
| `tilda_zero_note_under_buttons.py` (`NOTE_FILE`, `--dry`) | сноска под кнопками во всех указанных Zero Block | да, черновик |

Все пишущие скрипты требуют `TILDA_MCP_VAR` и папку снимков проекта; `--dry` (где есть) — сначала расчёт без записи.
