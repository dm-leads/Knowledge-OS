# questions — бриф вместо чистого листа

Любую непонятную/новую задачу начинаем отсюда. Цель — не угадывать, а **вытащить из пользователя бриф**:
что, для кого, когда, зачем, и что значит «сделано хорошо». На выходе — структурированный бриф, готовый на
вход любому агенту/навыку. (Идея из эфира Красинского: скилл «Вопросы» как первый шаг.)

## Процедура

1. **Определи оптику (эксперт-линзу).** Под тип задачи назови, чьими глазами смотрим (арт-директор для лендинга, аналитик для метрик, архитектор для системы, редактор для текста, продакт для фичи). Можно 1-3 линзы.

2. **Разложи по Job-to-be-Done.** Кто актор, в какой ситуации, какую работу «нанимает» результат, какой следующий шаг, что для него success. Отметь, чего пока не знаешь.

3. **Задай 7-20 вопросов, калиброванных по важности задачи.** Мелкая задача — ближе к 7, крупная/дорогая — к 20. Не вываливай всё разом: сгруппируй и иди по приоритету. Блоки вопросов:
   - **Цель и контур:** какой результат, к какому проекту/направлению относится, зачем сейчас.
   - **Аудитория/актор (JTBD):** для кого, в какой ситуации, что человек должен понять/сделать.
   - **Границы:** что входит и что НЕ входит (scope / out-of-scope).
   - **Критерии «хорошо» (DoD):** как поймём, что сделано качественно; какие метрики/проверки.
   - **Ограничения:** данные/ПДн, бренд/ТМ, каналы, дедлайн, бюджет, кто публикует.
   - **Риски и подводные:** где легко сделать брак, что уже пробовали и не сработало.
   - Для каждого блока — только реально нужные вопросы; пропускай очевидное.

4. **Для выбора из вариантов используй AskUserQuestion** (2-4 опции с рекомендацией), для открытых — обычный текст. Спрашивай столько, сколько нужно для брифа, но не изматывай: сначала самое решающее.

5. **Собери БРИФ** (это и есть результат навыка):
   - Задача (одна фраза) · Оптика/линза · JTBD (актор → ситуация → работа → success) ·
   - В scope / Не в scope · Критерии готовности (DoD) · Ограничения · Известные риски ·
   - Открытые вопросы, оставшиеся без ответа (явно) · Предлагаемый первый шаг.

6. **Отдай бриф как вход** следующему шагу/агенту/навыку — не начинай исполнение, пока бриф не подтверждён (если задача дорогая/необратимая).

## Правила

- **Сначала спросить, потом делать.** Час на бриф экономит недели переделок (порядок операций).
- **Калибровка:** не задавай 20 вопросов на пустяк и не лети в бой на сложной задаче с двумя.
- **Не выдумывай ответы за пользователя** — если чего-то не знает, помоги сформулировать, но зафиксируй как открытый вопрос.
- Уважай канон проекта, в котором работаешь (Second Brain / Knowledge-OS): бриф не заменяет каноничный документ, а готовит его.

## Мини-пример

Запрос: «Хочу лендинг под новый прибор». Линза: арт-директор + продакт.
Вопросы (сокр.): какой прибор и чем отличается? кто ЦА и в какой ситуации ищет? какое одно действие нужно от посетителя? какие доказательства (отзывы/цифры) есть? какие ограничения по бренду/ТМ? что считаем успехом (заявка? какая конверсия)? кто и где публикует? →
Бриф: задача, JTBD, scope/не-scope, DoD (оффер/доверие/форма/мобайл), ограничения (ТМ, публикует Дмитрий), первый шаг.
