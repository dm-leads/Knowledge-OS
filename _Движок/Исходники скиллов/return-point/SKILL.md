# return-point — точка возврата потока

Правила — в каноне: `D:\Knowledge-OS\Методологии\Стандарт — Непрерывность работы с агентами.md`, раздел 2.
Перед первым применением в сессии прочитай его. Здесь — порядок действий. Навыку нужны только чтение и запись
файлов и команды git, поэтому он одинаково работает в Claude Code, Codex и агенте Cursor.

Стандарт — черновик. Пока владелец его не принял, навык применяется только по слову человека. Навык и стандарт
разошлись — назови расхождение человеку.

## Записать — конец блока работы

1. **Найти файл.** Путь назван в паспорте проекта. Не назван — файл `Точка возврата.md` в корне проекта; у
   проекта несколько потоков — папка `Точки возврата\`, файл на поток. Новый путь вписать в паспорт, в раздел
   особенностей проекта, и сказать об этом человеку.
2. **Назвать пути потока** — папки и файлы, за которые отвечает этот поток, и репозитории, в которых они
   лежат. В общем репозитории работают и другие чаты: их изменения к потоку не относятся.
3. **Снять состояние, а не вспомнить его.** В каждом репозитории потока: `git status -sb` — ветка, сколько
   коммитов не отправлено, что не закоммичено; `git log -3 --oneline -- <пути потока>`. Папка без git — так и
   записать. Дату и время взять командой системы, а не из памяти.
4. **Перезаписать файл целиком** по форме ниже. Он помещается на один экран.
5. **Проверить четыре вещи:** в файле нет секретов, токенов и персональных данных; следующий шаг — одно
   действие, которое можно начать без вопроса; каждый путь из «Что читать» существует; сказанное о ветке и
   коммитах совпадает с выводом git.
6. **Дописать строку в журнал действий** проекта, если он есть. Точку возврата закоммитить тем же коммитом,
   что и работу, если проект в git и его правила это разрешают.

```markdown
# Точка возврата — <поток>

Обновлено: <дата и время> · <среда и агент>.
Пути потока: <папки и файлы>.
Состояние на момент записи: <репозиторий> — ветка <имя>, опорный коммит <хеш>; не закоммичено: <что>;
не отправлено: <сколько коммитов>. Эта запись уходит следующим коммитом вместе с работой.

## Цель и рамки
## Где остановились
## Следующий шаг
## Что читать
## Ждёт человека
## Не делать
## Вне файлов
```

Опорный коммит — последний коммит по путям потока перед этой записью. Что в каком разделе — таблица стандарта.
Коротко: цель — две-три строки или ссылка на стартер и постановку; «Что читать» — до семи путей в порядке
чтения; очередь задач — ссылкой на `TASKS.md` или план, а не копией; «Вне файлов» — что запущено или изменено
во внешних системах и какие MCP и доступы нужны.

## Свежа ли точка возврата

Точка возврата свежа, когда выполнены оба условия:

- последний коммит по путям потока — тот же, в котором записана она сама, либо она изменена позже него и ещё
  не закоммичена: сравнить `git log -1 --format=%h -- <пути потока>` и
  `git log -1 --format=%h -- "<файл точки возврата>"`;
- `git status -sb` по путям потока не показывает ничего сверх названного в её шапке.

Коммиты других потоков в том же репозитории её не старят. Папка без git — сравнить дату в шапке с датами
изменения файлов по путям потока.

## Поднять — новая сессия, другой агент, другая среда

1. До «да» человека ничего не менять: ни файлов проекта, ни точки возврата, ни паспорта.
2. Прочитать по порядку: паспорт проекта; правила работы агента
   `D:\Knowledge-OS\_Движок\Подключение\agent-rules.md`, если среда не загрузила их сама; точку возврата;
   последние записи журнала действий, а если журнала у проекта нет — `TASKS.md` и журнал изменений.
   В корне лежат и `CLAUDE.md`, и `AGENTS.md`, а строки `@AGENTS.md` в первом нет — главным считать
   `CLAUDE.md`, второй — копией; расхождение назвать человеку.
3. Проверить свежесть по разделу выше.
4. Ответить человеку пятью пунктами: где остановились; какой следующий шаг; свежа ли точка возврата и что
   расходится; каких доступов и MCP из раздела «Вне файлов» в этой среде нет; что предлагаю — выполнить шаг
   или сначала восстановить точку возврата и по каким источникам.
5. После «да», если точки возврата нет или она устарела, — восстановить её по журналу действий,
   `git log -20 -- <пути потока>`, `git status -sb`, `TASKS.md` и плану и записать по разделу «Записать».
   Память прежнего агента лежит обычными файлами: у Claude Code —
   `~/.claude/projects/<папка проекта>/memory/MEMORY.md`, у Codex — `~/.codex/memories/`. Брать из неё только
   то, что нужно для следующего шага; персональные данные и секреты в ответ и в файлы не переносить.
6. Выполнить следующий шаг. Недостающие доступы записать в «Ждёт человека». Закончив блок работы — «Записать».

## Когда записывать

По слову человека. Без напоминания — после блока работы, перед долгим прогоном и вопросом владельцу, перед
сменой среды, когда человек говорит, что лимиты на исходе, или среда предупреждает о сжатии контекста — только
после того, как владелец примет стандарт и правило появится в `agent-rules.md`.

## Чего не делать

- Не писать по памяти чата: точке возврата поверят, поэтому неверная хуже отсутствующей.
- Не дополнять старый текст: история живёт в журнале действий, здесь — только текущее состояние.
- Не копировать сюда `TASKS.md`, план и стартер чата — ставить ссылку.
- Не читать файл прежней сессии целиком и не отдавать его внешней модели: в сессиях встречаются токены и
  персональные данные. Хвост сессии — только отрывок, который дал человек.
- Не заводить точку возврата для вопроса или правки на один чат.
- Не называть работу закоммиченной, отправленной или проверенной, пока этого не показал git или проверяющий.
