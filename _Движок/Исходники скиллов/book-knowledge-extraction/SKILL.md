# book-knowledge-extraction — извлечение применимых знаний из книг и материалов

> **Черновик, улучшаем по применению** (добавлен 26.11.2026). Основа — переносимый навык
> `book-knowledge-extraction` Ильи Красинского (Heroes Camp / Product Heroes, 2026; лицензия и авторство —
> `LICENSE.md` рядом, ссылка: [heroes.camp](https://heroes.camp)), адаптирован под стандарт канона Knowledge-OS:
> [Стандарт — Извлечение знаний из обучающих материалов](<../../Канон/Стандарт — Извлечение знаний из обучающих материалов.md>).
> Пакет остаётся переносимым (`detachable: true`) и работает как внутри Knowledge-OS, так и автономно в других
> системах (Claude Code, Codex, Antigravity и др.).

## Суть и цель

Книга или обучающий материал — **не для «пересказать подряд»**, а сырьё для применимой базы знаний.
На выходе получается структурированная выжимка, в которой для каждой идеи понятно: **где она в источнике**,
**когда её применять**, **как действовать**, **какого результата ждать** и **что нового она даёт сверх уже известного**.

## Два режима работы

| Режим | Когда | Выходной файл и обязательные секции |
|---|---|---|
| **Внутри Knowledge-OS** | Работа ведётся в контуре `D:\Knowledge-OS\` | Выжимка по формату канона (`Выжимка — <Название> (<Автор>).md` или `NOTE-SRC-<слаг>-distill.md`): YAML-шапка, карта источника, карточки по 11 категориям, разметка `[факт: ...]`/`[вывод]`/`[гипотеза]`, таблица «устарело / не переносится в РФ», **Ф4 сверка с каноном** (совпадения / противоречия / дельта), **реестр покрытия** с итогом `N/N` |
| **Автономный (другие системы)** | Claude Code, Codex или внешний проект без Knowledge-OS | Один файл `{название-книги}_knowledge.md`: карта книги + карточки по шаблону `templates/knowledge-item-template.md` + проверка качества |

## Железные правила

1. **Законный доступ и честная сила источника.** Принимать только законно доступный текст, файл или открытую
   страницу. Не обходить защиту, платный доступ или авторизацию. Если полного текста книги нет — **не пересказывать
   по памяти и по чужим конспектам** под видом книги: фиксировать отсутствие первоисточника и помечать вторичные
   разборы явно (`[факт, вторичный: ...]`).
2. **Полное чтение, не первые строки.** Читать до конца файла или раздела; PDF/EPUB/DOCX/FB2 сначала извлекать в
   текст (`pymupdf` / `pandoc`), слайды-картинки и схемы просматривать отдельно.
3. **У каждого рабочего утверждения — адрес.** Формат: `[факт: источник, глава/раздел/страница]` (означает «так
   сказано в источнике», не «так в мире»), `[вывод]` (синтез при разборе), `[гипотеза]` (непроверенное утверждение
   или чужая цифра без замера).
4. **Числа, площадки, цены и законы из книг не переносятся как действующие.** Помечать как «у автора на год издания»;
   актуальные нормы, цены и интерфейсы проверять по первоисточнику на дату работы.
5. **Чистота данных.** Никаких персональных данных, паролей, ключей, токенов или закрытых данных клиентов.

## Порядок работы

### Шаг 0. Инвентаризация и подготовка текста (Ф0)

1. Зафиксировать состав источника: файлы, типы, объём, язык, год издания, сила источника (`первоисточник` / `вторичный`).
2. Если формат бинарный (EPUB, PDF, DOCX, FB2) — извлечь текст; проверить качество извлечения PDF (заголовки, таблицы,
   слайды-картинки).
3. Составить **карту книги / источника**: части → главы / модули → ключевые темы.

### Шаг 1. Сквозное чтение и извлечение по 11 категориям (Ф2–Ф3)

Проходить источник по разделам до конца, заполняя **реестр покрытия** (файл/раздел, тип, статус, что взято).
Извлекать только идеи, подтверждённые текстом — **без воды, мотивации и продажи курса автора**:

| Категория | Что фиксировать |
|---|---|
| **Фреймворк** | название, компоненты или шаги, входы, выходы, применимость |
| **Задача** | действие, контекст, ожидаемый результат |
| **Приём** | как сделать конкретный шаг, когда применять, пример |
| **Подход** | принцип или стратегия, границы применимости |
| **Главная идея** | тезис и его практический смысл |
| **Проблема** | какую трудность решает автор и какие есть риски |
| **Методология** | повторяемый процесс или набор инструментов |
| **Инсайт** | нетривиальное наблюдение и его следствие |
| **Чек-лист / критерий** | готовые пункты проверки или признаки хорошего результата |
| **Антипаттерн** | что не делать и почему |
| **Кейс** | краткая ситуация, действие, числа (с годом и контекстом) и вывод |

Для каждого значимого элемента использовать [шаблон карточки](templates/knowledge-item-template.md): контекст,
содержание своими словами, практическое применение (когда / как / ожидаемый результат / ограничения), связи и
короткую цитату только там, где точная формулировка критична.

### Шаг 2. Сверка с каноном (Ф4, для Knowledge-OS)

Сопоставить извлечённое с действующими документами `D:\Knowledge-OS\Методологии\` и разложить на три списка:
- **Совпадения** — подтверждает действующие правила;
- **Противоречия** — расходится с каноном (показать обе стороны; при конфликте более свежий канон и законы РФ имеют приоритет);
- **Дельта** — чего в базе знаний ещё не было (главная ценность источника).

### Шаг 3. Проверка качества (Ф6 / критик)

Перед сдачей проверить все пункты:
- [ ] Карта источника отражает реальные части и главы (без домыслов).
- [ ] Заполнен реестр покрытия с итогом `покрытие N из N` (или явный список пропусков с причиной).
- [ ] Для полноценной книги извлечено не менее 5 главных идей, 3 проблем, 2 фреймворков/методик и 3 инсайтов.
- [ ] У каждого элемента есть адрес (глава/раздел/страница), разметка `[факт]`/`[вывод]`/`[гипотеза]` и блок практического применения.
- [ ] Вторичные источники отделены от первоисточников; устаревшие цены/площадки/нормы вынесены отдельно.
- [ ] Выполнена сверка Ф4 (в режиме Knowledge-OS).
- [ ] Нет персональных данных, секретов и закрытых материалов без права распространения.
- [ ] Имя файла не содержит двоеточий (ограничение Windows: заменять двоеточие на дефис).

## Рекомендуемый запрос (для любой системы)

```text
Проанализируй [книгу / источник / файл] по навыку book-knowledge-extraction.
1. Зафиксируй силу источника (первоисточник / вторичный) и покажи карту (части → главы/разделы → темы).
2. Извлеки фреймворки, задачи, приёмы, подходы, главные идеи, проблемы, методологии, инсайты,
   чек-листы, антипаттерны и кейсы по шаблону knowledge-item-template.md.
3. У каждого пункта укажи адрес (глава/страница), разметку [факт]/[вывод]/[гипотеза], когда и как
   применять, ожидаемый результат и ограничения.
4. Добавь реестр покрытия (N из N) и сверку с имеющимся каноном (совпадения / противоречия / дельта).
Не пересказывай по памяти и не выдумывай числа; при отсутствии первоисточника укажи это явно.
```
