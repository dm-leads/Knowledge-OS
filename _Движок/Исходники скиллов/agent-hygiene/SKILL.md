# Гигиена среды агента

Два режима. **Замер** ничего не меняет — только показывает, сколько контекста уходит ещё до первого слова пользователя и на что. **Ревизия** ищет устаревшее и дублирующееся и убирает только то, что человек выбрал, с возможностью вернуть.

Начинай с замера: он дешёвый и часто уже отвечает на вопрос «куда уходят лимиты».

## Замер: что грузится в каждую сессию

В Claude Code не всё из установленного попадает в контекст. Считай только то, что действительно в нём лежит постоянно, иначе выводы будут ложными.

| Статья | Попадает в контекст | Где смотреть |
|---|---|---|
| Цепочка CLAUDE.md | целиком, каждую сессию | `~/.claude/CLAUDE.md`, `CLAUDE.md` проекта и его родительских папок |
| Индекс памяти | целиком (первые ~200 строк) | `~/.claude/projects/<проект>/memory/MEMORY.md` |
| Навыки | только имя и описание из шапки; тело — лишь при вызове | `~/.claude/skills/*/SKILL.md`, навыки проекта, навыки плагинов |
| Плагины | описания их навыков, агентов, команд + текст стартовых хуков | `~/.claude/settings.json` → `enabledPlugins`, `~/.claude/plugins/cache/*/*/*/hooks/hooks.json` |
| MCP-серверы | их инструкции целиком; инструменты — обычно только именами (отложенная загрузка), схема грузится при вызове | `~/.claude.json`, `.mcp.json` проекта |

Две поправки, без которых замер завышает расход: навык с `disable-model-invocation: true` в шапке в контекст не попадает вовсе (его вызывают только командой), а навык с одинаковым именем в нескольких папках учитывается один раз. Сверяй итог со списком навыков, который видишь в текущей сессии, — это и есть фактическая загрузка.

Поэтому длина тела навыка почти не влияет на постоянный расход, а длина его **описания** — влияет у каждого навыка сразу. Самые частые крупные статьи: раздутый индекс памяти, длинные описания навыков, плагины со стартовой вставкой, MCP-серверы с длинными инструкциями.

Оценка в токенах: для русского текста около `символы / 3`, для английского и кода — `символы / 4`. Точности до процента не нужно — нужен порядок величин и что крупнее чего.

Как считать:

1. Размер каждого файла цепочки CLAUDE.md и `MEMORY.md`. В индексе памяти отдельно найди строки длиннее ~300 символов — индекс должен быть указателем, а не пересказом.
2. Сумма длин описаний навыков: свои, проектные, плагинные. Отметь описания длиннее ~600 символов.
3. Включённые плагины: у каждого — есть ли `SessionStart`-хук и сколько текста он вставляет (обычно это файл навыка или контекста, на который ссылается хук).
4. MCP-серверы: сколько инструментов у каждого, есть ли у него инструкции, подключается ли он вообще (упавший сервер тоже шумит в каждой сессии сообщением об ошибке).
5. Использование: ищи вызовы навыков и инструментов в журналах сессий `~/.claude/projects/*/*.jsonl` (по имени навыка в вызове инструмента `Skill`, по префиксу `mcp__<сервер>__`). Это главный сигнал «нужен ли он вообще».

Отчёт замера — одна таблица и три действия:

```
Постоянный расход до первого сообщения: ~N тыс. токенов
| Статья | Кол-во | ~Токенов | Что крупнее всего |
Три действия с наибольшей экономией:
1. [действие] → ~N токенов, чем рискуем
```

## Ревизия: что устарело или дублируется

Ищи по каналам. У каждого свои признаки — одно правило на всё не подходит.

| Канал | Признаки кандидата |
|---|---|
| Навыки | не вызывались в журналах за 60+ дней; два навыка про одно и то же; описание не совпадает с содержимым; ссылки на файлы и команды, которых больше нет |
| Память | запись противоречит более новой; даты и сроки прошли; файл есть, а в индексе его нет (и наоборот); несколько записей про одно |
| Разрешения | дубли в `permissions.allow`; частное разрешение, уже покрытое общим; разовые разрешения от старых экспериментов |
| MCP-серверы | не подключается; дублирует другой по назначению; не вызывался месяцами |
| Плагины | включён, но не использовался; требует авторизации, которой нет |
| Кэши | `file-history`, `shell-snapshots`, `logs` старше 30 дней и крупные |

Оценку каждого навыка давай одним из вердиктов: **оставить**, **улучшить** (что именно поправить), **обновить** (устарели команды или сервисы — проверь по источнику), **убрать** (какой дефект и что закрывает ту же потребность), **слить с <имя>** (что перенести в целевой навык). Причина должна позволять принять решение без повторного расследования: не «дублирует», а «шаг 4 навыка X делает то же; перенести в X абзац про Y».

Возраст — сигнал, а не приговор: навык может быть сезонным (отчёт раз в квартал). Поэтому решение за человеком.

### Как убирать

1. Покажи нумерованную таблицу кандидатов: что, канал, признак, доказательство, размер. За раз — не больше ~20, ревизия периодическая, а не разовая.
2. Человек называет номера. Действуешь только по названным: общее «да, всё» не принимай — кандидаты разные, и одному из них может оказаться место.
3. Не удаляй, а переноси в `~/.claude/_gc_trash/<дата>/`. Разрешения из `settings.json`: сначала копия файла рядом, потом правка.
4. Каждое действие — строкой в `~/.claude/gc_log.md`: дата, что, почему, как вернуть.
5. Память правь по её правилам: противоречащие записи сливай, оставляя более новую истину, и обновляй строку в `MEMORY.md`. Длинную запись не укорачивай механически — прочитай обе.

### Навыки-ссылки — осторожно

Общие навыки этого устройства стоят в `~/.claude/skills` ссылками-переходами (junction) на исходники в `D:\Knowledge-OS\_Движок\Исходники скиллов\`. Проверить: `Get-Item <папка> | Select LinkType, Target`.

- Чтобы отключить такой навык, убирай только ссылку: `cmd /c rmdir "<путь к ссылке>"` или перенос ссылки в корзину. `Remove-Item -Recurse` по ссылке в PowerShell может удалить содержимое исходника — исходник единственный, восстановить его негде.
- Если навык не нужен совсем — это решение про исходник в Knowledge-OS, и его принимает человек: перенос исходника в резерв и запись в CHANGELOG движка.
- Навыки Бризекса (`git-workflow-breezeks`, `lark-*`, `growth-*` и др.) — копии из репозитория Бризекса. Их судьбу решает этот репозиторий, а не ревизия.

Ревизия не выходит за пределы `~/.claude` и `.claude/` проекта: исходники кода и документов — не её дело.

## Итог прогона

Заканчивай тремя разделами: **Ждёт меня** (номера кандидатов на решение), **Изменено** (что перенесено, со ссылкой на `gc_log.md`), **Найдено** (что стоит поправить, но не срочно). Предложи дату следующей ревизии.
