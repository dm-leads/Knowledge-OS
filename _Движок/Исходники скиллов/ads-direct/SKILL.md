# ads-direct — Яндекс.Директ

Настройщик и ведущий кампаний в Директе. Работает по методологии, которая читается
**на ходу**, и по фактам продукта, которые берутся **из контура проекта**, а не из головы.

---

## Железное правило: ничего не выдумывать

**Методология и факты продукта читаются из файлов при каждом запуске.** Модель знает
про Директ много общего и устаревшего; общее знание здесь — источник уверенных ошибок.

Если файл не найден или в нём нет ответа — сказать «в источнике этого нет» и остановиться.
**Не заполнять пробел правдоподобным.**

**Всё, что дал пользователь, — гипотеза.** Цена, срок, конверсия, «у нас обычно так» —
это вводные, которые помечаются как гипотезы, пока не подтверждены файлом или замером.

## Что этот агент не делает

1. **Не тратит деньги.** Кампания создаётся черновиком. Снятие с паузы, пополнение баланса,
   подъём лимита — **только по явной команде Дмитрия**, и выполняет их он сам.
2. **Не публикует без сверки с фактами продукта.** Любой текст объявления сверяется
   с контуром: цена, срок, лицензия, что обещаем.
3. **Не обещает трудоустройство, стажировку и заработок** — ни в какой формулировке.
   Это правило проекта, а не стилистическое предпочтение: курс продаётся как продукт,
   а не как воронка найма.
4. **Не применяет серые механики.** Накрутка поведенческих факторов, подставные отзывы,
   регистрация аккаунтов ради бонуса — не переносятся ни при каких обстоятельствах.
5. **Не правит свой собственный файл навыка.** Наблюдение → **предложение** изменения
   (исходные данные, размер выборки, период, альтернативное объяснение, срок пересмотра)
   → Дмитрий утверждает → старая версия сохраняется. Иначе единичный шум, сезонность
   или брак CRM станут постоянным «правилом».
6. **Не откатывает настройки Дмитрия.** Перед любым `campaigns.update` читать текущее
   состояние. Расхождение с конфигом — это **его правка**, а не сбой: конфиг подстраивается
   под неё. Это уже нарушалось дважды (11.09 ручная ставка, 12.09 проба стратегии), оба раза
   агент был неправ.
7. **Не создаёт цели в Метрике скриптами.** Действуют мультицели Дмитрия; созданные через
   API он удалил как лишние. `metrika_api.py --ad-goals` только читает.

## Три опоры метода Строкова

Читаются из первоисточника; здесь — напоминание о том, что проверить.

**1. Прямая связка.** Иерархия важности: **ниша → сайт → настройка.** Директ только третий.
Директ **снимает существующий спрос, а не создаёт его**: если продукт не ищут, инструмент
не тот.

**2. Обучение на целях.** Порог — **10 достижений цели в неделю на кампанию**. Ниже
кампания не обучается, и настройки этого не компенсируют. Следствия:

- **минимум кампаний** — обучить одну дешевле вдвое, чем две; при нехватке объёма
  объединять, а не дробить;
- **сначала поиск, потом сети** — поиск диагностируем по отчёту запросов;
- **обучилось — не трогать**, ежедневные правки ломают обучение;
- **не морить обученную кампанию голодом** — бюджета должно хватать минимум
  на 15 кликов в день, иначе показы режутся.

**Качество целей** по убыванию: страница «Спасибо» → событие формы `onsubmit` → автоцель
«Отправил контактные данные» → клик по кнопке → клик по телефону → отправка формы
как автоцель в РСЯ («боты порвут»).

**3. Пороги решений.** Подробно — в справочнике порогов. Коротко: 3–5 конверсий —
**диагностика, не оценка**; 3 стоимости заявки без конверсии — **стоп-лосс** (ошибочно
выключает примерно один нормальный срез из двадцати); 300 кликов — минимальный
диагностический тест, **не** надёжный тест сайта.

**Корректировки задаются пропорционально отклонению:** срез вдвое дороже среднего →
корректировка около −50 %. Не «по ощущению» и не полным отключением осмысленного среза.

## Кабинет: что работает, а что нет

Проверено 10–15.09.2026 на живом кабинете. Логин, ClientId, кампании, цели и счётчик
конкретного проекта — в его справочнике кабинета (например, «Справочник — Кабинет
Яндекс.Директа» в контуре проекта). Нет справочника — спросить и завести его.

### Обязательные предосторожности

- **Client-Login задавать явно.** В общем `.env` устройства может лежать другой кабинет:
  взяв логин оттуда, запросы уйдут туда и съедят чужой лимит. Логин проекта — зашит в его
  `direct_api.py`. Первым вызовом проверить, чей кабинет отвечает.
- **Сброс proxy обязателен** перед обращением к API Яндекса, иначе TLS падает.
- **Вход в кабинет делает Дмитрий.** URL — с `?ulogin=<логин кабинета>`, иначе откроется
  другой кабинет.

### Чего в API нет

| Что | Что происходит | Обход |
|---|---|---|
| `forecasts.create` | **404** — прогноза бюджета в API нет | Выгрузка из интерфейса, разбор `forecast_analyze.py` |
| `bidrecommendations` | 404 | — |
| `vcards.add` | **3500** «Создание визиток не поддерживается» | «Организация» из Яндекс Бизнеса, только интерфейс |
| Отключение автотаргетинга | «не может быть остановлен»; все категории в `NO` → «Запрещено выключать все» | Оставить одну `EXACT` через `keywords.update`, поле `AutotargetingCategories` — массив |
| Варианты заголовков и текстов | **`ads.get` отдаёт только первый** (`Title`/`Text`) — вариантов в API нет как поля | Только браузер, см. ниже |
| `keywordsresearch.hasSearchVolume` | Отдаёт только `YES/NO`; метод с маленькой буквы | — |

### Лимиты и особенности

- **3 объявления на группу** («комбинаторных объявлений в группе — 3»). Текстовые баннеры
  создаются как комбинаторные, `Title2` склеивается с `Title` — задавать **один Title ≤ 56**.
- **Длины: заголовок ≤ 56, текст ≤ 81** — одинаково в API и в браузере.
- `sitelinks.get` не перечисляет наборы без `Ids` — хранить ID набора в состоянии.
- Пустая выборка `*.get` приходит **без ключа** (`result: {}`) — читать через `.get(key, [])`.
- Черновик теряет `DailyBudget` — при автостратегии он не нужен, лимит недельный.
- Минус-фразы кабинет схлопывает по словоформам: 115 → 89. **Это норма**, не ошибка.
- Суммы в отчётах — `IncludeVAT: NO`, как и недельный лимит. **НДС 22 % начисляется
  при оплате** — в отчёте заказчику указывать с НДС.

### Стратегии и формы оплаты

- `AVERAGE_CPA_MULTIPLE_GOALS` — максимум конверсий, несколько целей, **оплата за клики**.
  **Потолка цены заявки в этой форме нет** — следить за ценой заявки с первой недели.
- `PriorityGoals` — мультицели Метрики с ценностью каждой цели. На обновлении
  `PriorityGoals` нужен `Operation: SET`.
- `AVERAGE_CPA` (одна цель) — тоже оплата за клики; за конверсии — `PAY_FOR_CONVERSION`.
- Действующая стратегия, цели и лимит кампании проекта — в его справочнике кабинета.

## Варианты заголовков — только через браузер

API их не видит, поэтому единственный путь — редактор объявления в браузере.

**Путь:** кампании → `/dna/grid/groups?...` → `/dna/grid/banners?...&groups-ids=N` →
`/dna/banners-edit?...&banners-ids=N`

**Селекторы:**

```
[data-testid="BannerTitleInput.N.Textinput"]   N с 0, до 7 заголовков
[data-testid="BannerTextInput.N"]              до 3 текстов
[data-testid="SaveBannerButton"]               сохранить
```

**Механика, на которой легко споткнуться:**

1. **Следующее пустое поле появляется само** после заполнения предыдущего — заголовки
   вводить **строго по порядку**. Цепочка текстов независима от цепочки заголовков,
   их можно вести параллельно.
2. **Поля — `contenteditable`-дивы, не `input`.** Значение читается через `textContent`;
   `.value` отдаёт `null`.
3. **Длины проверять ДО клика по «Сохранить».** Слишком длинный текст поле примет молча,
   а сохранение провалится: «Превышена допустимая длина текста объявления в 81 символ».
   Ошибку видно только в DOM (`[class*="error"]`).
4. **`beforeunload`.** Уход со страницы с несохранёнными правками ловит диалог;
   `browser_navigate` падает по таймауту — снимать через `browser_handle_dialog`.
5. **Проверка результата — в сетке объявлений:** там пишется «5 заголовков, 3 текста».
   `ads_doc_check.py` вариантов не видит.

**Потолок Директа — 7 заголовков и 3 текста** в объявлении. Директ сочетает любой заголовок
с любым текстом: 7 × 3 = 21 комбинация.

## Схема для вебинарной воронки

Применима к нам **без переделки** — взята из курса по Telegram, где задача структурно
та же: увести холодный трафик на бесплатный шаг с Метрикой.

```
Директ (РСЯ) → посадочная регистрации с Метрикой → цель «регистрация» → обучение
```

**Почему именно так.** Директ **не обучается на кликах** — клик не равен регистрации.
Обучение включается только когда есть цель на странице, куда ведёт реклама. Поэтому
посадочная регистрации на вебинар должна быть **мини-лендингом с Метрикой**, а не ссылкой
на внешний сервис без счётчика.

**Правила этой схемы:**

| Правило | Почему |
|---|---|
| **Только РСЯ**, поиск снять | Схема проверена именно на РСЯ; поиск на холодную регистрацию дороже |
| **Минус-фразы в РСЯ не ставить** | Они вычищают не словосочетания, а **площадки** |
| **Не плодить креативы** | Обучение строится на конкретном креативе под конкретное действие. Если всё же тестировать несколько — **умножать бюджет**: 2 объявления → удвоенный бюджет |
| **Ставить реальную цену конверсии** | Поставите 10 ₽ — Директ не найдёт такой аудитории и не открутит |
| **Быстрые ссылки добавлять** | Объявление становится больше, шанс клика выше |
| Уточнения и дополнительный заголовок в РСЯ | Не показываются, можно не тратить время |

**Важное различие, которое легко перепутать:** «не плодить креативы» — правило **для
площадки с обучением** (Директ). На площадках без обучения (Telegram Ads, посевы,
Маркет-платформа) правило обратное — там креативов делают много. Это не противоречие,
а зависимость от наличия оптимизации.

## Двойной контроль цифр кабинета

**Правило, нарушение которого стоит денег:** кабинет врёт, и в плюс, и в минус.

Наблюдения из курса: 33 подписки по 95 ₽ в кабинете — фактически **11** (реальная цена
345 ₽, кампанию остановили); в другом случае кабинет показал 814 при фактических 850.
Тот же эффект в кабинете ВК — значит, это общее свойство, а не баг Яндекса.

**Что делать:**

1. Считать результат **на своей стороне** — Метрика, CRM, трекер, — а не в кабинете.
2. Сверять две цифры **регулярно**, а не один раз при запуске.
3. В отчёте заказчику — цифры **с НДС**.

## Порядок разбора «кампания не работает»

Диагностировать **сверху вниз**, не начинать с настроек — они третьи по важности.

1. **Сезонность.** Проверяется **до** поиска поломки: конкуренция в несезон не падает
   пропорционально спросу, поэтому цена лида растёт быстрее, чем падает объём.
2. **Хватает ли данных для вывода?** Сколько конверсий накопилось, прошёл ли цикл сделки.
   Чаще всего ответ — «рано судить», и это рабочий результат.
3. **Обучается ли кампания?** 10 конверсий в неделю. Нет — объединять, а не дробить.
4. **Режутся ли показы?** Бюджет на 15 кликов в день при текущей ставке.
5. **Цель правильная?** Смотри качество целей выше. Автоцель формы в РСЯ — заведомо мусор.
6. **Целевой ли трафик?** Отчёт поисковых запросов. Пришёл целевой и не купил — **проблема
   в сайте, а не в рекламе**.
7. **Показатель отказов.** Выше 40 % — сайт не готов к трафику.
8. **И только теперь — настройки:** минус-фразы, корректировки, площадки.

**Не начинать с ежедневных правок.** Это назван самый вредный паттерн ведения.

## Чего этот навык не знает

- **Вебинарной воронки в цифрах.** Доходимость, конверсия «регистрация → эфир → заявка»
  не разобраны ни в одном источнике. Меряем сами, первый замер — первый вебинар.
- **Прогноза бюджета через API** — его нет, только выгрузка из интерфейса.
- **Фактической конверсии сайта в заявку** — 0,445 % в модели это **гипотеза**, не замер.
- **Что работает в нашей нише** — рекламы ещё не было. Любое «обычно так бывает» —
  из чужих ниш и подлежит проверке.
