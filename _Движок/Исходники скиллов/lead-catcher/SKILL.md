# Ловец лидов в Telegram

Методология — `D:\Knowledge-OS\Методологии\Методология — Подбор лидов в открытых сообществах (ловец лидов).md`:
этапы 0–8, стоп-правила аккаунта, раздел «Касание». Прочитай её перед первым этапом в сессии. Код — пакет канона
`D:\Knowledge-OS\_Движок\Пакеты\lead_catcher\` (`_manifest` пакетов). Проект держит **экземпляр** — папку
`lead_catcher_instance/` со своим `profile.yaml`.

## Запуск

```
uv run --project "D:\Knowledge-OS\_Движок\Пакеты\lead_catcher" python -m lead_catcher --instance "<папка экземпляра>" <команда>
```

Выставь `PYTHONIOENCODING=utf-8`, иначе консоль Windows исказит кириллицу.

| Команда | Что делает |
|---|---|
| `status` | по каждому номеру: ключи приняты (проба QR-входа без входа), есть ли вход, жива ли сессия, последний стоп |
| `login N --qr` | **основной вход**: QR в браузере, человек сканирует в Telegram на телефоне (Настройки → Устройства → Подключить устройство); агент может запустить сам, когда человек держит телефон; облачный пароль — `login N --password` у человека. По коду Telegram для свежего аккаунта через прокси отвечает «отправлено», но не доставляет (21.11.2026) |
| `login N --desktop` | **вход по коду — только так**: клиент представляется как Telegram Desktop. 21.11.2026 с умолчаниями Telethon («AMD64», en) Telegram коды свежим аккаунтам «отправлял», но не доставлял; с `--desktop` код пришёл с первого раза (№1). `login.cmd` (K) включает его сам |
| `login N` | вход по коду с умолчаниями Telethon — не использовать для свежих аккаунтов: **запускает человек в своём терминале** — телефон, код, облачный пароль вводит он. Код обычно приходит в приложение аккаунта (чат «Telegram»), не по SMS; команда пишет способ, Enter без кода — запросить другим способом. Вход вместе с агентом (человек сам попросил и дал номер): `login N --phone …` → человек передаёт код → `login N --code …`; облачный пароль — только `login N --password` у человека. Код не приходит — `--keys M` (ключи другого номера) и `--direct` (без прокси) отличают свежий `api_id` от прокси; `--desktop` — клиент представляется как Telegram Desktop (по умолчанию Telethon похож на бота). Дошёл ли код — видно в чате 777000 любой живой сессии этого аккаунта |
| `check [N]` | жива ли сессия |
| `use N` | сделать номер активным — **только по слову человека** |
| `find-chats слово … / @адрес …` | карта открытых групп: название, участники, живость; тексты не читаются |
| `chat-info @чат …` | трек «администраторы»: описание группы, контакт «по рекламе», видимые администраторы. В данные проекта — только признаки; описание и адреса — в `private_dir` профиля (вне git; без неё команда откажет). Без вступления видны обычно только боты-администраторы |
| `read-sample @чат[:часы] …` | пробное чтение разрешённых чатов (дневной потолок из профиля) |
| `search-groups --groups … --words …` | поиск по истории разрешённых чатов за `--days` |

Код выхода 4 — стоп-сигнал аккаунта.

## Хранилище устройства: ключи и сессии — одно место, проекты — свои папки

Ключи приложений и сессии Telegram — **общие для устройства**: `D:\Knowledge-OS\Секретные ключи\telegram\`
(`.env` с парами `TG_API_MAIN_KEY` / `TG_API_MAIN_SECRET`, `_2`, `_3` … и файлы `tg_reader_N.session` рядом). Папка
закрыта `.gitignore` канона. Номер аккаунта на устройстве значит одно и то же во всех проектах; вход — один раз на
номер, им пользуются все проекты. Одновременно одной сессией работает только один процесс — замок
`<сессия>.lock` (второй проект получит «сессия занята», упавший процесс замок не держит). На другой компьютер —
лучше свой вход; переносить файл сессии можно только переездом (на старом месте больше не запускать).

Проект держит своё: экземпляр (`profile.yaml`, `allowed_chats.txt`, `data/`) в своём репозитории.

## Общие базы чатов и каналов (для всех проектов)

Списки открытых чатов и каналов, которые нужны не одному проекту, лежат одной копией на устройство:
`D:\Knowledge-OS\Общие данные\Telegram\` (вне git канона). Сейчас там `Чаты и каналы ЖК\` — чаты и каналы жилых
комплексов Москвы, Петербурга и областей (xlsx: ссылка, участники, сообщений в сутки, можно ли писать, описание);
состав — `_manifest.md` папки. Проект берёт оттуда кандидатов в свой `allowed_chats.txt` (решение человека), файлы к
себе не копирует. Показатели в базах без даты съёма — живость перед выводами перепроверять (`find-chats`,
`read-sample`). Описания содержат контакты админов — в данные проекта только признаки.

## Подключить проект

1. Хранилище устройства уже есть — используй его. Нет — создай папку, `.env` с парами по номерам; если она внутри
   репозитория, закрой её `.gitignore`. Значения в чат не выводить.
2. Номер аккаунта для проекта — из тех, что в хранилище (`status` любого экземпляра покажет, у каких есть вход).
3. `onboard --secrets-env "D:\Knowledge-OS\Секретные ключи\telegram\.env" --sessions-dir "D:\Knowledge-OS\Секретные ключи\telegram" --account 2:TG_API_MAIN_KEY_2:TG_API_MAIN_SECRET_2 --proxy-env TG_READER_PROXY_URL HTTP_PROXY`
   — папка экземпляра в репозитории проекта рядом с работой по каналу. Onboard откажет, если сессии или ключи в
   git и не закрыты `.gitignore`. Скопируй в экземпляр `login.cmd` (двойной щелчок — вход по номеру; с аргументами —
   любая команда) из экземпляра Бризекса или собери такой же — только с переводами строк Windows (CRLF) и `.gitattributes` `*.cmd text eol=crlf`: с LF окно cmd рвёт строки с кириллицей на куски («не является командой»).
4. `status`: «ключи приняты» по каждому номеру. «не проверено: …» — сеть: проверь прокси.
5. Вход — команда `login N` человеку, в его терминал. Сам вход не запускай.

## Новая пара ключей (запасной аккаунт)

Две строки в `.env` хранилища устройства + строка в `accounts:` профиля проекта (`N: {api_id: ИМЯ, api_hash: ИМЯ,
session: tg_reader_N, proxy: null}`) → `status` → `login N` делает человек (один раз на устройство). Код не
меняется. У каждого номера своя сессия; один номер в нескольких проектах — можно, но не одновременно (замок).

## Правила, которые держит код, и которые держишь ты

- Только чтение. Вступление в группы, сообщения, реакции — нет команд и не делать в обход.
- Читать тексты можно только в чатах из `allowed_chats.txt` экземпляра. Пополняет список человек после карты чатов.
  Исключение — `find-chats`: по найденным группам берёт последние 100 сообщений ради живости, сохраняет только даты.
- Ожидание по просьбе Telegram до 5 минут код выжидает сам; дольше — стоп.
- Дневной потолок текстов для модели общий для `read-sample` и `search-groups`.
- Обезличивание до записи: телефоны, почты, ники, ссылки, номера квартир — пометками; автор не запрашивается.
  В отчётах — «житель», ссылка, текст без контактов.
- **Стоп** (PeerFlood/@SpamBot, ожидание > 5 мин, бан, отозванная сессия, жалоба админа): сбор стоит, причина в
  `data/stops.jsonl`. Номер **не переключай сам** и не предлагай «быстро продолжить с другого»: переход на
  следующий аккаунт после ограничения — обход ограничений Telegram, за него блокируют связку аккаунтов.
  Назови причину и готовые номера; решение — человека (`use N`).
- Разметка моделью (JEV) — только обезличенный текст; число запросов и цена — до прогона, затем «да».
- Условия Telegram API (п. 1.5) запрещают применять ИИ к данным площадки без согласия участников — риск
  аккаунта принимает владелец; не переспрашивать, если он уже принял, и не прятать риск, если нет.
- Успех сбора — «записано = прочитано обратно» и не ноль. Ноль — разобраться, не докладывать «готово».

## Проверка ключей без входа

`status` делает её сам. `help.getConfig`/`help.getNearestDc` ключи **не** проверяют — отвечают при любых;
настоящая проверка — `auth.exportLoginToken` (неверные → `API_ID_INVALID`). Токен не печатается, QR не строится.
