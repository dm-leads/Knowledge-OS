# kos-create-doc — создать документ по канону Knowledge-OS

Канон: `D:\Knowledge-OS\_Движок\Канон\`. Шаблоны: `D:\Knowledge-OS\_Движок\Шаблоны\`.
Читать каноничные стандарты по мере необходимости (типы / именование / метаданные / ссылки / SSOT-DRY).

## Этапы

0. **SSOT-предчек** ([Стандарт — SSOT и DRY]): уже есть документ по теме? Да → ссылка, не дубль. «Было бы
   неплохо» → запись в `0 — System Docs\BACKLOG.md`. Задача с дедлайном/исполнителем → не markdown.
0.5 **Memory-check**, если контур живой (есть `0 — System Docs\`).
1. **Интейк:** что документируем, для кого, постоянное знание или проектное.
2. **Placement:** проект / область / ресурс / инструмент; подпапка **по предмету** (не по типу).
   Системные файлы (CHANGELOG/BACKLOG/ADR) → `0 — System Docs\`.
3. **Тип** (закрытый список, по функции): намешан интент → **СТОП**, предложить разбить на 2–3 документа.
4. **Имя:** `<Префикс типа> — <Название>.md` по словарю префиксов (единый русский нейминг).
5. **Метаданные:** YAML-frontmatter из шаблона `Шаблоны\Шаблон — <Тип>.md`. Пустая строка перед `---`.
6. **Скелет тела** из того же шаблона.
7. **Перелинковка:** inline-ссылка на первом упоминании + футер «Связанные документы» (3–7) для
   содержательных типов.
8. **Проговорить placement / тип / имя ДО записи** → создать файл.

Git/публикация — отдельно (`обнови` / `сохрани черновик` / `опубликуй`).
