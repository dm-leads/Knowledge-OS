# Keys.so API

Keys.so хранит снятую выдачу по сотням миллионов запросов, поэтому отвечает на вопрос, которого нет в Вордстате и Вебмастере: **по каким запросам стоит чужой сайт**. Всё, что он говорит о трафике и бюджетах, — его модельные оценки. В отчётах так и пиши: «оценка Keys.so», а не «трафик конкурента».

Клиент — `scripts/keysso.py` (ключ `KEYSO_API_KEY` в мастер-.env). Полная спецификация — `reference/openapi.json`, сжатый справочник всех 155 методов на русском — `reference/методы.md`.

```
python scripts/keysso.py limits                                   # остаток квот
python scripts/keysso.py get report/simple/domain_dashboard base=msk domain=бризекс.рф --out <папка>
python scripts/keysso.py get report/simple/organic/keywords base=msk domain=tion.ru "sort=wsk|desc" "filter=pos<=10" --all --out <папка>
python scripts/keysso.py post tools/check-top base=msk --json тело.json --out <папка>
```

## Какой вопрос — какой метод

| Вопрос | Метод |
|---|---|
| Сводка по сайту: запросы в топ-1/3/5/10/50, видимость, реклама, ИИ-ответы, история по месяцам | `report/simple/domain_dashboard` |
| Кто наши конкуренты в органике / в рекламе | `report/simple/organic/concurents`, `report/simple/context/concurents`. Коммерческих конкурентов — по денежным запросам: `tools/check-top` по списку транзакционных фраз (общее пересечение собирает соперников блога) |
| По каким запросам стоит сайт, какая страница | `report/simple/organic/keywords` (фильтр по `pos`, `wsk`), `organic/keywords/bypage` |
| Какие страницы сайта собирают больше всего запросов | `report/simple/organic/sitepages`, `sitepages/withkeys` |
| Что сайт потерял | `report/simple/organic/lost_keywords`, `lost_pages` |
| **Есть у конкурентов, нет у нас** | `report/compare` с `view=organic`, `incl=<конкурент>`, `excl=<наш домен>`. `incl` — **пересечение** сайтов (запросы, что есть у всех перечисленных), не объединение; «есть хотя бы у одного» — по одному конкуренту и склейка |
| Сравнить свои списки фраз | `tools/compare` (`present_right`, `uniq`, `union`) |
| Что конкурент покупает в Директе: фразы, тексты, ссылки, УТП | `report/simple/context/keywords`, `context/ads`, `context/ads/links`, `context/ads/facts` |
| История рекламы, оценка бюджета | `report/simple/domain_ad_history`, поле `adcost` |
| Реклама конкурента в РСЯ | `report/ads/rsya/domains/<домен>` |
| Ссылки и доноры, ссылочный разрыв | `report/simple/links/backlinks-domains`, `report/compare` с `view=backlinks` |
| Упоминания в ответах Алисы | `report/simple/organic/ai-answers`, `organic/ai-concurents` (только база `msk`) |
| Кто в топе по моему списку запросов | `tools/check-top`, `check-top-concurents-domains`, `check-top-concurents-urls` |
| Расширить фразу, похожие запросы | `tools/extended_keywords`, `report/simple/similarkeys` |
| Кластеризация большого списка | `clustering` → `build` → `state` → `node` |
| Массовая частотность по своему списку | онлайн-парсер Wordstat: `wordstat/create-project` → `wordstat/report` |
| Групповой разбор до 100 доменов разом | `report/group` → `state` → `group/organic/*`, `group/context/*` |

## Как читать поля

- `ws` — базовая частотность (все словоформы и хвосты); `wsk` — точная («!слово»); `superwsk` — сверхточная. Решения принимай по `wsk`: `ws` завышает спрос в разы.
- `pos` — позиция; `it1`…`it50` — сколько запросов сайта в топ-1…топ-50; `vis` — оценка посетителей из поиска в сутки.
- `kei` — индекс эффективности ключа; `weight` — сколько сайтов-конкурентов в топ-50 по запросу; `docs` — документов в выдаче.
- `perc` — похожесть конкурента (доля общих ключей), `theme` — его тематичность, `cnt` — общих ключей в топ-50.
- `avbid` — цена входа клика; `adcost` — оценка бюджета конкурента в контексте (`bdg5`…`bdg100` — бюджет на долю охвата).
- `isgeo`, `isquest` — запрос с топонимом, вопросительный; `nw` — новый запрос; `delta` — изменение позиции.

## Базы

`msk` — Яндекс, Москва (по умолчанию и самая полная); `spb` — Яндекс, Санкт-Петербург; `gru` — Google, Москва; `zen` — Дзен; региональные Яндекс-базы — `ekb`, `nsk`, `kzn`, `krr`, `rnd` и др. Выбирай базу по рынку проекта: для сайта, продающего в Москве и Петербурге, — `msk` и `spb`, для оценки Google — `gru`.

## Правила

1. **Сначала квоты.** `keysso.py limits` в начале сессии. Суточные квоты большие, но у части инструментов квота месячная (пакетный анализ доменов, проверка по списку, подсказки) — их тратишь по плану, а не на пробу.
2. **Снимок каждого ответа.** Клиент кладёт JSON и CSV в `<out>/<дата>/` и пишет строку в `manifest.jsonl`. Подписка кончается — снимки остаются, поэтому ценное снимай полностью (`--all`), а не первой страницей.
3. **Отчёт строится асинхронно.** Ответ с полем `code: 202` при HTTP 200 значит «ещё готовится», это не данные. Клиент ждёт до 6 минут.
4. **Кириллический домен — как есть** (`бризекс.рф`). Punycode API не находит (404).
5. **Постраничная выгрузка — с сортировкой по двум полям**, иначе строки на стыке страниц теряются или повторяются. Клиент добавляет второе поле сам.
6. **Фильтры:** `поле=значение`, `!=`, `>`, `>=`, `<`, `<=`, `BETWEEN a@b`, `LIKE`, `NOT LIKE`, `STARTSWITH`, `ONE OF a DELIM b`, `REGEXP`; `^` — «и», `^OR` — «или». Пример: `filter=pos<=10^wsk>=50`. Для ссылок фильтр обязан содержать условие по `status`.
7. **Проекты, мониторинг, трекер нейросетей, кластеризация, парсеры Wordstat и выдачи** создают объекты в аккаунте и тратят месячные лимиты. Создавай их по плану исследования и записывай их id; удаление — только с согласия владельца аккаунта: вместе с проектом пропадает накопленная история.
8. **Оценки остаются оценками.** `vis`, `traf`, `adtraf`, `adcost` — модель Keys.so. Для своего сайта сверяй с Метрикой и Вебмастером; расхождение — не ошибка, а разница источников.
9. **Каждая выгрузка отвечает на вопрос.** Перед снятием назови, какое решение она поддержит (тема, страница на доработку, гипотеза, фраза в Директ). Выгрузка без вопроса — лишний расход квоты и контекста.
10. **Фраза у конкурента — ещё не задача.** Прежде чем передать её в контент или рекламу, проверь, что у проекта есть такой товар или услуга, какое у запроса намерение и какая у нас посадочная.
11. **Бюджет квот — до массовых запусков.** Распредели месячные лимиты по направлениям разбора заранее, а не когда лимит почти кончился.

## Keys.so в работе с гипотезами

Для любого проекта, где гипотезы ведутся системой (например, Движок роста). Проверено на Бризексе 28.09.2026.

1. **Сначала — в карту источников.** Keys.so — класс E «Внешний спрос». Запись: статус по пробе (`limits` и
   `domain_dashboard` своего сайта), история по базам, точка истины, ловушки, дата конца подписки, имя ключа.
   Без этой записи числа Keys.so в систему гипотез не входят.
2. **Роль — материал и идеи, а не факт своего сайта.** Число Keys.so может обосновать идею («если — то — потому
   что» с методом, базой и датой). Основанием кандидата и главной метрикой теста остаются свои счётчики:
   веб-аналитика, Search Console и Вебмастер, CRM.
3. **До любого SEO-диагноза — разделить свой поиск по системам.** Визиты из поиска по Google и Яндексу берутся из
   веб-аналитики, потеря в системе ищется в её базе Keys.so (`gru` — Google, `msk` / `spb` — Яндекс). На Бризексе
   «SEO −33 % год к году» оказался целиком Google (−49 %) при ровном Яндексе, а Keys.so показывал рост видимости
   в Яндексе вдвое.
4. **Оценку трафика своего сайта из Keys.so не использовать.** На Бризексе `visAvg` в `gru` рос, когда клики из
   Google по Search Console падали вдвое. Число запросов в топе — не трафик.
5. **Изменение, выведенное из Keys.so, идёт исполнителю через систему гипотез** — с датой старта и окном замера.
   Передача прямо в чат исполнителя портит замер. Исключение — постоянные нормы вроде запаса тем блога; тема,
   относящаяся к гипотезе, получает её номер.
6. **Фраза или спрос у конкурента — не гипотеза**, пока не проверено, что у проекта есть такой товар или услуга
   (правило 10). На Бризексе «рекуператор» и «приточная вентиляция» отпали: в ассортименте только бризеры.
7. **Подписка ограничена во времени.** Всё, что гипотезам понадобится после её конца, снимается в файлы заранее.

| Тип гипотезы | Что даёт Keys.so | Методы |
|---|---|---|
| Новые статьи, куст тем | запросы с точной частотностью, которых у нас нет, и кто по ним в топе | `report/compare` по одному конкуренту, `tools/check-top`, `similarkeys`, парсер Wordstat |
| Обновление страниц | какие запросы и страницы потеряны, в какой системе, кто занял место | `organic/lost_keywords`, `lost_pages`, `keywords/bypage` — в базе той системы, где потеря |
| Коммерческие посадочные | кто стоит по денежным запросам и какой страницей | `tools/check-top`, `check-top-concurents-urls` |
| Реклама: фразы и цена | фразы и тексты конкурентов, цена входа клика, конкуренция | `context/keywords`, `context/ads`, поле `avbid`, `report/compare` с `view=context` |
| Оффер и УТП | что обещают конкуренты в объявлениях | `context/ads/facts`, `context/ads/links` |
| Ответы нейросетей | где цитируют нас и где конкурентов | `organic/ai-answers`, `ai-concurents`, трекер нейросетей |
| Ссылки | доноры конкурентов, которых нет у нас | `report/compare` с `view=backlinks`, `links/backlinks-domains` |
| Замер SEO-гипотез | ряд позиций рядом с визитами — вспомогательный, не главная метрика | мониторинг позиций во всех системах, откуда идёт трафик |

## Стандартный цикл разбора

1. **Паспорт** — `domain_dashboard` своего сайта по нужным базам, `limits`.
2. **Карта конкурентов** — органические и контекстные конкуренты; разделить на прямых (продают то же), смежных и заменители (медиа, маркетплейсы, видео). В сравнение — до 30 сайтов.
3. **Разрывы** — чего нет у нас (`report/compare`), что потеряли (`lost_*`), что на позициях 11–30 (дешёвые победы), что конкуренты покупают в рекламе, где у них доноры, кого цитирует Алиса.
4. **Решения** — темы и страницы, фразы и тексты для рекламы, доноры, гипотезы; каждое с цифрой, методом и датой снятия.
5. **Замер** — мониторинг позиций и трекер нейросетей по тем же запросам: базовая точка фиксируется до изменений, потом — контрольные точки. На окне в несколько недель причинных выводов не делаем: сдвиг выдачи не отделить от колебаний.
6. **Архив** — копится с первого вызова (клиент сохраняет каждый ответ); в конце подписки — проверка полноты по `manifest.jsonl` и финальные снимки по своему сайту и ключевым конкурентам, выгрузки трекера и мониторинга.
