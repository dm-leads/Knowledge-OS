# kos-migrate-to-canon — папка → канон Knowledge-OS

Сценарий: `D:\Knowledge-OS\_Движок\Сценарии\Плейбук — Привести папку к канону.md`.
Канон: `D:\Knowledge-OS\_Движок\Канон\`. Шаблоны: `...\Шаблоны\`.

## Шаги

1. **kos-memory-check**, если контур живой (есть `0 — System Docs\`).
2. **Инвентаризация:** перечислить все файлы/папки; классифицировать (документы / код / медиа / дубли /
   черновики / устаревшее / мусор). Ничего не трогать.
3. **Карта-предложение:** для каждого элемента — контур (проект/область/ресурс/инструмент) или «в утиль»;
   каноничное имя `Тип — Название` и тип из закрытого списка; дубли → консолидация; тяжёлые ассеты →
   отдельно. Сомнительное помечать.
4. **СОГЛАСОВАНИЕ** — обязательный гейт. Показать карту целиком, дождаться «ОК». До этого изменений нет.
5. **Миграция:** PARA-раскладка; перемещение и переименование; YAML-frontmatter; сбор `_manifest.md`;
   перелинковка (+ `kos-doc-compliance`).
6. **Паспорт:** `CLAUDE.md` + корневой `_manifest` + первая запись `CHANGELOG`; добавить проект в
   `Канон\Справочник — Карта Knowledge-OS`.
7. **Верификация:** ledger «источник → цель»; ничего не потеряно; имена/метаданные/ссылки каноничны.

## Принципы

- **Не копировать хаос** (дубли/мусор/черновики — вычистить с согласования).
- **Без потери данных** (перемещение, не удаление; сомнительное — на согласование).
- **Превью перед изменениями.** ПДн/секреты — только локально, не в общий git/чат.
