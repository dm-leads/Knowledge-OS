# Методология — Подбор лидов в открытых сообществах (ловец лидов)

## Краткая суть

- **Ищем не группы, а людей в определённой ситуации.** Сначала — кто «наш» и на какой ступени лестницы Ханта он
  стоит; потом — как он говорит о своей задаче (семантика); и только потом — где он об этом говорит (карта мест).
  Группа «по нашему продукту» часто полна тех, кто продукт уже перерос.
- **Смысл, а не слова.** Фильтр по словам путает «ищу работу диспетчером» и «ищем диспетчера»: слово одно,
  человек противоположный. Каждое сообщение размечает модель-решатель вопросами о смысле; в коде отсекается
  только технический мусор (пусто, стикер, повтор).
- **Места оценивают по доле «наших»**, измеренной на пробном чтении, а не по размеру и названию.
- **Касается человек, а не код:** индивидуально, по правилам места. Код только читает и размечает.
- **Хранить минимум:** текст, дата, место, ссылка на сообщение. Без базы имён и ников.

## Этапы и ворота

| Этап | Что делаем | Выход — ворота к следующему |
|---|---|---|
| **0. Кого ищем** | Типы клиентов из сценариев (кто покупает, кто нет). Для «нашего» — на каких ступенях Ханта он бывает и что говорит на каждой. Кого не берём: конкуренты, продавцы, работодатели, те, кто продукт перерос | описание словами + 10–20 примеров фраз «наш / не наш», по ступеням |
| **1. Семантика** | Keys.so (или Вордстат): запросы по задаче клиента, а не по продукту — проблема (ступень 0–1), способ решения (1–2), продукт (2–3). Перевод в язык чата: в поиске пишут «кем работать из дома», в чате — «девочки, кто где работает в декрете?». Из запросов — **темы мест**: жизненные ситуации, где человек об этом говорит | таблица «ступень → запросы и частоты → как говорят в чате → темы мест» |
| **2. Карта мест** | Поиск мест по темам этапа 1: каталоги сообществ (TGStat, Telemetr), поиск площадки, обсуждения ВКонтакте. По каждому: тема, участники, сообщений в неделю, читается ли без вступления, разрешена ли реклама по правилам | 20–40 мест на «да» владельца; поровну «около продукта» и «около ситуации» |
| **3. Пробное чтение** | 6–8 мест, без вступления, **несколько окон: будни и выходные** (сутки — только проверка инструмента, не оценка потока). Хранить: текст, дата, место, ссылка. В тексте телефоны, почты, ники — пометками. Технический отсев: пусто, короче 15 знаков, дубли (см. «Дубли и боты») | файл выборки; по местам — фактический период, сообщений, уникальных текстов |
| **4. Разметка смыслом** | Модель-решатель на **каждом** сообщении выборки — вопросы по независимым осям (см. «Вопросы и эталон»). Полоса считается кодом. Эталон размечает человек вслепую, до прогона | точность и полнота целевого класса, согласие разметчиков, пороги по цене ошибки |
| **5. Оценка мест** | Доля «наших» и их число по каждому месту — диапазоном по окнам, по уникальным текстам; места без «наших» — вон; по найденным «нашим» уточнить темы и повторить этап 2 | короткий список мест с долей и объёмом (верхняя граница, если авторов не различить) |
| **6. Поток** | Регулярное чтение коротких окон (сутки–неделя) только по оставленным местам; разметка; отчёт «наши за период» со ссылками | отчёт для человека, а не база |
| **7. Касание** | Человек сам открывает ссылку и решает. **До заключения юриста:** ответ по делу в самом месте без навязанного предложения, если правила разрешают; личное сообщение — когда человек сам попросил. Иные форматы — по решению владельца с известным ему риском (38-ФЗ, ст. 18). Код ничего не отправляет | журнал касаний с минимумом полей: дата, место, полоса, исход — это тоже обработка данных, со сроком удаления |
| **8. Замер** | Две воронки отдельно: качество разметки (этап 4) и канал: сообщение → уникальный человек → касание допустимо → касание → ответ → квалифицированная заявка → оплата; цена: деньги и часы человека на одну заявку и оплату. Пороги, период и минимальный объём — до замера, гипотезой в системе гипотез | решение: масштабировать, сузить, закрыть |

## Правила

- **Порядок этапов не меняем.** Карту мест без семантики собирает случай; разметку без описания «кого ищем»
  проверить не по чему.
- **Одна мерка на всех.** Вопросы модели заданы до чтения и одинаковы для всего потока, включая отброшенное.
- **Ступень важнее темы.** Человек на ступени 0–1 («надоела работа, хочу из дома») — тоже «наш», но ему нужен
  прогрев контентом, а не предложение купить.
- **Модель ставит метку, решает человек.** Порог уверенности — по своему эталону, а не по чужим примерам.
- **Аккаунт:** отдельный и устоявшийся; вступать по несколько мест в день; паузы; ответы площадки «подождите» —
  стоп; из кода никаких сообщений и реакций.
- **Стоимость считается до прогона** по фактической медиане и верхней границе токенов на сообщение (на первой
  пробе — 1 790 при прогнозе 1 500), с повторами и временем человека; называется владельцу. Дневной потолок
  сообщений и денег — в коде; одинаковый текст размечается один раз (кэш по хэшу текста).
- **Одна версия конвейера.** Описание, файл вопросов и формула полосы — одной версии; формула не ссылается на
  вопрос, которого нет в файле (проверка кодом).

## Вопросы и эталон

- **Независимые оси, а не один большой выбор:** что делает автор (спрашивает / предлагает / рассказывает /
  рекламирует), его ситуация, о какой профессии речь, ступень лестницы, срок или следующий шаг, спрашивает ли про
  обучение, барьер. В `choice` — только взаимоисключающие варианты и «неясно»; то, что бывает вместе, — отдельными
  «да/нет».
- **Эталон стратифицированный:** случайная выборка всего потока + все положительные и пограничные. Размечают
  двое (или человек дважды с перерывом), вслепую, до прогона. Разметка другой моделью — «совпадение с арбитром»,
  не точность.
- **Считать по целевому классу:** точность и полнота, матрица ошибок. Общая доля верных на потоке без «наших»
  ничего не говорит.
- **Пороги — по цене ошибки:** ложное «наш» ведёт к неуместному касанию и жалобе, пропуск — только к меньшему
  объёму; поэтому порог ставят по точности целевого класса, неуверенное — всегда человеку.

## Дубли и боты

- Точный дубль — тот же текст после чистки; похожий — почти тот же (порог сходства в коде); межгрупповой — один
  текст в разных местах. Окно сравнения — весь период чтения.
- Единица счёта — уникальный текст; число авторов без их сохранения не установить, поэтому «людей» — верхняя
  граница. Кластеры кросс-постов и серийные объявления показываются отдельно: они делают место «живым» без людей.

## Данные и законность

- **Меньше полей — не значит «без персональных данных».** Текст, место, дата и ссылка позволяют найти автора;
  чтение, разметка, отправка во внешнюю модель и показ человеку — обработка.
- **Жизненный цикл до старта:** цель и основание, кто оператор, кто видит данные, срок хранения сырой выборки
  (удалять после разметки и отчёта), журнал доступа, что делать по обращению человека и при утечке.
- **Трансграничная передача:** модель-решатель и посредник могут быть за рубежом — уходит только очищенный текст;
  допустимость проверяет юрист.
- **Вопросы юристу под нишу:** основание обработки сообщений из открытых мест (152-ФЗ); квалификация каждого
  формата касания по 38-ФЗ, ст. 18, и доказательство согласия; трансграничная передача; соответствие способа сбора
  условиям площадки.

## Стоп-правила аккаунта

- Немедленный стоп чтения без автоматического возобновления: ограничение аккаунта (`PeerFlood`, сообщение
  @SpamBot), запрос площадки ждать дольше 5 минут, бан или удаление из группы, жалоба администратора, смена
  правил группы против сбора. Возобновление — только решением человека, с записью причины.
- Правила каждого места и площадки фиксируются на дату проверки; «открытая группа» ≠ разрешение на сбор.

## Чего не делать

- Рассылок по списку, шаблонных сообщений, автоматической отправки.
- Базы людей: имён, ников, номеров «на потом».
- **Продажи людей как лидов.** Передать чужие контакты и сообщения третьему лицу — передача персональных данных
  без согласия. Продуктом может быть сам метод и его настройка под нишу клиента, отчёт о рынке без персональных
  данных или поток людей через свою посадочную с согласием — но не выгрузка найденных людей.
- Обучения моделей на сообщениях площадки (условия Telegram API, п. 1.5).

## Как из метода сделать услугу

`[применение]` Для любой ниши повторяется один набор: описание «кого ищем» → семантика → карта мест → пробное
чтение с разметкой → отчёт «где ваши люди, сколько их в неделю, как они говорят». Это и есть сдаваемый результат
первого этапа: ценен сам по себе (язык клиента, темы контента, места для посевов) и показывает, стоит ли ниша
регулярного потока. Регулярный поток и касания клиент ведёт сам — своим аккаунтом и своими людьми.

**Роли в услуге — до договора:** вариант «передаём настроенный инструмент» (исполнитель к данным не
прикасается) и вариант «настраиваем и сопровождаем с доступом» (исполнитель — обработчик по поручению клиента).
Для каждого: кто оператор, что исполнитель видит, где ключи и сессии, удаление данных и доступов по окончании
(акт), ответственность. Договор поручения обработки и политика оператора — проверяет юрист.

## Чего метод не даёт

- Потока там, где клиент о своей задаче в открытых местах не пишет (закрытые рынки, длинный B2B).
- Разрешения на касание: основание обработки сообщений людей и формат обращения проверяет юрист под нишу.
