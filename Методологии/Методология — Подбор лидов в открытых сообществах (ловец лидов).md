# Методология — Подбор лидов в открытых сообществах (ловец лидов)

## Краткая суть

- **Ищем не группы, а людей в определённой ситуации.** Сначала — кто «наш» и на какой ступени лестницы Ханта он
  стоит; потом — как он говорит о своей задаче (семантика); и только потом — где он об этом говорит (карта мест).
  Группа «по нашему продукту» часто полна тех, кто продукт уже перерос.
- **Смысл, а не слова.** Фильтр по словам путает «ищу работу диспетчером» и «ищем диспетчера»: слово одно,
  человек противоположный. Каждое сообщение размечает модель-решатель вопросами о смысле; в коде отсекается
  только технический мусор (пусто, стикер, повтор).
- **Места оценивают по доле «наших»**, измеренной на пробном чтении, а не по размеру и названию.
- **Касается человек, а не код:** индивидуально, по правилам места. Код только читает и размечает.
- **Хранить минимум:** текст, дата, место, ссылка на сообщение. Без базы имён и ников.

## Этапы и ворота

| Этап | Что делаем | Выход — ворота к следующему |
|---|---|---|
| **0. Кого ищем** | Типы клиентов из сценариев (кто покупает, кто нет). Для «нашего» — на каких ступенях Ханта он бывает и что говорит на каждой. Кого не берём: конкуренты, продавцы, работодатели, те, кто продукт перерос | описание словами + 10–20 примеров фраз «наш / не наш», по ступеням |
| **1. Семантика** | Keys.so (или Вордстат): запросы по задаче клиента, а не по продукту — проблема (ступень 0–1), способ решения (1–2), продукт (2–3). Перевод в язык чата: в поиске пишут «кем работать из дома», в чате — «девочки, кто где работает в декрете?». Из запросов — **темы мест**: жизненные ситуации, где человек об этом говорит | таблица «ступень → запросы и частоты → как говорят в чате → темы мест» |
| **2. Карта мест** | Поиск мест по темам этапа 1: каталоги сообществ (TGStat, Telemetr), поиск площадки, обсуждения ВКонтакте. По каждому: тема, участники, сообщений в неделю, читается ли без вступления, разрешена ли реклама по правилам | 20–40 мест на «да» владельца; поровну «около продукта» и «около ситуации» |
| **3. Пробное чтение** | 6–8 мест за сутки, без вступления. Хранить: текст, дата, место, ссылка. В тексте телефоны, почты, ники — пометками. Технический отсев: пусто, короче 15 знаков, повтор | файл выборки, число сообщений по местам |
| **4. Разметка смыслом** | Модель-решатель на **каждом** сообщении выборки: сценарий автора (наш тип / ищет работу / предлагает / уже в теме / реклама / другое), о себе ли, признаки ступени. Полоса считается кодом. Эталон 50–150 сообщений, размеченных человеком; сверка; пороги | совпадение по вопросам, таблица порогов; вопросы правят один раз |
| **5. Оценка мест** | Доля «наших» и их число в неделю по каждому месту; места без «наших» — вон; по найденным «нашим» уточнить темы и повторить этап 2 | короткий список мест с долей и объёмом |
| **6. Поток** | Регулярное чтение коротких окон (сутки–неделя) только по оставленным местам; разметка; отчёт «наши за период» со ссылками | отчёт для человека, а не база |
| **7. Касание** | Человек сам открывает ссылку и решает: ответ по делу в самом месте, если правила разрешают, или личное сообщение под вопрос человека — каждое своё. Код ничего не отправляет | журнал касаний без персональных данных: дата, место, полоса, исход |
| **8. Замер** | Касание → ответ → заявка → оплата; гипотеза в Движке роста с порогом, названным до замера | решение: масштабировать, сузить, закрыть |

## Правила

- **Порядок этапов не меняем.** Карту мест без семантики собирает случай; разметку без описания «кого ищем»
  проверить не по чему.
- **Одна мерка на всех.** Вопросы модели заданы до чтения и одинаковы для всего потока, включая отброшенное.
- **Ступень важнее темы.** Человек на ступени 0–1 («надоела работа, хочу из дома») — тоже «наш», но ему нужен
  прогрев контентом, а не предложение купить.
- **Модель ставит метку, решает человек.** Порог уверенности — по своему эталону, а не по чужим примерам.
- **Аккаунт:** отдельный и устоявшийся; вступать по несколько мест в день; паузы; ответы площадки «подождите» —
  стоп; из кода никаких сообщений и реакций.
- **Стоимость считается до прогона:** число сообщений × токены × цена модели — называется владельцу.

## Чего не делать

- Рассылок по списку, шаблонных сообщений, автоматической отправки.
- Базы людей: имён, ников, номеров «на потом».
- **Продажи людей как лидов.** Передать чужие контакты и сообщения третьему лицу — передача персональных данных
  без согласия. Продуктом может быть сам метод и его настройка под нишу клиента, отчёт о рынке без персональных
  данных или поток людей через свою посадочную с согласием — но не выгрузка найденных людей.
- Обучения моделей на сообщениях площадки (условия Telegram API, п. 1.5).

## Как из метода сделать услугу

`[применение]` Для любой ниши повторяется один набор: описание «кого ищем» → семантика → карта мест → пробное
чтение с разметкой → отчёт «где ваши люди, сколько их в неделю, как они говорят». Это и есть сдаваемый результат
первого этапа: ценен сам по себе (язык клиента, темы контента, места для посевов) и показывает, стоит ли ниша
регулярного потока. Регулярный поток и касания клиент ведёт сам — своим аккаунтом и своими людьми.

## Чего метод не даёт

- Потока там, где клиент о своей задаче в открытых местах не пишет (закрытые рынки, длинный B2B).
- Разрешения на касание: основание обработки сообщений людей и формат обращения проверяет юрист под нишу.
