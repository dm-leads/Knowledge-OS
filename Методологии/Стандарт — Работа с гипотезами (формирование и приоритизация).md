# Стандарт — Работа с гипотезами (формирование и приоритизация)

> Правило: гипотезы формируем и приоритизируем ТОЛЬКО так. Каждый шаг — на данных, не из головы.
> Ничего не берём как факт без проверки (в т.ч. слова заказчика и наши собственные допущения).

## Принципы (проверено по авторам)

- **Бизнес-задача первична** — сначала «что растим» (конверсия/чек/возвращаемость/отток), потом гипотезы [Замесин].
- **Точка роста — из юнит-экономики** (плечо: где малое изменение даёт кратный рост) [Красинский].
- **Работаем с (1 − конверсия)** — с теми, кто НЕ сделал целевое действие; сначала делим Engaged / Not-engaged (если 80–90% not-engaged → проблема в привлечении ИЛИ в продукте) [Красинский].
- **Гипотезы из библиотеки механик под задачу, не из головы** (из доступных сработают 2–4) [Замесин].
- **Фальсификация** — гипотезу проверяем на опровержение, не на подтверждение [Красинский].
- **Кросс-функционально** — точки роста прячутся в гэпах на стыках маркетинг↔продажи↔продукт; единый источник истины (SOT) [Красинский].
- **Приоритет — быстро×дёшево×эффект×охват×уверенность** (это RICE/ICE, а не «правило»); дорогое/нестабильное (напр. перезапуск рекламы) падает само = высокий Effort + низкая Credibility.
- **Не тестировать мелочи** (эффект меньше доверительного интервала — не докажем) [Красинский]; **убирать лишнее, не добавлять фичи**.

## Процесс (8 шагов)

1. **Данные на вход** — Метрика · Директ · CRM · звонки/переписки · сквозная · скоринг. Только факты.
2. **Точка роста из юнит-экономики** (плечо) + деление **Engaged / Not-engaged** (привлечение vs продукт).
3. **Бизнес-задача** — назвать конкретную (рост конверсии / чека / возвращаемости / снижение оттока…).
4. **Понять ПОЧЕМУ** — диагностика по данным: воронка (где абсолютная конверсия рушится), Webvisor, анализ звонков, сегменты, граф работ (JTBD); барьеры/тревоги/спящие работы; «блокеры сделки» на этапах CRM.
5. **Генерация гипотез из механик** под задачу + формат **«если сделаем X → получим Y (метрика Z)»**.
6. **Приоритизация (скоринг)** — см. ниже; + проверка измеримости (ДИ).
7. **Кросс-функционально** — свести маркетинг+продажи+продукт; искать гэпы на стыках; SOT.
8. **HADI-цикл** — Hypothesis → Action → Data → Insights, циклично; фальсификация; кач→колич валидация. (HADI — общий термин; у авторов это эксперимент + ДИ + кач→колич.)

## Скоринг (RICE-адаптация)

`ПРИОРИТЕТ = Эффект ₽ × Вера ÷ Сложность`

- **Эффект ₽** = Impact, посчитанный через юнит-экономику (меняем одну метрику → Δ прибыли). Он **уже включает Reach × Impact**, поэтому Reach отдельно НЕ множим (иначе двойной счёт).
- **Вера (Credibility)** = среднее 6 под-факторов: доказательная база · ясность проблемы · близость к плечу · прецедент/benchmark · job-fit · измеримость.
- **Сложность (Effort)** = среднее 5 под-факторов: ресурсы · техника · зависимость · данные/трекинг · риск/откат.
- **Reach (охват)** — справочно: на скольких пользователей/сделок сработает (для прозрачности и сверки Эффекта).
- Шкала под-факторов 1–5, с определениями (см. лист «_Скоринг гипотез»).

> Под-факторное дробление — наше обогащение ICE (из семейства IceRice + таблицы-примера), не дословно Красинский (у него ICE проще). Формула приоритета — ICE с денежным Impact (точнее субъективного 1–10 у RICE).

## Честные пределы (всегда держим в голове)

- Приоритет — **относительный балл** для сортировки, не деньги.
- При малом объёме большинство гипотез — **ставки**, не доказуемые A/B (эффект < ДИ). Скоринг ранжирует, не доказывает.
- Эффект ₽ — **предположение** (Красинский: оцениваем грубо, не боимся ошибиться; пересчитываем при новых данных).
- Экономика достоверна лишь настолько, насколько достоверны входы (маржа, покрытие атрибуции) — см. проектный «Стандарт — Единая база экономики».

## Как переносить в другой проект

Ядро (принципы, 8 шагов, скоринг) — доменно-нейтральное. В новый проект берётся как есть; проектная специфика (какие данные, какая воронка, какая маржа) — в проектных документах. Лист «_Скоринг гипотез» копируется как шаблон.
