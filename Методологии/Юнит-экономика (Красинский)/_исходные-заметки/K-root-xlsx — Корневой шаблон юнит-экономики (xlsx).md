## 1. Концепции и идеи

- Шаблон предназначен для расчёта юнит-экономики бизнеса через поток пользователей/лидов, воронку конверсий, доходность на одного платящего и итоговую прибыль/убыток. (источник → лист «Шаблон», ячейка A2)
- Модель охватывает весь путь: привлечение пользователя → конверсия → покупка → доход → маржа → прибыль с потока. (источник → лист «Шаблон», строки 2–3)
- Предусмотрено разделение потока на платные и бесплатные каналы (строки 16–17: paid/free каналы). (источник → лист «Шаблон», A16, A17)
- Фиксированные расходы (зарплаты, аренда офиса, серверы) вычитаются отдельным слоем после маржи с потока, формируя итоговую прибыль после фикс. расходов. (источник → лист «Шаблон», Y2, Z2)
- Расходы на привлечение пользователей включают в том числе зарплаты продажников. (источник → лист «Шаблон», X2)
- Модель применяется к разным типам бизнесов: подписки, eCommerce, маркетплейсы, delivery, SaaS, B2B-сервисы. (источник → лист «Шаблон», строки 5, 8, 11, 14, 19, 21, 24)

## 3. Формулы

Все формулы — из лист «Шаблон», извлечены методом openpyxl. Условные обозначения столбцов соответствуют буквам ячеек Excel.

### Основные формулы (уникальные паттерны, 29 шт.):

| Столбец / метрика | Формула (паттерн) | Расшифровка |
|---|---|---|
| **T — Прибыль с потока** | `=B*(P−O)` | Поток × (AMPU − CPUser) |
| **Z — Прибыль после фикс. расходов** | `=T−Y` | Прибыль с потока − Фикс. расходы |
| **P — AMPU/LTV (на 1-го привлечённого)** | `=D*G` | Конверсия в покупку × ARPPU |
| **V — Маржа с потока (Gross Profit)** | `=E*G` | Число платящих × ARPPU |
| **G — ARPPU/CLTV (доход на 1-го платящего, с издержками 1-й продажи)** | `=H*I*L−K` | Ср.чек × доля маржи × кол-во покупок − издержка 1-й продажи |
| **G — ARPPU/CLTV (альтернативный, без K)** | `=H*I*L` | Ср.чек × доля маржи × кол-во покупок (для строк 15–25) |
| **O — CPUser (стоимость привлечения 1 пользователя)** | `=X/B` | Расходы на привлечение / Поток |
| **F — Payments (оплаченные заказы)** | `=L*E` | Кол-во покупок на 1 платящего × Число платящих |
| **Q — AMPU−CPUser (прибыль на 1-го привлечённого)** | `=P−O` | AMPU − CPUser |
| **R — ROI** | `=P/O` | AMPU / CPUser |
| **U — Revenue (выручка с потока)** | `=H*F` | Ср.чек × Кол-во платежей |
| **W — COGS с потока** | `=U−V` | Выручка − Валовая маржа |
| **E — Buyers (число платящих)** | `=D*B` | Конверсия × Поток |
| **D — Конверсия в 1-ю покупку** | `=E/B` | Платящие / Поток (обратный расчёт при известном E) |
| **M — CAC** | `=X/E` | Расходы на привлечение / Число платящих |
| **X — Расходы на привлечение (Acq Costs)** | `=E*M` или `=O*B` или `=M*E` | Платящие × CAC, или CPUser × Поток |
| **B (paid) — поток paid канала** | `=X_paid/O_paid` | Расходы paid / CPUser paid |
| **B (free) — поток free канала** | `=B_all−B_paid` | Весь поток − Платный поток |
| **B (музыка)** | `=U/P` | Выручка / AMPU (расчёт трафика из выручки) |
| **V (музыка)** | `=U−W` | Выручка − COGS |

(источник → лист «Шаблон», раздел «Формулы — 145 шт., 29 уникальных шаблонов»)

### Важные детали формул:
- Формула G имеет два варианта: `=H*I*L−K` (строки 5–12, с вычетом издержки 1-й продажи) и `=H*I*L` (строки 15–25, без K). (источник → лист «Шаблон»)
- X рассчитывается как `=E*M` (CAC-путь) или `=O*B` (CPUser-путь) — оба варианта встречаются в разных строках. (источник → лист «Шаблон»)

## 4. Пошаговые процедуры / алгоритмы

Явного пошагового алгоритма в виде текста в источнике нет. [мой вывод] Логика заполнения модели читается из структуры столбцов:

1. Задать поток (B): количество пользователей/лидов в периоде.
2. Задать конверсии (C, D): конверсия в лида и конверсия в первую покупку.
3. Рассчитать число платящих (E = D×B).
4. Задать экономику одной сделки: средний чек (H), долю маржи/COGS (I), скидку (J), издержку первой продажи (K), число повторных покупок (L).
5. Рассчитать ARPPU/CLTV (G = H×I×L − K).
6. Задать расходы на привлечение (X) или CAC (M), рассчитать CPUser (O = X/B).
7. Рассчитать AMPU/LTV (P = D×G) — маржа на 1-го привлечённого.
8. Рассчитать прибыль на 1 пользователя (Q = P−O) и ROI (R = P/O).
9. Рассчитать агрегаты по потоку: Revenue (U), Gross Profit (V), COGS (W), Acq Costs (X), Profit (T = B×(P−O)).
10. Вычесть фиксированные расходы (Y) → Прибыль после фикс. расходов (Z = T−Y).

(источник → лист «Шаблон», структура строк 2–5)

## 5. Фреймворки / модели

### Модель юнит-экономики Красинского (единственный лист «Шаблон»)

**Три уровня модели:**

**Уровень 1 — «Доход на 1-го платящего» (столбцы G–L, шапка G1: «доход на 1-го платящего»)**
- H: средний чек (Av. Price)
- I: доля маржи / COGS / комиссия
- J: скидка
- K: издержка на 1-й продаже (1st sale COGS)
- L: кол-во покупок / время жизни (Av Payment Count / LifeTime)
- G: ARPPU = H×I×L − K

**Уровень 2 — «На 1-го привлечённого» (столбцы O–R, шапка O1: «на 1-го привлечённого»)**
- O: CPUser = X/B (стоимость привлечения 1 пользователя)
- P: AMPU/LTV = D×G (маржа на 1-го привлечённого)
- Q: AMPU−CPUser = P−O (прибыль на 1-го пользователя)
- R: ROI = P/O

**Уровень 3 — Агрегаты по потоку (столбцы T–Z)**
- T: Profit = B×(P−O) (прибыль с потока)
- U: Revenue = H×F (выручка)
- V: Gross Profit = E×G (валовая маржа)
- W: COGS = U−V
- X: Acq Costs (расходы на привлечение)
- Y: Fix Costs (фиксированные расходы)
- Z: Прибыль после фикс. расходов = T−Y

**Входные параметры (драйверы, наиболее цитируемые ячейки):**
- E6, E8, E9 (4× каждая) — число платящих по кейсам
- B15, B21, B22, B24, B25 (4× каждая) — потоки по кейсам
- E5, B5, P5, O5 и др. (3× каждая) — метрики уровня 1–2

(источник → лист «Шаблон», раздел «Кандидаты в драйвер-ячейки»)

**Разделение каналов:**
- Строки 15–17 (доставка еды): общий поток (все пользователи) = paid + free
- B16 (paid) = X16/O16 — вывод платного потока из бюджета
- B17 (free) = B15−B16 — остаток = бесплатный канал

(источник → лист «Шаблон», строки 15–17, формулы B16, B17)
