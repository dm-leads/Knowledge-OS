## 1. Концепции и идеи

- [факт из материала] Юнит-экономика — система, описывающая, как деньги приходят от пользователей. Весь процесс описывается 4–5 метриками, одинаково для всех бизнесов. (источник → транскрипт, раздел «Прибыль на пользователя»)
- [факт из материала] Юнит — «то, что мы штабируем»: в 99% бизнесов это платящий пользователь или клиент. (источник → транскрипт, раздел «Определение юнита»)
- [факт из материала] Юнит-экономика управляет финансами, а не наоборот. Финансы предсказываются юнит-экономикой. (источник → транскрипт, раздел «Связь финансов и юнит-экономики»)
- [факт из материала] Модель юнит-экономики нелинейна из-за операции вычитания: малейшие колебания ключевой метрики приводят к кратному росту прибыли. Это называется «неустойчивость модели». (источник → транскрипт, раздел «Кратный рост»)
- [факт из материала] Люди принимают решения о покупке эмоционально, а не рационально (Канеман, Нобелевская премия 2002). «Человек неразумный» — базовая модель после 2002 года. (источник → транскрипт, раздел «Психология решений»)
- [факт из материала] Большинство бизнесов разоряются не потому, что не смогли сделать продукт, а потому что не смогли привлечь достаточно платящих пользователей. (источник → транскрипт, раздел «Почему разоряются бизнесы»)
- [факт из материала] Скидок не существует — есть сегментация по цене. Нелинейный эффект скидки: скидка 30% от среднего чека при узкой марже может уничтожить всю прибыль. (источник → транскрипт, раздел «Скидки и маржинальность»)
- [факт из материала] Инфраструктура страны, транзакционные издержки и уровень доверия в обществе влияют на применимость бизнес-моделей (пример: доставка по почте в США vs. России). (источник → транскрипт, раздел «Транзакционные издержки»)
- [факт из материала] Пристрастие выборки (survivorship bias): мы видим только выживших (One Dollar Shave Club, Google), но рядом было множество аналогичных компаний, которые не выжили. (источник → транскрипт, раздел «Пристрастие выборки»)
- [факт из материала] Точки роста смещаются: как только метрика поднята в зоне компетентности, проблема переходит в другую метрику/класс проблем. (источник → транскрипт, раздел «Траектория развития»)
- [факт из материала] Правильная последовательность работы с метриками: сначала — маржинальность и средний чек, потом — конверсия, потом — поток пользователей (на примере кейса HotWiFi / Архангельск). (источник → транскрипт, раздел «Кейс HotWiFi»)
- [факт из материала] Три исключения из правила «конверсия 2–3%»: заказ еды, заказ такси, медицинские услуги — там конверсия кратно выше, потому что выбор уже сделан до открытия приложения. (источник → транскрипт, раздел «Три исключения»)

## 2. Точные определения

- **Юнит** — «то, что мы штабируем»; в 99% случаев — платящий пользователь или клиент. (источник → транскрипт)
- **AMPPU (Average Margin Per Paying User)** — средняя маржа (прибыль) с одного платящего пользователя. «В АМПУ собраны все-все-все метрики, которые описывают некоторую ценность продукта на рынке». (источник → транскрипт)
- **AMPU (Average Margin Per User)** — средняя маржа с пользователя (включая неплатящих). (источник → транскрипт, упоминание рядом с AMPPU)
- **Average Payment Count** — среднее число повторных платежей на пользователя когорты. Считается: суммарное число платежей когорты / размер когорты. (источник → транскрипт, раздел «Когорты»)
- **Когорта** — группа пользователей, впервые купивших в определённый период. Для финансовых когорт важно, когда купили; для маркетинговых — когда пришли. (источник → транскрипт)
- **Cost per user (CPU)** — стоимость привлечения одного пользователя. Зависит от компетенций в канале и конкуренции в канале; НЕ зависит от продукта. (источник → транскрипт)
- **Gross profit** — выручка минус COGS (себестоимость), без учёта расходов на привлечение. (источник → транскрипт)
- **Неустойчивость модели** — эффект, при котором из-за операции вычитания двух близких цифр малейшие изменения ключевой метрики дают кратный рост прибыли. (источник → транскрипт)

## 3. ФОРМУЛЫ

### AMPPU (базовая)
```
AMPPU = Средний чек × Маржинальность(%) × Среднее число повторных покупок
```
(источник → транскрипт, устный вывод на примере Яндекс.Такси)

Пример (Яндекс.Такси):
- Средний чек: ~500 руб., доля платформы: ~20%, повторных покупок за год: ~10
- AMPPU ≈ 500 × 0,20 × 10 = 1 000 руб.

### Прибыль на поток пользователей
```
Прибыль = Поток пользователей × (AMPPU − Cost per user)
```
(источник → транскрипт, раздел «Расчёт прибыли на город»)

### Average Payment Count (когортный)
```
APC = Суммарное число платежей когорты / Размер когорты
```
Пример: когорта 6 000 чел. → 7 330–7 495 платежей → APC ≈ 1,22–1,25
(источник → транскрипт, раздел «Когорта 6000»)

### Конверсия в повторную покупку
```
Конверсия_2 = Число вернувшихся и купивших повторно / Размер когорты
```
Пример: из 6 000 → 600 вернулись → конверсия 10%
(источник → транскрипт, раздел «Когорты»)

### Эффект скидки на маржу
```
Прибыль со скидкой = (Средний чек × (1 − Скидка%)) − Себестоимость
```
Пример (кейс Клуб Бритв): чек 500 руб., себестоимость 400 руб., скидка 0% → прибыль 100 руб.
Скидка 30%: чек 350 руб. − себестоимость 400 руб. = убыток −50 руб.
(источник → транскрипт, раздел «Нелинейность скидок»)

### Формула кратного роста (кейс HotWiFi / Архангельск)
Базовая экономика:
- 50 000 пользователей × конверсия 10% = 5 000 покупателей
- Средний чек: 600 руб., комиссия 5% → 30 руб./покупку
- Повторных покупок: 1–2/мес. → AMPPU ≈ 36 руб.
- Cost per user: 2 руб.
- Прибыль = 50 000 × (3,6 − 2) ≈ 80 000 руб./мес.

После правок (средний чек ×2, комиссия ×3):
- AMPPU вырос в 6 раз → прибыль выросла в 12+ раз (нелинейный эффект операции вычитания)
(источник → транскрипт, раздел «Магия кратного роста»)

## 4. Пошаговые процедуры / алгоритмы

### Алгоритм поиска точки кратного роста
1. Посчитать юнит-экономику: AMPPU и Cost per user по текущим метрикам.
2. Определить, сходится ли экономика (AMPPU > CPU).
3. Выдвинуть гипотезы по каждой метрике: средний чек, маржинальность, конверсия, повторные покупки, поток пользователей.
4. Оценить каждую гипотезу в таблице — на сколько % можно изменить метрику.
5. Определить порядок работы: обычно — маржинальность → средний чек → конверсия → трафик.
6. Реализовать гипотезы, начиная с найденной точки роста.
7. После реализации точка роста сместится — повторить цикл.
(источник → транскрипт, раздел «Алгоритм работы»)

### Алгоритм расчёта когортного Average Payment Count
1. Зафиксировать когорту (все, кто первый раз купил в периоде).
2. Посчитать число платежей от когорты в каждый последующий месяц.
3. Просуммировать все платежи когорты за весь доступный период.
4. Разделить суммарные платежи на размер когорты.
(источник → транскрипт, раздел «Когорты»)

## 5. Фреймворки / модели

### «Слои юнит-экономики»
- **Слой финансов** — итоговые деньги компании (P&L).
- **Слой юнит-экономики** — AMPPU, CPU, конверсия, средний чек, маржа, повторные покупки, поток пользователей.
- **Слой нелинейных эффектов** — места кратного роста (операция вычитания, когортные эффекты).
- **Слой убеждений** — когнитивные искажения команды, которые мешают увидеть точку роста.

Связь: финансы = горизонтальный срез всех когорт по вертикали.
(источник → транскрипт, раздел «Когорты»)

## 6. Разобранные примеры / кейсы / цифры

### Кейс: Яндекс.Такси vs. Яндекс.Музыка
- Такси: AMPPU ~1 000 руб. (чек 500 × доля 20% × 10 покупок).
- Музыка: AMPPU ~60 коп. при узких допущениях (подписка ~200 руб., редкие повторные покупки).
- Вывод: разные JTBD-сценарии → AMPPU отличается в десятки раз при похожих моделях.
(источник → транскрипт)

### Кейс: Клуб Бритв (копия One Dollar Shave Club в России)
- Чек: ~500 руб./мес., себестоимость: ~400 руб., прибыль: ~100 руб./покупку.
- Конверсия: реально 0,28% (посчитали 2,8%, ошиблись — считали без когорт).
- Повторные покупки: 1–2 (90% купят один раз).
- Итог: экономика убыточна, бизнес закрылся.
- One Dollar Shave Club выжил: рядом было ~10 аналогичных компаний, которые не выжили (пристрастие выборки).
(источник → транскрипт)

### Кейс: HotWiFi / Архангельск (доставка еды)
- 50 000 пользователей, конверсия 10%, средний чек 600 руб., комиссия 5%.
- AMPPU: ~36 руб., CPU: 2 руб. → прибыль ~80 000 руб./мес.
- После: средний чек ×2 (другие рестораны), комиссия ×3 (перепереговорили).
- Прибыль выросла в 12+ раз (нелинейный эффект).
- Плюс рост конверсии на 10 п.п. → ещё ~+1 млн руб.
- Плюс платный трафик (теперь CPU 10–15 руб. позволить можем) → ещё +1,3–1,6 млн руб.
(источник → транскрипт)

### Кейс: PlayKey (стриминг игр)
- Привлекли 50 000 пользователей через YouTube.
- Оказались студенты/школьники без денег (сегментация не сделана).
- Фокус сместился на «громкую» неплатящую аудиторию.
- Итог: экономика не сошлась.
(источник → транскрипт)

### Кейс: доставка еды — цель 26% роста в неделю
- Линейная экстраполяция от «точка А → точка Б за 3 месяца акселератора».
- Реальный рост: +20%, +13%, +10%, затем провал.
- Сожгли запас денег.
- Вывод: линейная экстраполяция роста — типичная ошибка целеполагания.
(источник → транскрипт)

### Ориентиры по повторным покупкам (практические)
- Если не считали когорты — берите 1 и 2 (самые частотные значения).
- Рекуррентный бизнес (подписка, привязка карты): ~3 покупки/год при retention ~60%.
- B2B с удержанием 90%: ~7 покупок/год.
- 12 покупок/год — редкость, только при годовой предоплате.
(источник → транскрипт)

## 10. Термины в глоссарий

| Термин | Краткое определение |
|---|---|
| AMPPU | Average Margin Per Paying User — средняя маржа с платящего пользователя |
| AMPU | Average Margin Per User — средняя маржа с пользователя (все привлечённые) |
| Cost per user (CPU) | Стоимость привлечения одного пользователя из канала |
| Average Payment Count | Среднее число повторных платежей на пользователя когорты |
| Когорта | Группа пользователей, впервые купивших в один период |
| Юнит | Единица масштабирования (чаще всего — платящий пользователь) |
| Gross profit | Валовая прибыль (выручка − COGS, без расходов на привлечение) |
| Неустойчивость модели | Нелинейный эффект кратного роста из-за операции вычитания |
| Пристрастие выборки | Survivorship bias — видим только выживших |
| Рекуррентные платежи | Автоматически списываемые платежи (подписка); нет прямой связи с retention |

## 11. Типичные ошибки / антипаттерны

- [факт из материала] **Линейная экстраполяция роста**: цель «26% в неделю» из линейного деления точки A на точку B → провал через 3–4 недели. (источник → транскрипт, кейс доставки еды)
- [факт из материала] **Считать повторные покупки без когортного анализа**: «100 чел. за год сделали 600 покупок → в среднем 6» — ошибочная модель. Реально 90% купят 1 раз. (источник → транскрипт)
- [факт из материала] **Верить в прямую связь retention → повторные покупки**: прямой математической связи нет. При рекуррентных платежах они полностью независимы. (источник → транскрипт)
- [факт из материала] **Давать скидки без расчёта эффекта на маржу**: скидка 30% при узкой марже → прибыль в убыток. Нелинейный эффект: скидка меньше в 3 раза → потеря в 7 раз больше. (источник → транскрипт)
- [факт из материала] **Работать с upsell при плохой базовой экономике**: при AMPPU 36 руб. и конверсии 10%, upsell на 200 руб. даст ~40 коп. на пользователя = 18 000 руб./мес. за полгода работы команды. (источник → транскрипт)
- [факт из материала] **Сначала лить трафик, потом оптимизировать метрики**: при плохой марже рост CPU вместе с ростом трафика ×6 немедленно даёт убыток. (источник → транскрипт)
- [факт из материала] **Неправильные премии сейлзам**: от выручки (а не от когортного LTV) → сейлз привлекает клиентов на 1 месяц вместо годовых тарифов. (источник → транскрипт)
- [факт из материала] **Карго-культ копирования**: копировать внешние элементы успешного бизнеса, не понимая, что реально привело к успеху (пример: лендинг One Dollar Shave Club без понимания роли вирусного видео). (источник → транскрипт)
- [факт из материала] **Идти туда, где нет конкурента, из страха**: часто это город/рынок с меньшим чеком и плохой маржой (кейс Архангельск). (источник → транскрипт)
