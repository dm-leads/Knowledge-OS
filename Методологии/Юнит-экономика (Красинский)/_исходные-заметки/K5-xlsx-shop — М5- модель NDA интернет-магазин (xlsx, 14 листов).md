## 1. Концепции и идеи

- [факт] Модель строится на реальных данных NDA-интернет-магазина за 2017 год; аналитика подключена через GA (Google Analytics) с выгрузкой через Spreadsheet Add-On. (источник → лист «Report Configuration», лист «buyers new»)
- [факт] Ключевое разделение пользователей: **new** (дата 1-й сессии в ноябре 2017) vs **old** (были сессии до ноября 2017); кросс-чек на балансировку обязателен. (источник → лист «Юнит-экономика», строки A5–A10)
- [факт] GA использовал семплирование 48% сессий для расчёта метрик по покупателям («Contains Sampled Data: Yes», sample percentage = 0.4823); без семплирования — данные из когорт. (источник → лист «buyers new», строка C7; лист «Cohorts»)
- [факт] Комментарий автора: «48% это очень много конечно» — семплирование создаёт значительную погрешность; погрешность на новых пользователях составила ~697 424 руб. (источник → лист «Юнит-экономика», A32, W37)
- [факт] Модель содержит два подхода к юнит-экономике: (а) с семплированием (быстро из GA), (б) без семплирования — по когортам из сырых данных GA через Pivot Tables. (источник → лист «Юнит-экономика», A32)
- [факт] Когорты строятся по месяцу первой сессии (Cohort MonthYear), платежи отслеживаются помесячно. (источник → лист «transactions raw data», заголовки; лист «Cohort Buyers»)
- [факт] Churn rate (доля покупателей, не вернувшихся в следующем месяце) в данном магазине стабильно ~50% в месяц. (источник → лист «Cohorts», строки r13)
- [факт] В модели предусмотрен расчёт прогноза CLTV и сравнение с фактическим CLTV. (источник → лист «Cohorts», столбцы S33 «CLTV buyers new» и U33 «CLTV прогноз»)
- [факт] Для листа «ответы на вопросы» смоделирован пример A/B-теста конверсии с расчётом статистической значимости через доверительный интервал. (источник → лист «ответы на вопросы», строки r18–r28)
- [факт] Лист «Report Configuration» описывает 7 типов GA-запросов, необходимых для наполнения модели; запросы выполняются через GA Spreadsheet Add-On. (источник → лист «Report Configuration»)

## 2. Точные определения

- **Users / Leads (C)** — поток пользователей или лидов за период. (источник → лист «Юнит-экономика», C2–C3)
- **C1 conv to buyer (D)** — конверсия из потока в нового покупателя (= Buyers / Users). (источник → лист «Юнит-экономика», D2–D3)
- **Buyers (E)** — число платящих пользователей. (источник → лист «Юнит-экономика», E2–E3)
- **Payments (F)** — число оплат (транзакций). (источник → лист «Юнит-экономика», F2–F3)
- **AMPPU / CLTV (H)** — маржа на 1-го платящего (Average Margin Per Paying User) или Lifetime Value. (источник → лист «Юнит-экономика», H2–H3)
- **Av. Price (I)** — средний чек (= Revenue / Payments). (источник → лист «Юнит-экономика», I2–I3)
- **Margin / Commission (J)** — маржа/процент комиссии с оплаты. (источник → лист «Юнит-экономика», J2–J3)
- **COGS — Cost of Goods Sold (K)** — издержки на каждой продаже (себестоимость). (источник → лист «Юнит-экономика», K2–K3)
- **Discounts (L)** — скидки, если есть. (источник → лист «Юнит-экономика», L2–L3)
- **COGS 1st sale (M)** — издержки на 1-й продаже (может отличаться от последующих). (источник → лист «Юнит-экономика», M2–M3)
- **Av. Payment Count / LifeTime (N)** — среднее число оплат на 1-го платящего. (источник → лист «Юнит-экономика», N2–N3)
- **CAC — Customer Acquisition Costs (O)** — стоимость привлечения одного платящего (= Acq.Costs / Buyers). (источник → лист «Юнит-экономика», O2–O3)
- **CPO / SPS — Cost per Order / Cost per Sale (P)** — стоимость одного заказа (= Acq.Costs / Payments). (источник → лист «Юнит-экономика», P2–P3)
- **CPUser / CPLead (R)** — стоимость привлечения одного пользователя (= Acq.Costs / Users). (источник → лист «Юнит-экономика», R2–R3)
- **AMPU / LTV (S)** — маржа на 1-го привлечённого пользователя (= C1 × AMPPU). (источник → лист «Юнит-экономика», S2–S3)
- **AMPU − CPUser (T)** — прибыль на пользователя (экономика юнита). (источник → лист «Юнит-экономика», T2–T3)
- **Profit net (V)** — чистая прибыль с потока пользователей (= Profit − Fix Costs). (источник → лист «Юнит-экономика», V2–V3)
- **Profit (W)** — прибыль с потока пользователей (= Gross Profit − Acq.Costs). (источник → лист «Юнит-экономика», W2–W3)
- **Revenue (X)** — выручка. (источник → лист «Юнит-экономика», X2–X3)
- **Gross Profit (Y)** — доход с потока (= Revenue × Margin). (источник → лист «Юнит-экономика», Y2–Y3)
- **Acq. Costs до продажи (Z)** — расходы на привлечение пользователей. (источник → лист «Юнит-экономика», Z2–Z3)
- **COGS total после продажи (AA)** — суммарные издержки на потоке пользователей. (источник → лист «Юнит-экономика», AA2–AA3)
- **Fix Costs в месяц (AB)** — постоянные расходы в месяц (ограничены сверху). (источник → лист «Юнит-экономика», AB2–AB3)
- **Когорта** — группа новых покупателей, совершивших первую сессию в одном месяце. (источник → лист «transactions raw data», B1–B2)
- **Churn** — число покупателей, не вернувшихся в следующем периоде (= buyers_prev + buyers_new_prev − buyers_current). (источник → лист «Cohorts», A12, формулы C12:M12)
- **Churn rate** — доля от базы покупателей, которые не вернулись. (источник → лист «Cohorts», A13, формулы C13:M13)
- **Buyer base growth** — прирост базы покупателей = новые − ушедшие. (источник → лист «Cohorts», A15)
- **Уровень семплирования** — доля сессий, реально обработанных GA (Sample percentage); в данной модели 48.2%. (источник → лист «Юнит-экономика», B2–B3; лист «buyers new», C7)

## 4. Пошаговые процедуры / алгоритмы

### Алгоритм построения когортного анализа из GA

1. Настроить 7 типов GA-запросов в листе «Report Configuration» (View ID, Start Date, End Date).
2. Запустить запросы через GA Spreadsheet Add-On — данные обновятся в листах-источниках (raw data, buyers all, buyers new и т.д.).
3. В листе `transactions raw data` когорта определяется автоматически: `=if(A3<>"", date(year(A3),month(A3),1), "before Jan 2017")`.
4. Пересчитать Pivot Tables: `Cohort Buyers` (COUNTUNIQUE покупателей), `Cohort Transactions`, `Cohort Revenue` по осям Cohort MonthYear × Transaction MonthYear.
5. В листе `Cohorts` свести данные: revenue, gross profit, buyers new/old/before2017, churn, churn rate, buyer base growth по месяцам.
6. Рассчитать CLTV, CAC, T = CLTV − CAC для каждой когорты.
7. Переключить лист `Юнит-экономика` на когортные данные (строки 33–35) для расчёта без семплирования; сравнить с семплированными (строки 5–10).

(источник → листы «Report Configuration», «transactions raw data», «Cohorts», «Юнит-экономика»)

### Алгоритм сценарного анализа

1. Зафиксировать базовые показатели (строки 5–10 листа «Юнит-экономика»).
2. Разбить на сегменты: всего / new / free channel new / paid channel new / old.
3. Кросс-чек: old + new − all = 0 (строка r10).
4. Для каждой гипотезы (строки 13–17): изменить один параметр, остальные зафиксировать, пересчитать Profit и Revenue.
5. Для развёрнутых сценариев (строки 913–928): менять конверсию (D915 = D913 + 0.5%), наблюдать прирост Y916 = Y915 − Y913.

(источник → лист «Юнит-экономика», строки 5–17, 913–928)

### Алгоритм A/B-теста конверсии

1. Задать число пользователей (n) и конверсии вариантов A и B.
2. Рассчитать доверительный интервал каждого: `2 * SQRT(p*(1-p)/n)`.
3. Проверить: разница B − A > суммы их доверительных интервалов → вариант B статистически лучше.

(источник → лист «ответы на вопросы», строки r22–r28)

## 5. Фреймворки / модели

```
[B: уровень семплирования]
```

- r5: всего за ноябрь 2017

(источник → лист «Юнит-экономика»)

### Когортная модель (лист «Cohorts»)

```
Оси: строки = Cohort MonthYear (янв–дек 2017 + before Jan 2017)
     столбцы = Transaction MonthYear (янв–дек 2017)

Блоки:
  Revenue (r2–r16)        — выручка когорт помесячно
  Gross Profit (столбец P) — GP = Revenue × 30%
  Buyers (r33–r47)        — число покупателей когорты помесячно
  Transactions (r63–r77)  — число транзакций когорты помесячно

  C1, C2m ... C12m        — ретеншн-конверсии (средние и по каждой когорте)
  CLTV факт (S) | CLTV прогноз (U) | CAC (R) | T = CLTV−CAC
  churn | churn rate | buyer base growth
```

## 10. Термины в глоссарий

- **Cohort MonthYear** — год-месяц-01 первой сессии покупателя, ключ когорты
- **Transaction MonthYear** — год-месяц-01 совершения платежа
- **ga:dimension4** — пользовательское измерение GA = clientID (идентификатор пользователя)
- **ga:sessionCount** — порядковый номер сессии пользователя (1 = первая сессия)
- **Sample percentage** — доля сессий, реально обработанных GA при семплировании
- **Buyer base growth** — месячный прирост базы платящих = новые − ушедшие
- **CLTV прогноз** — прогноз Lifetime Value на основе средних ретеншн-конверсий (C2m...C12m)
- **Raw data** — сырые данные GA (без семплирования): сессии с транзакциями, clientID
- **Spreadsheet Add-On** — плагин Google Analytics для Google Sheets, выполняющий API-запросы в GA
- **Before Jan 2017** — категория пользователей без даты первой сессии в 2017 (старые покупатели)
- **Сценарий / гипотеза** — строка модели с изменённым одним параметром для оценки влияния на Profit/Revenue

## 11. Типичные ошибки / антипаттерны

- [факт] Использование семплированных данных GA без проверки уровня семплирования: при 48% погрешность составила ~697 424 руб. на потоке новых пользователей. Необходимо сравнивать с когортными данными (без семплирования). (источник → лист «Юнит-экономика», A32, W37)
- [факт] Некорректная трактовка «buyers new» из GA: лист `buyers new` показывает Users=2 590, New Users=2 660 — расхождение из-за семплирования; необходим кросс-чек через `raw data`. (источник → лист «buyers new», r11–r12)
- [факт] Кросс-чек old + new − all должен давать 0; строка r10 листа «Юнит-экономика» это проверяет (Revenue ≈ 1.86e-9 — ошибка плавающей точки, норма). (источник → лист «Юнит-экономика», r10)
- [факт] Пользователи без даты первой сессии попадают в «before Jan 2017» — их нельзя смешивать с когортой января 2017 и нужно выделять в отдельную группу. (источник → лист «transactions raw data», B3–B5)
- [мой вывод] Churn rate ~50%/мес означает, что CLTV без программы лояльности быстро выходит на плато — нельзя экстраполировать первый месяц на всю жизнь покупателя.
