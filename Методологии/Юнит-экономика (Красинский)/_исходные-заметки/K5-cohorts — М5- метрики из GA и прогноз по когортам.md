## 1. Концепции и идеи

- **Фичи — генераторы дополнительной работы.** Фича сама по себе не закрывает сценарий пользователя: «большинстве случаев она так реализована, она же ничего не знает по сценарии моего использования». Правильная единица — автоматизированный Job (сценарий), а не фича. (источник → расшифровка, начало текста)

- **Мышление сценариями.** Вместо «делаем фичу» — «автоматизируем джоб/сценарий пользователя». Это прямо меняет бэклог: гипотеза должна описывать, какой сценарий автоматизируется. (источник → расшифровка)

- **5 метрик — всё, что нужно.** Gross Profit зависит только от 5 рычагов: число пользователей (новые/старые), конверсия в первую покупку, конверсия в повторные покупки (C2+), средний чек (АМПУ/МППУ), стоимость привлечения (ACAC). Других рычагов нет. (источник → расшифровка, середина)

- **Юнит-экономика — одна из самых простых вещей в индустрии.** Сложность начинается не в самом расчёте, а при попытке извлечь данные из реальной аналитики. (источник → расшифровка)

- **Когортное мышление.** Как только появляется образ «я запускаю когорту — это треугольник, который влияет на действия людей завтра и послезавтра», мышление кардинально меняется. Вместо усреднённых моделей — когортные прогнозы. (источник → расшифровка)

- **Старые клиенты — предсказуемый доход.** Даже если полностью обрубить рекламу, когорты старых клиентов будут приносить доход. Это знание позволяет прогнозировать минимальный доход в будущем. (источник → расшифровка, кейс интернет-магазина обуви)

- **Оценка инвестиций в бренд.** Инвестиции в бренд практически невозможно оценить количественно — это «вопрос веры». Брендовые запросы в поисковиках — оцениваемы (через юнит-экономику по сегменту), телевизионная реклама — нет. (источник → расшифровка)

- **Retention ≠ повторные покупки.** Это принципиально разные метрики с разными математическими моделями. В B2B один человек платит, другой заходит в сервис — прямой связи нет. Retention может ограничивать конверсию в повторные покупки сверху, но прямой математической связи нет. (источник → расшифровка, финал)

- **Churn rate — некогортная метрика.** «Это альтернативный метод [прогноза] чарнрейта, его практически нет в паблику. Он гораздо более мощный, чем чарнрейт через чарнрейт». Формула 1/churn = LTV верна лишь для специального частного случая. (источник → расшифровка)

- **Сегментация по цене — двойной рычаг.** Одновременно повышает МППУ (за счёт премиум-тарифа) и конверсию (за счёт скидки для более дешёвого сегмента). Единственное управленческое решение, влияющее сразу на два параметра. (источник → расшифровка, последний кейс B2B)

- **Экспериментирование с ценой.** Нельзя подобрать цену «из головы». Единственный метод — A/B-тест (или последовательное изменение на отдельном городе/регионе). Максимизируется АМПУ при изменении цены, не выручка. (источник → расшифровка)

## 2. Точные определения

- **АМПУ (AMPU)** — прибыль с одного пользователя (Average Margin Per User); формула: разница доходов и расходов на одного пользователя. (источник → расшифровка)

- **МППУ (MPPU)** — margin per paying user; прибыль с одного платящего пользователя. (источник → расшифровка)

- **Байеры (Buyers/Baers)** — пользователи, у которых было хотя бы одно завершённое платёжное событие (транзакция > 0). Наиболее достоверная цифра для кросс-чека. (источник → расшифровка)

- **Когорта** — группа пользователей, объединённых по дате первого события (первая сессия, первая заявка, первая покупка). «Треугольник». Бывают три типа: маркетинговые (дата первой сессии), коммерческие (дата первой заявки/триала), финансовые (дата первой оплаты). (источник → расшифровка)

- **C23 (конверсия второй покупки)** — доля покупателей когорты, совершивших покупку на второй месяц жизни когорты. Считается относительно предыдущего месяца (для финансовых когорт) или абсолютно от основания когорты (для retention). (источник → расшифровка)

- **Retention** — возвращаемость пользователей в продукт; всегда считается как абсолютная конверсия от основания когорты. Влияет на MAU и на наличие Product-Market Fit, но НЕ является прямым предиктором повторных покупок. (источник → расшифровка)

- **MAU (Monthly Active Users)** — число пользователей, которые зашли в продукт за месяц. «Тупо число польз в месяц». (источник → расшифровка)

- **Сэмплирование** — ситуация, когда система аналитики считает не по 100% данных, а по выборке. В Google Analytics при большом объёме данных (много сессий за 30 дней) процент сэмплирования может падать до 48%, что вносит погрешность в расчёты. (источник → расшифровка)

- **Рекламная модель (монетизация через рекламу)** — АМПУ = CPM × (показы на пользователя / 1000). CPM — cost per mille (стоимость за 1000 показов). Retention напрямую влияет на рекламную модель: больше возвратов = больше показов = больше дохода. (источник → расшифровка)

- **Smile Effect** — нетипичный вид графика retention: сначала падает, потом растёт. Примеры: Dropbox, Evernote, Facebook. В этом случае полином-экстраполяция не применима. (источник → расшифровка)

- **Break-even** — момент, когда ежемесячный Gross Profit превышает ежемесячные фиксированные косты. (источник → расшифровка, финальный кейс B2B)

## 3. ФОРМУЛЫ

**Основная формула юнит-экономики (из расшифровки):**

```
АМПУ = (Доход с одного пользователя) - (Расходы на одного пользователя)
```

**Стоимость привлечения:**

```
CAC (Customer Acquisition Cost) = Расходы на маркетинг / Число новых байеров
```

**АМПУ через конверсию и средний чек:**

```
АМПУ = Конверсия × ППУ (прибыль с покупателя)
ППУ = Средний чек - COGS (на покупателя)
```

**Конверсия (правильная — по пользователям, не по сессиям):**

```
Конверсия = Число покупателей / Число пользователей
```

(НЕ: число транзакций / число сессий — это систематическая ошибка измерения)

**Прогноз MAU через retention (полиномиальная экстраполяция):**

```
Retention(месяц X) = Retention(месяц 1) × X^(-степень)
```

Где степень подбирается «на научный глаз» по первым 3 известным значениям retention, чтобы формула совпадала с ними. Чаще всего степень ≈ -1 (чистая гиперболическая функция 1/X), но бывает -1,5 и другие.

```
MAU(месяц N) = Новые пользователи × Мультипликатор(N)
Мультипликатор(N) = 1 + сумма Retention(месяц 1..N-1)
```

Мультипликатор стремится к асимптоте. (источник → расшифровка, кейс 5)

**Когорта: расчёт строки «до основания когорты» (старые клиенты):**

```
Число_Старых = Число_Всех - Число_Новых
```

Ключевой кросс-чек: сумма строки старых клиентов за ноябрь должна равняться соответствующей ячейке в P&L-табличке.

**Финансовая когорта (расчёт удержания относительно предыдущего месяца):**

```
Байеры(месяц M+1, когорта K) = Байеры(месяц M, когорта K) × C(M→M+1)
```

Аналогично для денег (Revenue):

```
Revenue(месяц M+1, когорта K) = Revenue(месяц M, когорта K) × C_revenue(M→M+1)
```

Важно: конверсия удержания по байерам и по деньгам — разные числа. (источник → расшифровка)

**LTV через Gross Profit когорты:**

```
LTV (когорты) = Сумма Gross Profit за время жизни когорты / Число байеров основания когорты
```

**Рекламная модель:**

```
ARPU = CPM × (Показы на пользователя / 1000)
Gross Profit = MAU × ARPU × Маржинальность
```

(источник → расшифровка)

## 4. Пошаговые процедуры / алгоритмы

### Алгоритм извлечения метрик из Google Analytics для юнит-экономики

1. Получить от аналитика (или сделать самостоятельно) **два ключевых запроса** к GA:
   - Запрос A: все пользователи за период с разбивкой по дате — `users`, `new_users`, `transactions`, `revenue`, `dimension4` (идентификатор пользователя/сессии), `session_count`.
   - Запрос B: то же самое, но с фильтром «первая сессия в этом периоде» (`session_count = 1`), для выделения новых байеров.
2. **Проверить на сэмплирование**: сравнить число пользователей с/без сэмплирования. Если расхождение > 5%, работать с несэмплированными данными.
3. Рассчитать **старых пользователей через вычитание**: `Старые = Все - Новые`. НЕ запрашивать «старых» отдельным сложным запросом — там чаще всего ошибки.
4. **Верить только зелёным ячейкам**: байеры (уникальное число людей с транзакцией > 0) и транзакции/выручка из базы — это достоверно. Конверсии и средний чек — рассчитываются, им не доверять напрямую.
5. **Кросс-чек**: `Выручка = Байеры × Средний чек`. Если не сходится — аналитик ошибся в запросе. Обычно 2–3 попытки до правильного результата.
6. Для работы без сэмплирования: выгрузить **исходные данные построчно** (каждая строка — одна транзакция: идентификатор пользователя + дата первой сессии + дата транзакции + сумма). (источник → расшифровка)

### Алгоритм построения когортной таблицы (треугольник)

1. Подготовить данные: таблица вида `[UserID | дата первой сессии (основание когорты) | дата транзакции | выручка]`.
2. Построить **сводную таблицу** (Google Sheets / Excel): строки = когорта (месяц первой сессии), столбцы = месяц транзакции.
3. Значения ячеек:
   - Байеры: `COUNTUNIQUE(UserID)` по ячейке (когорта, месяц транзакции)
   - Пейменты: `COUNTUNIQUE(TransactionID)` по той же ячейке
   - Выручка: `SUM(Revenue)` по той же ячейке
4. Добавить строку «до основания»: когорты пользователей, первая сессия которых была ДО начала анализируемого периода.
5. **Кросс-чек**: сумма по столбцу (конкретный месяц) = P&L выручка за этот месяц. Если не сходится — ошибка в данных.
6. Рассчитать C23 (конверсию второй покупки): `Байеры(месяц 2) / Байеры(месяц 1)` для каждой когорты. (источник → расшифровка)

### Алгоритм прогнозирования через retention

1. Взять фактические данные retention за первые 3 месяца из системы аналитики: например, 17%, 7%, 3% (доля пользователей, вернувшихся в 1-й, 2-й, 3-й месяц от основания когорты).
2. Подобрать параметр степени полинома «на научный глаз»: `R(x) = R(1) × x^(-a)`. При a = -1 это гиперболическая функция. Подбирать а так, чтобы формула давала ~17, ~7, ~3 при x = 1, 2, 3.
3. Рассчитать retention для последующих месяцев по формуле.
4. Рассчитать мультипликатор MAU: `mult(N) = 1 + R(1) + R(2) + ... + R(N-1)`.
5. `MAU(N) = Новые_пользователи × mult(N)`. Мультипликатор выходит на асимптоту — это и есть устойчивый уровень MAU при постоянном притоке новых пользователей. (источник → расшифровка)

### Алгоритм прогнозирования через финансовую когорту (B2B, рекуррентные платежи)

1. Взять исторические данные конверсии удержания C2 (2-й месяц / 1-й месяц) и C3 (3-й / 2-й) за 3–4 месяца.
2. Будущие когорты рассчитывать через относительную конверсию: `Байеры(M+1) = Байеры(M) × C(M→M+1)`.
3. Аналогично для Revenue: `Revenue(M+1) = Revenue(M) × C_rev(M→M+1)`. Конверсия по деньгам и по байерам — разные числа (особенно при рекуррентных платежах с разными тарифами).
4. Суммировать Gross Profit всех когорт по каждому месяцу.
5. Сравнить Gross Profit с фиксированными костами — найти точку break-even.
6. Подбирать число новых пользователей и МППУ (через сегментацию по цене), чтобы выйти на целевой Gross Profit. (источник → расшифровка)

## 5. Фреймворки / модели

### Три типа когорт (три типа вопросов)

| Тип когорты | Основание | Вопрос, на который отвечает |
|---|---|---|
| Маркетинговая | Дата первой сессии | Сходится ли экономика привлечения когорты? |
| Коммерческая | Дата первой заявки/триала | Какой цикл сделки? Точки кратного роста в воронке? |
| Финансовая | Дата первой оплаты | Каков прогноз по финансам? Выйдем ли в плюс? |

(источник → расшифровка)

### Иерархия доверия цифрам из аналитики

1. **Верим**: байеры (уникальные пользователи с транзакцией), транзакции (уникальный ID), выручка из базы данных — «зелёные» ячейки.
2. **Не верим**: конверсии (особенно по сессиям), средний чек из готового отчёта, retention из сложных SQL-запросов аналитика.
3. **Считаем сами**: конверсию (байеры / пользователи), средний чек (выручка / байеры), старых пользователей (все - новые).

(источник → расшифровка)

### Рекламная vs. транзакционная модель монетизации

- **Транзакционная**: АМПУ = Конверсия × (Средний чек - COGS). Retention влияет косвенно (через повторные покупки).
- **Рекламная**: ARPU = CPM × (показы / 1000). Retention влияет ПРЯМО и сильно — каждый возврат пользователя = новые показы рекламы. Именно поэтому рекламные сайты «утыканы баннерами».

(источник → расшифровка)

## 6. Разобранные примеры / кейсы / цифры

### Кейс 1: Интернет-магазин обуви (маркетинговые когорты)

- Продукт на рынке 10 лет. Половина дохода — от старых клиентов (когорты 2–10-летней давности).
- C23 (конверсия второй покупки) = ~3%. Интерпретация: 97% покупателей не возвращаются на следующий месяц (низкочастотный сценарий — обувь).
- Единственная когорта, которая «сошлась» = ноябрь (Чёрная пятница). Все остальные месяцы — отрицательный юнит.
- Вывод: бизнес жил за счёт накопленных старых когорт. Новые инвестиции в маркетинг — нецелесообразны до повышения конверсии.
- После расчёта когорт: подняли конверсию с ~1% до ~3%. (источник → расшифровка, кейс интернет-магазина)

### Кейс 2: Турбодилер (B2C, тарифные планы)

- Три тарифных плана: 190 руб. (конверсия 0,8%), 490 руб. (1,3%), 1990 руб. (0,3%).
- АМПУ по тарифам: 0,9 руб. / 5,7 руб. / 1899 - COGS руб.
- Попытка повысить цену самого дешёвого тарифа на 100 руб.: конверсия упала на 0,2 п.п. (с 0,8% до 0,6%), АМПУ выросла с 0,9 до 1,4.
- Ещё +200 руб.: АМПУ = 1,1 руб. — невыгодно.
- Вывод: оптимальная цена ищётся экспериментально (A/B-тест или последовательное изменение на одном городе). Срок эксперимента при малых конверсиях — до полугода. (источник → расшифровка)

### Кейс 3: Платные/бесплатные пользователи (freemium, Артём)

- 10 000 пользователей на входе. 1% стал платными (100 чел.), 90% — бесплатными (9 000 чел.).
- Бесплатные пользователи имеют отрицательное АМПУ (расходы на серверы > 0 доходов).
- Решение: в модели две строки — отдельно платные, отдельно бесплатные, каждая со своим АМПУ. Суммируются для итогового АМПУ. (источник → расшифровка)

### Кейс 4: Сэмплирование GA

- Ноябрь 2017 года, интернет-магазин.
- Новые байеры с сэмплированием (48% данных): 2 590 чел. Без сэмплирования: 2 660 чел.
- Конверсия с сэмплированием: 0,9%. Без сэмплирования: 1,1%.
- АМПУ: 20 руб. vs. 23 руб. — расхождение значимое.
- Вывод: при возможности считать без сэмплирования — всегда считать без сэмплирования. Для когортного анализа — выгружать исходные данные построчно. (источник → расшифровка)

### Кейс 5: B2B, прогноз через финансовые когорты (инструмент для создания сайтов)

- Исходные данные: 6 месяцев истории, рекуррентные платежи.
- C2 (удержание байеров на 2-й месяц): ~60–72%.
- C3 (удержание на 3-й месяц): ~79–89%.
- Конверсия удержания по деньгам — выше, чем по байерам (т.к. более дорогие клиенты лучше удерживаются).
- Начальные инвестиции: 1 млн долл. Ежемесячные фиксированные косты: 300 тыс. долл. Стартовый Gross Profit: ~62 тыс. долл.
- Без изменений: компания сжигает деньги, runway = 4 месяца.
- После сегментации по цене (подняли цену для enterprise-сегмента, ввели скидку для малого бизнеса): МППУ выросло. После повышения конверсии в новых когортах — Gross Profit превысил 300 тыс. долл. Достигнут break-even с остатком ~5 тыс. долл. (источник → расшифровка, финальный кейс)

### Кейс 6: Retention-мультипликатор для рекламной модели

- Retention: 17% (мес. 1), 7% (мес. 2), 3% (мес. 3) → экстраполяция по полиному.
- Мультипликатор MAU на 11–12-й месяц: 1,51.
- Интерпретация: если привлекать 100 тыс. новых пользователей в месяц, через год стабильный MAU ≈ 151 тыс.
- CPM = 5 долл. / 40 показов на пользователя → ARPU = 2 цента/мес.
- Вывод: для выхода на 1–2 млн MAU нужно или увеличить число новых пользователей, или поднять ARPU. (источник → расшифровка)

## 8. Схемы / диаграммы

*Источник содержит расшифровку видео. Диаграммы описаны словесно:*

**Когортный треугольник:** Таблица, где строки — месяцы прихода первых пользователей (основание когорты), столбцы — месяцы совершения транзакций. Каждая диагональ — «возраст» когорты в месяцах.

**График retention (единица / X):** Гиперболическая кривая, быстро падающая от 100% (месяц 0) к асимптоте около 0%. Формула: `R(x) = R(1) × x^(-a)`.

**Smile effect:** Нетипичный график retention — сначала падение, потом рост. Полином неприменим.

**Runway-диаграмма:** Ежемесячный Gross Profit растёт, фиксированные косты горизонтальны. Перекрёсток = break-even. До перекрёстка инвестиционные деньги «сгорают».

## 9. Важные цитаты

- «Фича в большинстве случаев это тупый генератор дополнительной работы, она не уменьшает объём работы джобы, она увеличивает объём джоба.» (источник → расшифровка, начало)

- «Люди, которые начали думать когортами принципиально отличаются в продуктовом мире от людей, которые когортами думать не начали.» (источник → расшифровка)

- «Если мы сейчас делаем так, что мои пользы в банковском клиенте смогут с конверсией на 10% выше выбрать тарифный план, то итоговая конверсия вырастет на 1% пункт.» (источник → расшифровка)

- «Юнит-экономику посчитать просто. Помните, я вам говорил, что юнит-экономика одна из самых простых, что это есть в индустрии, а вот дальше мы начинаем использовать реальную проблему.» (источник → расшифровка)

- «Это альтернативный метод чарнрейта, его практически нет в паблику, в публичных источниках. Вы очень мало где его найдёте, но он гораздо более мощный, чем чарнрейт через чарнрейт.» (источник → расшифровка)

- «Retention может ограничивать сверху конверсию второй покупки, но не более чем. Прямой связи нет.» (источник → расшифровка)

- «Нам очень нравятся старые клиенты, потому что мы легко по ним прогнозируем будущий доход. То есть мы знаем, что даже если мы полностью обрубим рекламу или сильно её обрубим, вот этот доход мы скорее всего получим.» (источник → расшифровка)

## 10. Термины в глоссарий

| Термин | Краткое пояснение |
|---|---|
| Сэмплирование | Расчёт GA на части данных, а не на 100%; вносит погрешность |
| Байер (Buyer/Baer) | Пользователь с хотя бы одной завершённой транзакцией |
| Пеймент (Payment) | Транзакция; один байер может иметь несколько пейментов |
| Когорта | Группа пользователей, объединённых датой первого ключевого события |
| C23 | Конверсия из 2-го в 3-й месяц жизни когорты |
| MAU | Monthly Active Users — месячная аудитория |
| Retention | Возвращаемость пользователей; считается абсолютно от основания когорты |
| Smile effect | Нетипичная форма графика retention (U-образная) |
| Мультипликатор MAU | Коэффициент, во сколько раз MAU > числа новых пользователей при стабильном притоке |
| Break-even | Точка, где Gross Profit = фиксированные косты |
| Runway | Число месяцев до исчерпания инвестиций |
| Полином (экстраполяция) | Метод предсказания retention по первым 3 точкам через функцию вида `R(1) × X^(-a)` |
| ARPU | Average Revenue Per User — средний доход с пользователя |
| CPM | Cost Per Mille — стоимость 1000 показов рекламы |
| Сегментация по цене | Введение нескольких тарифов для разных сегментов; повышает одновременно конверсию и средний чек |

## 11. Типичные ошибки / антипаттерны

1. **Считать конверсию по сессиям, а не по пользователям.** Google Analytics по умолчанию считает конверсию по сессиям — это «недоразумение». В GA4 наконец появились конверсии по пользователям. Все AB-тест-инструменты, считающие по сессиям, дают систематическую ошибку. (источник → расшифровка)

2. **Доверять одной системе аналитики.** «Вам всегда нужно минимум 2, минимум 2.» Разные системы дают разные цифры из-за проблем трекинга, сэмплирования, багов. (источник → расшифровка)

3. **Считать средний чек из агрегированного запроса.** Правильно: `Выручка / Байеры` — отдельными запросами, потом делим. Прямой запрос среднего чека через SQL часто даёт ошибку из-за условий фильтрации. (источник → расшифровка)

4. **Делать один сложный запрос для всего** (новые + старые + когорта + конверсия). Аналитики ошибаются в 9 из 10 случаев. Лучше простые запросы + операция вычитания для старых пользователей. (источник → расшифровка)

5. **Считать юнит-экономику за один месяц.** Полноценная юнит-экономика считается по всем месяцам через когорты. Один удачный месяц (например, ноябрь/Чёрная пятница) создаёт иллюзию сходимости. (источник → расшифровка)

6. **Приравнивать retention к повторным покупкам.** «Массовое заблуждение здесь есть, а прямой связи нет» — особенно в B2B, при автопродлениях, при низкочастотных покупках. (источник → расшифровка)

7. **Применять формулу LTV = 1/churn.** «Это вранье. Это специальный кейс» — работает только при экспоненциальном отмирании когорты с постоянным churn rate. На практике retention описывается степенной функцией. (источник → расшифровка)

8. **Запрашивать данные без кросс-чеков.** Аналитик ошибается почти всегда. Метод решения: выгрузить исходные данные и самостоятельно пересчитать когорту через сводную таблицу; расхождение = индикатор ошибки в запросе. (источник → расшифровка)

9. **Игнорировать строку «до основания» в когортной таблице.** В 95% когортных отчётов её нет. Без неё сумма по столбцу не совпадёт с P&L, и кросс-чек невозможен. (источник → расшифровка)

10. **Задавать сложные формулы retention/LTV вместо подбора «на глаз».** «Чем сложнее формулы, тем больше ошибок. Я очень простые старые формулы использую.» Параметр степени полинома быстрее и надёжнее подбирается визуально по 3 точкам. (источник → расшифровка)
