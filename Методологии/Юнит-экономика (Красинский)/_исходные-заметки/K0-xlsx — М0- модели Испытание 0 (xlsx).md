## 1. Концепции и идеи

- Главная задача модуля 0 — освоить базовые метрики юнит-экономики через три практических кейса («подвига») на разных бизнес-моделях: подписочный музыкальный сервис, интернет-магазин, hot wi-fi B2B. (источник → файл 1, листы 1–3)
- Экономика считается на 1 месяц жизни когорты И на 12 месяцев (или «за время жизни когорты»), чтобы увидеть, как AMPPU и AMPU меняются с ростом Av. Payment Count. (источник → файл 1, лист «подвиг 1», строки 13–14)
- Ключевой вопрос сходимости экономики: AMPU > CPUser и Profit > 0. (источник → файл 1, лист «подвиг 1», строка 20)
- В интернет-магазине organic + paid разделяются — нельзя механически суммировать Users по каналам, так как один пользователь мог прийти через оба канала; Buyers тоже нельзя складывать в общем случае (в этом кейсе пренебрегаем). (источник → файл 1, лист «подвиг 2», строка 17)
- Hot wi-fi — кейс с издержкой на первой продаже: AMPPU в месяц 1 отрицателен (−3000 при цене 3000), окупаемость наступает с 3-й оплаты. Задача — показать инвестору, что экономика сходится, но не сразу. (источник → файл 1, лист «подвиг 3», строки 7–17; файл 2, строки 31–35)
- Финансовые метрики рекомендуется считать справа налево: COGS total → Acq Costs → Gross Profit → Revenue → Profit. (источник → файл 1, лист «подвиг 2», строка 25)
- Дополнительный раздел в файле ведущего: «Сколько стоят наши идеи-гипотезы» — сравнение стартап vs корпорация по стоимости одной гипотезы при команде 1 и 10 человек. (источник → файл 2, строки 49–56)

## 2. Точные определения

- **AMPPU (or CLTV)** — маржа на 1-го платящего (Average Margin Per Paying User / Customer Lifetime Value). (источник → файл 1, все листы, строка 3 / столбец J)
- **AMPU (or LTV)** — маржа на 1-го привлечённого пользователя (Average Margin Per User). (источник → файл 1, все листы, строка 3 / столбец U)
- **CPUser (or CPLead)** — стоимость привлечения пользователя (Cost Per User / Lead). (источник → файл 1, все листы, столбец T)
- **CAC (Customer Acquisition Costs)** — стоимость платящего (столбец Q). (источник → файл 1, все листы, строка 3)
- **CPO / SPS (Cost per Order, Cost per Sale)** — стоимость заказа / оплаты (столбец R). (источник → файл 1, все листы, строка 3)
- **C1 (conv to buyer)** — конверсия в нового покупателя (столбец F). (источник → файл 1, все листы, строка 3)
- **Av. Payment Count (or LifeTime)** — среднее число оплат на 1-го платящего / период жизни клиента (столбец P). (источник → файл 1, все листы, строка 3)
- **COGS (Cost of Goods Sold)** — издержки на каждой продаже (столбец M). (источник → файл 1, все листы, строка 3)
- **COGS 1st sale** — издержка на первой продаже, отдельно от повторных (столбец O). (источник → файл 1, лист «подвиг 3»; файл 2)
- **Gross Profit** — доход с потока пользователей (= Revenue − COGS total; столбец AA). (источник → файл 1, все листы, строка 3)
- **Profit** — прибыль с потока пользователей (= Gross Profit − Acq. Costs; столбец Y). (источник → файл 1, все листы, строка 3)
- **Profit net** — чистая прибыль с потока пользователей (= Profit − Fix Costs; столбец X). (источник → файл 1, все листы, строка 3)
- **Fix Costs** — расходы в месяц, ограниченные сверху (зарплаты, аренда офиса, серверы; столбец AD). (источник → файл 2, строка 2)
- **Acq. Costs (до продажи)** — расходы на привлечение пользователей, в т.ч. зп продажников (столбец AB). (источник → файл 2, строка 2)
- **Кросс-чек** — контрольная строка: разница двух способов расчёта одних и тех же финансовых метрик должна быть = 0. (источник → файл 1, все листы; файл 2, строки 15/27/37)

### Два способа расчёта финансовых метрик (кросс-проверка)
- Способ 1: от Users × (AMPU − CPUser) = Profit; от C × AMPU = Gross Profit
- Способ 2: от Payments × AvPrice = Revenue; Revenue − COGS total = Gross Profit; Revenue − COGS total − Acq. Costs = Profit
- Кросс-чек = разность двух способов, должна быть = 0.
(источник → файл 1, все листы; файл 2)

## 10. Термины в глоссарий

- **AMPPU** — Average Margin Per Paying User (= CLTV в нотации Красинского)
- **AMPU** — Average Margin Per User (= LTV в нотации Красинского)
- **CPUser / CPLead** — стоимость привлечения пользователя / лида
- **CAC** — стоимость привлечения платящего (Customer Acquisition Costs)
- **CPO / SPS** — стоимость заказа / продажи (Cost per Order / Cost per Sale)
- **C1** — конверсия в первую покупку (conv to buyer)
- **Av. Payment Count / LifeTime** — среднее число оплат на платящего / период жизни
- **COGS 1st sale** — издержка на первой продаже (специфично для моделей с разовыми установочными затратами)
- **Gross Profit** — доход с потока пользователей за вычетом COGS (= Revenue − COGS total)
- **Profit net** — чистая прибыль (= Profit − Fix Costs)
- **Кросс-чек** — контрольная проверка двумя независимыми способами расчёта

## 11. Типичные ошибки / антипаттерны

- [факт из материала] Нельзя суммировать Users по каналам — один пользователь может приходить через несколько каналов. (источник → файл 1, лист «подвиг 2», строка 17)
- [факт из материала] Нельзя в общем случае складывать Buyers по каналам. (там же)
- [факт из материала] При масштабировании убыточной юнит-экономики убыток растёт кратно: Users ×3 → Profit не улучшается, а ухудшается пропорционально. (источник → файл 2, строка 9: масштабируемся с Users 100 000→300 000, Profit −1 940 000→−8 820 000)
- [факт из материала] Не считать финансовые метрики «слева направо» (от Users к Profit) без проверки кросс-чеком двумя способами. (источник → файл 1, все листы, блок кросс-чеков)
- [факт из материала] Для бизнес-моделей с издержкой на первой продаже (hot wi-fi) не применять стандартную формулу AMPPU = K×L×P — нужна модификация с вычитанием COGS 1st sale: `=K*P-O`. (источник → файл 1, лист «подвиг 3»; файл 2)
