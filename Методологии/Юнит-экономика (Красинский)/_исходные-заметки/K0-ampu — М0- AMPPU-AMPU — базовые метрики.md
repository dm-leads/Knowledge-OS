## 1. Концепции и идеи

- Юнит-экономика — инструмент системного взгляда на бизнес: «все бизнесы устроены одинаково» — вход-поток пользователей, выход-поток денег. (источник → транскрипт, ~60 000–68 000 симв.)
- Курс посвящён двум слоям: **экономика денег** (испытания 0–4) и **экономика внимания** (испытания 5–9). Продуктовые метрики управляют экономическими. (источник → транскрипт, ~20 000 симв.)
- **Навык, а не знание** — цель курса. Формулы должны «вылетать из-под пальцев, не включая голову». (источник → транскрипт, ~13 000 симв.)
- **Одна гипотеза обходится ~7–12 млн руб.** при команде 10 чел. × 0,5 млн руб./чел. и скорости ~2–4 гипотезы/мес; срабатывает 1 из 10 → стоимость успешной гипотезы ≈ 10 млн руб. (источник → транскрипт, ~35 000–40 000 симв.)
- **Масштабируемые vs фиксированные издержки** — ключевое различие проектного и продуктового бизнеса. Доходы продуктового бизнеса могут расти экспоненциально; расходы на команду ограничены сверху. (источник → транскрипт, ~55 000–58 000 симв.)
- Платные каналы часто убыточны; органика «условно бесплатна» и требует 6+ мес. для раскачки. (источник → транскрипт, ~91 000 симв.)
- Фреймворки нужны не все — «нам нужно юит (job) своё делать, но некоторые фреймворки полезны». (источник → транскрипт, ~31 000 симв.)
- Кейс авиакомпании: **всегда получаешь то, что измеряешь** — если цель «поднять конверсию», в отчёте увидишь только конверсию, а сегментация по новым/старым пользователям и по устройствам может показать обратное. (источник → транскрипт, ~43 000–52 000 симв.)
- **Управляемый кассовый разрыв** — из ~30–50 команд, пробовавших в РФ, справились единицы; пример: Callback Hunter продан за 6 млн руб. (источник → транскрипт, ~105 000 симв.)

## 2. Точные определения

- **Юнит** — то, что масштабируется в данной бизнес-модели: терминал (Qiwi), салон (сеть связи), комната (отель), платящий пользователь/клиент (B2C/B2B продукт). (источник → транскрипт, ~50 000–51 000 симв.)
- **COGS (Cost of Goods Sold) / Костов Гудсолд** — стоимость проданных товаров; включает издержки на каждую продажу (упаковка, доставка, себестоимость, комиссия платёжных систем) и издержки на первую продажу (пример: роутер + премия продавца). (источник → транскрипт, ~56 000–59 000 симв.)
- **Acquisition Cost (CAC / Cost per User / CPA)** — расходы на привлечение: контекстная реклама, таргет, реферальные программы, сети CPA. (источник → транскрипт, ~57 000–60 000 симв.)
- **Gross Profit (Валовая прибыль / Gross Margin)** — выручка минус COGS; «маржа на потоке пользователей». Примечание автора: в российской бухгалтерии называется «Валовая прибыль», не «Валовая выручка». (источник → транскрипт, ~62 000 симв.)
- **AMPPU (Average Margin Per Payment User)** — средняя прибыль на платящего пользователя за lifetime; зависит от среднего чека, числа повторных покупок и маржинальности. (источник → транскрипт, ~64 000–66 000 симв.)
- **AMPU (Average Margin Per User)** — средняя прибыль на привлечённого пользователя; AMPPU × конверсия в первую покупку. (источник → транскрипт, ~66 000–67 000 симв.)
- **LTV (Lifetime Value)** — прибыль с пользователя за всё время жизни; равно AMPU по смыслу (автор использует оба термина взаимозаменяемо). (источник → транскрипт, ~82 000 симв.)
- **Кросс-чек** — проверка: расчёт одной метрики двумя разными способами должен давать одинаковый результат (разница = 0). Позволяет убедиться в отсутствии ошибок округления и формул. (источник → транскрипт, ~97 000 симв.)
- **Техдолг** — накопленные ошибки/нерефакторированный код; чем больше техдолг, тем ниже скорость проверки гипотез. (источник → транскрипт, ~42 000 симв.)
- **Разработка** — «расходящийся процесс», в результате которого сроки увеличиваются в 2–3 раза, цена растёт в 2 раза, итог содержит баги. (источник → транскрипт, ~40 000 симв.)
- **Confirmation bias** — склонность подтверждать текущую модель мира, а не пересматривать её; «первый враг» правильного счёта. (источник → транскрипт, ~12 000 симв.)
- **Survivor's bias (Систематическая ошибка выжившего)** — работа не со всей совокупностью данных, а с частью, которую проще собрать. (источник → транскрипт, ~12 000 симв.)

## 3. Формулы

Все формулы даны дословно по логике транскрипта (педагогический разбор):

**AMPPU:**
```
AMPPU = Average Check × Average Payment Count × Margin%
```
(источник → транскрипт, ~64 000 симв.)

**AMPU через конверсию:**
```
AMPU = Conversion × AMPPU
```
(источник → транскрипт, ~66 000–67 000 симв.)

**Gross Profit (два эквивалентных способа):**
```
Gross Profit = Buyers × AMPPU
Gross Profit = Users × AMPU
```
(источник → транскрипт, ~67 000–68 000 симв.)

**Cost per User:**
```
Cost per User = Acquisition Spend / Users
```
(источник → транскрипт, ~93 000 симв.)

**Profit per User (сходимость по привлечённому пользователю):**
```
Profit per User = AMPU – Cost per User
               = Conversion × AMPPU – Cost per User
```
(источник → транскрипт, ~90 000–93 000 симв.)

**Пример: музыкальный сервис (вводный кейс):**
```
Avg Check = 200 руб., Margin% = 30%, APC = 3
  AMPPU = 200 × 3 × 0,30 = 180 руб.
  AMPU (при Conv=1%) = 0,01 × 180 = 1,8 руб.
  Cost per User = 20 руб.
  Profit per User = 1,8 – 20 = –18,2 руб.   (убыток)
При Conv=5%, APC=7:
  AMPPU = 200 × 7 × 0,30 = 420 руб.
  AMPU = 0,05 × 420 = 21 руб.
  Profit per User = 21 – 20 = +1 руб.   (точка безубыточности)
```
(источник → транскрипт, ~80 000–87 000 симв.)

**Пример: интернет-магазин (платный канал):**
```
Avg Check = 4 800 руб., COGS = 3 500 руб., APC = 3 (1 + 2 повт.)
  AMPPU = (4 800 – 3 500) × 3 = 3 900 руб.  (упрощённо)
  AMPU ≈ 6,1–6,6 руб.  (по данным кейса)
  Cost per User = 13,3–15 руб.
  Profit per User ≈ –7 руб.   (убыток по платному каналу)
```
(источник → транскрипт, ~93 000–96 000 симв.)

## 4. Пошаговые процедуры / алгоритмы

**Как посчитать юнит-экономику «закрытую» (без внутренних данных):**
1. Зайти в приложение/сайт, посмотреть тарифы → взять средний чек.
2. Маржинальность — из общения в индустрии (конференции, тусовки, бывшие сотрудники).
3. Конверсия: если не знаешь — ставь 1% как точку отсчёта.
4. Повторные покупки: предположи, затем валидируй через когорты (Испытание 5).
5. CAC: из рекламных кабинетов или оценочно по ставкам конкурентов.
6. Посчитать: AMPPU → AMPU → Profit per User → Gross Profit.
(источник → транскрипт, ~76 000–82 000 симв.)

**Алгоритм факторного анализа (кейс авиакомпании):**
1. Смотрим суммарную конверсию — замечаем рост.
2. Разбиваем по сегментам: новые vs старые пользователи → у новых упала, у старых выросла.
3. Разбиваем по устройствам: мобайл vs десктоп → упала на Android (баги).
4. Ищем внешние факторы: рассылки, акции параллельных команд.
5. Делаем вывод о причине (не откатывать систему, а фиксить баги на дешёвых Android).
(источник → транскрипт, ~45 000–52 000 симв.)

## 5. Фреймворки / модели

**Дерево метрик юнит-экономики:**
```
Пользователи (Users)
    │
    ├── × Конверсия → Покупатели (Buyers)
    │       └── × APC → Платежи (Payments)
    │               └── × Средний чек → Выручка (Revenue)
    │                       └── × Маржинальность → Gross Profit
    │
    ├── AMPU = Conversion × AMPPU
    └── Gross Profit = Users × AMPU  =  Buyers × AMPPU
```
(источник → транскрипт, ~60 000–68 000 симв.)

**Структура издержек:**
```
Масштабируемые (переменные):
  - COGS на каждую продажу: упаковка, доставка, себестоимость, комиссии
  - COGS на первую продажу: премия, пробный период, роутер при подключении
  - Acquisition Costs: контекст, таргет, CPA-сети

Фиксированные (ограничены сверху):
  - Зарплаты ключевой команды (разработчики, дизайнеры, PM)
  - Аренда, серверы (если не зависят от числа пользователей кратно)

Ловушка: расходы на преподавателей (edtech) и операционных менеджеров
         масштабируются → это переменные, не фикс.
```
(источник → транскрипт, ~55 000–62 000 симв.)

**Три уровня сходимости юнит-экономики:**
1. По привлечённым пользователям: AMPU > Cost per User.
2. По платящим пользователям: AMPPU > 0.
3. Финансовая сходимость: суммарная выручка > суммарных расходов (включая фикс).
(источник → транскрипт, ~91 000–93 000 симв.)

**Юниты по бизнес-моделям:**
| Бизнес-модель | Юнит |
|---|---|
| Qiwi-терминал | Терминал |
| Салон связи | Салон |
| Отель | Комната |
| Завод | Единица продукции |
| B2C digital-продукт | Платящий пользователь |
| B2B продукт | Платящий клиент |
| Агентство/разработка | Проект (не масштабируется экспоненциально) |
(источник → транскрипт, ~50 000–53 000 симв.)

## 6. Разобранные примеры / кейсы / цифры

- AMPPU ≈ 180 руб.; AMPU ≈ 1,8 руб.; Profit per User = **–18,2 руб.**
- Вывод: сервис нужен экосистеме, сам по себе низкомаржинален.
(источник → транскрипт, ~78 000–87 000 симв.)

**Кейс: Интернет-магазин (условные цифры)**
- Users: 600 000 (450 тыс. органика + 150 тыс. платный)
- Avg Check платный: ~4 800 руб.; COGS: ~3 500 руб.; APC: 3; CAC платный: ~13–15 руб.
- AMPU платный ≈ 6,1–6,6 руб.; Profit per User ≈ **–7 руб.**
- Органика держит среднее в плюсе; при добавлении 50 тыс. платных → убыток растёт.
(источник → транскрипт, ~89 000–98 000 симв.)

**Кейс: Роутер / COGS на первую продажу**
- COGS на первую продажу: роутер 3 000 руб. + премия 3 000 руб. = 6 000 руб.
- Экономика сходится только с 3-й покупки; при масштабировании → кассовый разрыв.
(источник → транскрипт, ~100 000–106 000 симв.)

**Кейс: Авиакомпания (новое веб-бронирование)**
- Трафик: ~4,6 млн чел./мес.; Conv до релиза: ~60%; после по старым: ~67%
- Conv новых: упала 4,3% → 3,2%; мобайл: 4,6% → 2,4% (Android-баги)
- Стоимость билета: ~10 000 руб.; потери: ~40 000 билетов = **~400 млн руб.**
- Стоимость разработки: ~10–20 млн руб. (6 мес. × команда)
(источник → транскрипт, ~43 000–52 000 симв.)

**Оценка стоимости гипотезы:**
- 1 чел. в команде с налогами/соцпакетом: ≥ 500 тыс. руб./мес.
- Команда 10 чел.: 5–10 млн руб./мес.; скорость 2–4 гипотезы/мес.; успешность 1/10
- Стоимость успешной гипотезы: **~7–12 млн руб.**
(источник → транскрипт, ~35 000–38 000 симв.)

## 8. Схемы / диаграммы

(Транскрипт — устный формат; схемы описаны голосом)

1. **Дерево метрик** — иерархия Users → Conversion → Buyers → Payments → Revenue → Gross Profit, с AMPU и AMPPU как агрегированными метриками. (описано выше в разделе 5)
2. **Burndown-диаграмма авиакомпании** — 150 ед. backlog; за 4 нед. срезали ~50 ед.; к 10-й нед. ≠ 0; поставка к 20-й нед. вероятность 19%; майские праздники не учтены; техдолг растёт. (источник → транскрипт, ~39 000–42 000 симв.)
3. **«Камин в виде поезда»** — метафора: красивый паровоз стоит, деньги горят, но «камин не едет». Метафора для команд, генерирующих гипотезы без результата. (источник → транскрипт, ~37 000 симв.)
4. **Кривая Даннинга-Крюгера** — «пик глупости» → «долина разочарования» (на ~4–5 испытании) → «склон просветления». (источник → транскрипт, ~11 000 симв.)
5. **Дерево когортного анализа** (новые/старые × устройства) — одно из самых частотных деревьев; разбивка: новые vs старые → мобайл vs десктоп → iOS vs Android. (источник → транскрипт, ~48 000–51 000 симв.)

## 10. Термины в глоссарий

| Термин | Краткое определение |
|---|---|
| AMPPU | Average Margin Per Payment User — средняя прибыль с платящего пользователя за lifetime |
| AMPU | Average Margin Per User — средняя прибыль с привлечённого пользователя (= Conv × AMPPU) |
| LTV | Lifetime Value — аналог AMPU; прибыль с пользователя за всё время жизни |
| Gross Profit | Валовая прибыль: Выручка – COGS |
| COGS | Cost of Goods Sold — стоимость проданных товаров/услуг (переменные издержки) |
| CAC / Cost per User | Стоимость привлечения одного пользователя |
| Conversion | Конверсия из пользователя в платящего (первая покупка) |
| APC | Average Payment Count — среднее число покупок за lifetime |
| Кросс-чек | Проверка расчёта двумя методами; результат должен быть = 0 |
| Кассовый разрыв | COGS на первую продажу превышает AMPU; масштабирование ведёт к убытку |
| Техдолг | Нерефакторированные решения; снижает скорость проверки гипотез |
| Confirmation bias | Склонность подтверждать текущую модель мира |
| Survivor's bias | Ошибка выжившего — работа только с удобными данными |
| Органика | SEO и прочие условно бесплатные каналы (CAC ≈ 0, требуют 6+ мес. раскачки) |

## 11. Типичные ошибки / антипаттерны

1. **Считать среднее по всем каналам** вместо разбивки органика/платный — маскирует убыток. (источник → транскрипт, ~91 000 симв.)
2. **Ставить одну метрику как цель** (например, «поднять конверсию») без контроля смежных — кейс Сергея. (источник → транскрипт, ~44 000–49 000 симв.)
3. **Не учитывать COGS на первую продажу** — кейс с роутером: экономика сходится с 3-й покупки. (источник → транскрипт, ~100 000–106 000 симв.)
4. **Считать APC = 12** для подписки — реально меньше из-за оттока; нужны когорты (Испытание 5). (источник → транскрипт, ~81 000 симв.)
5. **Округлять без формул** — >80% корп. финансовых документов содержат ошибки округления. (источник → транскрипт, ~93 000 симв.)
6. **Генерировать гипотезы без счёта** — «команды зажигают деньги»; гипотеза должна приносить ≥ 10× стоимости. (источник → транскрипт, ~37 000 симв.)
7. **Верить отчётам P&L без проверки** — отчёты составляются так, как выгодно показать. (источник → транскрипт, ~61 000 симв.)
8. **Путать Users и Buyers** — ошибка в расчёте AMPU vs AMPPU. (источник → транскрипт, ~65 000–67 000 симв.)
