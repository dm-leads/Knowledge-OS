## 1. Концепции и идеи

- **Юнит-экономика как инструмент оценки гипотез.** Цель подвига — не просто посчитать текущую экономику, а научиться быстро оценивать, насколько каждая гипотеза изменит Profit. Метод: скопировать строку с текущей экономикой и подставить в строку гипотезы, поменяв одну метрику. (источник → файл 1, лист «подвиг 1. юнит-экономика», B7–B10)

- **Плечи метрик.** Разные метрики дают разный «рычаг»: изменение одной метрики на X% может давать кратно больший прирост Profit, чем аналогичное изменение другой. Задача — найти текущее «плечо» и следующее «плечо» после его отработки. (источник → файл 3, лист «Экономика», A11)

- **Конверсия очень низкая — есть потенциал роста.** У НДФЛки из 238 706 посетителей покупает 626 — конверсия 0,26%. Даже если 80% нецелевых, это означает огромный потенциал улучшения воронки. (источник → файл 3, лист «Экономика», A6–A7)

- **Доверительный интервал как фильтр гипотез.** Сила гипотезы на конверсию должна быть больше доверительного интервала за неделю (иначе изменение нельзя измерить). Для данного кейса: ДИ за неделю > 0,04%. (источник → файл 1, лист «подвиг 3. генерация гипотез», B6; файл 3, лист «Гипотезы», B6)

- **Скорость оценки гипотез важнее качества оценки.** «Не бойтесь ошибиться, меньше рефлексируйте». Цель после курса — оценивать 50 гипотез за час. (источник → файл 1, лист «подвиг 3», B7)

- **Две оценки в команде — независимо.** Сначала быстрая оценка всеми (метрика + сложность + вера в успех), потом каждый независимо оценивает через юнит-экономику. (источник → файл 1, лист «подвиг 2», B30–B31)

- **Недельная воронка нужна для сравнения ДИ.** Более точный пересчёт месяца в неделю: умножить на 7/31. ДИ за неделю заведомо шире — это важно при выборе гипотез для теста. (источник → файл 1, лист «подвиг 2», B15–B20)

- **Сегментация по размеру вычета даёт разную экономику.** Ведущий разбивает пользователей по сегментам: нулёвки, до 5000 р., 5000–30 000 р., 30 000–100 000 р., 100 000+ р. Разные Av.Price и Conv. → разная AMPPU. (источник → файл 3, лист «Экономика», A29–A34)

- **При одновременном росте чека и падении конверсии Profit может упасть.** Пример ведущего: чек вырос до 1500 р., конверсия упала до 0,15% → Profit 294 883 р. против базовых 84 046 р. (здесь — рост, но сценарий «поднять ср. чек и конверсию упала» показан отдельно). (источник → файл 3, лист «Экономика», A23, r23)

## 2. Точные определения

- **AMPPU (Average Margin Per Paying User)** — маржа на 1-го платящего = Av.Price × Margin × Av.Payment Count = K × (1−COGS%) × P. (источник → файл 1, лист «подвиг 1», J3, формула J15)
- **AMPU (Average Margin Per User)** = AMPPU × C1 (конверсия в покупку). (источник → файл 1, лист «подвиг 1», U3, формула U12)
- **CAC (Customer Acquisition Costs)** — стоимость привлечения платящего = CPUser / C1. (источник → файл 3, лист «Экономика», O3)
- **CPUser** — стоимость привлечения пользователя = Acq.Costs / Users. (источник → файл 1, лист «подвиг 1», T3, формула T12)
- **Доверительный интервал (ДИ)** — статистический диапазон, в котором лежит реальное значение конверсии. Формула: 2σ × √(conv × (1 − conv) / users). (источник → файл 1, лист «подвиг 2», B6, F10)
- **Плечи метрик** — метрика, которая при минимальном изменении даёт максимальный прирост Profit. (источник → файл 3, лист «Экономика», A11)
- **Gross Profit** = Buyers × AMPPU = L × M в таблице гипотез. (источник → файл 1, лист «подвиг 2», N34–N35)
- **Profit** = Users × (AMPU − CPUser) = B × (R − Q) в модели ведущего. (источник → файл 3, лист «Экономика», U5, формула =B5*(R5-Q5))
- **COGS (Cost of Goods Sold)** — издержки на каждой продаже (в % или руб.); COGS 1st sale — издержки только на первой продаже. (источник → файл 1, лист «подвиг 1», M3, O3)

## 3. ФОРМУЛЫ

### Ключевые расчётные формулы (дословно из ячеек):

**Воронка:**
- Конверсия относительная: `=C10/C9` (D10) — отн. конверсия шага от предыдущего (источник → файл 1, лист «подвиг 2»)
- Конверсия абсолютная: `=C10/$C$9` (E10) — конверсия от верхушки воронки (источник → файл 1, лист «подвиг 2»)
- Доверительный интервал: `=2*SQRT(E10*(1-E10)/$C$9)` (F10) — 2 сигмы (источник → файл 1, лист «подвиг 2», B6)
- Альтернатива ДИ (3 сигмы): `=3*SQRT(E56*(1-E56)/B56)` (файл 3, лист «Экономика», F56–F67)
- Пересчёт воронки в неделю: `=C9*7/31` (C23) — более точный способ (источник → файл 1, лист «подвиг 2»)

**AMPPU и связанные:**
- `=K15*(1-M15)*P15` (J15) — AMPPU = Av.Price × (1 − COGS%) × Av.Payment Count (источник → файл 1, лист «подвиг 1»)
- `=J5*K5*N5` (I5, файл 3) — AMPPU = Av.Price × Margin × Av.Payment Count
- Вариант без COGS%: `=K152*P152` — только цена × кол-во оплат
- Вариант с COGS руб.: `=(K153-M153)*P153` — (цена − COGS_руб) × кол-во
- Вариант с COGS на 1-й продаже: `=K154*P154 - O154` — цена × кол-во − COGS_1st
- Комбо: `=(K162-M162)*P162-O162`
- Av.Price: `=Z12/H12` (K12) — Revenue / Payments

**AMPU, CPUser, Profit:**
- `=J12*F12` (U12) — AMPU = AMPPU × C1 (источник → файл 1, лист «подвиг 1»)
- `=AB12/C12` (T12) — CPUser = Acq.Costs / Users
- `=C12*(U12-T12)` (Y12) — Profit = Users × (AMPU − CPUser)
- `=B5*(R5-Q5)` (U5, файл 3) — Profit = Users × (AMPU − CPUser) [обозначения ведущего]

**Финансовые итоги:**
- Revenue: `=K15*H15` (Z15) = Av.Price × Payments
- Gross Profit: `=J15*G15` (AA15) = AMPPU × Buyers
- Acq.Costs: `=T15*C15` (AB15) = CPUser × Users
- COGS_total: `=V5-W5` (Y5, файл 3) = Revenue − Gross_Profit

**Сегментация и кросс-чеки:**
- Buyers из сегмента: `=D30*C30` — Users заполнили декларацию × Conv. оплатили (файл 3, E29–E34)
- Кросс-чек: сумма по сегментам должна совпадать с итогом (файл 3, A37)

**Оценка гипотез — средние командные оценки:**
- Сложность: `=(1+3+5+2)/4` → 2,75 (источник → файл 1, лист «подвиг 2», E39)
- Вера в успех: `=(90%+20%+10%+10%)/4` → 33% (источник → файл 1, лист «подвиг 2», F39)

**Таблица гипотез:**
- Buyers: `=J35*I35` (L35) = C1 × Users
- Gross Profit: `=M39*J39*I39` (N39) = AMPPU × C1 × Users
- AMPU: `=M35*J35` (O35) = AMPPU × C1
- Acq.Costs: `=P35*I35` (Q35) = CPUser × Users
- Profit: `=I35*(O35-P35)` (R35) = Users × (AMPU − CPUser)
- Эффект гипотезы: `=N39` (H39) — Gross Profit как прокси эффекта

**ДИ в таблице гипотез (ведущий):**
- `=2*SQRT(J2*(1-J2)/I2)` (K2, файл 3, лист «Гипотезы»)
- `=IFERROR(2*SQRT(J35*(1-J35)/I35))` — с защитой от ошибки (файл 2, лист «подвиг 2»)

(источник → файл 1, лист «подвиг 1», B7–B23)

### Алгоритм «подвиг 2: воронка продаж и оценка гипотез»
1. Посчитать относительную (D) и абсолютную (E) конверсию за месяц для каждого шага воронки.
2. Рассчитать ДИ за месяц по формуле: F10 = 2 × SQRT(E10 × (1 − E10) / C9).
3. Построить воронку за неделю (умножить месячное на 7/31).
4. Посчитать конверсии и ДИ за неделю — сравнить с месячным ДИ.
5. Быстрая оценка гипотез командой: каждый заполняет столбцы «метрика», «сложность», «вера в успех» (средние через формулу).
6. Каждый независимо оценивает избранные гипотезы через юнит-экономику (подставить прирост метрики в соответствующую колонку строки гипотезы).
7. Выбрать гипотезы, которые НЕ стоит брать в работу.
(источник → файл 1, лист «подвиг 2», B4–B32)

### Алгоритм «подвиг 3: приоритизация гипотез»
1. Выписать ВСЕ идеи по шаблону «если мы сделаем X, то получим Y» (мозговой штурм — не спорить).
2. Оценить каждую гипотезу через юнит-экономику — посмотреть эффект в деньгах.
3. Сравнить силу гипотезы с ДИ за неделю: если сила < ДИ — гипотезу нельзя измерить за неделю.
4. Выбрать 3 лучших гипотезы и поделиться с фаундером.
(источник → файл 1, лист «подвиг 3», B5–B8; файл 3, лист «Гипотезы», B40–B50)

## 10. Термины в глоссарий

- **AMPPU** — Average Margin Per Paying User; маржа на 1-го платящего
- **AMPU / LTV** — Average Margin Per User; маржа на 1-го привлечённого пользователя
- **CAC** — Customer Acquisition Costs; стоимость привлечения платящего
- **CPUser / CPLead** — Cost Per User / Lead; стоимость привлечения пользователя
- **COGS** — Cost of Goods Sold; себестоимость / издержки на продаже
- **COGS 1st sale** — издержки только на первой продаже (одноразовые)
- **С1** — конверсия из пользователя в покупателя (абсолютная)
- **Av.Payment Count / LifeTime** — среднее количество оплат на 1-го платящего
- **Плечи метрик** — метрика с наибольшим рычагом роста Profit при минимальном изменении
- **Доверительный интервал (ДИ)** — статистический диапазон неопределённости конверсии
- **Кросс-чек** — проверка согласованности модели: разница между исходной строкой и строкой «для поиска точек роста» должна равняться нулю
- **Gross Profit** — Buyers × AMPPU; доход с потока пользователей (до вычета Acq.Costs)
- **Profit** — Users × (AMPU − CPUser); чистая прибыль с потока пользователей
- **Fix Costs** — расходы в месяц, ограниченные сверху (аренда, зарплаты, серверы)

## 11. Типичные ошибки / антипаттерны

- **Оценивать гипотезы все вместе в обсуждении** — правило: сначала быстрая независимая оценка каждого, потом сравнение. «Только после быстрой оценки, пусть каждый выберет гипотезы и независимо от других оценит их». (источник → файл 1, лист «подвиг 2», B31)

- **Спорить при генерации гипотез** — «записывайте каждую идею и не спорьте». (источник → файл 1, лист «подвиг 3», B7)

- **Долго рефлексировать над оценкой** — «меньше рефлексируйте и предположите, на сколько вырастет метрика». (источник → файл 1, лист «подвиг 2», B31)

- **Оценивать гипотезы только на месячной воронке** — ДИ за месяц шире, за неделю — ещё шире; сила гипотезы должна превышать ДИ за неделю. (источник → файл 1, лист «подвиг 3», B6)

- **Запускать трафик с CPUser выше AMPU** — пример с рекламой VK: CPUser = 2 руб. > AMPU = 1,59 руб. → Profit = −138 155 руб. (источник → файл 3, лист «Гипотезы», r30)

- **Поднимать чек без учёта влияния на конверсию** — сценарий «поднять ср. чек и конверсию упала» (С1 = 0,15%) показывает: Profit = 294 883 руб. вместо 84 046 руб. (рост, но не до 1 млн; при сильном падении конверсии может быть и убыток). (источник → файл 3, лист «Экономика», r23)

- **Не делать кросс-чеки** — строка 17 (кросс-чеки = 0) обязательна для проверки корректности переноса формул. (источник → файл 1, лист «подвиг 1», B17)
