# Справочник — Экономика внимания

## Краткая суть

Модуль 4 Красинского — про два взаимосвязанных слоя: **экономику денег** (когорты, P&L, прогноз) и **экономику внимания** (активация, дизайн первой сессии, конверсия). Главный тезис: без когорт любой вывод о причинах роста или падения выручки ошибочен на 100%. Точка роста прячется не в 0,2% купивших, а в 99,8% некупивших — именно там кратный рост. (источник → транскрипт М4; слайд 24)

## Когорты и P&L

### Зачем нужны когорты

P&L показывает приход выручки и прибыли, но не показывает когорты и не показывает, что будет с когортами в будущем. В P&L почти всегда нет конверсий. Смотреть на P&L без когорт — делать на 100% неверный вывод. (источник → слайд 16; транскрипт М4)

**Правило:** всегда, когда доля старых пользователей > 5% — нужно считать когорты. (источник → слайд 4, 50)

Финансовые когорты связывают юнит-экономику и P&L и помогают прогнозировать продажи. (источник → слайд 4)

### Модель «бассейна» (системная метафора)

```
База пользователей(t) = База(t−1) + Приток новых − Отток старых
```
(источник → транскрипт М4)

- **Приток** = новые когорты.
- **Утечка** = отток (churn).
- **Уровень воды** = база активных пользователей.
- Если приток < утечки — база падает («бизнес-ресетор»). Бизнес, живущий только на новых: CAC постоянно растёт, экономика ухудшается. (источник → транскрипт М4)

### Два потока денег

Выручку нужно делить на **новые** и **старые** когорты в каждом периоде. Без этого разбиения стабильная суммарная выручка маскирует деградацию новых когорт. (источник → транскрипт М4)

**Кейс: интернет-магазин — деградация для новых**
- Выручка по периодам: ~22, 21, 20 млн руб. (выглядит стабильной).
- Разбивка:
  - Январь: 10 млн новые + 10 млн старые
  - Февраль: 10 млн новые + 11 млн старые
  - Март: **7 млн новые** + 12 млн старые
- Команда в марте переработала сайт, ухудшив его для новых пользователей. Маркетинг компенсировал акциями/скидками на старых когортах. Через 2–3 месяца — спад: компенсация исчерпана. Ошибка марта влияет на P&L до сентября. (источник → транскрипт М4)

### Компенсаторный механизм системы

Когда план продаж не выполняется, маркетинг запускает акции/скидки, которые временно скрывают проблему, выкачивая деньги из старых когорт. Эффект держится 2–3 месяца, потом спад. (источник → транскрипт М4)

### Треугольник когорт

**Структура:**
- Строки = период первого события (месяц/неделя)
- Столбцы = период n-го события (С2м, С3м … С12м)
- Ячейки = число/выручка пользователей из данной когорты на n-й период

**Три типа когорт:**

| Тип | Основание | Применение |
|---|---|---|
| Финансовая когорта | Дата первой оплаты | P&L-прогноз |
| Коммерческая когорта | Дата первого контакта/заявки | Анализ цикла сделки, отдел продаж (B2B) |
| Третий тип | — | Разбирается в Испытании 5; не покрыто в М4 |

(источник → транскрипт М4)

**Ключевая формула когортного P&L (лист «Когорты v4», xlsx):**
```
gross profit total[мес] = SUM(buyers_cohort[i] × AMPPU_monthly)
net profit = gross profit − acq costs − fix costs
```
(источник → лист «Когорты v4», формулы C2, N27)

**Паттерн ретеншн-кривой (степенной закон):**
```
R(N) = 30% × N^(−0,3)
```
Более агрессивное убывание: `R(N) = 17% × N^(−1,5)` (источник → лист «Когорты Saas», строка 66; лист «Рассчет MAU по ретеншену», строка 4)

**MAU как сумма когорт:**
```
MAU[тек. мес] = SUM(installs_когорты[i] × retention[N мес от i])
```
(источник → лист «Рассчет MAU по ретеншену», строка 5: `N5 = SUM(C5:M5)`)

## Алгоритмы когортного анализа

### Финансовые когорты (пошагово)

1. Выгрузить данные из базы/аналитики.
2. Определить основание когорты (дата первой оплаты / первой сессии / первой заявки).
3. Сгруппировать клиентов по периоду (месяц/неделя) первого события.
4. Построить треугольник когорт: строки = периоды первого события, столбцы = периоды повторных событий.
5. Суммировать строки → финансовые когорты.
6. Разделить выручку на «новые» и «старые» когорты на каждый период.
7. Сравнить — искать момент, когда начался спад именно по новым когортам.

(источник → транскрипт М4, кейс интернет-магазина)

### Коммерческие когорты — B2B / длинный цикл сделки

1. Зафиксировать дату, когда лид оставил заявку (основание когорты).
2. Отследить по неделям, сколько из этой когорты заплатили на 1-й, 2-й, 3-й … n-й неделе.
3. Первые 4 недели — целевой горизонт наблюдения.
4. Сравнивать когорты «сопоставимого возраста» (у которых прошло одинаковое количество недель).
5. Смотреть: почему одни платят быстро, другие — через 9–12 недель? Где мины в воронке продаж?

(источник → транскрипт М4, кейс B2B 2609 лидов)

**Данные из модели (лист «Когорты, длинный цикл сделки»):**
```
Конверсия лид→покупатель = buyers / leads
ARPPU = revenue / buyers
Revenue cohort = SUM(доход по всем неделям когорты)
```
Типовая конверсия B2B с длинным циклом: 1–3%. (источник → лист «Когорты, длинный цикл сделки», строки 11–27)

## Активация — главная продуктовая метрика

**Определение:** процент пользователей, которые поняли выгоду от продукта (в первой сессии или до покупки). Ограничивает снизу все остальные метрики. (источник → транскрипт М4)

**Целевые значения:**
- Цель: 80–90% пользователей активировано. (источник → слайд 123)
- В среднем по сервисам: >70% пользователей не понимают, в чём их выгода. (источник → слайд 122)
- Установка «активация 70–80% не бывает» — когнитивный блокер, ведущий к ошибочным решениям. (источник → слайды 277–278)

**Критичность первой сессии:** только в 1-ю сессию у нас есть 100% пользователей. Дизайн 1-й сессии — ключевое продуктовое действие для активации. (источник → слайд 121)

### Алгоритм работы с активацией

1. Определить, что значит «понял выгоду» для вашего продукта/сценария.
2. Замерить долю пользователей, которые это поняли в первой сессии.
3. Если активация < 60–80% — точка роста здесь, не в фичах.
4. Переписать коммуникацию: убрать «язык фреона», добавить «язык сценария пользователя».
5. Провести коридорный тест → получить фидбек.
6. Замерить изменение конверсии.

(источник → транскрипт М4)

**Вопросы для выявления выгоды:**
1. Что значит, что ваш продукт приносит пользу?
2. Кому он приносит пользу?
3. Кто принимает решение о покупке? Что он на самом деле покупает?
4. Как вы понимаете, что принесли ценность?

(источник → слайды 163, 189, 192)

## Конверсия: как считать правильно

**Правильные формулы (слайд 212–213):**
```
Конверсия в покупателя = покупатели / пользователи
Конверсия в лида       = лиды / пользователи
```

**Неверные способы (антипаттерны):**
```
Конв. в покупателя = заказы / пользователи      — неверно
Конв. в покупателя = покупатели / сессии         — неверно
Конв. в покупателя = покупатели / клики          — неверно
Конв. в покупателя = коэф. достижения цели (GA) — неверно (≈ заказы / сессии)
```
(источник → слайд 213)

**Переформулировка задачи:** не «поднять конверсию», а «снизить число тех, кто не купил». Мы не поднимаем конверсию. (источник → слайд 204; транскрипт М4)

**Пример расчёта потерь от низкой конверсии:**
```
Потери в рублях = (Целевая конверсия % − Текущая конверсия %) / Текущая конверсия % × Текущая выручка
```
Пример: 1,5 п.п. / 0,3 × 4 = **20 млн руб.** потеряно из-за непонимания пользователей. (источник → транскрипт М4, кейс формы регистрации)

**+0,3 п.п. к конверсии от 29,9% целевых некупивших = +25 млн руб. прибыли.** (источник → слайд 28)

## Воронка конверсии как «минное поле»

Каждый экран, шаг, форма в воронке — потенциальная «мина», на которой пользователь теряется. (источник → транскрипт М4)

**Ключевая ошибка:** оптимизировать начало воронки, когда мина — в конце. 40 A/B-тестов не дадут результата, если 97% пользователей отваливаются на экране эквайринга.

**Алгоритм:** сначала найти и устранить мины в конце воронки, потом работать с серединой и верхом.

**Кейс: Playki (стриминг игр):**
- 40 A/B-тестов за 3 месяца: конверсия выросла с 0,2% до 0,4% — несущественно.
- Обнаружена мина — экран привязки карты: новые пользователи 97% отваливались, только 3% привязывали карту.
- После устранения: конверсия органика **6%**, платные каналы **5–5,5%**.

(источник → транскрипт М4)

### Алгоритм написания оффера (кейс банка)

1. Записать JTBD-сценарий: «Когда [ситуация/триггер], пользователь хочет [желаемый результат], делает [действие]».
2. Убрать «выгодный налог» — скрыть или объяснить шаги, нужные компании, но не пользователю.
3. Перевести сценарий в текст выгоды: «Вы получаете [результат] сразу после [минимального действия]».
4. Проверить: есть ли на каждом экране хотя бы одна выгода для пользователя?

(источник → транскрипт М4, кейс «Номер счёта прямо сейчас»)

**Пример трансформации оффера банка:**
- Старый: «Бесплатное открытие счёта за 5 минут» + экраны без выгоды.
- Новый: «Номер счёта прямо сейчас. Вы получаете номер счёта сразу после заявки. Его уже можно давать контрагентам и подписывать договора. Работающий счёт уже сегодня. Никакой нудной работы с визитами — автоматически перенесём шаблоны и контакты контрагентов из старого банка.»
- Результат: конверсия в 2 раза выше. (источник → транскрипт М4)

## 4 места кратного роста

Кратный рост прячется там, где есть **операция вычитания**: (источник → слайд 99, 205)

```
AMPU − CPAcq
AvPrice − COGS (издержки)
Новые клиенты − Отток
[4-е место — не раскрыто во входных материалах]
```

**Плечо метрики:** малые изменения в операции вычитания дают кратный эффект на всём потоке.

Пример (слайд 98):
```
20 000 р. − 19 000 р. = 1 000 р. (свободные деньги до повышения)
25 000 р. − 19 000 р. = 6 000 р. (после +25% к зарплате)
→ зарплата выросла на 25%, свободные деньги — в 6 раз
```

## Системные петли (по Голдратту)

(источник → транскрипт М4, «Искусство системного мышления»)

| Тип петли | Описание | Пример |
|---|---|---|
| Усиливающая (positive loop) | Всё растёт взаимно | маркетинг → клиенты → доверие → LTV → маркетинг |
| Балансирующая (balancing loop) | Компенсаторный механизм | прибыль растёт → конкуренты входят → CAC растёт → прибыль падает |
| Ослабляющая/негативная петля | Деградирующий цикл | фичи → сложность → падение активации → рост CAC → падение прибыли |

**Цикл деградации продукта через фичи:**
```
Добавляем фичи → продукт усложняется → активация новых падает
→ конверсия падает → CPL/CAC растёт → маркетинг сокращают
→ выручка падает → новая стратсессия → снова фичи
```
(источник → транскрипт М4)

**Пример двойной усиливающей петли (кейс Bumble):**
Bumble запретил мужчинам первыми писать женщинам → пришло больше женщин → за ними пришли мужчины → продукт вырос. Удаление фичи из продукта часто делает продукт лучше. (источник → транскрипт М4)

## Ретеншн

**Ретеншн как мультипликатор к новым пользователям:**
```
80 000 (новые) × 1,35 (мультипликатор ретеншна) = ~108 000 (реальные пользователи)
```
(источник → слайд 248)

Ретеншн — производная метрика от Daily Usage. Ретеншн не напрямую, только косвенно влияет на повторные покупки и LTV. (источник → слайды 252–253)

**Игровой (Retention) Loop** — механизм возврата пользователя к сервису. Строится поверх базовой ценности продукта; виральность — поверх retention loop. Разорванный игровой цикл: петля прервана, пользователь не возвращается. (источник → транскрипт М4; слайды 243, 256)

**Churn rate (формула из модели):**
```
Churn rate = churn / buyers_total предыдущего месяца
```
(источник → лист «Когорты v4», формула E15: `=E14/D11`)

**Ретеншн-кривая (степенная модель):**
```
D4 = 0.17 × N^(−1,5)   — резкое убывание
R66 = 30% × N^(−0,3)   — мягкое убывание
```
(источник → лист «Рассчет MAU по ретеншену», строка 4; лист «Когорты Saas», строка 66)

**C2 (конверсия в 2-ю покупку):** ключевая метрика оттока. Целевое значение >50% — на горизонте 3–6 месяцев рост дохода в x6–7. При C2 ~10% — рост возможен только за счёт новых пользователей. (источник → слайды 55–59)

## Средний чек и инструменты продаж

Средний чек определяет инструменты продаж и roadmap. (источник → транскрипт М4; лист «ср. чек и инструменты продаж»)

| Средний чек | Инструмент | Цикл сделки | Продаж в год (на 1 млн целевой выручки) |
|---|---|---|---|
| > 10 млн р. | Личные встречи, СПИН, тендер | 3–12 месяцев | 1–10 |
| ~1 млн р. | Личные встречи, переговоры | 1–3 месяца | 3–20 |
| 50–100 тыс. р. | Встречи + сейлы | Недели | ~100 |
| 30–50 тыс. р. | Звонки, телемаркетинг, Zoom | Недели | 200–300 |
| ~10 тыс. р. | Пуши, рассылки, CRM, чат-боты | Дни | ~1 000 |
| ~1 тыс. р. | Лендинг + эквайринг | Минуты–дни | ~10 000 |

(источник → лист «ср. чек и инструменты продаж», строки 1–7; транскрипт М4)

«Личные продажи очень плохо и дорого при чеке 10–30 тыс. р. — только вначале для кастдева и до масштабирования.» (источник → лист «ср. чек и инструменты продаж», A24)

**Ценообразование от выгоды:**
```
если выгода пользователя = 500 000 р.:
  10–20% от выгоды → 50 000–100 000 р. (честная сделка)
  30% от выгоды   → 150 000 р. (зависит от монополии и умения продавать)
  50% от выгоды   → 250 000 р. (часто считается жадностью без явной выгоды)
```
(источник → слайды 36, 40, 82, 115, 227)

Как повышать цену: 1) увеличивать ценность; 2) и/или менять сегмент пользователей. (источник → слайды 36, 82, 227)

## Алгоритм поиска точек роста (основной игровой цикл)

1. Быстро понять, что происходит: основные проблемы в бизнесе, какие есть ресурсы.
2. Найти узкое место и точки роста.
3. Выдвинуть гипотезы — как наиболее дешёвым способом получить максимальный эффект.
4. Приоритизировать гипотезы и сформировать план действий.
5. Реализовать гипотезу.
6. Замерить результат и сделать выводы. Если всё сделали правильно → Profit.
7. Перейти к шагу 1 или 4.

(источник → слайд 259)

Точки роста часто скапливаются там, куда: 1) недостаточно смотрят; 2) где не хватает компетенций. (источник → слайд 197)

## Когнитивные искажения в аналитике

- **Ошибка выжившего (Survivor Bias):** общаемся с теми, кто купил или оставил заявку, а не с теми, кто ушёл молча. Продукт проектируется под старых, теряя новых. (источник → транскрипт М4)

- **Confirmation Bias:** 99,8% пользователей не покупают, но команда общается с 0,2%, которые купили, и экстраполирует их поведение на всех. (источник → транскрипт М4)

- «Мы не репрезентативны, стараемся подтвердить свою точку зрения, находим цифры, которые её подтверждают, и профессионально убедительны. Эти качества позволяют нам эффективно продвигаться по карьерной лестнице. И часто ведут к ошибочным решениям в управлении бизнесом.» (источник → слайд 5)

- **Нелинейность во времени:** ошибки/успехи в начале года влияют на P&L через 3–12 месяцев. Когорты медленно «созревают». (источник → транскрипт М4)

## Антипаттерны — топ-13

1. Смотреть на P&L без когорт — вывод всегда будет неверным. (источник → транскрипт М4)
2. Считать без когорт, когда доля старых пользователей >5%. (источник → слайд 4)
3. Делать фичи для старых пользователей: 80% фич под старых, а точка роста — конверсия новых. Фичи не имеют юнит-экономики. (источник → транскрипт М4; слайд 131)
4. Работать с началом воронки, когда мина — в конце. 40 A/B-тестов не помогут, если 97% отваливаются на эквайринге. (источник → транскрипт М4)
5. Использовать «язык фреон» в коммуникации. VIN-номер, cashback, «регистрация» — термины, которых не знает часть аудитории. (источник → транскрипт М4; слайды 151–154)
6. Называть кнопку «Регистрация» вместо «Оформить заказ». Пользователь хочет купить, не регистрироваться. (источник → транскрипт М4)
7. Неверный расчёт конверсии: делить заказы на сессии (или клики) вместо покупателей на пользователей. (источник → слайд 213)
8. Думать, что слово «бесплатно» — выгода. «Бесплатно» — усилитель, не ценность. (источник → транскрипт М4)
9. Компенсировать спад скидками/акциями. Работает 2–3 месяца, скрывает проблему. (источник → транскрипт М4)
10. Проектировать продукт одинаково для новых и старых пользователей. Они принципиально разные сегменты. (источник → транскрипт М4)
11. Убеждения-блокеры: «конверсия в 1-ю покупку 5–10% не бывает», «активация 70–80% невозможна» — ведут к ошибочным решениям. У лучших в индустрии метрики в x5–10 раз лучше среднестатистических. (источник → слайды 277–278, 285)
12. Начинать с идеи, а не с диагностики: 9 из 10 гипотез не срабатывают, расходы растут. (источник → слайд 106)
13. Игнорировать первую сессию: именно там 100% пользователей — именно там нужно активировать. (источник → слайд 121)

## Глоссарий

| Термин | Определение | Источник |
|---|---|---|
| Когорта | Группа пользователей/клиентов, объединённая по времени первого действия (основание когорты) | транскрипт М4 |
| Финансовая когорта | Когорта по дате первой оплаты; инструмент связи юнит-экономики и P&L | транскрипт М4; слайд 4 |
| Коммерческая когорта | Когорта по дате первого контакта/заявки; применяется в B2B и отделах продаж | транскрипт М4 |
| Основание когорты | Событие, по которому группируются пользователи (первая оплата, сессия, заявка) | транскрипт М4 |
| Активация | % пользователей, понявших выгоду от продукта; ограничивает снизу все метрики; цель 80–90% | транскрипт М4; слайд 123 |
| 1-я сессия | Единственный момент, когда у нас есть 100% пользователей | слайд 121 |
| Дизайн 1-й сессии | Продуктовое проектирование первого контакта пользователя с продуктом | слайд 188 |
| Ошибка выжившего (Survivor Bias) | Анализ только тех, кто «вернулся на базу» (купил/оставил заявку) | транскрипт М4 |
| Confirmation Bias | Подтверждение точки зрения за счёт искажённой выборки (0,2% купивших) | транскрипт М4 |
| Язык фреон | Описание продукта техническим/продуктовым языком вместо языка выгоды пользователя | транскрипт М4; слайды 151–154 |
| Выгода | То, что пользователь реально покупает; должна коммуницироваться явно на каждом экране | слайды 123, 163 |
| Выгодный налог | Шаг, нужный компании, но не нужный пользователю; задача — покрасить или объяснить | транскрипт М4 |
| Минное поле | Воронка с множеством препятствий (экранов/форм) для пользователя | транскрипт М4 |
| SuccessRate | % пользователей, успешно завершивших критический шаг | транскрипт М4 |
| Бизнес-ресетор | Бизнес, где приток новых < оттока старых; база сокращается | транскрипт М4 |
| Сценарий / JTBD-сценарий | Что человек делает, чтобы закрыть свои задачи; замена слова «фича» в продуктовом мышлении | транскрипт М4 |
| Retention loop | Петля удержания; базовая конструкция для виральных циклов | транскрипт М4; слайд 243 |
| Разорванный игровой цикл | Петля retention прервана, пользователь не возвращается | слайд 243, 256 |
| C2 | Конверсия в 2-ю покупку; ключевая метрика оттока; целевое значение >50% | слайды 55–59 |
| ABCD-сегментация | Сегментация пользователей по транзакциям за 60 дней и среднему чеку | слайд 240 |
| Actionable сегментация | Сегментация по признакам, пригодным для конкретных продуктовых действий | слайды 33, 81, 225 |
| Daily Usage | Базовая метрика частоты использования, от которой производится ретеншн | слайд 253 |
| Закон Хика | Чем больше одинаковых элементов → тем выше когнитивная нагрузка → тем ниже конверсия | слайд 184 |
| Плечо метрики | Кратный эффект малого изменения метрики при большом потоке пользователей | слайд 44 |
| MAU | Monthly Active Users; рассчитывается как сумма когорт с учётом retention | лист «Рассчет MAU по ретеншену» |
| ARPPU | Average Revenue Per Paying User за N дней (30, 60, 90 … 360) | лист «Когорты. Доставка» |
| Степенной закон ретеншна | R(N) = A × N^(−B); описывает убывание retention со временем | лист «Когорты Saas», строка 66 |
| CAC | Customer Acquisition Costs; стоимость привлечения платящего = расходы / Buyers | лист «Шаблон», Q169 |
| CPL / CPO / CPUser | Стоимость лида / заказа / пользователя = расходы на привлечение / поток | лист «Шаблон», строки R3–U15 |
| Churn rate | Отток / buyers_total предыдущего периода | лист «Когорты v4», E15 |
