# Справочник — Когорты и прогноз

## Краткая суть

Когортный подход — способ перейти от усреднённых цифр к реальной динамике бизнеса. Каждая когорта — «треугольник»: группа пользователей, привлечённых в один период, которая продолжает генерировать доход в последующих месяцах. Умение строить когорты и прогнозировать их хвосты разделяет тех, кто «думает когортами», от тех, кто нет. (М5 → расшифровка)

Методология выделяет два класса прогнозов: через **retention-мультипликатор** (для MAU рекламных и SaaS-продуктов) и через **финансовую когорту** (для транзакционных продуктов и B2B с рекуррентными платежами). Обе модели строятся на данных за 3–6 месяцев и не требуют сложных формул — принципиально важна правильная структура данных и кросс-чеки. (М5 → расшифровка)

---

## Три типа когорт

| Тип | Основание когорты | На какой вопрос отвечает |
|---|---|---|
| Маркетинговая | Дата первой сессии | Сходится ли экономика привлечения? |
| Коммерческая | Дата первой заявки / триала | Каков цикл сделки? Где точки роста воронки? |
| Финансовая | Дата первой оплаты | Каков финансовый прогноз? Выйдем ли в плюс? |

(М5 → расшифровка)

Выбор типа когорты — не технический, а управленческий: зависит от того, какое решение нужно принять. Для P&L-прогноза — финансовая. Для оценки маркетинга — маркетинговая. Для анализа продукта — коммерческая.

## Иерархия доверия данным из аналитики

При работе с GA данные делятся на три класса по достоверности. (М5 → расшифровка)

**Верить:**
- Байеры (уникальные пользователи с транзакцией > 0)
- Транзакции (уникальный TransactionID)
- Выручка из базы данных

**Не верить напрямую:**
- Конверсия из агрегированных отчётов (особенно по сессиям)
- Средний чек из готового отчёта
- Retention из сложных SQL-запросов аналитика

**Считать самостоятельно:**
- Конверсию: `Байеры / Пользователи`
- Средний чек: `Выручка / Байеры`
- Старых пользователей: `Все − Новые`

Практическое правило: при получении данных от аналитика ожидать 2–3 итерации до правильного результата; выгружать исходные данные построчно и пересчитывать через сводную таблицу. (М5 → расшифровка)

## Формулы — базовые метрики

### AMPPU и AMPU

```
AMPPU = AvPrice × Margin × AvPaymentCount
AMPU  = C1 × AMPPU
```

(М1 → слайды 75–77)

Здесь:
- `AvPrice` — средний чек
- `Margin` — маржинальность продажи
- `AvPaymentCount` — среднее число покупок на платящего; если данных нет — брать 1,2 (М1 → слайд 92)
- `C1` — конверсия в первую покупку: `Байеры / Пользователи` (НЕ транзакции / сессии)

```
AMPU (за всё время жизни) = LTV
AMPPU (за всё время жизни) = CLTV
```

(М1 → слайд 79)

Временны́е срезы: `AMPPU30` — за первый месяц, `AMPPU365` — за 365 дней. (М1 → слайд 75)

### CAC и CPUser

```
CAC    = CPUser / C1
CPUser = Acq.Costs / Users
CPO    = Acq.Costs / Payments
```

(М1 → слайды 61, 124)

`CAC` — удобен инвесторам, но не actionable для команды. Actionable компоненты: `CPUser` и `C1`. (М1 → слайд 120)

### Конверсия (правильная)

```
Конверсия = Байеры / Пользователи
```

НЕ: `Транзакции / Сессии` — это систематическая ошибка измерения, которую по умолчанию выдаёт большинство систем аналитики. (М5 → расшифровка; М1 → слайды 29–33 ист. 2)

### Условие сходимости экономики

```
AMPU > CPUser   →   экономика сходится
AMPU < CPUser   →   экономика не сходится, искать точку роста
```

Прибыль на потоке:
```
Profit     = Users × (AMPU − CPUser)
Profit net = Profit − Fix Costs
```

(М5 → лист «Юнит-экономика», W5, V5)

## Формулы — когортный треугольник

### Структура таблицы

Когортный треугольник: строки = месяц первой сессии/оплаты (основание когорты), столбцы = месяц транзакции. Каждая диагональ = «возраст» когорты в месяцах.

Три параллельных треугольника:
- по байерам (`COUNTUNIQUE(UserID)`)
- по пейментам (`COUNTUNIQUE(TransactionID)`)
- по выручке (`SUM(Revenue)`)

Строка «до основания» — пользователи, чья первая сессия была ДО начала анализируемого периода. Без неё сумма по столбцу не совпадёт с P&L. (М5 → расшифровка)

```
Старые = Все − Новые
```

Кросс-чек: сумма по столбцу (месяц) = P&L выручка за этот месяц. Если не сходится — ошибка в данных. (М5 → расшифровка; М5 → лист «Юнит-экономика», строка r10)

### Определение когорты в Excel/Sheets

```excel
=IF(A3<>"", DATE(YEAR(A3), MONTH(A3), 1), "before Jan 2017")
```

(М5 → лист «transactions raw data»)

### Retention в когорте (финансовый метод)

Относительная конверсия удержания по байерам:

```
C(M→M+1) = Байеры(когорта K, месяц M+1) / Байеры(когорта K, месяц M)
```

Прогноз следующего месяца:

```
Байеры(M+1) = Байеры(M) × C(M→M+1)
Revenue(M+1) = Revenue(M) × C_rev(M→M+1)
```

Важно: конверсия удержания по байерам и по деньгам — разные числа. Дорогие клиенты, как правило, удерживаются лучше. (М5 → расшифровка)

Ключевая формула в xlsx (с фиксацией основания когорты):

```excel
= $Основание_когорты × C2M
```

При перетаскивании по диагонали: столбец основания фиксируется, месяц транзакции перемещается. (М5 → расшифровка)

### LTV через Gross Profit когорты

```
LTV (когортный) = Σ Gross Profit за время жизни когорты / Байеры основания когорты
```

(М5 → расшифровка)

В xlsx-модели интернет-магазина:

```excel
= SUM(Gross_Profit_когорты) / Buyers_new    → CLTV факт
= Q35 / P35                                  → CAC
= S35 − R35                                  → T = CLTV − CAC
```

(М5 → лист «Cohorts»)

## Формулы — прогноз MAU через retention

Применяется для рекламных и SaaS-продуктов, где ключевой показатель — ежемесячная аудитория.

### Степенной закон retention

```
Ret(t) = a × t^b
```

Где:
- `a` — начальный уровень (берётся из GA за 1-й месяц, ячейка D4 в шаблоне)
- `b` — показатель степени убывания (обычно `-1.0`, задаётся вручную)
- При `b = -1`: гиперболическая функция `Ret(t) = a / t`

(М5 → лист «Расчёт MAU по ретеншну», ячейки E1, E2, D7)

Альтернативная кривая для зрелых продуктов с высоким retention:

```
Ret(t) = 0.33 × t^(-0.1)
```

(М5 → лист «Расчёт MAU по ретеншну», строка 33)

### Когортная матрица и мультипликатор MAU

```
MAU_когорты(t) = Начальная_когорта × Ret(t)
MAU_месяца     = Σ MAU_когорты за все активные когорты
```

В xlsx:

```excel
D11 = $C10 * D$7     → когорта янв., дожившие до февр. = начальная × Ret(1)
E12 = $C10 * E$7     → дожившие до марта = начальная × Ret(2)
O10 = SUM(C10:N10)   → итоговый MAU месяца
P10 = O10 / C10      → мультипликатор MAU
```

(М5 → лист «Расчёт MAU по ретеншну»)

### Формула мультипликатора

```
Мультипликатор(N) = 1 + Ret(1) + Ret(2) + ... + Ret(N-1)
MAU(N) = Новые_пользователи × Мультипликатор(N)
```

Мультипликатор стремится к асимптоте — это устойчивый уровень MAU при постоянном притоке новых пользователей. (М5 → расшифровка)

**Пример** (a=0.17, b=-1.0, когорта 900 000):

| Месяц | MAU | Мультипликатор |
|---|---|---|
| 1 | 900 000 | 1.00 |
| 3 | 1 129 500 | 1.26 |
| 6 | 1 249 350 | 1.39 |
| 12 | 1 362 041 | 1.51 |

(М5 → лист «Расчёт MAU по ретеншну», строки 10–21)

### Рекламная монетизация (ARPMAU)

```
ARPMAU = CPM / 1000 × Imps_Per_User
```

```excel
O25 = O26 * O27      → ARPMAU = AvPrice × Imps Per User
O26 = CPM / 1000     → цена одного показа
```

```
Gross Profit = MAU × ARPMAU × Маржинальность
```

(М5 → расшифровка; М5 → лист «Расчёт MAU по ретеншну», строки 25–27)

## Алгоритмы

### 1. Извлечение метрик из GA для юнит-экономики

1. Получить два ключевых запроса к GA:
   - Запрос A: все пользователи за период — `users`, `new_users`, `transactions`, `revenue`, `ga:dimension4` (clientID), `sessionCount`
   - Запрос B: то же, фильтр `sessionCount = 1` (новые пользователи)
2. Проверить уровень семплирования: при > 5% расхождения — работать с несемплированными данными (сырая построчная выгрузка)
3. Рассчитать старых пользователей: `Старые = Все − Новые`. НЕ запрашивать отдельным сложным запросом
4. Верить только байерам и выручке из базы; конверсию и средний чек считать самостоятельно
5. Кросс-чек: `Выручка = Байеры × Средний чек`
6. Для когортного анализа без семплирования: выгружать исходные данные построчно (UserID, дата первой сессии, дата транзакции, сумма)

(М5 → расшифровка)

### 2. Построение когортной таблицы

1. Подготовить данные: `[UserID | дата первой сессии | дата транзакции | выручка]`
2. Построить сводную таблицу: строки = когорта (месяц первой сессии), столбцы = месяц транзакции
3. Значения ячеек: байеры — `COUNTUNIQUE(UserID)`, пейменты — `COUNTUNIQUE(TransactionID)`, выручка — `SUM(Revenue)`
4. Добавить строку «до основания»: пользователи с первой сессией ДО начала анализируемого периода
5. Кросс-чек: сумма столбца = P&L выручка за этот месяц
6. Рассчитать C2 (конверсию второй покупки): `Байеры(месяц 2) / Байеры(месяц 1)` для каждой когорты

(М5 → расшифровка)

### 3. Прогнозирование через MAU-мультипликатор

1. Взять фактические данные retention за первые 3 месяца из GA (например: 17%, 7%, 3%)
2. Подобрать параметр `b` «на научный глаз»: `Ret(t) = a × t^b`. Формула должна совпадать с 3 известными точками. Параметр `a` = Ret(1)
3. Рассчитать retention для последующих месяцев по формуле
4. Рассчитать мультипликатор: `mult(N) = 1 + Ret(1) + Ret(2) + ... + Ret(N-1)`
5. `MAU(N) = Новые_пользователи × mult(N)`; мультипликатор выходит на асимптоту — это устойчивый уровень MAU

(М5 → расшифровка; М5 → лист «Расчёт MAU по ретеншну»)

### 4. Прогнозирование через финансовые когорты (транзакционная / B2B)

1. Взять исторические данные конверсии удержания C2m (2-й мес / 1-й мес) и C3m (3-й / 2-й) за 3–6 месяцев
2. Усреднить retention по когортам: `C_avg_2m = AVERAGE(C2m по всем когортам)`
3. Прогнозировать будущие когорты: `Байеры(M+1) = Байеры(M) × C_avg`
4. Аналогично для выручки: `Revenue(M+1) = Revenue(M) × C_rev_avg`
5. Суммировать Gross Profit всех когорт по каждому месяцу
6. Сравнить Gross Profit с фиксированными костами — найти точку break-even
7. Для устаревших (старых) когорт применять постоянный churn rate (экспоненциальное затухание)

(М5 → расшифровка; М5 → лист «Когорты прогноз. LTV»)

### 5. Расчёт Runway

```
Остаток_инвестиций(N) = Остаток(N-1) + Gross_Profit(N) − Fix_Costs(N)
Месяцев_до_нуля = Текущий_остаток / |Fix_Costs − Gross_Profit|
```

```excel
E96 = D96 + D99      → остаток = предыдущий + (GP − fix costs)
D100 = D96/ABS(D99)  → месяцев до нуля
```

(М5 → лист «Когорты прогноз. LTV»)

### 6. A/B-тест конверсии — статистическая значимость

```
ДИ(вариант) = 2 × SQRT(p × (1 − p) / n)
```

Вариант B статистически лучше, если:
```
(B − A) > ДИ(A) + ДИ(B)
```

(М5 → лист «Юнит-экономика», ячейка E22; лист «ответы на вопросы»)

## Churn: расчёт и интерпретация

```
Churn         = Байеры(пред. мес) + Байеры_новые(пред. мес) − Байеры_текущие
Churn rate    = Churn / Байеры_база
База_прирост  = Новые − Ушедшие
```

(М5 → лист «Cohorts»)

**Важное предупреждение:** Формула `LTV = 1 / Churn_rate` является ложью — это частный случай, работающий только при экспоненциальном отмирании когорты с постоянным churn rate. На практике retention описывается степенной функцией, убывающей медленнее. (М5 → расшифровка)

**Churn users vs Churn total** (в модели MAU):

```excel
Q56 = SUM(C55:N55) - SUM(D56:N56)   → Churn users месяца
R56 = SUM(C$54:C55) - SUM(D56:N56)  → Churn total (накопленный)
```

(М5 → лист «Расчёт MAU по ретеншну»)

**Отрицательный churn** — ситуация, когда выручка от апсейла существующих клиентов превышает потери от ушедших. Пример из NDA SaaS: `churn по выручке в ноябре = −5.0%` (апсейл). (М5 → лист «Когорты прогноз. LTV»)

## Retention: типы, ограничения, Smile Effect

**Retention** — возвращаемость пользователей в продукт; всегда считается как абсолютная конверсия от основания когорты. Влияет на MAU и является индикатором Product-Market Fit.

**Retention ≠ повторные покупки.** Это принципиально разные метрики с разными математическими моделями. В B2B один человек платит, другой заходит в сервис. Retention может ограничивать конверсию в повторные покупки сверху, но прямой математической связи нет. (М5 → расшифровка)

**В рекламной модели** — связь прямая и сильная: каждый возврат пользователя = новые показы рекламы = новый доход. (М5 → расшифровка)

**Smile Effect** — нетипичная форма графика retention: сначала падение, потом рост. Характерен для Dropbox, Evernote, Facebook. При этой форме полиномиальная экстраполяция неприменима. (М5 → расшифровка)

**Целевые значения C2 (конверсия на 2-й месяц):**
- C2 ~10% — высокий отток; рост только за счёт новых пользователей
- C2 > 50% — на горизонте 3–6 месяцев возможен рост дохода в 6–7 раз

(М1 → слайд 135)

## Сегментация по цене как двойной рычаг

Введение нескольких ценовых сегментов — единственное управленческое решение, влияющее одновременно на два параметра: повышает AMPPU (за счёт премиум-тарифа) и конверсию (за счёт скидки для более дешёвого сегмента). (М5 → расшифровка)

Цену нельзя подобрать «из головы» — единственный метод: A/B-тест или последовательное изменение на отдельном городе/регионе. Максимизируется AMPPU при изменении цены, не выручка. (М5 → расшифровка)

Ориентиры ценообразования: 10–20% от выгоды клиента — честная сделка; 30% — зависит от монополии/бренда; 50% — если ценность внятно показана. (М1 → слайд 156)

## Антипаттерны

1. **Конверсия по сессиям вместо пользователей.** GA по умолчанию выдаёт `транзакции / сессии`. Для принятия решений нужна `байеры / пользователи`. (М5 → расшифровка; М1 → слайды 29–33)

2. **Считать в среднем по новым и старым.** Усреднённые метрики скрывают реальную картину: на новых можно уронить конверсию, на старых — поднять акциями. Итог усреднения — ложный вывод «всё хорошо». Пример: ошибка обошлась компании в −409 млн руб./мес. (М1 → слайды 52, 54)

3. **Один сложный запрос вместо нескольких простых.** Аналитики ошибаются в 9 из 10 случаев при сложных запросах. Лучше: простые запросы + вычитание для старых пользователей. (М5 → расшифровка)

4. **Доверять данным без кросс-чеков.** Обязательный кросс-чек: `Выручка = Байеры × Средний чек` и `сумма по столбцу когорты = P&L выручка`. (М5 → расшифровка)

5. **Игнорировать строку «до основания» в когорте.** В 95% когортных отчётов её нет. Без неё сумма не сойдётся с P&L. (М5 → расшифровка)

6. **LTV = 1 / churn.** Формула верна только при постоянном churn rate — специальный частный случай. На практике retention описывается степенной функцией. (М5 → расшифровка)

7. **Retention = повторные покупки.** Прямой математической связи нет, особенно в B2B, при автопродлениях, при низкочастотных покупках. (М5 → расшифровка)

8. **Семплирование GA без проверки.** При 48% семплировании погрешность на потоке новых пользователей составила ~697 тыс. руб. Нужно сравнивать с когортными данными (без семплирования). (М5 → лист «Юнит-экономика», A32)

9. **Отправлять минус-транзакции в GA.** Переопределяет каналы привлечения и увеличивает число пользователей/сессий/транзакций. (М1 → слайд 19 ист. 2)

10. **Масштабировать до решения проблемы retention.** При C2 ~10% рост только за счёт новых пользователей — «розовый единорог». Сначала fix retention, потом scale. (М1 → слайды 136–139)

## Глоссарий

| Термин | Определение |
|---|---|
| Когорта | Группа пользователей, объединённых датой первого ключевого события (сессия / заявка / оплата) |
| Байер (Buyer) | Пользователь с хотя бы одной завершённой транзакцией (сумма > 0) |
| Пеймент (Payment) | Транзакция; один байер может иметь несколько пейментов |
| C1 | Конверсия в первую покупку = Байеры / Пользователи |
| C2 / C2m | Конверсия на 2-й месяц жизни когорты (доля байеров, вернувшихся) |
| Retention | Возвращаемость в продукт; считается абсолютно от основания когорты |
| MAU | Monthly Active Users — ежемесячная аудитория |
| Мультипликатор MAU | Коэффициент: во сколько раз MAU превышает число новых пользователей при стабильном притоке |
| Smile Effect | U-образная форма retention-кривой; полиномиальная экстраполяция неприменима |
| Break-even | Точка, где Gross Profit = фиксированные косты |
| Runway | Число месяцев до исчерпания инвестиций при текущем burn rate |
| AMPPU | Average Margin Per Paying User = AvPrice × Margin × AvPaymentCount |
| AMPPU30 / AMPPU365 | AMPPU за первые 30 / 365 дней |
| AMPU | Average Margin Per User = C1 × AMPPU |
| CLTV | Customer LifeTime Value = AMPPU за всё время жизни |
| LTV | AMPU за всё время жизни когорты |
| AvPC LifeTime | Average Payment per Customer LifeTime = GP когорты / Buyers когорты |
| ARPMAU | Average Revenue Per MAU; в рекламной модели = CPM/1000 × Imps Per User |
| CPM | Cost Per Mille — стоимость 1000 показов рекламы |
| Imps Per User | Число показов рекламы на одного пользователя в месяц |
| a, b | Параметры степенного закона retention: a — начальный уровень, b — скорость убывания (b < 0) |
| Семплирование | Расчёт GA на части данных (не 100%); вносит систематическую погрешность |
| Cohort MonthYear | Год-месяц-01 первой сессии, ключ когорты |
| ga:dimension4 / clientID | Идентификатор пользователя в GA (строка, не число) |
| Churn users | Потерянные пользователи за месяц из данной когорты |
| Churn total | Накопленные потери пользователей |
| Отрицательный churn | Выручка от апсейла превышает потери от ушедших клиентов |
| fix costs burn rate | Фиксированные операционные расходы в месяц |
