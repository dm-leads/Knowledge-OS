# Справочник — Юнит-экономика: метрики и формулы

## Краткая суть

Юнит-экономика описывает, как деньги приходят от пользователей, через 4–5 метрик, одинаково для всех бизнесов: вход — поток пользователей, выход — поток денег. (М0 → транскрипт, ~65 000 симв.) Юнит — «то, что масштабируется»: в 99% бизнесов это платящий пользователь или клиент. (М1 → транскрипт, раздел «Определение юнита»)

Ключевая задача расчёта — проверить **три уровня сходимости**: платящий клиент прибылен (AMPPU > 0), привлечённый пользователь прибылен (AMPU > CPUser), бизнес в целом прибылен (Profit > 0 с учётом Fix Costs). (М2 → txt, раздел «Три критерия сходимости»)

## 1. Метрики: определения и формулы

### 1.1 Сводная таблица

| Метрика | Полное название | Определение | Формула |
|---|---|---|---|
| **UA / Users** | User Acquisition / Поток пользователей | Число привлечённых пользователей за период | — ввод |
| **C1** | Conversion to Buyer | Конверсия из пользователя в первую покупку | — ввод |
| **Buyers** | Покупатели | Число совершивших первую покупку | `Buyers = Users × C1` |
| **APC / Av. Payment Count** | Average Payment Count | Среднее число оплат на платящего пользователя за lifetime когорты | `APC = Суммарные платежи когорты / Размер когорты` |
| **Payments** | Платежи | Суммарное число транзакций | `Payments = Buyers × APC` |
| **Av. Price** | Average Price | Средний чек (одна транзакция) | — ввод |
| **Margin%** | Маржинальность | Доля маржи в среднем чеке | — ввод |
| **COGS** | Cost of Goods Sold | Себестоимость: все переменные (масштабируемые) издержки на каждой продаже — упаковка, доставка, себестоимость, комиссии платёжных систем | — ввод |
| **COGS 1st sale** | COGS на первую продажу | Единовременные издержки при первой продаже: онбординг, настройка, установочное оборудование, премия продавца | — ввод |
| **Revenue** | Выручка | Суммарная выручка | `Revenue = Payments × Av. Price` |
| **COGS total** | Суммарная себестоимость | COGS по всем транзакциям | `COGS total = Revenue × (1 − Margin%)` **или** `COGS total = COGS × Payments` |
| **Gross Profit** | Валовая прибыль | Выручка минус COGS (до расходов на привлечение) | `Gross Profit = Revenue − COGS total` = `Buyers × AMPPU` = `Users × AMPU` |
| **AMPPU** | Average Margin Per Paying User (= CLTV) | Средняя маржа с одного платящего пользователя за lifetime; «в АМПУ собраны все-все-все метрики, описывающие ценность продукта на рынке» | см. раздел 1.2 |
| **AMPU** | Average Margin Per User (= LTV) | Средняя маржа с привлечённого пользователя (включая неплатящих) | `AMPU = C1 × AMPPU` |
| **CAC** | Customer Acquisition Cost | Стоимость привлечения одного **платящего** клиента; производная от CPUser и конверсии | `CAC = Acq. Costs / Buyers` |
| **CPUser** | Cost Per User | Стоимость привлечения одного **пользователя**; определяется конкуренцией в канале и компетенцией команды — **не зависит от продукта** | `CPUser = Acq. Costs / Users` |
| **CPL** | Cost Per Lead | Стоимость лида | `CPL = Acq. Costs / Leads` |
| **CPO / SPS** | Cost per Order / Cost per Sale | Стоимость заказа / продажи | `CPO = Acq. Costs / Payments` |
| **Acq. Costs** | Acquisition Costs | Суммарные расходы на привлечение (контекст, таргет, CPA-сети, зарплата сейлзов) | — ввод |
| **Fix Costs** | Фиксированные (не масштабируемые) расходы | Расходы, не растущие с ростом числа пользователей: зарплаты продуктовой команды, аренда, серверы | — ввод |
| **Profit** | Прибыль на потоке | Прибыль до Fix Costs | `Profit = Gross Profit − Acq. Costs` = `Users × (AMPU − CPUser)` |
| **Profit net** | Чистая прибыль | С учётом всех расходов | `Profit net = Profit − Fix Costs` |

(Структура таблицы — М0 xlsx, М1 xlsx лист «Шаблон», строки 1–3; М0 xlsx файл ведущего)

> **Важно:** CAC и CPUser — разные метрики. При C1=10% CAC в 10 раз выше CPUser. Публичные материалы по юнит-экономике почти всегда считают через CAC — это выгодно для инвесторов, но неверно для управления продуктом. (М2 → txt)

### 1.2 Формулы AMPPU по типу бизнес-модели

Формула AMPPU зависит от структуры издержек. Все варианты — дословно из xlsx-моделей:

#### Подписочная / транзакционная (нет COGS на каждой продаже, только маржинальность):
```
AMPPU = Av. Price × Margin% × Av. Payment Count
```
(М0 → xlsx файл 1, лист «подвиг 1», J13 = `=K*L*P`; М1 xlsx, I7 = `=J7*K7*P7`)

Пример (музыкальный сервис): Av. Price=200 р., Margin=30%, APC=7 → AMPPU=420 р. (М0 xlsx, файл 1)

#### Магазин / транзакционная (COGS — фиксированная себестоимость на единицу товара):
```
AMPPU = (Av. Price − COGS) × Av. Payment Count
```
(М0 → xlsx файл 1, лист «подвиг 2», J = `=(K-M)*P`)

Пример (интернет-магазин): Av. Price=5 000 р., COGS=3 500 р., APC=1,21 → AMPPU=1 818 р. (М0 xlsx, файл 1)

#### С издержкой на первую продажу (COGS 1st sale: оборудование, онбординг):
```
AMPPU = Av. Price × Margin × Av. Payment Count − COGS_1st_sale
```
(М0 → xlsx файл 1, лист «подвиг 3», J = `=K*P-O`; М1 xlsx, I47 = `=J47*K47*P47 - O47`)

Пример (hot wi-fi B2B): Av. Price=3 000 р., COGS 1st=6 000 р., APC=1 → AMPPU= −3 000 р. (убыток). При APC=3: AMPPU= +3 000 р. — экономика выходит в плюс с третьей оплаты. (М0 xlsx, файл 1, лист «подвиг 3»)

#### С COGS на каждой продаже и COGS 1st sale (комбинированная):
```
AMPPU = (Av. Price − COGS) × Av. Payment Count − COGS_1st_sale
```
(М1 xlsx, I139 = `=(J139-L139)*P139 - O139`)

#### Со скидкой:
```
AMPPU = Av. Price × (1 − Discount%) × Av. Payment Count
```
(М1 xlsx, I303 = `=J303*(1-N303)*P303`)

#### С налогом и COGS:
```
AMPPU = (Av. Price × (1 − Tax%) − COGS) × Av. Payment Count
```
(М1 xlsx, I93 = `=(J93*(1-K93) - L93)*P93`)

### 1.3 Производные формулы

#### AMPU через C1:
```
AMPU = C1 × AMPPU
```
(М0 → транскрипт, ~66 000 симв.; xlsx файл 1, U = `=F*J`)

#### Gross Profit — два эквивалентных способа (кросс-чек):
```
Gross Profit = Buyers × AMPPU
Gross Profit = Users × AMPU
```
(М0 → транскрипт, ~67 000–68 000 симв.)

#### Profit — два эквивалентных способа (кросс-чек):
```
Profit = Users × (AMPU − CPUser)    ← способ 1: от пользователей
Profit = Revenue − COGS total − Acq. Costs    ← способ 2: от денег
```
(М0 xlsx, файл 1, Y = `=C*(U-T)` и Y alt = `=Z-AC-AB`; М2 → txt)

#### Revenue — два эквивалентных способа (кросс-чек):
```
Revenue = Payments × Av. Price
Revenue = Gross Profit + COGS total
```
(М0 xlsx, Z = `=H*K` и Z alt = `=AA+AC`)

> **Кросс-чек** — расчёт одной метрики двумя независимыми способами; разность должна быть = 0. Позволяет обнаружить ошибки до движения дальше. Если не сходится — найти ошибку в данных, не двигаться дальше. (М0 → транскрипт, ~97 000 симв.; М2 → txt)

---

### 1.4 Average Payment Count (когортный)

```
APC = Суммарное число платежей когорты / Размер когорты
```
(М1 → транскрипт, раздел «Когорты»)

Пример: когорта 6 000 чел. → суммарно 7 330–7 495 платежей → APC ≈ 1,22–1,25. (М1 → транскрипт)

**Ориентиры по APC (если когорт нет):**
- Если не считали — брать 1 и 2 (самые частотные значения, «не сильно соврёте»). (М1 → транскрипт)
- Рекуррентный бизнес (подписка, привязка карты): ~3 покупки/год при retention ~60%.
- B2B с удержанием 90%: ~7 покупок/год.
- 12 покупок/год — редкость, только при годовой предоплате. (М1 → транскрипт)

## 2. Три уровня сходимости юнит-экономики

| Уровень | Критерий | Что означает |
|---|---|---|
| 1. На платящем клиенте | AMPPU > 0 | Каждая продажа прибыльна после COGS |
| 2. На привлечённом пользователе | AMPU > CPUser | Привлечение окупается с учётом конверсии |
| 3. На финансах | Profit > 0 (с учётом Fix Costs) | Бизнес прибылен с учётом Fix Costs |

(М0 → транскрипт, ~91 000–93 000 симв.; М2 → txt, раздел «Три критерия сходимости»)

**Прибыль на привлечённого пользователя:**
```
Profit per User = AMPU − CPUser
               = C1 × AMPPU − CPUser
```
Если Profit per User < 0 — каждый привлечённый пользователь генерирует убыток. Масштабирование при отрицательной юнит-экономике кратно увеличивает убыток. (М0 → транскрипт, ~90 000–93 000 симв.; М0 xlsx кейс Users ×3: Profit −1,94 → −8,82 млн р.)

## 3. Дерево метрик

```
Пользователи (Users / UA)
    │
    ├── × CPUser ──────────────────────────────────── Acq. Costs
    │
    └── × C1 (конверсия) ──────── Buyers (Покупатели)
                │
                └── × APC ──────── Payments (Платежи)
                        │
                        └── × Av. Price ─── Revenue (Выручка)
                                │
                                └── × Margin% ─── Gross Profit (Валовая прибыль)
                                          │
                                          └── − Acq. Costs ─── Profit
                                                    │
                                                    └── − Fix Costs ─── Profit net

Агрегаты:
  AMPPU = Gross Profit / Buyers
  AMPU  = Gross Profit / Users  =  C1 × AMPPU
```

(М0 → транскрипт, ~60 000–68 000 симв.; М1 xlsx лист «Шаблон», структура столбцов B–AI)

## 4. Структура издержек

Юнит-экономика разделяет издержки на **масштабируемые** и **не масштабируемые** (не «переменные/постоянные» — это бухгалтерские категории, создающие путаницу). (М2 → txt)

| Тип | Примеры | Поведение при росте продаж |
|---|---|---|
| **Масштабируемые (переменные)** | COGS на каждую продажу (упаковка, доставка, себестоимость, комиссии), COGS 1st sale (оборудование, онбординг), Acq. Costs (реклама, CPA) | Растут пропорционально числу пользователей/заказов |
| **Не масштабируемые (фиксированные)** | Зарплаты продуктовой команды (разработчики, дизайнеры, PM), аренда, серверы (если не зависят от числа пользователей кратно) | Ограничены сверху; не растут при росте продаж |

**Ловушка:** расходы на преподавателей (edtech), операционных менеджеров, службу поддержки — масштабируются с ростом, это переменные, не фикс. (М0 → транскрипт, ~55 000–62 000 симв.)

## 5. Гипотезы роста: таблица эффектов

На примере кейса «Доставка еды» (база: 50 000 Users, C1=10%, APC=1,2, Av.Price=600, Margin=5%, CPUser=10 р., Profit=80 000 р.):

| Гипотеза | Изменение | Profit | Эффект к базе |
|---|---|---|---|
| База | — | 80 000 р. | ×1 |
| Больше пользователей (+20%) | +10 000 Users, CPUser=12 | −504 000 р. | убыток (!) |
| Снизить CPUser | 10 р. → 5 р. | −84 000 р. | убыток |
| Апсел +200 р. (30% конв.) | AMPU_апсела = 0,36 р. | +18 000 р. | мало |
| Поднять конверсию ×2 | C1: 10→20% | 260 000 р. | ×3,25 |
| Рост среднего чека ×2 | Av.Price: 600→1 200 р. | 260 000 р. | ×3,25 |
| Рост APC ×2 | 1,2→2,4 | 260 000 р. | ×3,25 |
| Маржа ×3 + чек ×2 | Margin 5→15% + Av.Price ×2 | 980 000 р. | ×12,25 |
| Комбо: конв. ×2 + маржа ×3 + чек ×2 | все три | 2 060 000 р. | ×25,75 |

(М1 xlsx, лист «Шаблон», r22–r39)

**Вывод:** нелинейность из-за операции вычитания (AMPU − CPUser) означает, что комбинация улучшений даёт эффект, кратно превышающий сумму отдельных улучшений. (М1 → транскрипт, раздел «Магия кратного роста»; М2 → txt)

**Правило порядка работы с метриками:** сначала — маржинальность и средний чек, потом — конверсия, потом — поток пользователей. (М1 → транскрипт, кейс HotWiFi / Архангельск)

## 6. Алгоритм расчёта юнит-экономики

1. Задать поток Users, C1 → вычислить Buyers = Users × C1.
2. Задать Av. Price, Margin% (или COGS), APC, COGS_1st (при наличии) → выбрать формулу AMPPU по типу бизнес-модели (раздел 1.2).
3. Вычислить AMPU = C1 × AMPPU.
4. Задать Acq. Costs → CPUser = Acq. Costs / Users.
5. Вычислить Profit per User = AMPU − CPUser.
6. Масштабировать: Profit = Users × (AMPU − CPUser).
7. Вычесть Fix Costs → Profit net = Profit − Fix Costs.
8. Выполнить кросс-чеки (раздел 1.3) — убедиться, что расхождение = 0.
9. Проверить три уровня сходимости (раздел 2).

(М0 xlsx, файл ведущего; М1 xlsx лист «Шаблон»; М0 → транскрипт, ~76 000–82 000 симв.)

## 7. Паттерны по типу бизнес-модели

### Подписочный SaaS (когортная модель)

Ключевые дополнительные метрики:

| Метрика | Формула |
|---|---|
| Churn rate (месяц) | `churn_rate = buyers_churn / buyers_total_prev` (М1 xlsx, лист «Когорты Saas», E15) |
| AMPPU monthly | `AMPPU_monthly = Av. Price × Margin%` (М1 xlsx, C44) |
| Buyers_old_next | `buyers_old_next = buyers_old_prev + buyers_new_prev − buyers_churn_this` (М1 xlsx, E9) |
| Retention степенной | `retention(N) = 30% × N^(−0.3)` (М1 xlsx, Q66) |
| Gross Profit когорты | `GP_когорты = buyers_когорты × AMPPU_месяца` (М1 xlsx, N27) |

При **статичном retention** (константа по периодам): база «портится», churn_rate растёт. При **степенном retention** (`a × N^(−b)`): база и прибыль растут существенно быстрее — разница net_profit может быть почти в 2 раза. (М1 xlsx, сравнение листов «Когорты Saas» vs «Когорты v4»)

### Транзакционный (доставка, e-commerce)

- Churn rate обычно >90%/мес.
- ARPPU нарастающим итогом: `ARPPU_30 = Revenue_мес1 / Buyers_когорты`; `ARPPU_60 = ARPPU_30 + Revenue_мес2 / Buyers_когорты`.
- Прогноз через степенную функцию: `ARPPU(N) = ARPPU_1 × N^0.16`. (М1 xlsx, лист «Когорты. Доставка»)

### Агентская / комиссионная

```
AMPPU_агент = Av. Price × Av. Payment Count    (комиссия уже в Av.Price)
AMPPU_комиссия_с_COGS_1st = (Av. Price − COGS) × APC − COGS_1st
```
(М1 xlsx, лист «Экономика агенты и страховки», I5, I286)

### B2B с длинным циклом сделки

- Когорты строятся **понедельно** (не помесячно): покупки растянуты на 1–16 недель от лида.
- `Конверсия_лид = Buyers / Leads` (считать отдельно от C1 по неделям).
- ARPPU в B2B когортах может отличаться в 8 раз между когортами. (М1 xlsx, лист «Когорты, длинный цикл сделки»)

### Типология инструментов продаж по среднему чеку

| Средний чек | Инструмент | Цикл |
|---|---|---|
| >10 млн р. | СПИН, тендеры, личные встречи | 3–12 мес. |
| 1 млн р. | Личные встречи, СПИН | 1–3 мес. |
| 50–100 тыс. р. | Сейлзы + удалённо | Недели |
| 30–50 тыс. р. | Звонки, телемаркетинг, зум | Недели |
| 10–30 тыс. р. | Пуши, рассылки, CRM, чат-боты | Дни |
| 1–10 тыс. р. | Лендинги + биллинг | Минуты–дни |
| <1 000 р. | Лендинги, боты, авто-воронка | Мгновенно |

(М1 xlsx, лист «ср. чек и инструменты продаж», r1–r7)

## 8. Типичные ошибки и антипаттерны

1. **Считать среднее по каналам** вместо разбивки organic/paid/агент — маскирует убыточные сегменты. (М0 → транскрипт, ~91 000 симв.)
2. **Масштабировать убыточную юнит-экономику** — при AMPU < CPUser рост Users кратно увеличивает убыток: Users ×3 → Profit −1,94 млн → −8,82 млн р. (М0 xlsx, файл ведущего, строка 9)
3. **Не учитывать COGS 1st sale** — экономика сходится только с N-й покупки; масштабирование до сходимости → кассовый разрыв. (М0 → транскрипт, ~100 000–106 000 симв.)
4. **Считать APC без когортного анализа** — «100 чел. за год сделали 600 покупок → в среднем 6» — ошибка: реально 90% купят 1 раз. (М1 → транскрипт)
5. **Путать CAC и CPUser** — CAC в (1/C1) раз выше CPUser; использование CAC завышает эффективность привлечения. (М2 → txt)
6. **Брать конверсию из аналитики (GA/Метрика)** вместо биллинга/CRM — погрешность до 30–40%; самые надёжные данные — биллинг. (М2 → txt)
7. **Суммировать Users по каналам** — один пользователь может прийти через несколько каналов; нельзя складывать Buyers по каналам в общем случае. (М0 xlsx, файл 1, лист «подвиг 2»)
8. **Давать скидки без расчёта эффекта на маржу**: скидка 30% при узкой марже → прибыль в убыток. Формула: `Прибыль со скидкой = (Av.Price × (1 − Скидка%)) − COGS`. (М1 → транскрипт, кейс «Клуб Бритв»)
9. **Путать статичный и степенной retention** — при степенном retention прибыль когортной модели почти в 2 раза выше. (М1 xlsx, сравнение листов)
10. **Работать с конверсией, игнорируя маржинальность** — поднятие комиссии на 10 п.п. может решить задачу быстрее года работы с конверсией. (М2 → txt, кейс FlowWow)

| Термин | Определение |
|---|---|
| **UA / Users** | Поток привлечённых пользователей за период |
| **C1** | Конверсия в первую покупку (conv to buyer) |
| **APC / Av. Payment Count** | Среднее число оплат на платящего пользователя за lifetime |
| **Av. Price** | Средний чек одной транзакции |
| **COGS** | Cost of Goods Sold — все масштабируемые издержки на каждой продаже |
| **COGS 1st sale** | Единовременные издержки при первой продаже (онбординг, оборудование) |
| **AMPPU** | Average Margin Per Paying User (= CLTV) — средняя маржа с платящего пользователя за lifetime |
| **AMPU** | Average Margin Per User (= LTV) — средняя маржа с привлечённого пользователя (= C1 × AMPPU) |
| **CPUser** | Cost Per User — стоимость привлечения пользователя; не зависит от продукта |
| **CAC** | Customer Acquisition Cost — стоимость привлечения **платящего**; = Acq. Costs / Buyers |
| **CPL** | Cost Per Lead |
| **CPO / SPS** | Cost per Order / Cost per Sale |
| **Gross Profit** | Валовая прибыль: Revenue − COGS total |
| **Profit** | Прибыль: Gross Profit − Acq. Costs |
| **Profit net** | Чистая прибыль: Profit − Fix Costs |
| **Fix Costs** | Не масштабируемые (фиксированные) расходы |
| **Кросс-чек** | Расчёт метрики двумя независимыми способами; разность = 0 |
| **Кассовый разрыв** | COGS 1st sale превышает AMPU; масштабирование до сходимости ведёт к убытку |
| **Неустойчивость модели** | Нелинейный эффект: малые изменения у метрик близких к нулю (AMPU ≈ CPUser) дают кратный рост прибыли |
| **Churn rate** | Доля ушедших покупателей от активной базы в периоде |
| **Retention(N)** | Доля оставшихся через N периодов; степенная модель: `a × N^(−b)` |
| **ARPPU** | Average Revenue Per Paying User (в т.ч. накопленным итогом за N дней) |
| **CLTV / LTV** | Синонимы AMPPU / AMPU в нотации Красинского |
| **MAU** | Monthly Active Users |
| **Морфинг бизнес-модели** | Смещение продукта к соседним «работам» для улучшения метрик (частотности, среднего чека) |
| **Плечи метрик** | Анализ чувствительности прибыли к изменению разных метрик (варьирование) |
| **Масштабируемые издержки** | Издержки, растущие пропорционально объёму (COGS, Acq. Costs) |
