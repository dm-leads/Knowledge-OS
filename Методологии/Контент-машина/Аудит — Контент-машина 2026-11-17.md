## Пять ответов

### 1. Логика

Цепочка от спроса до выкладки одна и та же в карте, методологии каталога, навыке и коде (`next` операций) — факт.
Разрывы:

- **Ставка стоит сбоку.** На `queue bet` указывает только `queue card` (`contracts.yaml`); у `queue take` — лишь
  пометка «лучше под гипотезу со ставкой». Тема без ставки проходит до публикации; машина предупреждает при брифе,
  тексте и записи выкладки, а замер даст «ставки нет — сравнивать не с чем» — факт (`core/bets.py`, `bet_missing`).
- **От выпуска к доказательству перехода нет.** `index status` — тупик; контур Д включается только расписанием, а его
  у первого проекта не ставили — факт.
- **Граница с Движком роста намеренная, но без переносчика.** Статус гипотезы меняет только Движок (`bets_cmd.py`):
  `bet propose` пишет файл-предложение, назад приходит решение `kill`/`scale` по направлению — факт. Пробел в том, что
  никто не переносит предложение в Движок ни по расписанию, ни по чек-листу — оценка.
- **Документы отстают от кода:** манифест машины — на волне 1, карта — от 25.10, «Карта Knowledge-OS» — выпуск 1.5.2
  при фактическом 1.5.4 — факт.

### 2. Источники

Из 126 механик К. Васина взяты 122, 4 отклонены с причиной; своих 29, главная их часть — деньги (факт, сверка).
Противоречие не между Васиным и нами, а между нашим денежным слоем и нашими же стандартами: итог ставки и закрытие
направления без гейта шума, три разных «позиции» под одним именем, «деньги страницы» без когорты и атрибуции Ядра
данных, окупаемость по выручке вместо маржи (факт по текстам). SEO-канон (04–06.11) написан позже машины, ссылок между
ними нет ни в одну сторону — отсюда JSON-LD по умолчанию против правила Microdata для Яндекса и дожим по возрасту,
который может тронуть лидеров выдачи (факт). Полная таблица — раздел «Противоречия источников».

### 3. Работает ли

Подтверждено живым запуском у первого проекта: А1–А3, Б2, Б4, Б5, В1–В7, Г2, Г4 и ручная Г1 — 15 статей (факт).
Только тестами и прогонами на копии инстанса: судья, `publish apply` и откат, `index submit`, весь контур Д
(пульс, замер ставки, экономика, аудит, дожим, ИИ-видимость, поведение), заморозка дальше скана, разведка, «поле
шире» — факт. Учёт отстаёт от сайта: 5 статей открываются, а в машине «взято»; у трёх «не доехало» — на сайте из
title пропало двоеточие (факт, отчёты «Доехало» 16.11).

### 4. Адаптивность

Всё проектное — в профиле (441 строка, каждое поле обязательно, молчаливых значений нет) и адаптерах инстанса; в
шаблоне и коде пакета нет ни одной привязки к первому проекту (факт: шаблон, тест границы пакета). У первого проекта
под себя написаны сборщик конструктора, картинки kie.ai + S3, запись в Google-таблицу, деньги за окно из Roistat
(последний не подключён) — факт. Учиться машина умеет только через Движок роста: решение `kill`/`scale` меняет очередь,
дожим берёт страницы по позициям (факт, код). На деле петля не замыкалась ни разу (факт). Обучения «какие типы тем
сыграли» внутри машины нет — оценка.

### 5. Перенос

Да, но не «одним профилем». Выпуск ставится одной командой, самопроверка честно называет каждое «не подключено» с
подсказкой (факт). Ломается: без Keys.so или Yandex Search API кластеры не строятся и очереди нет; корпус читается
только из папок markdown с шапкой — сайту с историей на CMS нужен экспорт всех текстов, иначе анти-дубли его не видят;
у нового сайта без статей самопроверка всегда красная; прямую публикацию в CMS никто не проверял — нужен свой сборщик
или публикатор; без источника денег вся денежная часть даёт «нет данных» (факт). Оценка времени: 1 день на профиль и
доступы, 1–2 дня на экспорт корпуса у сайта с историей, 1–3 дня на сборщик под CMS, первая статья — день.

## Чек-лист переноса в новый проект

**Что нужно от проекта**

| Что | Обязательно | Зачем |
|---|---|---|
| Ниша: кластер 10–15 запросов с сотнями показов, регион не узкий | да | машина забирает спрос, а не создаёт |
| Источник выдачи: `KEYSO_API_KEY` или `YANDEX_SEARCH_API_KEY` + `YANDEX_FOLDER_ID` | **да** | без него нет кластеров и очереди |
| Консоли: Search Console (файл сервисного аккаунта), Вебмастер (`YANDEX_WEBMASTER_TOKEN`) | для сайта с историей — да; для нового — со дня запуска | спрос по своим показам, пульс, индексация |
| Корпус: папка markdown с шапкой (slug, title, url) — экспорт всех опубликованных текстов; карта сайта — только сверка | для сайта с историей — да; новому — пустая папка | анти-дубли видят живые страницы |
| CMS: ручная вставка или публикатор (`static_repo`, `cms_api`, свой `module:`) + сборщик | да, режим — решение | `apply` нигде не проверен — закладывать день-три |
| Источник денег по страницам и за окно (Ядро данных, CRM, CSV) | для денежного слоя — да | без него ставка, экономика и закрытие — «нет данных» |
| Источник гипотез Движка роста | для ставок — да | без него ставка вручную |
| Генератор картинок и хранилище — своё, не первого проекта | по желанию | платно, с ценой и «да» |
| Файл секретов вне git | да | только имена переменных в профиле |

**Шаги**

1. Подключить проект к канону (плейбук «Подключить проект к канону»): паспорт, журнал, база инцидентов.
2. `kos_release.py issue --package _Движок/Пакеты/content_engine --into <проект>/Скрипты/content_engine --first`.
3. Сайт с историей — выгрузить все опубликованные тексты в папку markdown с шапкой; новый сайт — создать пустую папку.
   `content-engine profile template > content_instance/profile.yaml`, заполнить: домены, разделы, регион и базы
   выдачи, источники, корпус, роли моделей (`-latest`), `schema_format: microdata` под Яндекс, права — ступень `files`.
4. `profile check` → `check` → починить красное и однозначное.
5. `onboard` — годность ниши, два решения человека (режим вычитки, ритм выпуска).
6. `demand collect` → `cluster` → `map build` → `queue build` → `queue refill`.
7. Ставки: подключить источник гипотез, `queue bet` для каждой темы до взятия; `bets.min_step: 1`, если итог ставки
   должен опираться только на деньги.
8. Первая статья по маршруту каталога: `queue take` → `prepare` → `write` → `review` → `gate article` → `images` →
   `assemble build` → публикация → `publish verify`.
9. В тот же день: деньги за окно, `schedule install --apply` по «да», первый `pulse run` и `bet backfill`.
10. Свои известные ответы (`known-answers`), запись в журнал проекта.

**Время** — оценка: шаги 1–5 — день; экспорт корпуса у сайта с историей — 1–2 дня; сборщик или публикатор под CMS —
1–3 дня; первая статья — день; денежный слой — по готовности данных проекта.

**Риски:** нет источника выдачи — машина стоит на шаге 6; нет экспорта корпуса — анти-дубли пропускают живые
страницы (Н17); новый сайт — красная самопроверка (Н7) и пустые консоли
первые недели; прямая публикация не обкатана; денежный слой без гейта шума (Н2) даст ложные итоги, как только
появятся деньги.
