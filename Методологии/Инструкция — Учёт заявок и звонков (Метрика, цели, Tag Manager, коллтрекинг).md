# Инструкция — Учёт заявок и звонков (Метрика, цели, Tag Manager, коллтрекинг)

## Краткая суть

- **Цель должна означать заявку, а не жест.** Клик по кнопке, клик по номеру, автоцель «Отправка формы» срабатывают без
  заявки: пустая форма, неудачная отправка, боты в РСЯ («достижений в 5 раз больше, чем заявок» — Строков). Надёжная цель
  — событие успешной отправки формы, звонок через коллтрекинг, оплата.
- **Каждую цель проверить руками до запуска рекламы** и сверить число заявок в Метрике с фактом в CRM или у владельца
  — при старте и затем регулярно. Необъяснённые потери или дубли — рекламу не масштабируют.
- **Различать обращения и людей.** Один человек оставляет заявку, звонит и пишет — это три обращения, но, возможно, один
  клиент. Сколько людей — дедупликация в CRM; в Метрике — целевые посетители по объединению макроцелей, а не сумма
  достижений.
- **Звонки без коллтрекинга не видны.** Если звонки — заметная доля обращений, коллтрекинг ставится до старта рекламы.
- **Метрика — заменитель денег.** Решение о канале — по оплатам из учётной системы ([Ядро данных](<Ядро данных/_manifest.md>)),
  Метрика даёт заявки и путь до них.
- Пути в интерфейсе меняются: в тексте они даны на дату проверки, перед работой смотреть справку.

Пометки: **MAED** (2022), **Строков**, **Пресняков** (2025) — откуда правило; **[вывод]** — наше; **[справка]** —
сверено с официальной справкой 10.11.2026 ([сверка со ссылками](<_исходные-заметки/MAED — Директор по digital-маркетингу (2026-10)/Сверка — Интерфейс Метрики, Директа, Tag Manager, Callibri на 10.11.2026.md>)).
Адреса в курсах — в выжимках
`_исходные-заметки\MAED — Директор по digital-маркетингу (2026-10)\`.

## Шаг 1. Счётчик

1. **Один счётчик — один способ установки**: либо кодом на сайте, либо через Tag Manager. Стоит в двух местах —
   визиты удваиваются (MAED). Код — на все страницы, как можно выше в `<head>`.
2. **При создании**: Вебвизор и карты включить сразу; поддомены и несколько адресов — если они есть; фильтр «Не
   учитывать мои визиты»; фильтры по IP своих офисов — до 30 фильтров (MAED, Строков) **[справка]**. Роботов,
   представившихся явно, Метрика исключает сама; «Фильтровать роботов по поведению» удаляет данные безвозвратно —
   Яндекс не рекомендует включать без необходимости **[справка]**.
3. **Конструктор (Тильда и подобные)**: номер счётчика — в настройках аналитики сайта, после этого **опубликовать**
   все страницы, иначе счётчик не встанет (Строков).
4. **Номер счётчика для рекламного кабинета** брать из кода живого сайта, а не со слов владельца: «может быть каша»
   (Строков).
5. **Проверить установку**: «Настройка → Проверка счетчика»; затем на сайте с параметром `_ym_debug=2` — панель
   отладки (значок внизу страницы). Панель работает с новым кодом счётчика; со старым кодом — консоль браузера
   **[справка]**. Свои визиты отфильтрованы — тестировать в режиме инкогнито или с другого устройства (MAED).
6. **Доступы**: владелец — у компании; подрядчику — по необходимости; при уходе подрядчика доступ закрыть.

## Шаг 2. Список действий на сайте

Пройти сайт сверху вниз и выписать каждое действие, которое может стать обращением (Пресняков):

| Где (страница, блок) | Действие | Способ отследить | Идентификатор цели | Сработала ли | Примечание |
|---|---|---|---|---|---|

Заодно — убрать на сайте то, что не отследить (Строков): **один номер телефона** под подмену коллтрекингом (два номера
— половина звонков не видна); у каждой формы — понятный результат отправки. Проход часто находит поломки сайта
(кнопка «Скачать прайс» не работает).

## Шаг 3. Цели по надёжности

Типы целей Метрики на 10.11.2026 **[справка]**: посещение страниц, количество просмотров, продолжительность визита,
**«Целевое событие»** (так теперь называется цель на JavaScript-событие), составная цель (до 5 шагов, до 10 условий
«ИЛИ» в шаге, шаги по порядку в одном визите), мультицель, звонки, чаты; отдельно — **автоцели** (клики по телефону и
почте, отправка формы, переходы в мессенджеры и соцсети, скачивание файлов, поиск по сайту и др.), их Метрика создаёт
сама. Две разные оси: **что отслеживаем** (тип действия) и **как создана цель** (вручную или автоматически). Ту же
«Отправку формы» можно настроить вручную на конкретную форму; надёжность решает проверка конкретной реализации (шаг 6),
а не название цели.

| Цель | Способ | Для обучения рекламы | Источник |
|---|---|---|---|
| Заявка — по факту успешной отправки формы | JS-событие из кода сайта или Tag Manager (шаг 4) | **да**, первый выбор | Строков, Пресняков |
| Заявка — страница «Спасибо» | цель «Посещение страниц» | да, если страница открывается только после отправки и закрыта от индексации | Строков — основной способ; Пресняков — не советует: страницу сохраняют и открывают повторно |
| Звонок | коллтрекинг, интеграция с Метрикой (шаг 5) | **да** | Строков, MAED |
| Оплата онлайн | JS-событие или электронная коммерция; плюс цель «Возвращение из платёжной системы» | да | Пресняков |
| Квиз, чат, оплата сторонним сервисом | JS-событие с идентификатором из справки сервиса | да, если сервис отдаёт событие | Пресняков |
| Автоцель «Заполнение контактных данных» | автоцель | с осторожностью | Строков |
| Переход в мессенджер, клик по почте | автоцель или Tag Manager | вспомогательная | Пресняков, Строков |
| Клик по номеру телефона | автоцель | **нет**: только мобильные, не каждый клик — звонок, в РСЯ скликивают | Строков |
| Клик по кнопке | Tag Manager | **нет**: нажал — не значит отправил | Строков, Пресняков |
| Автоцель «Отправка формы» (все формы) | автоцель | **нет**: ловит пустые формы и ботов | Строков, Пресняков |
| Время на сайте, глубина просмотра | микроцель | **нет**: часто не связана с заявкой | Пресняков |

**Составная «склейка»**: если макроцелей мало для обучения стратегии — составная цель с одним шагом «заявка ИЛИ
звонок ИЛИ чат» (Пресняков). Порог обучения — по справке Директа (шаг 7).

**Оплата через платёжную систему**: посетитель уходит на страницу банка и возвращается — визит дробится, источник
подменяется («два человека — один заказ»). Цель «Возвращение из платёжной системы» — заменитель оплаты, не оплата.
Пресняков советует при расхождении цели оплаты и возврата в 2–3 раза оптимизировать по возврату; **сначала** сверить
обе цели с подтверждёнными оплатами по номерам заказов (неуспешные платежи, повторные возвраты) и брать для
оптимизации ту, что ближе к факту **[вывод]**. Исправление источника после платёжки — отдельная задача (исключить домен
платёжной системы из источников по справке Метрики).

**Интернет-магазин** — электронная коммерция обязательна, внедряет разработчик или модуль CMS (Пресняков). Маркетолог
ставит задачу и принимает: электронная коммерция включена в настройках счётчика; имя массива данных (по умолчанию
`dataLayer`) совпадает в настройках и коде; события `detail`, `add`, `remove`, `purchase` с id, названием, ценой,
количеством, номером заказа **[справка]**; тестовая покупка видна в отладке, а номер заказа и сумма совпадают с
учётной системой.

**Имена целей** **[вывод]**: `тип_действие_место` латиницей (`lead_form_header`, `call`, `pay_success`); одно имя — одна
цель навсегда. **Цели, на которых обучена кампания, не удалять** — стратегия теряет ориентир (Строков); менять через
новую цель.

## Шаг 4. Цели через Tag Manager

Нужен, когда у сайта нет события отправки в коде, а программиста нет (Пресняков). Цель через Tag Manager — три части:
цель «Целевое событие» в Метрике + тег «Пользовательский HTML» с `ym(<номер>, 'reachGoal', '<идентификатор>'[, параметры])`
+ триггер на действие. **Идентификатор в Метрике и в теге совпадает посимвольно**; в нём нельзя `/ \ & # ? = "`, знак
`+` заменяют на `%2B` **[справка]**.

**Установка контейнера** (MAED, Пресняков): первая часть кода — как можно выше в `<head>`, вторая (`noscript`) —
сразу после `<body>`; на Тильде — ID контейнера в настройках аналитики сайта и переопубликовать все страницы; на CMS —
код из Tag Manager передать разработчику как задачу. Проверить, что контейнер загружается (предварительный просмотр
показывает «Container Loaded»). Если счётчик Метрики переносится в контейнер — ручной код удаляется в момент публикации.

**Порядок**: сначала цели в Метрике, потом теги; триггер всегда сужен условием (Click ID, Click Classes, Click URL) —
триггер «все клики» без условия даёт «срабатывает на всё подряд». Несколько условий в одном триггере — «И»; несколько
триггеров у тега — «ИЛИ».

**Рецепты** (Пресняков, готовый контейнер):

| Что | Триггер |
|---|---|
| Клик по телефону | клик по ссылке, Click URL содержит `tel:` |
| Клик по почте | клик по ссылке, Click URL содержит `mailto:` |
| Переход в мессенджер | Click URL по регулярному выражению (t.me, wa.me, vk.me и т. д. — дополнить мессенджерами проекта, например MAX) |
| Копирование телефона и почты | свой HTML-слушатель событий копирования на ссылках `tel:` и `mailto:` |
| Отправка формы | **один из трёх способов** — событие платформы в dataLayer (на Тильде `submit_form_<номер>`), встроенный триггер «Отправка формы», «Видимость элемента» на сообщение об успешной отправке. Какой работает — проверить на сайте |
| ClientID в параметры визита | тег берёт `getClientID` и отправляет параметром визита Метрики. В CRM он сам не попадает — см. шаг 8 |

**Проверка**: режим предварительного просмотра Tag Manager — **публиковать для проверки не нужно**, просмотр показывает
текущий черновик (Preview → адрес сайта → Connect → вернуться в Tag Assistant) **[справка]**. Нажать каждую кнопку,
отправить каждую форму, увидеть, какой тег сработал; затем — достижение цели в Метрике (с задержкой). Публиковать
версией с понятным названием; откат — к прошлой версии. Триггер «Видимость элемента»: по умолчанию 50 % видимости;
для сообщения, которое появляется после отправки, включить наблюдение за изменениями DOM **[справка]**.

**Чужой готовый контейнер** импортировать только с разбором: в контейнере Преснякова шесть тегов «Телеграм» отправляют
страницу, UTM-метки и ClientID в Apps Script и Telegram-бот прежнего клиента. До первой публикации: **удалить чужие
теги и константы**, подставить свой номер счётчика, сверить идентификаторы целей с Метрикой, события платформы и
классы кнопок со своим сайтом, просмотреть все теги, которые отправляют данные наружу, — иначе данные посетителей
уходят третьему лицу и за рубеж (политика ПДн, локализация). Затем предварительный просмотр и публикация.

При импорте: «Перезаписать» заменяет всё; «Объединить» — с переименованием конфликтующих; перед подтверждением
просмотреть список добавлений, изменений и удалений **[справка]**.

**Доступы** **[справка]**: в контейнере четыре уровня — чтение, редактирование, утверждение (создаёт версии, не
публикует), публикация. Подрядчику — редактирование; публикует владелец или назначенный им человек (политика: «доступ
не равен разрешению»).

## Шаг 5. Коллтрекинг

**Нужен ли** — если звонки заметная доля обращений. Ориентир Преснякова — от 30 % обращений; MAED — «много звонков и
значимый бюджет»; канон — «если звонки значимы, обязателен».

| Вид | Что видно | Для чего |
|---|---|---|
| Статический | канал (свой номер на канал или носитель) | карты, справочники, офлайн, визитка в поиске |
| Динамический | кампания, объявление, ключ (номер из пула на посетителя на время) | Директ, ВК |
| Комбинированный | динамика на рекламу, статика на остальное | малый бизнес — меньше номеров |

**Сколько номеров** — источники расходятся:

| Источник | Правило |
|---|---|
| MAED 2022 | визиты в день / 100 + 1; всегда один статический номер — звонок на него значит, что номеров не хватает; минимум 2–3; точно — после недели статистики |
| Пресняков 2025 | около 1 номера на 100 посещений в сутки по типичному дню; до 100 — один номер |
| Callibri, справка на 10.11.2026 | **максимум одновременных визитов в минуту + 1 резервный номер**, с учётом длительности сессии и пиков **[справка]** |

**Берём** **[вывод]**: расчёт по одновременным визитам канала подмены и резерв по справке выбранного сервиса;
«визиты в сутки / 100» — только грубая прикидка до статистики. Резерв ёмкости пула и статический номер, который
показывается, когда пул исчерпан (индикатор MAED), — разные механизмы: как ведёт себя сервис при нехватке, смотреть в
его справке. Контролировать: пиковую одновременную нагрузку, срок закрепления номера, журнал нехватки номеров и долю
звонков, не связанных с визитом. Чем меньше номеров при пересекающихся визитах, тем выше риск приписать звонок не тому
посетителю — до ключевой фразы такие данные ненадёжны.

**Бесплатный коллтрекинг Директа** («Динамический коллтрекинг β») **[справка]**: только Россия; привязывает звонок к
кампании, объявлению и фразе; журнал и записи хранятся два месяца; доступен в Простом старте и Единой перфоманс-
кампании при правах владельца или представителя организации в Яндекс Бизнесе. Работает в местах показа Яндекса —
поиск, списки организаций, Карты (с исключениями) — и **не подменяет номер на вашем сайте**. Для звонков с сайта нужен
сервис коллтрекинга.

**Настройка** (Пресняков, Callibri — пример сервиса):

1. Основной номер — в своей телефонии; номер сервиса — «расходник», переадресация на ваш номер (MAED).
2. Подмена только для рекламы: условие — переход из Директа или UTM-метки; для ВК — свои метки.
3. Интеграция со счётчиком Метрики: отдельные цели по звонкам, чатам, почте; классы обращений (лид, спам) ставят
   менеджеры; что отправлять — только первичные или все обращения. Конверсии передаются по динамическим каналам при
   наличии ClientID **[справка Callibri]**.
4. Цели по звонкам Метрика создаёт сама — в течение суток после первой передачи данных, а не в момент подключения;
   отчёты — в группе «Звонки» **[справка]**.

**Целевой звонок** — карточка метрики по стандарту консистентности, одна на все отчёты **[вывод]**: порог длительности
(в кейсе MAED — дольше минуты), первичные или все, класс «лид». Изменить определение — новая метрика с новым именем.

**Ограничения** (MAED): часть звонков не связывается с визитом; номер может достаться не тому посетителю; спам-атаки;
без меток не виден ключ; атрибуция — по последнему переходу. **Решать по накопленной статистике, а не по одному-двум
звонкам.**

**Включение и отключение коллтрекинга** — примечание в Метрике и строка в журнале действий проекта: после отключения
цели звонков показывают ноль, и без пометки его читают как поломку (опыт проекта, 05.2026).

**Право**: номера звонящих и записи разговоров — персональные данные; где хранит данные сервис и есть ли договор
поручения — по [политике ПДн](<Политика — Персональные данные, секреты и доступ к внешним системам.md>), раздел
«Обязанности оператора». Предупреждение о записи разговора Пресняков объясняет требованием закона — нормы в наших
источниках нет, вопрос юристу. Рекламные звонки и рассылки — [справочник маркировки](<Платный трафик/Справочник — Маркировка интернет-рекламы.md>), раздел «Рассылки и звонки».

## Шаг 6. Проверка до запуска и сверка с фактом

1. **Каждое действие из списка шага 2** выполнить на сайте в режиме отладки (`_ym_debug=2` или предварительный
   просмотр Tag Manager) и увидеть срабатывание нужной цели (Пресняков).
2. **Пустая форма**: отправить форму без данных — цель сработала, значит цель брак (Пресняков).
3. **Сквозной тест формы** **[вывод]**: заполненная форма — заявка дошла до CRM или почты; одна принятая отправка —
   одно событие; повторное нажатие и повторный показ сообщения об успехе не дают второй цели; при ошибке отправки цель
   не срабатывает.
4. **Тестовый звонок** на подменный номер из рекламного перехода — звонок появился в сервисе и в Метрике.
5. **Сверка при старте** (Строков) и затем регулярно: число заявок и звонков в Метрике против факта в CRM или у
   владельца за один и тот же период, с учётом задержки данных. Сравнивать одинаковые единицы: обращения с
   обращениями, уникальных — с уникальными. Не сходится — разбирать цели; Метрика сходится, кабинет показывает меньше —
   смотреть, сколько заявок с рекламы, с поиска, с прочего. Расхождение между системами неизбежно — масштабирование
   блокируют необъяснённые существенные потери или дубли, а не любое отличие (порог — правило проекта).
6. **Дальше — регулярно**: кабинет против Метрики против учётной системы ([Пороги решений](<Платный трафик/Справочник — Пороги решений и статистика.md>), раздел 5).

## Шаг 7. Передача целей в Директ

- Счётчик указан в параметрах кампании; оптимизация — по надёжной цели (заявка, звонок, оплата) (Строков).
- Порог объёма: справка Директа — «выберите цель, которая достигается не реже 10 раз в неделю», бюджет — на 10–20
  конверсий в неделю **[справка]**. Мало конверсий — составная «склейка» или стратегия без оптимизации по конверсиям
  ([метод Строкова](<Методология — Контекстная реклама (метод Строкова).md>), раздел 2).
- Ключевые цели Директа считают рентабельность только внутри Директа; доход в Метрике — ценностью цели, из CRM или
  электронной коммерции (MAED).

## Шаг 8. Деньги и атрибуция

**Расходы и доход в Метрике** (MAED): UTM-метки на всех рекламных ссылках (обязателен `utm_source`); расходы других
каналов загружаются в Метрику — **без НДС**, как расходы Директа, иначе каналы несравнимы; расходы Директа приходят
сами, повторная загрузка их задвоит **[справка]**. Офлайн-конверсии из CRM — загрузкой CSV или через API, нужен хотя
бы один идентификатор: ClientID, UserID, yclid или PurchaseId **[справка]**.

**Связка с CRM** **[вывод]**: получить ClientID на странице → передать его вместе с заявкой (скрытое поле формы или
коллтрекинг) → сохранить в карточке CRM → при оплате связать со статусом и временем → загрузить в Метрику в отдельную
цель → проверить в отчёте загрузки, сколько строк принято и сопоставлено с визитами. Срок дописывания считается от
визита до обработки загрузки — выгружать часто, особенно пока действует специальный режим.
Обычный срок, в который конверсия дописывается к визиту, — 21 день; **на 10.11.2026 Метрика в «специальном режиме»**:
срок временно 10 дней для визитов из Директа и 3 дня для остальных — проверять статус режима в справке **[справка]**.

**Атрибуция** — решение об отключении канала не принимают по одной модели (MAED). Модели Метрики на 10.11.2026
**[справка]**: «Последний переход», «Первый переход кросс-девайс», «Последний значимый переход кросс-девайс»,
«Автоматическая атрибуция»; четыре старые модели отключены с 20.05.2026; в «специальном режиме» модели с историей
визитов ограничены, история учитывается заново с 11.10.2026. В каждом отчёте явно смотреть, какая модель выбрана.

- длина цикла — отчёт «Время с первого визита»; эвристика MAED без данных: короткий цикл — последний значимый
  переход, длинный — первый переход и ассоциированные конверсии; MAED сам советует отвечать на девять вопросов (длина
  решения, число касаний, известность бренда и др.) и сравнивать модели между собой. Поведение когорт — «Отчёты →
  Retention», «Когортный анализ» **[справка]**;
- **оценка кампании вилкой** **[вывод по MAED; в курсе — на данных Google Analytics]**: снизу — заявки по модели
  «Последний значимый переход кросс-девайс»; сверху — заявки посетителей, в пути которых кампания была хоть раз
  (сегмент Метрики по источнику за окно, равное длине цикла). Результат сравнивать с экономическим пределом цены заявки
  или покупателя (Красинский). Решение — только после окна дозревания когорты: укладывается и снизу — усиливать; не
  укладывается и сверху — отключать или переделывать; между — дорабатывать; мало данных или нет истории визитов
  (специальный режим) — верхняя оценка недоступна, ждать;
- брендовые запросы отделять от небрендовых — иначе бренд «забирает» заслугу рекламы.

**Вебвизор и карты** — источник гипотез о сайте, а не решение о рекламе: «что хотите увидеть, то увидите» (Строков);
карты кликов и прокрутки статистичнее. Полезные сегменты: «дошёл до оформления и не купил», «страница входа»,
скликивание — много коротких визитов с одинаковыми источником, ОС и браузером (MAED).

## Типовые ошибки

| Ошибка | Симптом | Защита |
|---|---|---|
| Счётчик дважды (код + Tag Manager) | визиты удвоились | один способ установки |
| Цель на жест | достижений больше заявок; в РСЯ — в разы | цель по факту отправки; тест пустой формой |
| Повторное «Спасибо» | цель срабатывает без заявки | событие отправки или защита страницы |
| Два номера на сайте | половина звонков не видна | один номер под подмену |
| Потеря меток на редиректах | нет фразы и источника | сохранять yclid и UTM при переадресации |
| Подмена источника платёжкой | «два человека — один заказ» | исключить платёжную систему из источников; сверка целей с оплатами по номерам заказов |
| Удалили цель обучения | стратегия теряет ориентир | цель не удалять, вводить новую |
| Счётчик со слов владельца | в кампании чужой номер | номер из кода сайта |
| Конструктор без публикации | счётчик не встал | опубликовать |
| Достижения вместо людей | заявка + звонок = 2 клиента | обращения отдельно, клиенты — дедупликацией в CRM; в Метрике — целевые посетители по объединению макроцелей |
| НДС в расходах | каналы несравнимы | всё без НДС |
| Отключение по последнему клику | режут вспомогательный канал | вилка оценок, ассоциированные конверсии |
| Чужой контейнер Tag Manager | данные уходят третьему лицу | удалить чужие теги до публикации |
| Ноль звонков после отключения коллтрекинга | читают как поломку | примечание в Метрике и журнал действий |

## Чего инструкция не покрывает

- Пиксель и передачу событий в VK Рекламу — в источниках нет; см. навык `ads-vk` и справку VK Рекламы.
- Сквозную аналитику с хранилищем — это [Ядро данных](<Ядро данных/_manifest.md>).
- Выбор сервиса коллтрекинга и цены — по рынку на дату.
- Google Analytics: для проекта в России с Директом и ВК необязателен; старая версия (Universal Analytics) закрыта.
