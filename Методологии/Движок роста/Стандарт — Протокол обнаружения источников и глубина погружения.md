# Стандарт — Протокол обнаружения источников и глубина погружения

## Краткая суть

- Система не знает заранее, какие данные есть у компании. **Шаг 0** — интервью по шести
  классам источников плюс пробы доступа; результат — «Карта источников» со статусами.
- Класс определяется **вопросом, который источник закрывает**, а не названием сервиса.
  Маршрутизатор планирует путь по классам.
- **Диалоги клиентов** — полноправный класс (F), а не дополнение: цифры говорят *где*, диалоги —
  *почему*.
- Диагноз не завершён, пока не достигнута **единица действия** — уровень, на котором можно
  что-то конкретно изменить. У каждого класса своя лестница спуска; где данные кончаются,
  в маршрут встаёт шаг добычи, а не догадка.
- Число без знаменателя не факт на любой ступени.

## Что нормируется

Шаг 0 алгоритма ([методология](<Методология — Движок роста (цикл, ворота, маршрутизатор).md>)),
артефакт «Карта источников» и ворота шага 3 «спуск до единицы действия».

## Требования к результату

### 1. Шесть классов источников

| Класс | Примеры (обобщённо) | Какие вопросы закрывает | Что теряется без него |
|---|---|---|---|
| **A. Поведение на сайте** | веб-аналитика | визиты, страницы, конверсия первого шага, устройства, поведение | нет разреза по страницам; конверсия только из сквозной |
| **B. Платный трафик** | рекламные кабинеты | расход, клики, CPU по каналу и кампании | нет CPUser → нет сходимости на уровне привлечённого |
| **C. Сквозная аналитика / воронка** | сквозная система или CRM-воронка | заявки → квалификация → передано в продажи → продажи по каналам | нет связи канал → деньги; всё канальное = `proxy` |
| **D. CRM и деньги** | CRM + учётная система | покупатели, оплаты, чек, маржа, COGS | нет AMPPU/AMPU → модель лидовая, что помечается явно |
| **E. Внешний спрос** | частотность запросов, позиции, выдача, тренды; панели вебмастеров поисковых систем; базы выдачи с данными о конкурентах | спрос, сезонность, позиции, конкуренты: по каким запросам они стоят, что покупают в рекламе, где их цитируют | нет потолка рынка и сезонной поправки; разрывы с конкурентами — догадка |
| **F. Диалоги клиентов** | записи звонков, переписки, отзывы, тикеты, интервью | **почему** не покупают: барьеры, возражения, работы, язык выгоды, скрытые источники обращений | гипотезы строятся только на цифрах — «что» без «почему» |

Для класса F минимальный путь при отсутствии системы речевой аналитики: выборка 20–40 диалогов
и извлечение фактов с дословной цитатой. Правило переносимо: **нет цитаты — нет факта**;
факт виден агрегатам при ≥20 наблюдениях.

### 2. Интервью обнаружения

Идёт по классам, а не по анкете. По каждому классу три вопроса: *есть ли такой источник; кто
владеет доступом; с какой даты история*. Ответ «есть» без пробы доступа статуса `подключён`
не даёт: тихие ошибки авторизации выглядят как «данных нет».

Повтор — инкрементально перед каждым циклом: «появилось ли что-то новое, что-то отвалилось».

### 3. Артефакт «Карта источников»

По каждому источнику:

| Поле | Значения |
|---|---|
| класс | A–F |
| статус | `подключён` · `есть, нет доступа` · `нет` · `не применимо для этого бизнеса` |
| глубина истории | с какой даты; известные обрывы |
| точка истины | за что отвечает; **точки истины разных источников не смешиваются** |
| известные ловушки | инстанс-специфично: пустые метрики, сломанные формулы, фильтры, режущие знаменатель |
| проба доступа | одна команда или один запрос, воспроизводимый |
| секреты | только **имена** переменных окружения, никогда значения |

### 4. Лестница глубины — до единицы действия

Правило: гипотеза формулируется только на единице действия. С более высокого уровня она не
принимается валидатором реестра.

| Класс | Лестница (сверху вниз) | Единица действия | Если данных нет на нижней ступени |
|---|---|---|---|
| **A** | канал → тип страницы → **URL** → блок / скролл / клик / событие → шаг формы или квиза → устройство | блок, CTA, шаг формы на конкретной странице | поставить события — шаг добычи в маршрут; до этого коридорный тест или записи сессий на 20 визитах |
| **B** | канал → кампания → группа → ключ / креатив → посадочная → устройство / регион | ключ × посадочная × устройство | разрез по устройству обязателен: сломанная мобильная версия выглядит как «нецелевая аудитория» |
| **C** | компания → канал → **поток** (веб / без визита / офлайн) → страница входа → сделка → этап остановки | этап × поток × источник | без разделения потоков конверсия первого шага может быть смешанной метрикой — стоп |
| **D** | компания → сегмент (ABCDX) → продукт → сделка → менеджер → задача после разговора | сегмент × продукт × менеджер | нет полей — задача владельцу CRM с обоснованием в ₽ |
| **E** | **поисковая система** → категория → куст запросов → запрос → позиция × URL → сезон помесячно | запрос × наша страница × позиция в конкретной системе | нет истории — честно; тренд не выдумывать |
| **F** | корпус → сегмент / контур → **этап разговора** (контакт → выяснение → оффер → возражение → решение) → **паттерн обрыва** → диалог с цитатой и ссылкой | паттерн: на каком этапе, какими словами, после чего клиент уходит — с N примерами и долей от базы | выборка руками + экстракция с цитатами; порог ≥20 фактов на паттерн |

Два правила класса E:

- **Поиск — не один канал.** До диагноза поискового трафика он делится по системам (веб-аналитика и панели
  вебмастеров): спад в одной системе при ровной другой — другой диагноз и другие гипотезы. Пример первого инстанса:
  «поиск −33 % год к году» оказался целиком спадом одной системы.
- **Базы выдачи — оценка, а не факт своего сайта.** Их трафик и бюджеты — модель сервиса со статусом `оценка`;
  своя видимость — факт панелей вебмастеров и веб-аналитики. Базы выдачи дают материал и идеи (чужие запросы,
  реклама, страницы, ссылки); основание кандидата и главная метрика теста берутся из своих источников.

Три следствия, вшитые в алгоритм:

1. Шаг 3 заканчивается на единице действия, а не на метрике. «Узкое место — конверсия» не
   принимается; принимается «узкое место — поток без визита, −N заявок, причина не установлена →
   следующая ступень: диалоги + журнал изменений CRM».
2. Количество и качество идут парой на каждой ступени. Спуск по A или C без ступени F даёт
   гипотезу-догадку; маршрутизатор помечает это понижением уверенности.
3. «34 диалога с возражением» — из скольких, за какой период, какая доля. Без знаменателя —
   не факт.

## Способ проверки

- Гейт инстанса проверяет: у каждого источника со статусом `подключён` проба выполняется
  и возвращает данные; у каждого — заполнена точка истины и глубина истории.
- Валидатор реестра отвергает гипотезу, у которой поле «единица действия» пусто или
  указывает на уровень выше нижней ступени класса.
- Ревью маршрута цикла: для каждого шага перечислены классы; для отсутствующих — одно из
  четырёх решений маршрутизатора.

## Исключения

- Бизнес без сайта → класс A `не применимо`, лестница C начинается с потока «офлайн».
- Бизнес без платного трафика → класс B `не применимо`; сходимость на уровне привлечённого
  считается по стоимости производства канала, если она известна, иначе `нет данных`.
- Исключения фиксируются в конфигурации инстанса, а не в каноне.
