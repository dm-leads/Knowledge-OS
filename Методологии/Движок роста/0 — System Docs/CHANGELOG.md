## 2026-11-22 — growth_engine 1.9.0: защитная метрика, критерии остановки, «нет исходного замера»
- Карточка запуска получила поля `guard_metric`, `guard_threshold` (доля в (0; 1]), `stop_criteria` (список строк) и
  флаг `baseline_missing`. Страж 7 отказывает в переводе в «в тесте» и «ждёт владельца», если нет защитной метрики с
  порогом, она совпадает с главной, нет критериев остановки или один из них повторяет критерий провала, или поднят
  флаг «нет исходного замера» (эта причина называется первой). После запуска поля карточки другими переходами не
  переписываются.
- Совместимость: реестры без новых колонок читаются (колонки дописываются в конец шапки при первой записи); запуски
  до 1.9.0 (все три поля пусты, флаг не поднят) задним числом не проверяются. Переход «ждёт владельца → в тесте»
  требует новых полей и у старой записи. Команда `registry` отклоняет `stop_criteria` и `rat` строкой вместо списка.
- Причина: стандарт гипотез, раздел «Карточка гипотезы» (17.11.2026, разбор Gap Theory Красинского) — запись
  BACKLOG закрыта. Код проверен Codex 22.11.2026: исправлена ошибка — переход в «отложенный замер» мог стереть
  поля карточки, и запуск 1.9.0 выглядел старым. Тесты пакета: 1206 прошло, 0 упало.
- Урок для инстансов: в JSON запуска дописать три поля; навык `growth-hypotheses` их называет. viklimat (ссылка
  `pip install -e`) получает правку сразу; Бризекс (выпуск 1.0.0) — только новым выпуском через `kos_release.py`.
  Новые колонки не добавлены в видимые колонки листа Google (`HYPOTHESIS_VISIBLE`) — вид книги меняет владелец.

## 2026-11-18 — growth_engine 1.8.0: порог шума по разнице и минимум мощности
- Страж 5 считает порог вердикта по шуму разницы доли базы и доли теста: `2·√(p(1−p)·(1/N_база + 1/N_тест))`
  (было `2·√(p(1−p)/N_тест)` — при равных объёмах ложная победа ~7,9 % вместо ~2,3 %). Ожидание меньше минимума
  ≈ 2,842·SE (мощность 80 %) — `research` кодом. При замере порог пересчитывается по фактическому N теста, берётся
  больший; объявленный до старта не переписывается (страж 7). Записи до 1.8.0 читаются и сверяются по своему правилу.
- Причина: разбор GrowthBook, расчёты проверены второй моделью 18.11.2026 (`Методологии\_исходные-заметки\GitHub —
  внешние материалы (2026-11-17)\`). Код проверен Codex: исправлены две ошибки — замер без фактического N у
  новой записи больше не засчитывается по объявленному порогу; минимум мощности считается от объявленного порога
  (порог + 0,842·SE), если он выше шума. Тесты пакета: 1141 прошло, 0 упало.
- Урок для инстансов: гейт строже — часть ожиданий, которые проходили раньше, уйдёт в `research`; при малом трафике
  удлинять окно, а не смотреть чаще. viklimat (ссылка `pip install -e`) получает правку сразу; Бризекс (выпуск 1.0.0)
  — только новым выпуском через `kos_release.py`.

## 2026-11-17 — growth_engine 1.7.0: хранилище фактов — система денежной модели
- Адаптер хранилища фактов (`sources/datacore.py`, чтение файла публикации): источник числа — публикация целиком
  (`D:datacore:publish`), запрос хранилища — в пояснении; уровень — из конфигурации инстанса, как у адаптера
  витрины; разрез по измерению без значения — список его сегментов или пусто («в ответе нет»), окна нет в файле
  совсем — отказ; окно из нескольких целых месяцев — сумма месячных строк арифметикой движка (страж 3).
- Причина: при переводе денежной модели с витрины поставщика на хранилище фактов подпись источника по метрике
  делала выручку и себестоимость одной публикации «смешанной величиной» (страж 4), а словарь уровней хранилища
  (выручка — по оплатам) расходился с уровнями движка.
- Урок для инстансов: смена системы денежной модели — новые имена денежных метрик, если определения различаются
  (например, выручка по дате оплаты против выручки витрины). Сравнивать месяцы разных систем под одним именем нельзя;
  месяц, снятый в обеих системах, — мост определений.

## 2026-09-28 — Навыки шагов: исходник в каноне, в проектах — ссылки
- Исходник шести навыков шагов (`growth-step0-sources`, `growth-step1-goal`, `growth-route`, `growth-diagnose`,
  `growth-hypotheses`, `growth-close-cycle`) перенесён из репозитория первого инстанса в

- Установщик движка (`growth_engine.install_skills`) ставит ссылки, а не копии: копия на месте ссылки уходит
  в резерв рядом с папкой навыков (не внутрь — иначе навык виден дважды), чужая ссылка не трогается; корень канона —
  переменная `KNOWLEDGE_OS`. Тест навыков читает тексты из канона и следит, чтобы второй копии в коде не появилось.
- Причина: навыки ставились копией, и другой проект получал их снимком на день копирования — как и канон до
  исправления гайда установки. Открытый вопрос — где жить ядру кода `growth_engine/core`: пока оно внутри
  репозитория первого инстанса, новый проект получает его только копией.
