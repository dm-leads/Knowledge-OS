# ADR-0004 — Реестр не привязан к продукту хранилища

- **Статус:** Accepted
- **Дата:** 2026-09-13

## Контекст

Первый инстанс ведёт модель и реестр в корпоративном табличном процессоре компании. Другая
компания его не знает и знать не должна. Жёсткая привязка канона к одному продукту убивает
переносимость.

## Решение

Контракт реестра описывает семь артефактов, поля по моментам заполнения, статусы и шесть
операций. Хранилище — адаптер: универсальный табличный процессор по умолчанию, корпоративный
табличный процессор компании, реляционная база для сервера, файл для аварийного режима.
При установке агент задаёт вопрос «где ведём реестр?». Модель экономики — в том же
хранилище, что и реестр. ⛔ Ни один документ ядра не называет продукт хранилища.

## Рассмотренные альтернативы

- Один фиксированный продукт (тот, что у первого инстанса) — отвергнуто: непереносимо.
- Только собственная база с первого дня — отложено до серверного этапа: команды работают
  в таблицах и должны видеть реестр без нового инструмента.

## Последствия

- (+) перенос = выбор адаптера, а не переписывание канона.
- (+) серверный этап меняет адаптер, не документы.
- (−) каждый адаптер обязан реализовать все шесть операций и валидацию — это работа на
  каждый новый тип хранилища.
