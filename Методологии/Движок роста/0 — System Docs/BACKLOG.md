# BACKLOG — Движок роста

## 2026-10-10 — Инстанс без сторонней сквозной системы: адаптеры своих баз и чего для них не хватает в пакете

Второй инстанс поставлен в проект, где деньги и воронка лежат не у поставщика сквозной аналитики, а в своей
локальной базе проекта, и разговоры — тоже в своей базе. Установка дошла до зелёного гейта, но только командой
инстанса. Что выяснилось по коду пакета 1.4.1:

1. **Штатного способа подключить адаптер инстанса нет.** Список адаптеров — словарь в `adapters.py`; команды берут
   адаптер по имени раздела `sources`. Гайд установки при этом рисует в инстансе папку «адаптеры — по одному на
   источник». Инстанс обошёлся обёрткой, которая в своём процессе дописывает свои адаптеры в этот словарь и
   передаёт управление командам пакета без изменений. Работает для всех команд, но `py -3 -m growth_engine.health`
   без обёртки отвечает «в движке нет адаптера» и зелёным не становится. Нужна точка расширения: ключ конфигурации
   с модулем адаптеров инстанса или точки входа пакета.
2. **Адаптер Ядра данных (`sources/datacore.py`) в список адаптеров не включён** — ни одна команда его не построит.
3. **Денежной системой он быть не может:** у каждого его числа источник — «D:datacore:<метрика>», а денежная
   модель делит и складывает только числа с одинаковым источником (страж 4: `ratio`, `per_unit`, `check_pnl`).
   Пять ролей модели с пятью разными источниками остановятся на первом же делении. Числа одной публикации должны
   нести один источник, а класс — браться из конфигурации: своя база может быть и сквозной (C), и учётом денег (D).
4. **Нет команды, которая заводит семь листов в хранилище markdown:** `RegistryStore.ensure_sheets()` не зовёт ни
   одна команда, книгу Google собирает `google_book`, а папку markdown — никто. Гейт на пустой папке отвечает
   «артефакт не заведён» по каждому листу.
5. **Адаптер спроса (`yandex_search`) требует переменную с идентификатором каталога облака.** Там, где вызовы идут
   по одному ключу без каталога, адаптер не собрать — источник остаётся в карте без адаптера.
6. **Что помогло и стоит записать в гайд:** дату съёма своей базы ставить по дате её сборки, а не по дате запуска
   (иначе гейт не увидит устаревший снимок); известный ответ сверять другим путём, чем читает адаптер (прямой
   запрос к учётной системе); эталон для расхода рекламы брать по дозревшему месяцу — свежий месяц дорастает задним
   числом.
7. **Что нашла независимая приёмка адаптеров инстанса** — те же ошибки возможны в любом новом адаптере:
   посетители сайта, поставленные знаменателем к оплатам всего магазина, проходят стража 4, если адаптер пометит
   их общим потоком, — такое число должно нести статус proxy, пока оплаты не разделены на потоки; период вне окна
   базы отдавался нулём, а не «нет данных»; срок сделки, посчитанный по всем оплатам, занижен — считать по
   зрелым когортам; тождество «выручка − себестоимость = прибыль» при себестоимости из допущения о марже
   сходится по построению и ничего не проверяет; ловушки карты источников уходят на лист хранилища — если книгу
   видит заказчик, внутренние замечания держать отдельным списком в файле карты, а текст для листа утверждать
   перед выгрузкой: список запретных слов такое разделение не держит.
8. **Обёртка инстанса над командами пакета — место для обхода гейта.** Запрет чужой конфигурации, написанный
   чёрным списком ключей, обошёлся сокращённым ключом: разбор аргументов пакета принимает сокращения длинных
   ключей. Нужен белый список ключей на команду и путь конфигурации первой строкой вывода. Штатная точка
   расширения в пакете (пункт 1) сняла бы саму обёртку.

Делать новой версией пакета по сценарию `code-system`, когда появится третий инстанс или второй запросит то же.
Источник: установка инстанса 10.10.2026; данные и числа остаются в проекте.

## 2026-09-28 — История статусов гипотез и диаграмма потока (CFD)

Реестр хранит текущий статус гипотезы, но не историю его смены (проверено по коду пакета 1.0.0,
`core/storage.py`): у строки есть `revision` и `updated_at` последней правки и `start_date` теста, а при смене
статуса строка перезаписывается на месте. С историей движок мог бы строить диаграмму накопленного потока
гипотез: сколько в работе, скорость закрытия, время от идеи до решения, копится ли очередь «кандидатов». Источник —
воркшоп Красинского (Доп8, раздел 1.8); как читать диаграмму — «Методология — Работа с ИИ-агентами в проекте»,
раздел 7. Делать, когда в реестре станет больше двух–трёх десятков гипотез, иначе картинка ничего не покажет.
Изменение контракта реестра — новой версией пакета по сценарию `code-system`.
