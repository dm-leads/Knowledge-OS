# Методология — Движок роста (цикл, ворота, маршрутизатор)

## Краткая суть

- Движок роста — **цикл**, а не анализ: цель → диагноз → узкое место → гипотезы → проверка →
  вывод → знание → снова цель. Каждый шаг — ворота: не сошлось — назад, а не вперёд.
- **Путь между воротами система строит сама** — из цели, формы бизнеса и того, какие данные
  реально есть. Ворота неизменны, маршрут — нет. Это отличие от шаблонного «сценария роста».
- Цель — **вход цикла**, но алгоритм обязан поднять её «5 почему» до денег компании и показать,
  где KPI расходится с прибылью. Иначе система оптимизирует не то.
- Диагноз завершён только на **единице действия**: конкретная страница и блок, конкретный этап
  диалога и паттерн обрыва. «Поднять конверсию» — не диагноз и не гипотеза.
- Порядок кандидатов в узкое место — **маржа → чек → конверсия → поток**; первый вопрос к любой
  идее — что **убрать**, а не что добавить.
- Всё, от чего зависит достоверность, живёт в коде и схеме, а не в промпте
  (см. [Стражи](<Стандарт — Стражи Движка роста.md>)).

## Принципы

Шесть принципов, каждый взят у авторов и доведён до правила исполнения.

1. **Одно узкое место.** Система движется со скоростью самого узкого звена; улучшать всё
   подряд — распылять силы ([ТОС](<../Справочник — Теория ограничений (Голдратт).md>)).
   Красинский формулирует то же через «плечо»: точка кратного роста там, где вычитаются две
   близкие метрики (`AMPU ≈ CPUser`).
2. **Оспорить цель до анализа.** Врученная цель часто неверна; анализировать путь к неверной
   цели — самая дорогая ранняя трата (NMT, шаг 1). Поднимаем «5 почему» до денег, различаем
   локальный и глобальный оптимум.
3. **Сначала данные, потом гипотеза.** Из структурированных данных извлекаем всё, что можно;
   гипотезируем только пробелы (NMT, шаг 3). Мозговой штурм без экономики — рационализация
   опыта команды, ≥90% идей уходят «где светло» — в конверсию (Красинский, М2).
4. **Число без статуса — не число.** У каждой величины период, источник и статус
   `факт / оценка / proxy / нет данных`. `нет данных` ≠ 0.
5. **Эффект против шума.** Гипотеза с ожидаемым приростом меньше `±2√(p(1−p)/N)` не
   проверяется тестом — она `research`. Иначе цикл штампует ложные победы (Красинский, М3).
6. **Вычитание — мета-оператор.** Убрать допущение, сегмент, канал, шаг, фичу — почти всегда
   дешевле и сильнее, чем добавить (NMT, «Subtraction»). Каждый цикл письменно отвечает,
   что убрали.

## Подход

### Шесть слоёв

Каждый слой — одна обязанность и явный контракт наверх. Адаптеры стоят на **обоих** концах:
снизу к источникам данных, сверху к хранилищу реестра.

```
6. ИНТЕРФЕЙС        как обращаемся: агент в IDE · бот · API
5. РЕЕСТР и ПАМЯТЬ  контракт артефактов → адаптер хранилища
4. ДВИЖОК ГИПОТЕЗ   механики → двухшаговая оценка → RAT → HADI → вывод
3. ДВИЖОК ЭКОНОМИКИ модель + кросс-чеки + плечи + сценарии + шум
2. СЛОЙ ДАННЫХ      обнаружение → адаптеры → канонические схемы → снапшоты со статусом
1. КАНОН            алгоритм, стандарты, стражи, словарь
```

Правила границ:

- Слои 3–5 **не знают имён полей источников**. Меняется источник — переписывается один адаптер.
- Слой 5 **не знает, где физически лежит реестр**. Операции над артефактами — в контракте,
  реализация — в адаптере хранилища
  ([Контракт реестра](<Стандарт — Контракт реестра и адаптеры хранилища.md>)).
- Каждое число, поднимающееся из слоя 2, несёт период, источник и статус. Без них число не
  принимается — правило в схеме, а не в промпте.
- Слой 1 переносится **без изменений**. Всё остальное конфигурируется под компанию.

### Операционный алгоритм — одиннадцать шагов с воротами

Сшивка алгоритма NMT ([the-algorithm](<../Next Move Theory (Замесин)/Next-Move-Theory-Canon/Algorithms/the-algorithm.md>))
с дисциплиной Красинского ([плейбук диагностики](<../Юнит-экономика (Красинский)/Плейбук — Диагностика узких мест и точки роста.md>))
и правилами этого движка. Один цикл — одна цель. Шаг — ворота: не сошлось — назад.

| # | Шаг | Что делает система | Ворота |
|---|---|---|---|
| 0 | **Обнаружение источников** | спрашивает по шести классам, пробует доступ, строит карту источников ([стандарт](<Стандарт — Протокол обнаружения источников и глубина погружения.md>)); один раз на инстанс, потом инкрементально | без карты источников цикл не начинается |
| 1 | **Оспорить цель** | берёт цель владельца; «5 почему» до валовой прибыли; локальный или глобальный оптимум; **показывает, где KPI расходится с деньгами** | цель без связи с деньгами возвращается владельцу |
| 2 | **Диагноз состояния** | модель экономики за период с кросс-чеками; сходимость на трёх уровнях (платящий · привлечённый · финансы); сегменты новые/старые → устройство → канал; работа с (1−конверсия) | кросс-чек ≠ 0 → искать ошибку, дальше нельзя |
| 3 | **Узкое место** | одно; где копится запас перед шагом; плечо; порядок кандидатов **маржа → чек → конверсия → поток**; спуск по лестнице глубины до единицы действия | узкое место названо как метрика, а не как единица действия → не принято |
| 4 | **Сегменты и работы** | из данных: диалоги (барьеры, возражения, язык), CRM, страницы → сегменты по работам, граф, consideration set; гипотезы только где данных нет | сегмент без денежной работы → не сегмент |
| 5 | **Механики под задачу** | из каталога (механики Замесина + рычаги Красинского) отфильтровать по бизнес-задаче; сработают 2–4 | механика без места в графе работ → отклонить |
| 6 | **Гипотезы** | формула «если для [сегмент/единица действия] изменим [X], потому что [факт], то [метрика] на [Δ], проверим через [источник] за [окно]»; первый вопрос — что убрать; правила — [Стандарт гипотез](<../Стандарт — Работа с гипотезами (формирование и приоритизация).md>) | нет метрики, факта или единицы действия → брак в работу не пускаем |
| 7 | **Оценка и приоритет** | качественно (сложность, вера по под-факторам) → количественно (Δ метрики → ₽ через модель); шум `±2√(p(1−p)/N)`; `приоритет = эффект ₽ × вера ÷ сложность`; у каждой — **владелец** | эффект < шума → `research`, не тест |
| 8 | **RAT** | допущения в утвердительной форме; `P × цена ошибки ÷ цена проверки`; сначала — можно ли допущение убрать | ключевое допущение ложно → пивот, не «ещё раунд» |
| 9 | **Тест и замер** | своё — в исполнение; чужое — **пакет владельцу** (данные, эффект в ₽, RAT, дешёвая проверка); замер по порогу, объявленному до старта | порог не объявлен до старта → замер не засчитывается |
| 10 | **Вывод и память** | `scale / iterate / kill / research`; **что узнали о рынке** → карта знаний; что убрали → журнал решений; возврат к шагу 1 | цикл без решения не закрыт |

Два ритма поверх цикла: **недельный** — быстрые метрики (визиты, заявки, конверсии первого
шага), **месячный** — деньги и пересборка модели. Для рычагов с долгим дозреванием (контент,
поиск) — статус `отложенный замер` с датой, иначе их объявят провальными по недозревшим данным.

Что здесь принципиально добавлено к авторам: шаг 0 как часть алгоритма; обязательный статус
числа; спуск до единицы действия как ворота шага 3; пакет владельцу на шаге 9; карта знаний
на шаге 10; стоп-правило «эффект < шума».

### Маршрутизатор — как система выбирает путь

Ворота неизменны. Путь между ними строится на каждый цикл из трёх входов:

```
ЦЕЛЬ (шаг 1)  ×  ФОРМА БИЗНЕСА  ×  КАРТА ИСТОЧНИКОВ
                        ↓
                 МАРШРУТ ЦИКЛА
   какие шаги углубляем · какие данные тянем · какие механики
   рассматриваем · что заменяем качественным · что честно пропускаем
```

**Форма бизнеса** — шесть признаков, которые радикально меняют путь. Оба автора говорят об
этом прямо: «нет второй продажи — retention не ваш рычаг» (Красинский, Доп4); ветвление по
стадии PMF и типу продукта (NMT, §5).

| Признак | Как меняет маршрут |
|---|---|
| разовая покупка / повторная | разовая → когорты только как **цикл сделки** (лид → первая оплата), retention и LTV не строим; повторная → когортный треугольник обязателен |
| высокий чек / низкий | высокий → рычаги чек, маржа, конверсия в покупателя; A/B недостижимы по объёму → RAT и «ухудшающий эксперимент» |
| B2C / B2B | B2B → работы ЛПР эмоциональнее, продажа = «обосновать трату»; диалоги важнее веб-аналитики |
| стадия PMF | нет → маршрут через сегмент и ценность, экономику считать рано; сильный → масштаб, чек, каналы |
| доля офлайна и ручных сделок | высокая → атрибуция как первый рычаг |
| длина цикла сделки | длинная → недельный ритм только на быстрых метриках; деньги с лагом; отложенный замер |

**Работа с данными.** Каждый шаг объявляет, какие классы источников ему нужны. Маршрутизатор
сверяет с картой и делает одно из четырёх:

1. **есть** → тянем;
2. **нет, но есть заменитель** → качественное вместо количественного (нет конверсии по
   страницам — смотрим, на что жалуются в диалогах на этапе выбора) и **понижаем уверенность**
   явно;
3. **нет и критично** → шаг добычи (подключить источник, поставить события, собрать 20 диалогов)
   встаёт в маршрут как задача с оценкой цены;
4. **нет и некритично** → `нет данных`, идём дальше.

**Библиотека стартовых маршрутов.** Бизнес-задача первична (Замесин); под типовые задачи —
отправные точки с обязательными воротами. Это не сценарии: отклонение разрешено и ожидаемо,
но записывается с причиной.

| Бизнес-задача | С чего начинает маршрут | Куда обычно ведёт |
|---|---|---|
| объём лидов | разделить вход на потоки (веб / без визита / офлайн); проверить, не смешана ли метрика; спрос и сезон | трафик по сегментам, конверсия по страницам до блока, атрибуция ручных сделок |
| конверсия в покупку | (1−конверсия): кто не купил и почему → диалоги первыми | барьеры, язык выгоды, ABCDX по платящим |
| средний чек / маржа | ABCDX платящей базы → работы A/B-сегмента → упаковка оффера | сегментация цены, «ухудшающий эксперимент» |
| экономика канала | CPU против AMPU по каналу, не blended | порог цены лида, отсечение убыточного |
| возвращаемость | сначала проверка: есть ли вторая продажа вообще | если нет — маршрут закрывается выводом «не рычаг» |

Каждый пройденный маршрут сохраняется в библиотеку ядра (обезличенно): «в бизнесе формы X
с данными Y работал путь Z». Так знание накапливается у самой системы, отдельно от знания
о рынке конкретной компании.

**Артефакт «Маршрут цикла»** пишется **до** исполнения: шаги, данные, заменители, что пропущено
и почему, ожидаемая уверенность вывода. Форма — в [контракте реестра](<Стандарт — Контракт реестра и адаптеры хранилища.md>).

## Как применять

1. Убедиться, что инстанс установлен ([гайд](<Гайд — Установка Движка роста в новый проект.md>))
   и гейт зелёный.
2. Взять цель владельца → шаг 1. Записать результат оспаривания: цель на правильном уровне,
   выбор локальный/глобальный, отброшенные альтернативы с причинами.
3. Построить маршрут цикла → согласовать с владельцем → исполнять по шагам 2–10.
4. На каждом шаге фиксировать артефакты по контракту; статусы чисел и гипотез выставляются кодом.
5. Закрыть цикл решением и строкой в карту знаний; следующий цикл начинается с шага 1, а не
   с шага 6.

Чего движок **не делает**: не считает деньги в чате, не пишет в источники, не заменяет владельца
в решении, не оптимизирует метрику, не поднятую до денег.
