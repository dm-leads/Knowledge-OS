# Методология — Advanced JTBD (Замесин)

## Краткая суть

**JTBD (Jobs To Be Done)** — фреймворк, в котором единицей анализа является **работа**: переход человека из состояния «цель не выполнена» в состояние «цель выполнена» с учётом контекста, альтернатив и возможных исходов. Работа первична; продукт, его функциональность, интерфейсы, тексты лендингов, бизнес-модель — производные от работы. (М1 → Z-osnovy, «Основы JTBD»; М1 → Z-book-kak-delat, стр.12)

**AJTBD (Advanced JTBD)** — прикладная надстройка над JTBD, созданная Иваном Замесиным за пять лет. AJTBD добавляет к ядру JTBD: принципы принятия решения человеком (нейронаука, предиктивный мозг), граф работ как вторую единицу анализа, алгоритмы создания ценности, решения бизнес-задач, коммуникации продукта через работы и барьеры, инструменты поиска и ранжирования сегментов, логику качественных и количественных исследований. (М1 → Z-book-kak-delat, стр.34–35, стр.66)

Ключевое отличие от CJM: из CJM извлекается ~3 вида продуктовых решений (устранить проблему, убить шаг, скопировать конкурента), из графа работ — 13+ механик создания ценности и 50+ механик решения бизнес-задач. (М1 → Z-osnovy, ответы на вопросы в финале; М1 → Z-book-kak-delat, стр.69)

## Принципы

### 1. Три разрыва шаблона (mindset shift)

Прежде чем применять AJTBD, необходимо перестроить мышление по трём осям. (М1 → Z-ajtbd, «Три разрыва шаблона»)

1. **Людям не нужны наши продукты.** Людям нужно выполнять свои цели, лучше себя чувствовать. Наличие работы первично.
2. **Всё, что нужно для создания продукта — в головах клиентов**, а не в наших головах.
3. **Единица анализа — работа и граф работ**, а не продукт, конкурент или воронка.

### 2. Нейронаука принятия решений

Мозг работает как **инвестор**: инвестирует ресурсы сейчас, предсказывая получение большего в будущем (по Лизе Фельдман Барретт, «7.5 уроков о мозге»). (М1 → Z-osnovy, «Мозг как инвестор»; М1 → Z-why-buy, «Принцип 1»)

**Нейронаука решения о покупке (fMRI-исследование 2007 года):** (М1 → Z-osnovy, «Нейронаука принятия решений»)
1. Показывают оффер → активируется **Nucleus Accumbens** (предвкушение, ожидание вознаграждения).
2. Показывают цену → активируется **Insula** (боль от расходов).
3. **Medial Prefrontal Cortex** взвешивает: стоит ли будущий результат текущих страданий — принимает итоговое решение.

**Дофамин — универсальная валюта мотивации:** всплеск перед действием мотивирует его совершить; всплеск после — закрепляет поведение; ошибка предсказания → штраф снижением дофамина → мозг корректирует модель. (М1 → Z-why-buy, «Дофамин»)

Около **90% решений** человек принимает на автомате, не осознавая этого. Внутренний нарратор (левое полушарие) конструирует убедительные, но часто ложные объяснения поведения. (М1 → Z-why-buy, «90%»)

### 3. Психологические потребности как корень работ

Работы — это цели, которые мозг автоматически формирует для удовлетворения **9 базовых потребностей** (мета-анализ SDT, Consistency, МакКлелланда, SCARF, Маслоу, Альдерфер, Дэвид Рок и др.): (М1 → Z-why-buy, «9 потребностей»; М1 → Z-osnovy, «9 потребностей — консенсус моделей»)

1. Базовые физиологические (еда, вода, укрытие, отдых, сон)
2. Социальные (контакт, эмоциональный и глубинный интимный контакт, принадлежность)
3. Безопасность (физическая, финансовая, эмоциональная)
4. Уважение (статус, признание)
5. Символизация роста / самореализация
6. Автономия (контроль над жизнью и решениями)
7. Компетентность (овладение и развитие навыков)
8. Согласованность и когнитивный баланс
9. (В тексте перечислено 8 явно при декларированном числе 9 — расхождение источника, не домысел)

**Связь потребностей, целей и эмоций:** (М1 → Z-why-buy, «Собираем картинку воедино»)
```
Базовые психологические потребности (не осознаются)
        ↓
Мозг автоматически формирует Цели = Работы (более-менее осознаются)
        ↓
Эмоции: позитивные = «приближаюсь к цели» / негативные = «удаляюсь от цели»
        ↓
Продукт: помогает достигать цели эффективнее, меньшими инвестициями,
         с меньшими негативными и большими позитивными эмоциями
        ↓
Коммуникация: на языке эмоций (точка текущего переживания клиента)
```

### 4. Работа первична, решения заменяемы

«Работа первична. Всё остальное: продукт, его польза и ценность, конкретная функциональность, интерфейсы приложений, тексты лендингов и писем, коммуникация ценности, бизнес-модель являются производными от работы.» (М1 → Z-book-kak-delat, стр.12)

### 5. Ценность

**Экономическая формула (консенсус):**
```
Ценность = Польза (бенефиты) − Инвестиции (косты)
```
Автор считает её неполной («ценность считается по какой-то нелинейной формуле»), используется как приближение. (М1 → Z-osnovy, «Ценность»)

**AJTBD-формула ценности:**
```
Ценность = более энергоэффективное выполнение работ клиентов
         = меньше инвестиций (деньги, время, энергия)
           + больше пользы (качественнее, больше работ, удовлетворённые потребности)
           относительно конкурентов
```
(М1 → Z-book-kak-delat, стр.46)

**«Вау»-реакция** — когда прогноз превзойдён: граф проще, инвестиций меньше, пользы больше, чем ожидал клиент. Базовое качество = попасть точно в прогноз мозга по графу, костам и бенефитам. (М1 → Z-book-kak-delat, стр.57)

**Схема ошибки прогноза (из слайда 9.1 AJTBD стр.40):** (Визуал → Z-visual, «Costs vs Benefits»)
- Прогноз: Costs=4, Benefits=8 → ожидание положительного результата.
- Сбой решения: Costs↑ выше ожидания, Benefits↓ ниже ожидания → штраф дофамином + негативные эмоции.

### 6. Границы применимости AJTBD

AJTBD **не работает** с: (М1 → Z-book-kak-delat, стр.71)
- Аддиктивными продуктами (соцсети, гемблинг, алкоголь, наркотики — сильная дофаминовая стимуляция)
- Травматическим поведением (иррациональное поведение вследствие психотравмы)
- Глубокой творческой мотивацией (стадия самореализации)
- Статусом, продолжением рода и другими сильными неосознаваемыми потребностями
- Решениями, где процесс принятия решения настолько неосознан, что интервью даст только рационализацию (жениться, стать врачом, родить ребёнка). (М1 → Z-osnovy, ответы на вопросы)

## Подход

### Граф работ (Job Graph)

**Граф работ** — иерархия работ, которые человек выполняет для удовлетворения своих потребностей; это **граф** (с связями многие-ко-многим), а не дерево. (М1 → Z-ajtbd, «Граф работ»; М1 → Z-book-kak-delat, стр.38)

```
Глубинные потребности (неосознаваемые)
          ↓
Высокоуровневые работы (цели, которые мозг формулирует для потребностей)
          ↓
Работы среднего уровня (под что нанимается продукт)
          ↓
Работы ниже уровня / подработы (возникают из-за выбранного решения)
          ↓
Налоговые работы (незапланированные — из-за сбоя решения)
```
(М1 → Z-osnovy, «Граф работ»)

**Ключевое свойство:** одна работа нижнего уровня может иметь связи с несколькими работами верхнего уровня. Пример из слайда (9.1 AJTBD стр.30): «разобраться в JTBD» обслуживает одновременно «Быть классным продактом» и «Реализовать идею пет-проекта». (Визуал → Z-visual, «Граф работ: связи нижнего уровня»)

**Свойства по уровню графа:** (М1 → Z-ajtbd, «Свойства графа через бизнес-перспективу»)
- Чем выше по графу → больше эмоций, меньше конкретного продукта в описании.
- Чем ниже по графу → меньше эмоций, больше конкретного продукта в описании.
- Высокоуровневые работы не меняются десятилетиями (хотеть дом, добраться из А в Б, иметь семью).
- Низкоуровневые работы появляются, меняются и исчезают быстро (10 лет назад — SMS, сейчас нет; год назад — читать статьи и вычленять смысл, сейчас ChatGPT делает это).

**«Мотивация работы»** пропорциональна количеству работ выше уровня, с которыми она связана: чем больше связей вверх, тем выше мотивация выполнять эту работу. (М1 → Z-ajtbd, «Формулы»)

**Неожиданные конкуренты:** продукты, нанятые на одну и ту же работу, часто не похожи друг на друга. Матрасы конкурируют с кофе и снотворным (сегмент «не высыпаюсь на важном проекте»); складское приложение — с Excel; система логистики — с WhatsApp. (М1 → Z-ajtbd, «Свойства графа»)

### Типы работ

| Тип | Определение | Ключевое свойство |
|---|---|---|
| Последовательные | Выполняются поэтапно, каждая следующая разблокируется результатом предыдущей | Похожи на проект; разные развилки |
| Частотные | Работы, которые люди выполняют регулярно | Важны для моделей с когортами и возвращаемостью |
| Виральные | Выполняются для другого человека или вместе с другим человеком | Основа вирального роста; можно целенаправленно искать в интервью |
| Налоговые | Не планировались, возникли из-за сбоя решения; ошибка прогнозирования + нежелание выполнять | Признак провала текущего решения; мишень для улучшения |
| Ложные | Фантазии о будущем действии, которое человек реально не выполняет | Проверочный вопрос: «Когда последний раз делал? Делал ли вообще?» |
| Спящие | Работы, которые у человека есть, но к выполнению которых он не приступает | Потенциал роста конверсии при «пробуждении» |

Типы не взаимоисключающие: одна работа может быть одновременно частотной и налоговой. (М1 → Z-ajtbd, «Типы работ»)

### 6 принципов формирования графа работ

(М1 → Z-ajtbd, «Шесть принципов формирования графа»)

1. Выбор решения для работы **определяет** граф работ ниже уровня (клиент, выбравший ваш продукт, соглашается с предлагаемым вами графом работ).
2. Одна работа нижнего уровня может иметь связи с несколькими работами верхнего уровня.
3. Одно решение может быть нанято на несколько работ одного человека и разных людей (единица анализа — работа, а не человек).
4. Люди всегда прогнозируют граф работ (имеют ожидания по предстоящему графу).
5. Люди могут отказываться от выполнения работ (спящие работы).
6. Знание и прошлый опыт (активирующее знание) запускают появление или корректировку работы.

### Сегментация

**Сегмент** = полное совпадение «когда + хочу + чтобы» (полное описание работы). (М1 → Z-osnovy, «B2C и B2B работы»)

**Демографическая сегментация** (возраст, доход, класс жилья) — ложное ощущение ясности; не содержит причинно-следственных связей и не позволяет принимать эффективные решения. (М1 → Z-book-kak-delat, стр.24–25)

**Сегментация по парам «работа + решение»** — наиболее удобная для продуктовых решений. (М1 → Z-book-kak-delat, стр.25)

**ABCDX-сегментация** — дополнительная сегментация по маржинальности и удовлетворённости клиентов; используется в связке с сегментацией по работам. (М1 → Z-book-kak-delat, стр.70)

### B2B-специфика

В B2B LPR (лицо, принимающее решение) нанимает продукт одновременно на **две работы**: (М1 → Z-osnovy, «B2B специфика»)

```
LPR = Бизнес-работа (выполнить бизнес-цель) + Личная работа (карьера, статус, job security)
```

По данным исследования Google: 80% мотивации принять решение о покупке B2B — личная мотивация LPR. Бизнес-работа описывается в терминах бизнес-целей и результата. Личная работа — как B2C.

**Тип интервью в зависимости от роли респондента:** (М1 → Z-internal, «Матрица тип интервью»)

| Кто респондент | Тип интервью | Акцент |
|---|---|---|
| ЛПР (руководитель) | B2B-интервью | Бизнес-работы имеют большой вес |
| Дорогие конечные сотрудники (аналитики, разработчики) | B2B с фокусом на бизнес-работах | Значимый фокус на бизнес-работах + личные работы |
| Линейные сотрудники (продавцы, операторы) | По большей части B2C-интервью | Основная мотивация — «чтобы мне как сотруднику было легче жить» |

### AJTBD для внутренних продуктов

Методология применяется к внутренним продуктам так же, как и к внешним. Три нюанса: (1) сегментация сотрудников, (2) понимание «валюты» ценности, (3) тип интервью. (М1 → Z-internal, «Нюансы»)

**ABCD-сегментация сотрудников** — ранжирование по ценности для бизнеса: небольшой процент сотрудников делает 80% всего результата (кейс Kidsway: водители с собственным автомобилем или для кого компания — единственный источник заработка). (М1 → Z-internal, «Кейс Kidsway»)

**Критерий ценности внутреннего продукта:** (М1 → Z-internal, «Матрица административное навязывание»)
- При **рыночных условиях** (без монополии): сотрудник добровольно переходит с текущего решения на новое — один в один с внешним продуктом.
- При **административном навязывании**: минимальный критерий — «клиенты, пользуясь вашим продуктом, не страдают» (попадание в базовое качество или выше). Монополия развращает: падает мотивация инвестировать в ценность.

### Механики создания ценности

«Главная механика создания ценности — убийство работ, она лежит в корне многих других если не всех механик.» (М1 → Z-book-kak-delat, стр.56)

**«Удобно», «проще», «быстрее»** — всегда означает убийство работ (тот же результат при меньшем количестве подработ). (М1 → Z-osnovy, «Убийство работы»; М1 → Z-book-kak-delat, стр.55)

**Базовые механики создания ценности:** (М1 → Z-book-kak-delat, стр.56, стр.59–62)
- Начать выполнять работу, которая никак не выполняется
- Починить проблемы (устранить налоговые работы)
- Выполнять больше работ одним решением
- **Убить работы** (главная механика)
- Сокращать временные задержки между выполнением работ
- Снизить косты не убивая работы (сделать дешевле)

**Стратегические механики:**
- Выйти на следующую работу
- Выйти на предыдущую работу *(«Почти весь контент-маркетинг — это выполнение предыдущих работ»)*
- Выйти на высокоуровневую работу
- Забрать выполнение работы с человека (автоматизация)
- Разбить пользу и давать её раньше (сдвинуть Benefits левее на таймлайне)
- Сместиться в соседний сегмент
- Добавить статусности
- Снизить Job/Solution Cost на старте (механика №13 из слайда)
- Переиспользовать существующие привычки вместо борьбы с ними

Всего в курсе описано 50+ механик решения бизнес-задач. (М1 → Z-book-kak-delat, стр.56)

«Инновации — не более чем применение одной или нескольких механик создания ценности.» (М1 → Z-book-kak-delat, стр.64)

### Привычки клиентов

Привычка — автоматические нейросети для повторяющихся действий, хранящиеся в striatum. Мозг переоценивает потери от изменения поведения относительно выгод нового. Исследование Макгонигал: 74% уверены, что смогут привить новую привычку; реально — ~51%; большинство недооценивают время. (М1 → Z-book-kak-delat, стр.81–83)

Стратегия: **переиспользовать существующие привычки** вместо борьбы с ними (кейс PitchMe — надстройка над стандартным ATS рекрутеров без требования менять интерфейс → PMF найден). (М1 → Z-book-kak-delat, стр.86–87)

## Как применять

### Формула описания работы

**Полная формула:** (М1 → Z-book-kak-delat, стр.7)
```
«Когда [я в контексте] [у меня есть прошлый опыт/знания]
 [у меня есть психологические особенности]
 [испытываю негативные эмоции] [случился триггер]
 — хочу получить [ожидаемый результат] [с какими критериями]
 — чтобы получить [ожидаемый результат выше уровнем]
 — и чувствовать себя по-другому после»
```

**Минимальная формула:** «хочу + глагол» (М1 → Z-book-kak-delat, стр.7)

**Расширенная минимальная:** «хочу + глагол + существительное», например: «хочу закрыть попап с куками» (М1 → Z-book-kak-delat, стр.7)

**Важно:** изменение одного слова в описании работы может полностью изменить продукт. Каждое слово в работе на вес золота. (М1 → Z-book-kak-delat, стр.92)

### Алгоритм прокапывания графа работ

Граф прокапывается с любой работы в четырёх направлениях: (М1 → Z-ajtbd, «Алгоритм прокапывания»)

**Вверх (работы высшего уровня):**
1. Узнать ожидаемый результат изучаемой работы.
2. Спросить: «Зачем вам этот результат? Чтобы что?»
3. Повторять (+1–2 уровня вверх обычно достаточно; до базовых потребностей идти редко).

**В прошлое (предыдущие работы):**
1. «Что вы делали перед тем, как решили воспользоваться [изучаемым решением]?»
2. Каждый ответ — действие; к каждому: «Какой результат вы хотели получить?»

**Вниз — частотные работы:**
1. «Для каких задач/сценариев вы используете [решение]?»

**Вниз — последовательные (проектные) работы:**
1. «Что вы делали для того, чтобы получить ожидаемый результат [работы выше уровня]?»

**Вправо (следующие работы):**
1. «Что вы делали после того, как [выполнили изучаемую работу]?»

**Общее правило:** находить людей, которые **уже что-то делают** для выполнения изучаемых работ — не фантазирующих о будущем. Начинать с изучения решения → спрашивать какой результат хотели → в какой ситуации → что чувствовали до/после. (М1 → Z-ajtbd, «Общее правило старта»)

### Алгоритм создания ценности через граф работ

(М1 → Z-book-kak-delat, стр.56)

1. Изучить графы работ фокусных сегментов с текущими решениями, в том числе проблемы и ожидания.
2. Генерировать гипотезы, какие механики ценности можно применить над этими графами.
3. Ранжировать механики по критериям:
   - более высокий уровень работ в графе
   - работы, входящие в **критическую последовательность** (которые нельзя пропустить)
   - работы в критической последовательности с наибольшим отвалом

### Алгоритм решения бизнес-задач (AJTBD)

(М1 → Z-book-kak-delat, стр.63–64)

1. Определить бизнес-задачу с наибольшим ROI (найти точку роста через юнит-экономику или знание о возможности создать ценность).
2. Экспертно предположить, как выглядят графы работ разных сегментов; предположить сегменты и подсегменты.
3. Из экспертного списка предположить, какие механики имеют потенциал решить бизнес-задачу.
4. Провести исследование: качественный AJTBD-кастдев, экспертные интервью, количественные исследования, анализ конкурентов.
5. Генерировать гипотезы механик решения бизнес-задач на полученных данных.

### Switch-интервью (смена решения)

Изучает контекст, барьеры, ценность и факторы смены решения через три стадии: (М1 → Z-book-kak-delat, стр.93)

1. Человек раздражён проблемами со старым решением и принимает решение искать новое.
2. Человек активно ищет новое решение.
3. Человек принимает решение о покупке или использовании нового решения.

**Гайд switch-интервью (блоки вопросов):** (М1 → Z-book-kak-delat, стр.94–95)

*Блок 1 — момент решения искать новое:*
- Было ли что-то, что вас не устраивало в том, как предыдущее решение решало ваши задачи?
- В какой момент вы впервые задумались о смене?

*Блок 2 — поиск нового решения:*
- В какой момент вы стали искать решение?
- Как вы искали? Что гуглили? Что читали?
- Рекомендовали ли вам что-то друзья? Какими словами?
- Было ли что-то, что останавливало от покупки?
- Какие альтернативы рассматривали?
- Какой бюджет был на эту задачу?

*Блок 3 — покупка / начало использования:*
- Какую ценность вы ждали?
- Кто или что помогло принять финальное решение?
- Расскажите подробно, как вы покупали новое решение?

### Экспертные интервью

Интервью с людьми, которые уже продают продукты на изучаемом рынке (конкуренты, прямые и косвенные). Один из лучших инструментов на этапе superdiscovery. Конверсия в договорённость — 50%+; в 9/10 случаев окупается многократно. Минимум 2 эксперта (один может ошибаться). (М1 → Z-book-kak-delat, стр.95–99)

**Скрипт экспертного интервью:** (М1 → Z-book-kak-delat, стр.96–97)
1. Какие сегменты на рынке есть? Какие задачи они решают? Чем отличаются?
2. Что у людей сильнее всего болит? Есть ли люди, у которых болит сильнее? Что их объединяет?
3. Как выглядит последовательность решения подзадач сегмента?
4. Как каждый сегмент решает свои задачи? Насколько удовлетворён? Есть ли проблемы?
5. Видите ли возможность создать ценность для каких-то сегментов?
6. Если бы вы сейчас делали продукт — какой? Почему?
7. Что происходит с рынком? Новые игроки?
8. Какие риски создавать продукт для сегмента X?
9. Что самое главное нужно знать про продажу сегменту X?

### Рекурсивный вопрос для выявления эмоций

(М1 → Z-why-buy, «Инструмент Красинского»)

Для выхода на эмоциональный корень проблемы:
1. Человек называет проблему.
2. Спросить: «Что тяжёлого в том, что [проблема]?»
3. Рекурсивно повторять до выхода на эмоцию (злость, страх, тревога, стыд и т.д.).

Аналогично для ценности: «Что классного в том, что [это]?»

### Зоны осознанности потребностей → методы изучения

(М1 → Z-why-buy, «Изучение потребностей по зонам осознанности»)

| Зона | Примеры | Метод |
|---|---|---|
| Осознаваемые цели | Еда, доставка, работа | JTBD-интервью; количественная валидация (размер, важность, частота, платёжеспособность) |
| Неосознаваемые цели | Статус, брак, дорогая машина | Интервью не подходит — нарратор даст ложную историю; конструировать гипотезы самостоятельно (психология, наблюдение); валидировать тестами продаж |
| Частично осознаваемые цели | — | Отдавать профессиональным исследователям с опытом проективных методик |

### Бизнес-задачи, для которых AJTBD даёт алгоритмы

(М1 → Z-book-kak-delat, стр.68–69)

- Создать ценность продукта
- Найти сегмент для нового продукта
- Снизить отток, улучшить удержание, увеличить возвращаемость
- Вырастить конверсию в регистрацию, оплату
- Коммуницировать продукт
- Эффективнее привлекать клиентов
- Масштабировать существующий продукт
- Выходить из прямой конкуренции
- Создавать прорывные (disruptive) продукты

### Антипаттерны (критически важные)

- **Фокус на следствии, а не причине:** работать с фичами, CJM, багами без знания работ — 90% гипотез не работают. (М1 → Z-book-kak-delat, стр.18)
- **«Чинить боли» как единственная стратегия:** не позволяет создавать прорывные продукты, не работает на зрелых рынках. (М1 → Z-book-kak-delat, стр.23–24)
- **Демографическая сегментация:** ложное ощущение ясности без причинно-следственных связей. (М1 → Z-book-kak-delat, стр.24–25)
- **Проводить интервью с людьми, которые фантазируют** о будущих действиях, а не с теми, кто уже что-то делал; задавать вопросы о будущих намерениях. (М1 → Z-ajtbd, «Антипаттерны»)
- **Копать граф только вниз** (к фичам), не поднимаясь вверх к работам более высокого уровня (где больше эмоций и возможностей для коммуникации). (М1 → Z-ajtbd)
- **Считать прямым конкурентом только похожий продукт:** реальные конкуренты — неожиданные (Excel, WhatsApp, кофе). (М1 → Z-ajtbd)
- **Использовать ChatGPT для AJTBD-анализа интервью при высоких ставках:** не знает логику AJTBD, галлюцинирует, меняет ключевые слова в работах. (М1 → Z-book-kak-delat, стр.91–93)
- **Игнорировать виральные работы** как канал привлечения. (М1 → Z-ajtbd)
- **Прививать новую привычку без значительно большей ценности:** долго, дорого, почти невозможно для стартапа. (М1 → Z-book-kak-delat, стр.87)
- **Делать большой редизайн одним обновлением:** ломает привычки, ухудшает метрики, нельзя диагностировать причину. (М1 → Z-book-kak-delat, стр.88–89)
- **Применять JTBD без проведения интервью:** без хотя бы 3 реальных интервью перепрошивки мозга не происходит. (М1 → Z-osnovy, «Формат и рекомендации»)
