# Гайд — Применение JTBD в маркетинге и SEO

## Краткая суть

AJTBD (Advanced Jobs to be Done, Иван Замесин) — методология, в которой единицей анализа служит **работа (джоба)**: то, зачем человек нанимает продукт, а не его демографический портрет. Маркетинг и SEO, построенные на языке работ, точнее попадают в интент, снижают барьеры и активируют ценность на каждом шаге воронки. Данный гайд переводит теорию в конкретные шаги — сегментация, ценностное предложение, конверсия, работа со спящими работами, применение LLM.

## Для кого и что узнаешь

**Для кого:** маркетологи, SEO-специалисты, продакты, которые уже знакомы с базой JTBD и хотят переходить к практике.

**Что узнаешь:**
- Как выбрать и ранжировать сегменты по экономической привлекательности, а не по демографии.
- Как формулировать ценностное предложение и коммуницировать его на каждом шаге воронки.
- Как выявлять и пробуждать спящие работы — главный рычаг роста конверсии там, где привычка конкурента сильна.
- Как использовать LLM-инструменты (GPT) на реальных продуктовых и маркетинговых задачах без галлюцинаций.
- Где JTBD-логика переносится в SEO: ключи, контент, посадочные страницы.

## 1. Сегментация по работам: выбор, ранжирование, фокус

### 1.1 Почему работы, а не демография

Демография описывает группу людей; работа — то, за что реально конкурирует продукт. «Целевые работы» точнее «целевой аудитории» — они привязаны к конкретной джобе, а не к безликому возрасту/доходу. При разработке контента, рекламных текстов, SEO-семантики первичен вопрос: **за какую работу мы конкурируем?** (источник → [txt-1.1])

> «Пожалуйста, не забывайте, что в описании сегмента… именно за работу мы конкурируем, не за демографию.» (источник → [txt-1.1])

**Сегмент по работам** — группа людей, у которых прямо сейчас есть работа, либо которые выполняли её в прошлом, либо с высокой вероятностью начнут в ближайшее время. (источник → [txt-1.1])

### 1.2 Экономическая карта сегментов

Формула для ранжирования сегментов:

```
Size × AMMPPU × Extra Value × Competition
```

- **Size** — количество людей, выполняющих эту работу.
- **AMMPPU / AMPPU** — средний/рентабельный денежный показатель на пользователя (оба варианта присутствуют в источниках; расшифровка не раскрыта).
- **Extra Value** — возможность создать дополнительную ценность.
- **Competition** — конкурентная ситуация (меньше — привлекательнее).

(источник → [diag-1.1], [diag-1.2], [diag-1.3], [seg-pdf])

Дополнительная формула ранжирования — 4 оси:

```
Важность × Частотность × Размер × Неудовлетворённость (текущим решением)
```

Визуально: Размер — пузырь, Частотность / Важность-Денежность — оси, Удовлетворённость — цвет (красный = неудовлетворён, целевой; зелёный = доволен). (источник → [txt-1.1])

### 1.3 Алгоритм поиска и выбора целевых работ (5 этапов)

1. **Широкая гипотеза работы** — убрать все заужения (конкретный формат, конкретный объект), сформулировать максимально высокоуровневую джобу. Три ситуации: нет идей → Super Discovery; есть идея → преобразовать в гипотезу, забыть идею; не уверены → аналогично. (источник → [txt-1.1])
2. **Оценка рынка в деньгах** — итерировать параллельно с п.1 до попадания на достаточно денежный рынок. (источник → [txt-1.1])
3. **Качественное Job-driven исследование** — итерации по 6–8 интервью; рекрутинг по критерию «платит деньги за решение, связанное с широкой гипотезой»; после каждой итерации кластеризовать сегменты и выделять не-сегменты; стоп — когда за последние 10 интервью нет принципиально нового (~80% полноты). (источник → [txt-1.1])
4. **Количественная валидация** — ранжировать по формуле Важность × Частотность × Размер × Неудовлетворённость; убирать сегменты без ресурсов/компетенций или не совпадающие с принципами. (источник → [txt-1.1])
5. **Акт выбора** — назначить работы целевыми; только после этого прокапывать граф на нижние уровни. (источник → [txt-1.1])

**Скоринг зрелости сегментации (диагностика):**
- Используете Core Jobs + Big Jobs в сегментации? (вес ×3; шкала 0/1/2)
- Есть знание/гипотеза, что работаете на экономически самый привлекательный сегмент? (вес ×2)
- Сохраняете фокус на фокусных сегментах (5 последних гипотез → всё ли на фокусный сегмент)?

(источник → [diag-1.1], [seg-pdf] стр.1)

### 1.4 Граф работ как инструмент стратегии

Продукт конкурирует не за одну джобу, а за кусочек графа. Точки роста — смежные работы: предыдущие (подготовка к целевой работе), следующие (что делают после), высокоуровневые (зачем всё это нужно). Знание графа позволяет применять 30+ механик продуктовой стратегии. (источник → [txt-1.1])

**Доменный крюк (иллюстрация переносимости):** язык работ клиента → семантическое ядро и контент в SEO; карта сегментов → приоритизация посадочных страниц по экономической привлекательности сегментов.

### 1.5 Антипаттерны сегментации

- Влюбиться в сегмент — блокирует рациональную оценку opportunity cost. (источник → [txt-1.1])
- Начинать с узкой гипотезы работы — упустите более привлекательные соседние сегменты. (источник → [txt-1.1])
- Не знать сегменты конкурентов и почему они их выбрали — высокая вероятность локального оптимума. (источник → [diag-1.3])
- Прокапывать граф низкоуровневых работ до выбора сегмента — инвестиции сгорят. (источник → [txt-1.1])

## 2. Ценность: создание, формула, коммуникация

### 2.1 Основная формула ценности

```
Ценность = Польза − Косты
         = Бенефиты − Косты
```

Уточнённая формула для пары «работа + решение»:

```
Job Solution Value = Job Solution Benefits − Job Solution Costs
```

Ценность уникальна для конкретной пары работа + решение; при смене решения меняются и бенефиты, и косты. (источник → 10. Принципы создания ценности.txt)

**Ценность растёт, если:**
1. Снижаем Job Solution Costs (при тех же бенефитах).
2. Растим Job Solution Benefits (при тех же или меньших костах).
3. Одновременно снижаем косты И растим бенефиты.

(источник → 10. Принципы создания ценности.txt)

### 2.2 Ценностное предложение

Формат:

```
Core Job + ценность + фичи — менее 15 слов
```

(источник → 2.2 Ценность вашего продукта.pdf, стр. 1)

Знание критериев выбора/оценки результата и конкурирующих решений обязательно для отстройки. Источник знания о ценности: минимум 10+ интервью + 30+ единиц обратной связи от фокусного сегмента. (источник → 2.2 Ценность вашего продукта.pdf, стр. 1)

### 2.3 Двенадцать механик создания ценности

**Первый приоритет (делать в первую очередь):**
1. Выполнить важную работу, которую никто не выполняет (или вернуть выполнение работы, которая перестала выполняться).
2. Починить проблемы важных работ (устранить боли, налоговые работы).
3. Обеспечить базовое качество (выполнять ожидаемые работы на ожидаемом уровне костов и бенефитов).

**Второй приоритет:**
4. Убивать низкоуровневые работы (сокращать количество шагов).
5. Выполнять больше работ одного человека одним решением.
6. Выполнять работы разных сегментов одним решением (открытие новых сегментов).
7. Выполнять следующую работу в последовательности (рост среднего чека, удержание).
8. Снижать Job Solution Cost, не убивая работы (скидка, близость, доставка, доступность).
9. Растить Job Solution Benefit внутри тех же работ (линейное улучшение важной характеристики).
10. Удовлетворять больше глубинных потребностей (статус, безопасность, attachment, автономия, саморазвитие, принадлежность к стае).
11. Коммуницировать выполнение высокоуровневой работы + «мы компетентны это выполнить».
12. Пробуждать спящие работы.

(источник → 10. Принципы создания ценности.txt)

> «Убивать работы — одна из самых важных механик создания ценности. Возможно, самая главная.» (источник → 10. Принципы создания ценности.txt)

**Доменный крюк:** механика №11 — коммуникация высокоуровневой работы в title, H1, мета-описании и тексте посадочной — напрямую влияет на SEO-релевантность и CTR в выдаче.

### 2.4 Алгоритм решения продуктовой бизнес-задачи через механики

1. Определить / получить бизнес-цель; вычеллнджить её («что бы что»).
2. Выбрать механики, применимые к данной цели (например, «рост среднего чека» → 8 механик из 12).
3. Получить «сырьё»: аналитика поведения, сегментация, AJTBD-интервью, граф работ, конкурентный анализ, тренды.
4. Применить механики к сырью → сгенерировать 20–30 гипотез.
5. Отранжировать по RICE: Impact (по табличке механик), Reach, Credibility, Effort.

(источник → 10. Принципы создания ценности.txt)

### 2.5 Антипаттерны ценности

- «Проклятый цикл пиления фич»: озарение → продажа стейкхолдерам → метрики → разработка → баги → «выпилим через 2 года»; ценность минимальна, opportunity cost скрыт. (источник → 10. Принципы создания ценности.txt)
- Конкурировать только ценой — ухудшает юнит-экономику, запускает ценовые войны; цена в B2B — 5-й–6-й фактор влияния на выбор. (источник → 10. Принципы создания ценности.txt)
- Коммуницировать «курикулум и тичеров» вместо высокоуровневой работы клиента (кейс Practicum: правильно — «стабильная работа, смена сферы, более высокая зарплата»). (источник → 10. Принципы создания ценности.txt)

## 3. Конверсия и спящие работы

### 3.1 Конверсия как КПД продукта

```
Конверсия = Количество людей, выполнивших работу с нашим продуктом /
            Количество людей с целевой работой, поданных на вход воронки
```

(источник → txt, воркшоп «Спящие работы»)

Две фундаментальные ситуации роста конверсии: (а) у человека уже есть работа и текущее решение — нужно переключить; (б) у человека спящая работа — нужно пробудить. (источник → txt)

### 3.2 Семь условий конверсии (когда работа уже есть)

Все 7 должны совпасть:

1. Привлекли лида с работой — целевой сегмент попал в воронку.
2. Предложили ценность выше — наше решение воспринимается ценнее текущего.
3. Лид понял ценность — ценность загружена на языке работ.
4. Нет тревог и возражений к нашему решению — барьеры к продукту сняты.
5. Нет тревог и возражений к выполнению работы в целом — клиент верит, что работа получится.
6. Лид активировался в ценность и не отвалился — дошёл до aha-moment.
7. Не сломались по пути — технически всё работает.

(источник → txt, раздел «От чего зависит конверсия»)

**Доменный крюк:** условия 3–5 — прямая задача SEO-контента и посадочных: язык работ в тексте загружает ценность, снимает барьеры и проводит до aha-moment.

### 3.3 Четыре силы прогресса (Four Forces)

Инструмент для тройки: **Сегмент — Старое решение — Новое решение**.

**Силы вперёд (к новому решению):**
- Воспринимаемая ценность нашего решения выше текущего.
- Проблемы с текущим решением.

**Силы назад (удерживают у старого):**
- Барьеры к новому решению (страхи, тревоги, сомнения).
- Привычка к текущему решению.

**На что можно влиять:** воспринимаемая ценность, барьеры (коммуникация, фичи, кейсы).
**На что сложно влиять:** привычка — не бороться, а оседлать/переиспользовать (кейс PitchMe: встроились в интерфейс старой ATS, не заменяя её).

(источник → txt, раздел «Четыре силы прогресса»)

### 3.4 Aha-moment: как сдвинуть выше по воронке

1. Узнать, через сколько шагов/времени клиент получает ценность (качественные интервью: «В какой момент вы поняли ценность?»).
2. Транслировать aha-moment словами реальных клиентов в маркетинговой коммуникации (лендинг, реклама, скрипт продаж).
3. Воспроизводить ситуацию: «если ты сделаешь X — получишь такой результат».
4. Постоянно напоминать о ценности на каждом шаге воронки, пока клиент не дошёл до неё.

(источник → 10. Принципы создания ценности.txt; txt, раздел «Активация ценности»)

**Пример Motion (AI-календарь):** реклама → лендинг 1 → лендинг 2 (соцдоказательство) → экран оплаты — на каждом шаге не «дай денег», а «ты инвестируешь ради вот этой ценности». (источник → txt, кейс Motion)

### 3.5 Спящие работы: определение и типы

**Спящая работа** — работа, которую человек ещё не выполнял, но при достижении определённых условий или получении активирующего знания может начать выполнять. Термин оригинальный — Замесин; не встречается в других источниках по JTBD. (источник → txt)

**Два типа:**

| Тип | Описание | Что делать |
|---|---|---|
| Тип 1 | Человечество уже научилось пробуждать; работа пробудилась не у всех | Пропихивать по популяции: изучать тех, у кого уже проснулась, и переносить на ранние стадии |
| Тип 2 | Человечество ещё не научилось пробуждать (iPhone, каршеринг, такси) | Открытый вопрос; здесь «скрыты сотни миллиардов» |

(источник → txt, раздел «Спящие работы»; 10. Принципы создания ценности.txt)

### 3.6 Тройка активирующих знаний

Для пробуждения спящей работы необходимо последовательно загрузить в голову:

```
1. Знание, что эту работу возможно выполнить (новый способ существует как класс)
2. Знание, что наша версия работы более эффективна / удобна / ценна
   для выполнения верхнеуровневой работы
3. Знание о конкретном удобном решении, с которым эту работу можно выполнить
```

(источник → txt)

**Кейс Yango (Денис Кучин):** работа — «инвестировать в облигации» вместо депозитов. Партнёрство с банком: сотрудник лично загружал тройку знаний («облигации так же надёжны как депозит + ставка выше + гибче»). Результат: конверсия в пополнение выросла с **10% до ~65%**; компанию купил SoftBank. (источник → txt, кейс Yango)

### 3.7 Алгоритм пробуждения спящей работы

1. Найти людей, у которых спящая работа уже проснулась (выполняют её).
2. Провести job-standard-interview: работы, особенности сегмента, квалифицирующие факторы.
3. Узнать активирующее знание — что именно привело к появлению работы.
4. Сформировать тройку активирующих знаний (п. 3.6).
5. Найти людей из того же сегмента на более ранних этапах (в т.ч. с проблемами текущего решения) — загружать им тройку.
6. Коммуницировать, что выполнение новой работы позволит выполнять больше верхнеуровневых работ.
7. Снижать барьеры к решению и барьеры к выполнению работы.
8. Итерировать: увеличивать число людей, выполняющих работу.

(источник → txt, раздел «Спящая работа»)

**Доменный крюк:** спящие работы → контент, который «активирует» запрос ещё до того, как он стал устойчивым поисковым паттерном; FAQ-аудит и Schema — рычаги для попадания в нейровыдачу Яндекса на уровне работ Тип 1.

### 3.8 Антипаттерны конверсии

- Игнорировать привычку — строить продукт, требующий смены бизнес-процессов. «Гарантированно убивает конверсию». (источник → txt)
- Делать большие редизайны одновременно (кейс Яндекс.Острова 2013–2014: −8–10% выручки). (источник → txt)
- Забывать коммуницировать ценность на каждом шаге воронки — клиент «забывает, зачем это делает» и дропается. (источник → txt)
- Просить избыточные косты при отложенной ценности (кейс балийского кинотеатра: 20 минут на покупку одного билета). (источник → txt)
- Экстраполировать сегменты из одной страны на другую без отдельного исследования (6 стран, 200+ респондентов: сегменты фундаментально разные). (источник → txt)

## 4. LLM/GPT в маркетинговой и продуктовой работе

### 4.1 Природа GPT и где применять

GPT — «бесконечно ресурсный джуниор-сотрудник, который может делать всё, что ты ему скажешь, но требует очень чётких инструкций и очень внимательного надзора». (Дима Зарюта, источник → транскрипт, ~5 000 сим.)

**Хорошо работает:**
- Генерация большого объёма гипотез (40+ вариантов без контекста продукта).
- Сужение/фильтрация из уже готового набора.
- Обработка существующего текста (интервью, транскрипты) — галлюцинаций почти нет.
- Транскрибация слайдов/PDF с дизайном через Vision API.

**Плохо работает:**
- Синтез «из ничего»: «какие боли решает этот продукт?» при показе материалов продукта → нерелевантный результат.
- Real-time продажи: каждый раз новая формулировка → нестабильность скрипта.
- Сложные числовые расчёты (10+ параметров) без JSON-форматирования → галлюцинации в числах.

(источник → транскрипт, ~5 000–48 000 сим.)

### 4.2 Структура описания B2B-персоны для GPT-онбординга

```
BUYING PERSON
  └── Objectives (Big Jobs) — «за что повысят/уволят»
        └── Jobs (Small Jobs) — ежедневные действия
              └── Pain Points — эмоциональные препятствия

ПРОДУКТ
  └── Фичи
        └── Бенефиты
              └── Бенефициары / Пользователи
                    └── Success Cases (кейсы похожих компаний/ролей)
```

Jobs (ежедневные действия) легче всего находить в job descriptions компаний-целей на сайтах вакансий. (источник → транскрипт, ~9 000 сим.)

**Формула B2B outreach:** «сказать правильные слова правильному человеку в правильное время через правильный канал». (источник → транскрипт, ~5 500 сим.)

### 4.3 GPT-цепочка (многоходовка) против галлюцинаций

```
ШАГ 1: Генерация широкого множества (40 вариантов) БЕЗ контекста продукта
  ↓
ШАГ 2: Фильтрация С контекстом продукта (выбрать 3–5 из 40)
  ↓
ШАГ 3: Обогащение из материалов клиента (добавить пропущенное)
```

Принцип: GPT плохо синтезирует с нуля, хорошо генерирует и хорошо фильтрует. (источник → транскрипт, ~16 000–18 000 сим.)

### 4.4 Алгоритм написания промптов (Зарюта)

1. Начинать с простого промпта (1 абзац; первое слово — глагол); в ~40% случаев достаточно.
2. Если результат волатилен при нулевой температуре — «джедайская техника»:
   - Шапка: задача в общем, ссылки на материалы.
   - Блок материалов: описание продукта, клиента и т.д.
   - Инструкция «следуй step-by-step».
   - Пошаговая инструкция (thinking aloud или нет).
   - Финальный шаг review: «прочитай источник и свой ответ; если ответа нет в материалах — напиши "недостаточно материала"».
3. Использовать «найди в материалах», а не «скажи» — снижает галлюцинации.
4. В начале и конце промпта дублировать ключевые ограничения (середина «теряется»).
5. Для сложных промптов — «промпт для написания промптов»: вставить задачу в meta-промпт, сделать 5 regenerate, дотюнить.

(источник → транскрипт, ~21 000–23 000 сим.)

### 4.5 Практические сценарии для продактов и маркетологов

- **Обработка CastDev-интервью:** транскрипт → GPT-4 с промптом «вытащи инсайты/работы как продакт-менеджер» → экономия 2–2,5 часа на интервью. (источник → транскрипт, ~60 000–63 500 сим.)
- **Работа с текстами:** не «напиши за меня», а «улучши мой черновик». (источник → транскрипт)
- **Поиск информации:** Perplexity — диалоговый поиск со ссылками на источники. (источник → транскрипт)
- **Генерация рекламных материалов (кейс SkySmart):** GPT в роли «целевого клиента» → 400 креативов → CTR-тесты → «смешные деньги» на валидацию релевантности работ для холодного трафика. (источник → транскрипт, ~45 500 сим.)
- **Генерация образовательных программ (кейс SkySmart):** параметры (класс + предмет + уровень + цель + сроки) → JSON-структура программы. MVP — Google-таблица с промптом → ручная вставка в ChatGPT → валидация → упаковка в ~100 шаблонов без GPT. (источник → транскрипт, ~38 000–48 000 сим.)

### 4.6 Антипаттерны LLM-применения

- Просить GPT написать холодное письмо «в лоб» → 4 абзаца «убесистого текста», никто не читает. (источник → транскрипт, ~6 500 сим.)
- Класть всё в один огромный промпт → внимание к середине теряется, нужны цепочки. (источник → транскрипт, ~19 500 сим.)
- Использовать GPT в real-time продажах: нестабильность формулировок снижает уверенность продавца и ухудшает KPI. (источник → транскрипт, ~46 500 сим.)
- Давать сложные математические расчёты без JSON-форматирования → галлюцинации в числах. (источник → транскрипт, ~38 000–39 000 сим.)
- Упаковывать джобу без конкретного исполнителя в B2C с личным контактом: родители нанимают человека, не платформу. (источник → транскрипт, ~32 500 сим.)

## 5. JTBD-логика в SEO и контент-маркетинге

Данный раздел описывает принципы переноса; детальная механика для конкретного проекта — в отдельных документах «Применение».

**Семантика = язык работ.** Ключи, отражающие реальные джобы клиентов, точнее попадают в интент. Сегментация по работам → кластеры семантики с разной воронкой: осознание работы (Тип 1 спящей) → поиск решения → сравнение → выбор. (принцип из [txt-1.1]; применение — доменный крюк)

**Приоритизация посадочных.** Экономическая карта сегментов (Size × AMMPPU × Extra Value × Competition) применима к выбору, какие посадочные разрабатывать в первую очередь. Высокий размер + высокая неудовлетворённость текущим решением = приоритет. (источник → [diag-1.1])

**Контент по уровням работ.** H1 и мета-заголовок — высокоуровневая работа (механика №11). Тело страницы — конкретные Jobs и Pain Points на языке клиента. FAQ — тройка активирующих знаний для спящих работ. (принципы из 10. Принципы создания ценности.txt; txt)

**Снятие барьеров на посадочной.** «Людям нравится, что их конкретные страхи, тревоги и сомнения знают и уважают» (цитата Красинского, источник → txt). Явное называние барьеров и их снятие — часть условия №4 из 7 условий конверсии.

**Выбор темы — по покупке, а не по новизне** (практика первого инстанса, 07–09.2026). Фильтр «тема не занята и по ней кликают» вытягивает страшилки без покупателя: трафик есть, заявок нет. Тема считается занятой, если своя продающая страница уже стоит в выдаче по этому запросу. Порядок отбора снизу вверх: спрос → деньги, которые приносят соседние страницы того же куста → покрытие своими текстами → выдача. Проверка «тема свободна» — по правилу поиска дублей из [Справочника классов ошибок](<../../Справочник — Классы ошибок данных и автоматизации.md>) (раздел «Причины и отрицания»).

## Что дальше

1. **Выбрать фокусный сегмент** — пройти 5-этапный алгоритм (раздел 1.3) или экономическую карту сегментов (раздел 1.2).
2. **Сформулировать ценностное предложение** ≤ 15 слов в формате Core Job + ценность + фичи (раздел 2.2).

6. **Перенести в SEO** — перепроверить семантику, H1/title/мета и FAQ на соответствие языку работ (раздел 5).
