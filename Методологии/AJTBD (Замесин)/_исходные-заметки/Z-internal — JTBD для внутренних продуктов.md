## 1. Концепции и идеи

- JTBD применяется для внутренних продуктов так же, как и для внешних — Jobstupid.com (инструментарий AJTBD) «прекрасно подходит для внутренних инструментов». (источник → Модуль 1, урок 8)
- Нюансы применения JTBD к внутренним продуктам три: (1) сегментация, (2) понимание ценности и «валюты», (3) тип интервью (B2B vs. B2C). (источник → Модуль 1, урок 8)
- Первый шаг — понять мотивацию стейкхолдеров (держателей бюджета), которые выделяют деньги на создание внутреннего продукта. (источник → Модуль 1, урок 8)
- Оптимизация дорогих сотрудников (разработчики, аналитики) → фокус на создании ценности и снижении проблем, потому что их тяжелее найти и заменить. (источник → Модуль 1, урок 8)
- Оптимизация массовых/линейных сотрудников → фокус на масштабе: небольшой прирост эффективности × тысячи сотрудников = значимый бизнес-эффект. (источник → Модуль 1, урок 8)
- Если использование инструмента навязано административно (монополия), мотивация инвестировать в создание ценности падает: «зачем — и так будут пользоваться». (источник → Модуль 1, урок 8)
- При административном навязывании минимальный критерий ценности — «клиенты, пользуясь вашим продуктом, не страдают», то есть попадание в базовое качество или его превышение. (источник → Модуль 1, урок 8)
- При отсутствии административного принуждения условия рыночные: сотрудник должен добровольно перейти с текущего решения (старая стилка, внешний платный сервис, самописное решение) на новое. (источник → Модуль 1, урок 8)

## 2. Точные определения

- **Внутренний продукт** — инструмент, создаваемый внутри компании для оптимизации работы сотрудников или ключевых сервисов (CRM, ABT-стилка, система аналитики, tax tracker и пр.). Не продаётся на внешнем рынке. (источник → Модуль 1, урок 8)
- **Административное навязывание** — ситуация, когда руководство обязывает всех сотрудников пользоваться конкретным внутренним инструментом, лишая их выбора альтернативы. (источник → Модуль 1, урок 8)
- **Рыночные условия (для внутреннего продукта)** — ситуация, когда использование инструмента не навязано: сотрудник сам выбирает решение, переход возможен только при создании реальной ценности. (источник → Модуль 1, урок 8)
- **ABCD-сегментация сотрудников** — метод выделения сегментов среди сотрудников по ценности (вкладу в бизнес), аналог ABCD-сегментации внешних клиентов. Позволяет найти тех, инвестиции в инструмент для которых дают наибольший бизнес-эффект. (источник → Модуль 1, урок 8)

## 4. Пошаговые процедуры / алгоритмы

**Алгоритм работы с внутренним продуктом по JTBD:**

1. Выяснить мотивацию стейкхолдеров: какая бизнес-задача стоит за инвестицией в внутренний продукт (оптимизация дорогих сотрудников / массовых / ключевых сервисов / снижение time-to-market). (источник → Модуль 1, урок 8)
2. Определить сегментацию: применить ABCD-сегментацию сотрудников, выделить тех, кто даёт наибольшую ценность бизнесу. (источник → Модуль 1, урок 8)
3. Найти более ценных сотрудников, которые уже выполняют целевую работу. (источник → Модуль 1, урок 8)
4. Провести job-стабильное интервью: узнать, как звучат их работы, построить граф работ ниже уровня. (источник → Модуль 1, урок 8)
5. Сгенерировать гипотезы ценности из графа работ. (источник → Модуль 1, урок 8)
6. Создать продукт и тестировать гипотезу до тех пор, пока сотрудники не перейдут с текущего решения на новое. (источник → Модуль 1, урок 8)
7. Дополнительно: проводить UX-тесты, анализировать причины, по которым люди не конвертируются. (источник → Модуль 1, урок 8)

## 5. Фреймворки / модели

### Матрица «тип оптимизации → подход к сегментации»

| Тип оптимизации | Пример | Фокус | Сегментация |
|---|---|---|---|
| Дорогие сотрудники | Разработчики, аналитики (ABT-стилки, системы хранения данных) | Создание ценности + снижение проблем | ABCD по вкладу сотрудника × маржинальности продукта |
| Массовые/линейные сотрудники | Агенты продаж, операторы колл-центра | Масштаб: прирост × тысячи сотрудников | ABCD по вкладу; те, кто делают 80% результата |
| Ключевые сервисы/продукты | Сервисы, генерирующие основную прибыль | Качество сервиса, снижение time-to-market | По доле прибыли продукта в компании |

(источник → Модуль 1, урок 8)

### Матрица «тип интервью по роли респондента»

| Кто респондент | Тип интервью | Акцент |
|---|---|---|
| ЛПР (руководитель службы) | B2B-интервью | Бизнес-работы имеют большой вес |
| Дорогие конечные сотрудники (аналитики, разработчики, менеджеры) | B2B с фокусом на бизнес-работах | Значимый фокус на бизнес-работах + личные работы |
| Линейные сотрудники (продавцы, операторы) | По большей части B2C-интервью | Основная мотивация — «чтобы мне как сотруднику было легче жить» |

(источник → Модуль 1, урок 8)

### Матрица «административное навязывание → критерий ценности»

| Ситуация | Критерий успеха | Аналогия |
|---|---|---|
| Использование НЕ навязано (рыночные условия) | Сотрудник перешёл с текущего решения на новое (добровольно) | Один в один с внешним B2C/B2B продуктом |
| Использование навязано административно (монополия) | Клиенты пользуются продуктом и не страдают (попадание в базовое качество или выше) | Монополия; мотивация инвестировать в ценность ниже |

(источник → Модуль 1, урок 8)

## 6. Разобранные примеры / кейсы / цифры

- **Кейс Kidsway (ABCD-сегментация сотрудников):** компания Kidsway (доставка детей от родителей до кружков и обратно) провела ABCD-сегментацию водителей и выяснила, что очень небольшой процент сотрудников (те, у кого есть свой автомобиль или для кого Kidsway — единственный источник заработка) делает 80% всех поездок. Вывод: инвестиции в инструмент для именно этой группы бизнесу выгоднее. (источник → Модуль 1, урок 8; кейс из видео Артёма Зевича об ABCD-сегментации)
- **Пример ABT-стилки:** при оптимизации аналитиков выгоднее создавать инструмент для более эффективных аналитиков, работающих в продуктах с наибольшей прибылью компании. «Не все аналитики одинаково полезны, не все разработчики одинаково полезны». (источник → Модуль 1, урок 8)
- **Пример страховой компании с линейными продавцами:** тысячи агентов продаж → инвестиции во внутренние инструменты обработки заказов дают прибыль «в массе». (источник → Модуль 1, урок 8)
- **Переход с текущего решения:** примеры того, с чего сотрудник может переходить — старая ABT-стилка, самописное решение, внешний платный сервис. (источник → Модуль 1, урок 8)

## 10. Термины в глоссарий

- **JTBD для внутренних продуктов** — применение методологии Jobs To Be Done к инструментам, создаваемым для сотрудников внутри компании.
- **ABCD-сегментация сотрудников** — ранжирование сотрудников по ценности для бизнеса (аналог ABCD-сегментации клиентов).
- **Граф работ** — иерархическая карта работ (jobs) сотрудника/пользователя, используется для генерации гипотез ценности.
- **Административное навязывание** — принудительный перевод всех сотрудников на внутренний продукт без права выбора альтернативы.
- **Рыночные условия (внутренний продукт)** — ситуация, при которой сотрудник сам выбирает инструмент (монополии нет).
- **Job-стабильное интервью** — интервью по JTBD, нацеленное на выявление стабильных (не ситуативных) работ пользователя.
- **Валюта (внутреннего продукта)** — сигнал ценности: при рыночных условиях — добровольный переход с текущего решения; при монополии — отсутствие страданий у пользователей.
- **B2B-работы / бизнес-работы** — работы, связанные с достижением бизнес-целей (в контексте внутреннего продукта — цели подразделения/компании).
- **B2C-работы / личные работы** — работы, связанные с личным комфортом и удобством конкретного сотрудника.
- **Time-to-market** — скорость выкатки продукта/гипотезы в продакшн; один из ключевых KPI при оптимизации ключевых сервисов.

## 11. Типичные ошибки / антипаттерны

- **Игнорировать мотивацию стейкхолдеров** — начинать с разработки, не поняв, какую бизнес-задачу должен решить внутренний продукт. (источник → Модуль 1, урок 8)
- **Не делать сегментацию сотрудников** — считать всех сотрудников одинаково ценными; упускать из виду, что небольшой процент делает 80% результата. (источник → Модуль 1, урок 8)
- **Ориентироваться только на ЛПР** — при административном принятии решений забывать о конечных пользователях (линейных сотрудниках), которые будут пользоваться продуктом ежедневно. (источник → Модуль 1, урок 8)
- **Расслабляться при административной монополии** — «и так будут пользоваться» → падение мотивации инвестировать в ценность → продукт деградирует. (источник → Модуль 1, урок 8)
- **Не проводить UX-тесты** — пропускать анализ причин, по которым сотрудники не конвертируются (не переходят на новый инструмент). (источник → Модуль 1, урок 8)
