## 1. Концепции и идеи

- Раздел охватывает **«Первый приоритет» (способы 1–3)** и начало **«Второго приоритета» (способы 4–12)** создания ценности для клиентов. (источник → стр. 55–58)
- **Первый приоритет** — базовое: вернуть работавшее, починить проблемы, обеспечить базовое качество. Без этого не имеет смысла работать над остальным. (источник → стр. 55–57)
- **Второй приоритет** — рост ценности: убивать работы, покрывать больше работ, работать с сегментами, двигаться вперёд по цепочке работ, снижать издержки, растить Benefits, удовлетворять психологические потребности, коммуницировать, пробуждать спящие. (источник → стр. 58)
- Способ №4 «Убить низкоуровневую работу»: устранение шагов, которые пользователь вынужден делать сам, но которые можно автоматизировать/сократить — резкое уменьшение количества действий в цепочке. (источник → стр. 59)
- Способ №5 «Выполнять больше работ человека одним решением»: суперапп закрывает несколько ранее разделённых работ. (источник → стр. 64)
- Способ №6 «Выполнять высокоуровневые работы разных сегментов одним решением»: один продукт, несколько тарифов/режимов под разные сегменты. (источник → стр. 69)
- Способ №7 «Выполнять следующую работу»: после того как пользователь сделал шаг А (форма), продукт сам предлагает/выполняет шаг Б (анализ откликов) без переключения инструмента. (источник → стр. 71)
- Пример UZON (не включён в основную нумерацию способов, использован как иллюстрация): смена формы флакона (Job/Solution Benefit) → продажи +700%. [факт из материала — твит, не верифицированный автором курса отдельно] (источник → стр. 67)

## 2. Точные определения

- **Способ №1 — Вернуть выполнение работы, которая выполнялась, но перестала:** создание ценности через восстановление утраченной функциональности. (источник → стр. 55)
- **Способ №2 — Починить проблемы:** устранение существующих болей при выполнении работы (дорого, медленно, нестабильно). (источник → стр. 56)
- **Способ №3 — Обеспечить базовое качество:** приведение продукта к состоянию, при котором реальность соответствует ожиданию клиента (Costs и Benefits соответствуют заявленному). (источник → стр. 57)
- **Способ №4 — Убить низкоуровневую работу:** сократить количество шагов в цепочке, которые клиент вынужден выполнять вручную. (источник → стр. 59)
- **Способ №5 — Выполнять больше работ человека одним решением:** один продукт покрывает несколько ранее разделённых работ одного человека. (источник → стр. 64)
- **Способ №6 — Выполнять высокоуровневые работы разных сегментов одним решением:** один продукт с несколькими вариантами/тарифами обслуживает разные сегменты с разными высокоуровневыми работами. (источник → стр. 69)
- **Способ №7 — Выполнять следующую работу:** продукт не останавливается после выполнения текущей работы, а сразу переходит к выполнению следующей работы в цепочке. (источник → стр. 71)

## 6. Разобранные примеры / кейсы / цифры

**Способ №1 — Вернуть работу (пример: русские за рубежом):** (источник → стр. 55)
- Работа: «Русскому оплатить с карты за границей»
- 2022: VISA, MasterCard — работало (зелёная галочка)
- После санкций: перестало (красный крест)
- 2023: Счёт в Казахстане — снова работает (смайл)

**Способ №2 — Починить проблемы (пример: USDT):** (источник → стр. 56)
- Работа: «Переводить USDT»
- Было: Сеть ETH — иногда дорогие транзакции ($15 на 100 USDT), иногда зависают и идут час
- Стало: Сеть TRON — дешёвые транзакции, идут стабильно 3–5 минут

**Способ №3 — Базовое качество (пример: сайт продукта):** (источник → стр. 57)
- Работа: «Сделать сайт продукта»
- Ожидание: Costs=4, Benefits=8 (голубой столбик Benefits выше — пунктирный, не залитый)
- Реальность: Costs=4, Benefits=8 (оба залиты, зелёная галочка — всё соответствует обещанному)
- Шаги: обсудить бриф → согласовать концепцию → получить варианты сайта → … → получить готовый сайт

**Способ №4 — Убить работу (пример: личная точка доступа Mac/iPhone):** (источник → стр. 59)
- Было: 8 шагов (см. п. 4)
- Стало: 2 шага (Mac сам видит hotspot телефона без действий на телефоне)

**Способ №4 — Убить работу (пример: Binance Deposit Crypto):** (источник → стр. 62)
- Было: поле «Search Coin» пустое — нужно самому вводить
- Стало: сразу показаны топовые монеты (USDT, BTC, TRX, BNB, RVN) — одно нажатие

**Способ №4 — Убить работу (пример: Сбер, перевод):** (источник → стр. 63)
- Работа: «Перевести все деньги со счёта на счёт»
- Было: нужно вводить сумму вручную
- Стало: кнопка «Все 71 866,37 ₽» — убита работа ввода суммы

**Способ №5 — Больше работ одним решением (пример: Яндекс GO):** (источник → стр. 64)
- 2014: три разных работы → три разных решения:
  - «Заказать готовую еду» → Delivery Club
  - «Купить продукты» → Вкусвилл
  - «Передвигаться по городу» → Яндекс.Такси
- 2024: все три работы → Яндекс GO (одно приложение)
- Пометка: «= фичи» (внизу слайда — [мой вывод]: имеется в виду, что объединение работ — это и есть фичи суперапа)

**Способ №6 — Разные сегменты одним решением (пример: Яндекс.Такси):** (источник → стр. 69)
- Сегмент 1: «Недорого добраться из А в Б» → тариф Эконом
- Сегмент 2: «С комфортом добраться из А в Б» → тариф Комфорт
- Сегмент 3: «Статусно и с комфортом добраться из А в Б» → тариф Ultima
- Все три сегмента → один продукт Яндекс.Такси

**Способ №7 — Следующая работа (пример: сбор откликов на вакансию):** (источник → стр. 71)
- Работа: «Собрать отклики на вакансию»
- Шаги: понять, какая информация нужна → сделать форму → проанализировать отклики
- Было: форма в Typeform (зелёный — выполняется) + анализ в Google Sheets (красный — разрыв, смена инструмента)
- Стало: форма в Typeform → анализ тоже в Typeform (синяя стрелка-петля — следующая работа выполняется тем же инструментом)

**Иллюстрация к Solution Benefits (пример: UZON, флаконы кремов):** (источник → стр. 67)
- Твит @BrianRoemmele: «UZON changed the shape of the product bottles and sales increased by 700%. Early tests were so strong that they paid for the bottle company to rush the first orders.»
- [факт из материала: это скриншот чужого твита, не заявление автора курса напрямую]

## 8. Схемы / диаграммы

**Схема 1. «Вернуть работу» — сравнение 2022 vs 2023** (источник → стр. 55)
- Заголовок: «1 — Вернуть выполнение работы, которая выполнялась, но перестала»
- Работа (голубая капсула сверху): «Русскому оплатить с карты за границей»
- Левый блок (2022): зелёная капсула «VISA, MasterCard» → красный крест (не работает)
- Стрелка вправо
- Правый блок (2023): зелёная капсула «Счет в Казахстане» → зелёный смайл (работает)

**Схема 2. «Починить проблемы» — ETH vs TRON** (источник → стр. 56)
- Заголовок: «2 — Починить проблемы»
- Работа (голубая капсула): «Переводить USDT»
- Левый блок: зелёная капсула «Хранить и переводить в сети ETH», под ней красный текст: «Иногда дорогие транзакции $15 на 100 USDT», «Иногда зависают и идут час» → красный крест
- Стрелка вправо
- Правый блок: зелёная капсула «Хранить и переводить в сети TRON», зелёный текст: «Дешевые транзакции», «Идут стабильно 3–5 минут» → зелёный смайл

**Схема 3. «Обеспечить базовое качество» — Ожидание vs Реальность** (источник → стр. 57)
- Заголовок: «3 — Обеспечить базовое качество»
- Пример: «Сделать сайт продукта»
- Верхняя часть (Ожидание): цепочка кружков — обсудить бриф → согласовать концепцию → получить варианты сайта → … → получить готовый сайт; справа столбики: бежевый (Costs=4) и голубой пунктирный ненасыщенный (Benefits=8, как бы «задекларированный, но не реальный»)
- Нижняя часть (Реальность): та же цепочка кружков, начиная с первого (залитый синий); справа столбики: бежевый залитый (Costs=4) и голубой насыщенный залитый (Benefits=8) → зелёная галочка
- Тег внизу: «главные работы»
- [мой вывод]: слайд показывает, что «базовое качество» — это когда реальные Benefits соответствуют обещанным, а не просто «сделать фичи»

**Схема 4. «Убить низкоуровневую работу» — Mac hotspot** (источник → стр. 59)
- Заголовок: «4 — Убить низкоуровневую работу»
- Работа: «Подключиться с компа к интернету с телефона»
- «Было»: цепочка 8 кружков (см. шаги в п. 4), все серые
- «Стало»: цепочка 2 кружков — «на маке нажать wifi» → «выбрать нужную сеть» → зелёный смайл
- [мой вывод]: визуализирует кратное сокращение количества шагов

**Схема 5. «Выполнять больше работ одним решением» — Яндекс GO** (источник → стр. 64)
- Заголовок: «5 — Выполнять больше работ человека одним решением»
- «2014»: три голубых круга сверху (три высокоуровневые работы), каждый соединён линией вниз со своим продуктом: Delivery Club / Вкусвилл / Яндекс.Такси (зелёные капсулы)
- «2024»: все три линии сходятся вниз к одной большой зелёной капсуле «Яндекс GO»
- Тег внизу: «= фичи»

**Схема 6. «Разные сегменты одним решением» — Яндекс.Такси** (источник → стр. 69)
- Заголовок: «6 — Выполнять высокоуровневые работы разных сегментов одним решением»
- Три голубых круга вверху, над каждым подпись сегмента:
  - «Недорого добраться из А в Б»
  - «С комфортом добраться из А в Б»
  - «Статусно и с комфортом добраться из А в Б»
- Под каждым кругом — линия вниз к тарифу: «Эконом» / «Комфорт» / «Ultima» (зелёные капсулы)
- Все три тарифа объединены снизу большой зелёной капсулой «Яндекс.Такси»

**Схема 7. «Выполнять следующую работу» — Typeform** (источник → стр. 71)
- Заголовок: «7 — Выполнять следующую работу»
- Работа: «Собрать отклики на вакансию»
- Левая сторона (Было): голубой начальный круг → цепочка 3 шага: «понять, какая информация нужна» (белый) → «сделать форму» [Typeform, зелёный] → «проанализировать отклики» [Google Sheets, красный]
- Правая сторона (Стало): голубой круг → та же цепочка: «понять...» → «сделать форму» [Typeform, зелёный] → «проанализировать отклики» [Typeform, зелёный]; между «сделать форму» и «проанализировать отклики» — синяя дуговая стрелка, означающая «следующую работу выполняет тот же инструмент»

**Схема 8. Обзорный слайд: способы 9, 10, 11 (mini-превью двух версий материала)** (источник → стр. 68)
- Слайд показывает попарно слайды версии AJTBD/32 (вверху) и версии Value/30–40 (внизу) для трёх способов:
  - №9 «Растить Job/Solution Benefits внутри одной работы»: диаграмма столбиков Job/Solution Cost vs Job/Solution Benefits (Benefits растёт вверх, Cost остаётся)
  - №10 «Начать выполнять одну из психологических потребностей» / «Начать выполнять базовые психологические потребности»: схема с кружками-потребностями (Безопасность, Эмоциональный контакт, Статус) и стрелками к «выбрать новостройку»; подпись «связь: выбрать новостройку + статус, эм. контакт, безопасность»; снизу теги «higher salary / stability / int work... / diff lifestyle» и цепочка кружков «работа→работа→работа→работа→работа»
  - №11 «Коммуницировать, что мы выполняем высокоуровневую работу»: схема: кружок Victor Filippov + «мы делаем это!» стрелка → цепочка работ; слова «работа1→работа2→работа1.3→работа1.N→работа(N)»

## 10. Термины в глоссарий

- **Job/Solution Cost** — издержки клиента при выполнении работы (время, деньги, усилие, риск)
- **Job/Solution Benefits** — выгоды клиента при выполнении работы через данное решение
- **Убить работу (Kill the job)** — устранить низкоуровневый шаг из цепочки выполнения работы
- **Следующая работа** — работа, которую клиент выполняет после текущей; продукт создаёт ценность, если берёт на себя и её
- **Суперапп** — одно решение, закрывающее несколько разных работ одного человека
- **Сегментация по работам** — разные высокоуровневые работы у разных групп → разные тарифы/режимы одного продукта
- **Первый приоритет создания ценности** — базовые условия: работа выполняется, проблем нет, качество соответствует ожиданиям
- **Второй приоритет создания ценности** — рост: убийство работ, расширение покрытия, работа с сегментами, цепочка работ, снижение Cost, рост Benefits, психологические потребности, коммуникация, пробуждение спящих работ
