# Справочник — Ценность: создание и коммуникация (JTBD)

## Краткая суть

Ценность — это **польза минус косты**. Её нужно сначала создать, а затем загрузить в голову клиента: даже суперпродукт не работает, если ценность не коммуницирована. Фича — лишь производная ценности; создавать ценность через придумывание фич («проклятый цикл») означает неуправляемый opportunity cost. Системный путь — изучить граф работ клиента и применять типовые механики создания ценности. (источник → 10. Принципы создания ценности.txt)

## Формулы ценности

**Базовая формула:**
```
Ценность = Польза − Косты
         = Бенефиты − Косты
```
(источник → 10. Принципы создания ценности.txt; подтверждение → стр. 32 vis-10)

**Уточнённая для пары «работа + решение»:**
```
Job/Solution Value = Job/Solution Benefits − Job/Solution Costs
```
Ценность уникальна для конкретной пары «работа + решение»; при смене решения меняются и Benefits, и Costs. (источник → 10. Принципы создания ценности.txt; стр. 36 vis-10)

**Рост ценности — три рычага:**
```
Ценность растёт, если:
  1. Снижаем Job/Solution Costs (при тех же бенефитах)
  2. Растим Job/Solution Benefits (при тех же или меньших костах)
  3. Одновременно снижаем косты И растим бенефиты
```
(источник → 10. Принципы создания ценности.txt)

**Ценностное предложение (формат):**
```
Core Job + ценность + фичи — менее 15 слов
```
(источник → 2.2 Ценность вашего продукта.pdf, стр. 1)

**Решение о покупке (нейробиология):**
```
Решение = Ожидаемое вознаграждение − Боль (цена / ресурсы)
```
Nucleus Accumbens оценивает оффер → Insula оценивает цену как боль → Medial Prefrontal Cortex принимает итоговое решение «купить / не купить». (источник → 3.1 Почему люди покупают.txt)

## Механики создания ценности

Всего в таблице Airtable — **31 механика** (скриншот → стр. 26 vis-10); 12 сгруппированы в воркшопе №10 по приоритетам; остальные 19 включают стратегические механики (суперапп, экосистема, tripwire, выход из прямой конкуренции и др.).

### Первый приоритет — делать в первую очередь

1. **Вернуть выполнение работы, которая выполнялась и перестала.** Без этого не имеет смысла работать над остальным. Пример: после санкций VISA/MasterCard перестали работать за рубежом → счёт в Казахстане вернул работу «оплатить с карты за границей». (источник → 10. Принципы создания ценности.txt; стр. 55 vis-10)

2. **Починить проблемы.** Устранить боли, налоговые работы и нестабильность при выполнении работы. Пример: USDT в сети ETH (дорого, нестабильно) → TRON (дёшево, 3–5 минут). (источник → 10. Принципы создания ценности.txt; стр. 56 vis-10)

3. **Обеспечить базовое качество.** Реальные Costs и Benefits должны соответствовать тому, что продукт декларирует. (источник → 10. Принципы создания ценности.txt; стр. 57 vis-10)

### Второй приоритет — когда первого уже недостаточно для конкуренции

4. **Убивать низкоуровневые работы.** Сокращать количество шагов для выполнения высокоуровневой работы. Пример: Mac Personal Hotspot — 8 шагов → 2 шага. Пример: Сбер — кнопка «Все 71 866,37 ₽» убивает ручной ввод суммы. «Убивать работы — одна из самых важных механик создания ценности. Возможно, самая главная.» (источник → 10. Принципы создания ценности.txt; стр. 59, 63 vis-10)

5. **Выполнять больше работ одного человека одним решением.** Больше бенефитов за те же косты. Пример: Яндекс GO 2024 — три ранее разделённые работы (еда, продукты, такси) в одном приложении. (источник → 10. Принципы создания ценности.txt; стр. 64 vis-10)

6. **Выполнять высокоуровневые работы разных сегментов одним решением.** Открытие новых сегментов → рост потенциальной выручки. Пример: Яндекс.Такси — Эконом / Комфорт / Ultima под одним продуктом. (источник → 10. Принципы создания ценности.txt; стр. 69 vis-10)

7. **Выполнять следующую работу в последовательности.** Рост среднего чека и удержания. Пример: Typeform добавил аналитику откликов внутри интерфейса — забрал следующую работу у Google Sheets. (источник → 10. Принципы создания ценности.txt; стр. 71 vis-10)

8. **Снижать Job/Solution Cost, не убивая работы.** Скидка, близость точки, ускорение доставки, повышение доступности. (источник → 10. Принципы создания ценности.txt)

9. **Растить Job/Solution Benefits внутри тех же работ.** Линейное улучшение важной характеристики: звук, картинка, скорость, качество. (источник → 10. Принципы создания ценности.txt)

10. **Удовлетворять глубинные психологические потребности.** Статус, безопасность, attachment/контакт, принадлежность к стае, самореализация, автономия, саморазвитие, Job Security (B2B). Пример: AirPods Max (549$, виден в Zoom) — статус. (источник → 10. Принципы создания ценности.txt)

11. **Коммуницировать выполнение высокоуровневой работы.** «Мы дадим тебе стабильность / статус / свободу» + объяснение компетентности. Это то, что делает маркетинг. Пример: Практикум (QA в США) — правильная механика: «стабильная работа, смена сферы, более высокая зарплата» вместо «суперкурикулум и тичеры». (источник → 10. Принципы создания ценности.txt)

12. **Пробуждать спящие работы.** Создавать достаточно удобное, простое и недорогое решение для работы, которая ранее не выполнялась. (источник → 10. Принципы создания ценности.txt)

## Алгоритм решения продуктовой бизнес-задачи

Системная замена «проклятого цикла фич»: (источник → 10. Принципы создания ценности.txt; стр. 25 vis-10)

1. Определить / получить **бизнес-цель**. Вычеллнджить её («что бы что»: зачем делаем это, точно ли это нужная цель).
2. Выбрать набор **механик создания ценности**, применимых к данной цели — отфильтровать по бизнес-задаче в Airtable (например, «рост среднего чека» → 8 механик).
3. Получить **сырьё**: аналитика поведения клиентов, сегментация, AJTBD-интервью (качественное → количественное), граф работ, конкурентный анализ, тренды.
4. **Применить механики** к сырью → сгенерировать 20–30 гипотез.
5. **Отранжировать гипотезы по RICE**: Impact (оценивается по таблице механик), Reach, Credibility, Effort.

Результат: управляемый, точный алгоритм роста ценности; opportunity cost известен и минимизируем. (источник → стр. 28 vis-10)

## Работы бизнеса vs работы клиентов

Один компонент продукта одновременно выполняет работы клиентов **и** работы бизнеса. При разработке нужно явно выписывать оба типа работ в требованиях. (источник → 10. Принципы создания ценности.txt; стр. 21–23 vis-10)

Пример — LMS «Как делать продукт»:
- «Доступ к материалам» → работа клиентов → LMS
- «Снизить % пиратства» → работа бизнеса → Авторизация + Kinescore
- «Улучшать материалы» → работа бизнеса → Аналитика

(источник → стр. 23 vis-10)

## Психологические основы покупки («Почему люди покупают»)

### Четыре базовых вычислительных процесса мозга

1. **Мозг-инвестор:** инвестирует ресурсы сейчас, чтобы получить больше ресурсов в будущем (Лиза Фелдман Барретт, «7,5 уроков о мозге»). Решение о действии принимается на основе прогноза, а не факта. (источник → 3.1 Почему люди покупают.txt; стр. 30 vis-10)

2. **Стремление к позитивным эмоциям:** мозг автоматически повторяет ситуации, дающие позитивные переживания (радость, спокойствие, удовлетворение, восторг, уверенность); избегает негативных (раздражение, тревога, злость, сомнение, грусть, отвращение). (источник → 3.1 Почему люди покупают.txt)

3. **Дофаминовые нейросети:** дофамин — универсальная валюта мотивации. Всплеск до действия мотивирует; всплеск после — закрепляет поведение. Базовый уровень дофамина падает при зависимостях → депрессия. (источник → 3.1 Почему люди покупают.txt)

4. **Сравнение вознаграждение − боль:** Nucleus Accumbens (предвкушение оффера) → Insula (боль от цены) → Medial Prefrontal Cortex (итоговое решение). (источник → 3.1 Почему люди покупают.txt)

### Структура: Потребности → Цели → Эмоции → Продукт

```
Базовые психологические потребности (не осознаются)
        ↓
Мозг автоматически формирует Цели (более-менее осознаются)
        ↓
В контексте движения к целям — Эмоции:
    позитивные = «я приближаюсь к цели» (сигнал повторить поведение)
    негативные = «я удаляюсь от цели» (сигнал менять поведение)
        ↓
Продукт помогает достигать цели эффективнее,
    с меньшими инвестициями ресурсов,
    с меньшими негативными и большими позитивными эмоциями
        ↓
Коммуникация — на языке эмоций (точка текущего переживания клиента)
```
(источник → 3.1 Почему люди покупают.txt)

### 9 базовых психологических потребностей (мета-анализ 7 теорий: SDT, Consistency, МакКлелланда, SCARF, Маслоу и др.)

1. Базовые физиологические (отдых, сон, питание, жидкость)
2. Социальные (контакт, эмоциональный и глубинный интимный контакт)
3. Безопасность (физическая, эмоциональная)
4. Уважение (в т.ч. статус)
5. Символизация роста
6. Автономия
7. Компетентность
8. Согласованность и когнитивный баланс

*(В тексте источника упоминается «9», при перечислении явно выделено 8 — не покрыто во входных материалах.)* (источник → 3.1 Почему люди покупают.txt)

### Три зоны осознанности потребностей

| Зона | Метод изучения |
|---|---|
| **Осознаваемые цели** (еда, работа, доставка) | JTBD-интервью — люди дают более-менее правдивые ответы; валидировать количественно |
| **Неосознаваемые цели** (статус, брак, дорогая машина) | Интервью не подходит — нарратор придумает ложную историю; конструировать гипотезы, тестировать продажами |
| **Частично осознаваемые** | Отдавать профессиональным исследователям с опытом проективных методик |

(источник → 3.1 Почему люди покупают.txt)

### Рекурсивный вопрос для выявления эмоций в основе проблемы

1. Человек называет проблему.
2. Спросить: «Что тяжёлого в том, что [проблема]?»
3. Получить ответ → снова задать вопрос «Что тяжёлого в том, что [новый ответ]?»
4. Повторять рекурсивно до выхода на эмоцию (злость, страх, тревога, стыд и т.д.).

Аналогичный вопрос для ценности: «Что классного в том, что [это]?» — рекурсивно до эмоции.
(источник → 3.1 Почему люди покупают.txt)

### Как сдвинуть Aha-момент выше по воронке

1. Узнать Aha-момент через качественные интервью («В какой момент вы поняли ценность этого решения?»).
2. Транслировать Aha-момент словами реальных клиентов в коммуникации (лендинг, реклама, скрипт продаж).
3. Воспроизвести ситуацию: «если ты сделаешь Х — получишь такой результат».
4. Сделать практику / онбординг, в которой человек получает Aha-момент как можно раньше.

## Типичные ошибки и антипаттерны

1. **«Проклятый цикл пиления фич»**: озарение → продажа стейкхолдерам → придумывание метрик → разработка → починка багов → «выпилим через 2 года». Ценность мала, процесс неуправляем, opportunity cost адовый и скрытый. (источник → 10. Принципы создания ценности.txt)

2. **Влюбляться в фичу** до тестирования — мешает убивать 9 из 10 гипотез, которые не подтверждаются. Правильная позиция: «серийный убийца гипотез». (источник → 10. Принципы создания ценности.txt)

3. **Конкурировать только ценой** — ухудшает юнит-экономику, запускает ценовые войны; в B2B цена — 5-й–6-й фактор влияния на выбор. (источник → 10. Принципы создания ценности.txt)

4. **Dark Patterns** — краткосрочный рост бизнес-ценности за счёт выжигания накопленной лояльности клиентов. (источник → 10. Принципы создания ценности.txt)

5. **Не валидировать ценность от фокусного сегмента**: решения на основе нескольких обращений в саппорт. Норма: 10+ интервью + 30+ единиц обратной связи от фокусного сегмента. (источник → 2.2 Ценность вашего продукта.pdf, стр. 1)

6. **Коммуницировать «курикулум и тичеров»** вместо высокоуровневой работы клиента («стабильная работа, смена сферы, более высокая зарплата»). (источник → 10. Принципы создания ценности.txt)

7. **Рассказывать только про фичи** в первой точке контакта вместо ценности через Jobs — оценка 0 по критерию коммуникации. (источник → 3.1 База коммуникации ценности.pdf, стр. 1)

8. **Верить интервью при изучении неосознаваемых потребностей** — нарратор придумает убедительную ложную историю; для неосознаваемых целей — только гипотезы + тесты продаж. (источник → 3.1 Почему люди покупают.txt)

9. **Игнорировать работы бизнеса** при разработке требований — фокусироваться только на работах клиентов. (источник → 10. Принципы создания ценности.txt; стр. 21 vis-10)

10. **Работать над коммуникацией ценности ДО выбора фокусного сегмента** — все TOD-задачи выполняются только после сегментации. (источник → 3.1 База коммуникации ценности.pdf, стр. 1)

## Глоссарий

| Термин | Определение |
|---|---|
| **Ценность для клиента** | Польза минус косты; бенефиты минус косты. Чем больше разница — тем более ценным клиент считает продукт. (источник → 10. Принципы создания ценности.txt) |
| **Job/Solution Value** | Ценность, уникальная для пары «работа + решение» = J/S Benefits − J/S Costs. (источник → 10. Принципы создания ценности.txt) |
| **Job/Solution Cost** | Суммарные расходы времени, денег и энергии на выполнение всех работ ниже уровня при использовании конкретного решения. (источник → 10. Принципы создания ценности.txt) |
| **Job/Solution Benefit** | Все ресурсы и плюшки (включая сэкономленные время и деньги), которые человек получает на выполнение работ с конкретным решением. (источник → 10. Принципы создания ценности.txt) |
| **Фича** | Производная ценности by design — знание/сигнал о том, что кто-то считает конкретную особенность продукта ценной. (источник → 10. Принципы создания ценности.txt) |
| **Бизнес-ценность** | Вся ценность в зоне компетенции продукта: выручка, прибыль + метрики юнит-экономики (конверсии, возвращаемость, удержание). (источник → 10. Принципы создания ценности.txt) |
| **Налоговая работа** | Незапланированная работа, возникшая из-за отказа решения (провод перетёрся → купить новые наушники). В отличие от кост — это расходы, которые человек не планировал. (источник → 10. Принципы создания ценности.txt) |
| **Спящая работа** | Работа, которая не выполняется, пока не появится достаточно удобного, простого и недорогого решения. Тип А: человечество ещё не научилось пробуждать. Тип Б: алгоритм уже существует. (источник → 10. Принципы создания ценности.txt) |
| **Aha-момент (A-moment)** | Описание контекста и событий, в которых произошла активация ценности у клиента — момент, когда клиент сказал «вау, я понял, в чём фишка». Должен быть доступен до оплаты. (источник → 10. Принципы создания ценности.txt; 3.1 База коммуникации ценности.pdf) |
| **Активация в ценность** | Переход клиента из состояния «не понимал ценность» в «понял ценность». (источник → 10. Принципы создания ценности.txt) |
| **Opportunity Cost** | Упущенная выгода от принятия худших альтернативных решений. При «проклятом цикле фич» — скрытый и адовый; при работе через механики — управляемый. (источник → 10. Принципы создания ценности.txt) |
| **Dark Pattern** | Механика, растящая бизнес-ценность, не улучшая или ухудшая ценность для клиента — выжигает накопленную лояльность. (источник → 10. Принципы создания ценности.txt) |
| **Работы бизнеса/продукта** | Цели бизнеса, описываемые в том же формате, что и работы клиентов («когда… хочу, чтобы…»). (источник → 10. Принципы создания ценности.txt) |
| **Точка А** | Текущая ситуация клиента: контекст, триггер, эмоции и боли ДО использования продукта. (источник → 3.1 База коммуникации ценности.pdf) |
| **Точка Б** | Желаемый результат: эмоции, результат Core Job / Big Goal ПОСЛЕ использования продукта. (источник → 3.1 База коммуникации ценности.pdf) |
| **AB-клиенты** | Клиенты, прошедшие путь от точки А к точке Б (купили и получили ценность). Основной источник для AJTBD-интервью по ценности. (источник → 3.1 База коммуникации ценности.pdf) |
| **Увольнение конкурентов** | Демонстрация в первой точке контакта, почему именно ваш продукт лучше альтернатив, которые рассматривал клиент. (источник → 3.1 База коммуникации ценности.pdf) |
| **Дофаминовая петля** | Механизм закрепления поведения через всплески дофамина; основа зависимостей (TikTok, казино). (источник → 3.1 Почему люди покупают.txt) |
| **Мозг-инвестор** | Принцип: мозг инвестирует ресурсы сейчас, чтобы получить больше в будущем (Лиза Фелдман Барретт). Решение принимается на основе прогноза. (источник → 3.1 Почему люди покупают.txt) |
| **Внутренний нарратор** | Вычислительный процесс в левом полушарии, сохраняющий когнитивный баланс — конструирует убедительные, но часто ложные объяснения поведения. (источник → 3.1 Почему люди покупают.txt) |
| **Число Данбара** | ~150 — максимальное количество связей, которые мозг одного человека способен нормально управлять. (источник → 3.1 Почему люди покупают.txt) |
| **RICE** | Фреймворк приоритизации гипотез: Reach / Impact / Credibility (как в источнике; в классическом RICE — Confidence) / Effort. (источник → 10. Принципы создания ценности.txt) |
| **Суперапп** | Механика дистрибуции: привлечение по людям, а не по работам; одно решение закрывает несколько разных работ одного человека. (источник → стр. 23 Airtable vis-10) |
| **Экосистема** | Способ массово пробуждать спящие работы за счёт кардинального снижения Job/Solution Cost. (источник → стр. 24 Airtable vis-10) |
| **Tripwire** | Механика привлечения через очень большую дельту между transaction cost и ценностью. (источник → стр. 25 Airtable vis-10) |
