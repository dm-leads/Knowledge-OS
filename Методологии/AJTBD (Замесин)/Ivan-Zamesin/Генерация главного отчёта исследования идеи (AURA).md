# Инструкция: главный отчёт исследования идеи (AURA)

Ты генерируешь **главный отчёт исследования идеи** в стиле фреймворка AURA (AJTBD, RAT, Unit Economics, фокус, коммуникация). Отчёт — ключевой артефакт; из него пользователь потом переходит в блоки «Подробнее о продукте» и в детальный разбор каждого сегмента.

## Входные данные

- **Описание продукта/идеи (обязательно):** %productDescription%
- **Дополнительный контекст из диалога (если есть):** %dialogContext%
- **Название продукта (если указано):** %productName%
- **Сайт (если указан):** %site%
- **Стадия продукта (если указана):** %stage%
- **Тип бизнеса (если указан):** %businessType%
- **Ценностные предложения (если указаны):** %valuePropositions%
- **Функции/фичи (если указаны):** %features%
- **Ссылки на конкурентов (если указаны):** %competitorLinks%

Если какое-то поле не заполнено, используй формулировку «не указано» или сформулируй предположение на основе описания продукта.

## Структура отчёта (выдай в Markdown)

1. **Заголовок** — название продукта.
2. **Краткая карточка:** статус (GO / Hold / и т.п.), дата, количество сегментов, критические риски, доля рынка (если можно оценить).
3. **Краткое описание продукта** (1–2 предложения).
4. **Вердикт** — вывод по привлекательности идеи, ключевые сегменты, основные риски и возможности в 2–4 предложениях.
5. **Ключевые риски** — маркированный список (3–6 пунктов).
6. **Ключевые возможности** — маркированный список (3–5 пунктов).
7. **Альтернативные направления** — пронумерованный список (направления развития: сегмент, канал, монетизация, технология и т.д.) с кратким обоснованием.
8. **Следующие шаги** — пронумерованный список конкретных действий.
9. **Top рисковых гипотез (RAT)** — для каждой: категория, название, описание, риск/влияние/сложность (если уместно), как проверить. 3–6 гипотез.
10. **Оценка рынка** — TAM, SAM, SOM (если можно оценить).
11. **Конкуренты** — кратко: кто, тип (прямой/косвенный), цены, сильные/слабые стороны (если контекст позволяет).
12. **Возможности коммуникации** — тезисно (если уместно).
13. **Ценообразование** — варианты и обоснование (если уместно).
14. **Сегменты** — список сегментов; для каждого укажи: номер, название, Core Job (кратко), балл привлекательности (число 0–100 или аналогичная шкала), одно предложение описания. Сегменты должны быть кликабельными блоками в UI, поэтому выводи их чётко (например, подзаголовок ### для каждого сегмента).

Формат вывода: **только Markdown**, без JSON. Заголовки используй уровней ## и ###. Списки — маркированные или нумерованные по смыслу.
