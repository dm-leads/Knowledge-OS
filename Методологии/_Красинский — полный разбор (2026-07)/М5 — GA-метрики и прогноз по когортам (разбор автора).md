## О чём
Практический модуль: как ВЫГРУЗИТЬ метрики из аналитики (GA) без ошибок и построить когортный
треугольник, чтобы прогнозировать будущее. Здесь — механика построения когорт (то, что в М4 показано
как результат): сводная таблица «первая сессия × месяц транзакции», строка «до основания», кросс-чеки,
retention-мультипликатор MAU, когортный LTV.

## Ключевые концепции (с механикой)

**1. Иерархия доверия данным аналитики.** `[факт: транскрипт]` **Верить** только: байеры (уник.
пользователи с транзакцией), транзакции (уник. ID), выручка из базы. **Не верить** готовым: конверсии
(особенно по сессиям), среднему чеку из отчёта, retention из сложных SQL. **Считать самим:** конверсию
(`байеры/пользователи`), средний чек (`выручка/байеры`), старых (`все − новые`). «Аналитик ошибается
в 9 из 10 случаев при сложном запросе — лучше простые запросы + вычитание».

**2. Байеры считаются по идентификатору.** `[факт: транскрипт]` «байеры записаны в поле… Dimension 4…
мне надо посчитать уникальное число». → когорта строится по `ga:dimension4` (clientID).

**3. Треугольник нельзя «тащить» механически — С23 ≠ retention.** `[факт: транскрипт]` «проблема с
треугольниками в том, что вы не можете просто так их тащить. Почему С23 считается по-другому? …
у них другой смысл, в отличие от Retention». → **[вывод, критично]** конверсия повторной покупки
(С23, относительно предыдущего месяца) и retention (абсолютно от основания) — РАЗНЫЕ метрики с разной
математикой; путать нельзя.

**4. Сэмплирование GA.** `[факт: транскрипт]` 41 упоминание; при большом объёме GA считает по выборке
(до 48%), аппроксимируя остальное → погрешность. «Первые два запроса нужны для расчёта СЫРЫХ данных,
чтобы посчитать всё без сэмплирования». → для когорт выгружать построчно, без сэмплирования.

**5. Степенной retention и мультипликатор MAU.** `[факт: транскрипт]` «единица на X — это единица в
степени X−1… первый коэффициент — просто первый месяц (17%)». Мультипликатор: «1 → 1,17 → быстро
превращается в асимптоту, ограничение сверху». → `MAU(N)=Новые×Мультипликатор(N)`, мультипликатор
выходит на плато = устойчивый MAU при постоянном притоке.

**6. Churn — НЕкогортная метрика; LTV=1/churn — ложь.** `[факт: транскрипт]` «почему чарн-рейт —
некогортная метрика, почему расчёты чарн-рейта умеренно бесполезны… много заблуждений». → формула
`LTV=1/churn` верна лишь при постоянном churn (экспоненциальное затухание); на практике retention
степенной, убывает медленнее.

**7. Retention ≠ повторные покупки.** `[факт: транскрипт]` «retention может ограничивать сверху
конверсию 2-й покупки, но прямой связи нет» (особенно B2B/автопродления/низкочастотные).

## Формулы (из xlsx и транскрипта, дословно)

```
Конверсия C1        = Байеры / Пользователи              (НЕ транзакции/сессии)
Средний чек         = Выручка / Байеры
Старые              = Все − Новые                        (вычитанием)
Когорта (Sheets)    = IF(A3<>""; DATE(YEAR(A3);MONTH(A3);1); "before Jan 2017")
Ячейка треугольника : байеры=COUNTUNIQUE(UserID) · пейменты=COUNTUNIQUE(TransactionID) · выручка=SUM(Revenue)
Retention (степен.) : Ret(t) = a × t^b        (b обычно −1; при b=−1 → гипербола a/t)
Мультипликатор(N)   = 1 + Ret(1) + Ret(2) + … + Ret(N−1);   MAU(N)=Новые×Мультипликатор(N)
Финансовая когорта  : Байеры(M+1)=Байеры(M)×C(M→M+1);  Revenue(M+1)=Revenue(M)×C_rev(M→M+1)
Когортный LTV       = Σ Gross Profit за жизнь когорты / Байеры основания
ARPMAU (реклама)    = CPM/1000 × Imps_Per_User;  GP = MAU × ARPMAU × Маржа
```
`[факт: xlsx]` формула фиксации основания при протягивании по диагонали: `= $Основание_когорты × C2M`
(знак `$` фиксирует колонку основания, месяц транзакции перемещается).

## Обязательные приёмы (кросс-чеки)
- **Строка «до основания»** (before Jan 2017) — пользователи с первой сессией ДО периода. «В 95%
  когортных отчётов её нет. Без неё Σ по столбцу ≠ P&L». `[факт: транскрипт]`
- **Кросс-чек №1:** `Выручка = Байеры × Средний чек` (Δ=0).
- **Кросс-чек №2:** `Σ по столбцу (месяц) = P&L выручка месяца`. Не сходится → ошибка в данных.

## Разобранные числовые кейсы
- **Интернет-магазин обуви** `[факт: транскрипт]`: продукт 10 лет на рынке; **C23 ≈ 3%** (97% не
  возвращаются на след. месяц — низкочастотный товар); половина дохода — от старых когорт; единственная
  «сошедшаяся» когорта — ноябрь (Чёрная пятница). → бизнес жил за счёт накопленных старых; новые
  инвестиции в маркетинг нецелесообразны до роста конверсии.
- **Сэмплирование (ноябрь 2017):** байеры с сэмпл. 2590 vs без 2660; конверсия 0,9% vs 1,1%; AMPU
  20₽ vs 23₽ — расхождение значимо. `[факт: транскрипт]`
- **B2B SaaS (прогноз по фин. когортам):** C2 удержания байеров ~60–72%, C3 ~79–89%; удержание по
  ДЕНЬГАМ выше, чем по байерам (дорогие клиенты держатся лучше); runway/break-even через сумму GP
  когорт против фикс-костов. `[факт: транскрипт]`
- **MAU-мультипликатор (реклама):** retention 17/7/3% → мультипликатор на 12-й мес ≈ 1,51. `[факт: xlsx]`

## Пошаговые алгоритмы
1. **Выгрузка из GA:** запрос A (все: users/new_users/transactions/revenue/dimension4/sessionCount),
   запрос B (то же с фильтром `sessionCount=1` — новые). Проверить сэмплирование (>5% → сырьё).
   Старые = все − новые (НЕ отдельным запросом). Верить только байерам/выручке; конверсию/чек считать.
   Кросс-чек `Выручка=Байеры×Ср.чек`.
2. **Построение треугольника:** данные `[UserID | первая сессия | дата транзакции | выручка]` → сводная
   (строки=месяц первой сессии, столбцы=месяц транзакции) → три параллельных (байеры/пейменты/выручка)
   → строка «до основания» → кросс-чек Σ столбца = P&L → C23 = Байеры(мес2)/Байеры(мес1).
3. **Прогноз через retention:** взять факт retention 3 мес → подобрать `b` «на глаз» → достроить кривую
   → мультипликатор → MAU(N).
4. **Прогноз через фин. когорты (B2B):** усреднить C2m/C3m по когортам → достроить будущие когорты →
   Σ GP по месяцам → сравнить с фикс-костами → break-even/runway.

## Антипаттерны (дословно из М5)
1. Конверсия по сессиям вместо пользователей (систематическая ошибка GA).
2. Усреднять new/old (пример ошибки −409 млн ₽/мес — из М1).
3. Один сложный запрос вместо простых + вычитание (аналитик ошибается 9/10).
4. Доверять без кросс-чеков.
5. Забыть строку «до основания» (Σ≠P&L).
6. `LTV=1/churn` (верно лишь при постоянном churn).
7. `Retention = повторные покупки` (прямой связи нет).
8. Семплирование GA без проверки (48% → погрешность ~697 тыс.₽).
9. Считать юнит-экономику за один месяц (удачный ноябрь создаёт иллюзию).
10. Сложные формулы retention вместо подбора «на глаз» по 3 точкам.

## Как применяется в управлении бизнесом (какое решение меняет)
- **Прогноз выручки/плана продаж** — из устойчивых когортных коэффициентов, а не из P&L.
- **Стоит ли лить в маркетинг** — если конверсия низкая и когорты не сходятся (кроме сезонных пиков) —
  сначала чинить конверсию/чек, потом масштабировать.
- **Достоверность цифр** — не доверять готовым отчётам аналитики; пересчитывать самому с кросс-чеками
  (это прямо ложится на наш [[rule-metric-consistency]] и гейт сводимости).

## Термины в глоссарий
Байер · пеймент · когорта (маркетинг/коммерч/фин) · C1 · C23 (конв. 2-й покупки, ≠ retention) ·
retention (абсолютно от основания) · MAU · мультипликатор MAU · «до основания» (before Jan 2017) ·
сэмплирование · степенной retention `a·t^b` · ARPMAU · CPM · когортный LTV=ΣGP/байеры · Smile Effect.
