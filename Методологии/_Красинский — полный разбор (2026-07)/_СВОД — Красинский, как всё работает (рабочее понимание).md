## 1. Корневой фрейм: теория ограничений + слоёная модель

**[факт] Весь курс = теория ограничений Голдратта, применённая к метрикам** (М2, дословно). Отсюда всё
остальное: ищем ОДНО узкое место (ограничение), а не улучшаем всё подряд.

**[факт/вывод] Слоёная модель (М1), снизу вверх управляет сверху вниз:**
```
Финансы (P&L)            ← показывают ПРОШЛОЕ, не определяют будущее
   ↑ определяются
Юнит-экономика когорт    ← предсказывает, как когорта будет жить (будущее)
   ↑ рычаги нелинейны
Слой нелинейного роста   ← операция вычитания: малое изменение у метрики ≈0 даёт кратный эффект
   ↑ мешает увидеть
Слой убеждений/эмоций    ← команда не видит очевидного (цикл Кюблер-Росс: отрицание→гнев→торг→принятие)
```
→ **[вывод]** P&L не годится для прогноза плана продаж — его определяют устойчивые когортные
коэффициенты. А главный барьер к правильному решению — не данные, а убеждения команды.

## 2. Ядро юнит-экономики (М0/М1) — метрики и формулы

**Юнит** — то, что масштабируется (в 99% — платящий пользователь). Управляем ПОВЕДЕНИЕМ пользователя,
не метрикой напрямую («у ценности нет рук, ног и мозга»).

```
Buyers      = Users × C1                         C1 = Buyers/Users (НЕ транзакции/сессии)
Payments    = Buyers × APC                       APC = Σ платежей когорты / размер когорты (≈1,2, НЕ «6»)
Revenue     = Payments × AvPrice
AMPPU (=CLTV) = AvPrice × Margin × APC           варианты: −COGS, −COGS_1st, −Tax, −Discount
AMPU  (=LTV)  = C1 × AMPPU
CPUser      = Acq.Costs / Users                  ← actionable для команды
CAC         = Acq.Costs / Buyers = CPUser / C1   ← только для инвесторов (NPV/IRR), НЕ для операционных решений
Gross Profit = Buyers × AMPPU = Users × AMPU     ← кросс-чек: два пути, разница = 0
Profit      = Users × (AMPU − CPUser) = Revenue − COGS − Acq.Costs   ← кросс-чек
```

**Три уровня сходимости (М0):** ① AMPPU>0 (платящий прибылен) ② AMPU>CPUser (привлечённый окупается)
③ Profit>Fix Costs (бизнес в плюсе).

**[факт] Кросс-чек — дисциплина, а не формальность:** любую метрику считать двумя независимыми путями,
разница = 0; не сошлось → искать ошибку, дальше не идти. → **прямо ложится на наш гейт сводимости и
[[rule-metric-consistency]].**

**[факт] Издержки: масштабируемые / немасштабируемые** (НЕ бухгалтерские «переменные/постоянные»).
Тест: что будет с этой статьёй при ×100 продаж? Растёт → масштабируемая (COGS, Acq); нет → фикс.
OPEX/CAPEX (Доп4) — «бесполезные бухгалтерские категории» для юнит-экономики.

## 3. Механика кратного роста — операция вычитания (М1, ядро)

**[факт] Кратный («нелинейный») рост берётся из ВЫЧИТАНИЯ двух близких чисел:** `Profit/user = AMPU −
CPUser`. Когда AMPU≈CPUser, малое улучшение AMPU даёт кратный скачок прибыли. Кейс Архангельск:
чек ×2 и комиссия ×3 → AMPU ×6, но итоговая прибыль ×12,3.

**[факт] Второй источник вычитания — работать с `(1 − конверсия)`** (Доп2/Доп4): изучать НЕ купивших
(их большинство), а не оптимизировать «конверсию» абстрактно. `AMPPU = AvPrice×Margin×APC − COGS_1st`
— тоже вычитание (Доп4: чек 30k→65k дал AMPPU ×2,8, не ×2, из-за вычитаемого онбординга).

**[факт] Порядок работы с рычагами:** сначала **маржа**, потом **средний чек**, потом **конверсия**,
в последнюю очередь **поток**. Масштабировать поток при несходящейся экономике — кратно увеличить
убыток (Архангельск: Users×3 → Profit −1,94 → −8,82 млн). **Точка роста «переезжает» во времени**
(Доп2) — нельзя годами держаться за один рычаг, надо передиагностировать.

## 4. Когорты (М4/М5) — как выглядит и читается ПРАВИЛЬНО

**[факт] Когорта — «треугольник»/«лесенка».** Строка = месяц привлечения (основание), тянется по
диагонали через последующие месяцы. **По ВЕРТИКАЛИ (Σ столбца) = финансы/P&L месяца; по ГОРИЗОНТАЛИ
(строка) = юнит-экономика одной когорты во времени.** Метафора бассейна: приток новых − отток старых.

**Типы когорт (основание):** маркетинговая (первая сессия) / коммерческая (первая заявка) /
финансовая (первая оплата). Выбор — под задачу.

**[факт, критично для viklimat] Длинный цикл сделки / высокий чек:** когорта = «когда лиды ВПЕРВЫЕ
оплатили» (цикл сделки по неделям/месяцам), **повторы НЕ считаем**. «Высокий чек → повторные покупки
редкость → смещаемся в конверсию» (М4). → у viklimat релевантен именно этот лист, а НЕ retention.

**Обязательные приёмы (М5):** строка «до основания» (иначе Σ≠P&L); кросс-чеки `Выручка=Байеры×Ср.чек`
и `Σ столбца=P&L`; `Старые=Все−Новые` вычитанием; **C23 (конв. 2-й покупки) ≠ retention** («у них
другой смысл»). Иерархия доверия: верить байерам/транзакциям/выручке; конверсию/чек/старых — считать сам.

**Прогноз:** ретеншн-мультипликатор MAU `Ret(t)=a·t^b`, выходит на асимптоту; когортный LTV=ΣGP/байеры
основания. **[факт, ОБНОВЛЕНИЕ Доп4]:** «churn rate / retention — формула 15-летней давности, выбросить;
считать повторы когорты НАПРЯМУЮ». Это жёстче классического курса (там churn/retention ещё промежуточные).

**Когда когорты НЕ нужны:** «если есть вторая продажа — обязаны считать когортами; нет второй продажи —
retention не ваш рычаг». Для разового товара главное — конверсия и чек.

## 5. Диагностика узких мест (М2)

- **Сегментировать, а не усреднять; порядок: старые/новые → устройство → канал → (недели при длинном
  цикле).** Усреднение прячет убыточный сегмент (FlowWow: AMPU 10,9 vs CPU платного канала ≈23 —
  экономика не сходится на ПЛАТНОМ, маскируется органикой).
- **CPU — для операционных решений, CAC — только для инвесторов.**
- **Правильный порядок в кейсе FlowWow:** сначала маржа (комиссия до ~30% — почти бесплатно дало прирост
  GP), потом чек, потом конверсия (команда 1–2 года билась за конверсию и год пилила приложение — 0 эффекта).
- **Эвристика слепого пятна (Доп4, «на тысяче команд»):** где команда уверена в фактах = компетенция,
  риска нет; где мутно/защищается = там реальное узкое место.
- **Факт / Интерпретация / Эмоция (М2)** — авторская замена CustDev: интерпретация = рационализация,
  эмоция = «что испытывает тело». **Ошибка выжившего** — смотреть только на купивших/вернувшихся.
- **Скрининг:** «>2% в корзину → проблема discovery, скорее всего, нет».

## 6. Гипотезы (М3)

- **Двойная бухгалтерия:** таблицу считать дважды — от сырых данных (точность) и переписанной «покупатели
  из конверсии» (мгновенный пересчёт гипотез copy-paste).
- **Двухшаговая оценка:** сначала быстрая КАЧЕСТВЕННАЯ всей командой (влияние/сложность 1–5/вера, без
  спора, усреднение) — отсекает ~половину; выжившие → КОЛИЧЕСТВЕННЫЙ расчёт эффекта в рублях. Цель:
  50 гипотез за 30 мин.
- **Плечо метрики → в рубли:** банк, конверсия формы +1,5 п.п. = +1200 карт = 17 млн ₽ медиабюджета
  при стоимости эксперимента 2 млн/полгода.
- **«Конец воронки раньше начала»** — не улучшать регистрацию до оплаты (нецелевой трафик).
- **Ухудшающий эксперимент** вместо полугода A/B по цене: разово поднять цену везде (неделя) — увидеть,
  где просела. Сегментацию «из головы» подобрать нельзя.
- **A/B дорого и часто не сходится (>90%):** ~10k на вариант (30k суммарно); AA-тест показывает, что
  одинаковые варианты дают разную наблюдаемую конверсию (изменчивость). CI-санити перед тестом (М8):
  0,4%±0,2 vs 0,6% — интервалы пересекаются → тест бессмыслен.
- **Выручка — глазами КЛИЕНТА** (что заплатил), не компании (что осталось).

## 7. Продукт: активация, CJM, коридорные тесты (М6/М7)

- **[факт] Активация — метрика-потолок** для всей юнит-экономики (ограничивает конверсию, retention, LTV
  сверху). **Всего 2 рычага: обучить пользователя или упростить продукт.** Третьего нет.
- **Антифичепиление:** фича — «генератор дополнительной работы», часто прячется от пользователя
  (Альфа-Банк 2016: 74 фичи за 3 мес из-за смешения когорт → «антиактивация»). Допустим нулевой
  фич-план на год ради техдолга (кейс — ×20 метрики). KPI — на когортные метрики + число проверенных
  гипотез/неделю (иначе закон Гудхарта: «% зелёных тестов», «место по числу фич»).
- **Решение задачи «с конца»** (ТРИЗ ИКР + мин. критическая цепочка Голдратта): целевой GP ÷ AMPU =
  нужно клиентов ÷ прирост базы/мес = срок.
- **JTBD вместо персон/user story:** сценарий + триггер. Фримиум лимитировать по ИСПОЛЬЗОВАНИЮ, не по
  времени (Notion, «после 1000 тикетов»).
- **Коридорные тесты (М6):** метод «3 вопроса» (что видишь/понимаешь/делаешь), мышь не давать, старт с
  РЕКЛАМЫ (не с лендинга), двое ведущих; **специально НЕ на ЦА** (иначе ошибка выжившего); **раскадровка
  вместо кликабельного прототипа** (прототип прячет «гэп между экранами»); фокус-группы отвергнуты.
  Кейсы: GPS-часы МегаФон конверсия +до 22–30%; лендинг «Бумпланер» 0,2%→1,7% за неделю.

## 8. Ценность, цена, «налог» (М8/М0/М9)

- **[факт] Выгода vs «налог»:** «налог» = абстрактный/недоказанный текст, не дающий читателю выгоды
  («налог на внимание»). Правило: **«сомневаешься, выгода или налог — значит налог»** (но один и тот же
  факт — налог для одного сегмента, выгода для другого).
- **«Фреон»-язык:** инженерные термины (компрессор, фреон) вместо выгоды («холодная сверху под пиво,
  менее холодная снизу под овощи»). **N-почему** — от фичи до эмоциональной выгоды (кейс Bookerson:
  выгода не «имя ребёнка в книге», а «родителям тишина/отдых»).
- **Ценообразование ~30% от выгоды клиента** (10–20% честно, 50% при внятной ценности); потолок чека
  ~500k ₽/сделка (дальше тендеры, смена ЛПР). **Сегментация цен — двойной рычаг** (одновременно ↑ чек и
  ↑ конверсию); оптимум 3–4 тарифа или безвыборное автоназначение.
- **Майнинг звонков продаж (М8, actionable):** слушать реальные звонки вместе с продавцами, только
  задавать вопросы (никогда не давать фидбэк) → извлечь язык выгоды и слепые пятна; сверить лендинг с
  реальным устным скриптом (команды почти никогда не слушали свой лендинг).
- **B2B — эмоциональнее B2C** (М2): ЛПР оптимизирует не «сэкономить», а «обосновать трату перед другими
  ЛПР»; продукт для ЛПР по факту — отчёт/презентация (Intercom). Скидка в B2B — недоказанное убеждение
  (кейс Новосибирск: биллинг без скидок → ×2 ARPU).

## 9. Операции и COGS (М9)

- **Операционный процесс = JTBD-сценарий, где «пользователь» — сотрудник.** Рефлекс «напишем свою
  CRM/приложение» почти всегда убыточен («цена фичи = не ноль, а −несколько миллионов»; Инвитро:
  рассылка без deliverability → OpenRate 0%).
- **Touch Time = (min+max)/2 на шаг × число циклов; Lead Time ≈ 10× Touch Time** (90% — простой).
- **Узкое место = throughput роли** (рабочие часы 176→88/мес с 50%-дисконтом / touch time на проект);
  самый нагруженный/незаменимый ресурс ограничивает систему.
- **COGS через команду:** кейс CarrotQuest/Dashly ≈23k ₽/клиент; смена состава ролей двигает COGS,
  добавление разработчиков при объёме — почти нет.
- **Морфинг бизнес-модели (М9/Доп4):** если экономика не сходится ни при каких допущениях — не
  оптимизировать, а **менять кто-кому-за-что платит** (тот же функционал: 3k как инструмент vs
  60–100k как «рост продаж»/методология; dating→event-агентство).

## 10. Актуальные обновления этого года (Доп1–4) — что жёстче/новее классики

- **[обновление] churn/retention — «выбросить», считать повторы напрямую** (Доп4). Для разового товара
  это подтверждает: retention не строим, смотрим конверсию/чек.
- **Морфинг бизнес-модели** — как named-приём (Доп4) для несходящейся экономики.
- **AI-менеджмент (Доп1):** ключевой скилл — **фальсификация гипотез** (заставить агента показать
  разрыв ожидание↔результат, иначе «врёт, что сделал»); личная система **~80 стандартов (ДНК) + ~100
  скиллов** поверх; **промпт = новая программа**; **97 из 100 задач не двигают ни одной метрики**;
  **гэпы на стыках команд** (маркетинг↔продажи) — главный источник роста; сдвиг найма (не берут
  джунов/мидлов, ставка на сеньоров+модели).
- **Разметка engaged/not-engaged через JTBD+AI** (Доп2) — замена «целям» Метрики и bounce rate; AI в
  дизайне = «секретарские функции» (контекст, потерянные детали), не вкус (Доп3).
- **Мост «attention трансформера ↔ внимание в продажах»** (Доп1) — НЕ путать с «экономикой внимания» М4
  (там смысл когортно-финансовый).

## 10а. Квизы (Доп7, дополнено Доп5 и М3/М7) — добавлено 24.09.2026
Детали и цитаты — в Доп7 (раздел «Квизы», 9 частей) и Доп5 (раздел «Квизы»). Здесь — рабочие правила.
- **[факт, Доп7] Квиз — это вопросы продавца, а не форма заявки:** «Квиз – самая ближайшая метафора – это вопрос,
  который задает sales для покупки». Каждый вопрос помогает человеку понять, что ему нужно; сомневаешься, выгоден
  ли вопрос человеку, — «значит, это налог».
- **[факт, Доп7] Опорные вопросы:** что человек хочет, чего ожидает, чего боится; рядом с вопросом — выгода
  («идеальное место для оффера тут, потому что люди невнимательно читают лендинг»).
- **[факт, Доп5] Вопросы — из звонков, только те, без которых нельзя сделать оффер** («порядка 7 вопросов»); после
  вопросов — сразу цена или вилка, а не «перезвоним»; на финале повторить слова клиента.
- **[факт, Доп7] Нормы:** до конца доходят 80–90 % (не менее 80 % и на телефоне, и на компьютере); первый экран
  теряет не больше 5–10 п.п. (позже автор говорит 10–20 %); большой отвал на экране — смотреть экраны ДО него.
- **[факт, Доп7] Устройство:** один экран — один вопрос, крупные кнопки, без выпадающих списков; прогресс-бар и
  крестик автор удаляет, но призывает проверять тестом.
- **[факт, Доп7] Финал без скидки:** «у меня в жизни не было ни одного квиза, который заканчивался скидкой» — в конце
  подбор под ситуацию. Контакт — через выгоду, мессенджеры первыми, звонок последним (звонка хотят 13–15 %);
  кнопка «у меня вопрос» на каждом экране.
- **[факт, Доп7/Доп5] Ответы квиза — в продажу:** «Квиз работает не сам по себе… когда вы используете для продажи
  информацию с квиза»; поле телефона без маски и списка стран (Доп5).
- **[факт, Доп7] Язык клиента, деньги вместо процентов:** сложный вопрос — потеря конверсии; «процентов нельзя писать».
- **[вывод] Проверка:** «Если вы сделали квизы и сегментацию, и не узнали ничего нового… вы точно сделали херню» —
  итог теста квиза должен дать новое знание о сегментах, иначе тест поставлен неверно.
- **Чего у автора нет:** порядка вопросов по данным (отложен на курс), норм конверсии квиза в заявку, схемы квиза
  физического товара для частного покупателя, требований закона РФ к согласию на ПДн (совет убрать галочку — его
  мнение, нужен юрист).

## 11. Сводные антипаттерны
Усреднять new/old · конверсия по сессиям · путать CPU и CAC · масштабировать несходящуюся экономику ·
не учитывать COGS_1st (кассовый разрыв) · APC без когорт («6 покупок» вместо 1,2) · `LTV=1/churn` ·
`retention=повторы` · забыть «до основания» · один сложный запрос вместо простых+вычитание · доверять
без кросс-чеков · семплирование GA без проверки · A/B без расчёта мощности · копировать «выживших»
(ошибка выжившего) · фичепиление без когортного обоснования · KPI на игрибельных метриках · персоны/
user story вместо JTBD · кликабельный прототип · фокус-группы · «фреон»-язык / «налог» на лендинге ·
писать свою CRM без проверки · масштабировать личные продажи при низком чеке.

## 12. Прямое применение к viklimat (что берём / что не наше)
- **Наше:** кросс-чеки и «одно определение метрики» (гейт, [[rule-metric-consistency]]); сегментация
  (старые/новые→устройство→канал), которую уже даёт сквозная/речевая; **когорта длинного цикла сделки**
  (лид→первая оплата), а НЕ retention-повторы; работа с `(1−конверсия)` — узкое место категория→карточка;
  порядок «маржа→чек→конверсия→поток»; майнинг звонков (у нас речевая аналитика!) для языка выгоды;
  «выгода vs налог» и N-почему для карточек/лендингов; CPU-логика вместо CAC.
- **НЕ наше (разовый высокочековый товар):** retention/повторные покупки, LTV-хвост, MAU-мультипликатор —
  Красинский сам разворачивает такой бизнес В КОНВЕРСИЮ. → «когорта ради когорты» строить не надо;
  когортный аппарат уместен только как **цикл сделки** + честная сегментация new/old.
