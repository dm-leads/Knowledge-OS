записаны в `..\TASKS.md`, раздел «Решено Дмитрием 13.10.2026», строки о паспорте и о правилах канона.
Решение владельца: **ждёт** — принята / уточнить / отклонена.

Объём по стандарту «Цепочка постановки»: меняем работающую систему, значит три файла — эта постановка,

## Проблема

Паспорт проекта — `CLAUDE.md`. Его читают Claude Code и агент Cursor; Codex читает `AGENTS.md`. Правила канона
подключены одним способом — импортом в `~/.claude/CLAUDE.md`, который работает только в Claude Code. Отсюда:

- Codex открывает проект без паспорта либо с его копией: импорт Codex сам создаёт `AGENTS.md` из `CLAUDE.md`.
  Найдено три такие копии — глобальная, в корне канона и в корне рабочей папки компании; все три уже
  отличаются от оригиналов;
- агент Cursor паспорт читает и пути журнала и базы инцидентов из блока канона знает, но правил канона не
  получает; Codex не получает ни того, ни другого. Глобальный файл правил Codex ссылается на папку, которой нет;
- `kos_connect.py` пишет блок канона только в `CLAUDE.md` (строка `passport = project / "CLAUDE.md"`). Шаблон
  паспорта, стандарт «Три файла проекта» и плейбук подключения называют паспортом `CLAUDE.md`; бутстрап
  ставит навыки для Claude Code и Cursor, о Codex в нём ничего нет.

В день обрыва это означает: запасной агент начинает работу, не зная правил, а Codex — и самого паспорта.

## Нужный результат

1. Любой из трёх агентов, открытый в папке проекта, без ручных действий получает один и тот же паспорт
   и узнаёт из него, где лежат правила канона, журнал действий, база инцидентов и точка возврата.
2. У паспорта один источник, копий нет: правка паспорта видна всем трём агентам сразу.
3. Проверка: свежая сессия в каждой из трёх сред, открытая в папке проекта, без подсказок называет заголовок
   правил канона и путь точки возврата.

Не входит: содержание самих правил; единый набор MCP для трёх сред; перенос истории чатов; резервная копия;
проекты вне канона и рабочей папки компании.

## Ограничения

- Windows: импорт `@AGENTS.md`, а не символическая ссылка — так велит документация Claude Code.
- У Codex предел 32 КиБ на файлы правил; паспорт остаётся коротким.
- Блок канона руками не правят: его пишет `kos_connect.py`.
- Массовая правка паспортов — со снимком «до» и откатом одной командой. Корень рабочей папки компании не
  репозиторий: откат там — только из снимка.
- Запрет — в коде, а не в промпте: порядок закрепляют тесты `kos_connect.py`.
- Коммит только своих путей; на сервер — по команде владельца.
- В файлах рабочей папки компании личные проекты владельца не упоминаются; их перевод в эту задачу не входит.
- Настройки сред и глобальные файлы меняются только после «да» владельца на конкретный шаг.

## Факты и предположения

**Со слов Дмитрия (13.10.2026):** на `AGENTS.md` перейти можно, без потери правил канона; правила канона
давать через паспорт проекта, как рекомендовано.

**Проверено по документации и на машине:** кто какой файл читает; три разошедшиеся копии; неработающая ссылка
в `~/.codex/AGENTS.md`; строка `kos_connect.py`; число файлов с упоминанием `CLAUDE.md`; запуск `second-agent`
в рабочей папке. Источники — «2 — Разбор сред», «4 — Сверка с каноном», карточка «Оценка AGENTS.md».

**Предположения агента — это решения для спецификации, а не требования:**

- источник паспорта — `AGENTS.md`, в `CLAUDE.md` остаётся строка `@AGENTS.md` и то, что нужно только
  Claude Code;
- блок канона называет файл правил с пометкой «прочитай до работы» и путь точки возврата;
- `kos_connect.py` пишет блок в `AGENTS.md`, ставит строку импорта, уже подключённый проект переводит без
  потери текста, повторный запуск ничего не меняет;
- проверяющий `second-agent`, которому нужна независимость от правил канона, запускается из папки вне проекта.

Пункты 1–3 нужного результата — моё прочтение двух решений Дмитрия. Прочитай постановку целиком и поправь
понятое неверно.
