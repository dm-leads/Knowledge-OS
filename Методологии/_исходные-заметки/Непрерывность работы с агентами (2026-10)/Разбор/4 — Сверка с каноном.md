# 4 — Сверка с каноном: что уже решает непрерывность и чего не хватает

Снято 13.10.2026. Прочитаны: стандарт «Три файла проекта», стандарт «Цепочка постановки», методология «Работа
с ИИ-агентами в проекте» (разделы 2–5), бутстрап движка, `agent-rules.md`, карта Knowledge-OS, `kos_connect.py`
(шапка и список функций), один стартер чата из hub, README `codex_import_sync`. Состояние машины — из
«1 — Карта машины».

## Что уже есть и что оно закрывает

| Что есть | Что закрывает для обрыва | Где не дотягивает |
|---|---|---|
| **Паспорт проекта** (`CLAUDE.md`, стандарт «Три файла») | Новый чат знает, что за проект и как с ним работать | Имя файла читает только Claude Code. Codex читает `AGENTS.md`; при импорте он сам сделал из паспорта копию (рабочая папка компании, 11.10) — копия уже отличается от оригинала и дальше будет расходиться |
| **Журнал действий** | Что делали и что менялось, в том числе во внешних системах | Это история, а не состояние: отвечает «что было», но не «с чего начать сейчас». В рабочей папке компании лежит вне git — версии и удалённой копии нет |
| **База инцидентов** | Новый агент не повторяет известную ошибку | Там же вне git |
| **Цепочка постановки** и `TASKS.md` | Задача крупнее мелочи живёт файлами; план пишется так, чтобы «исполнитель без доступа к переписке выполнил задачу» | Покрывает задачи, заведённые по цепочке. Поток, который идёт неделями в одном чате (отчёты, контент, обязательства), состояния файлом не имеет |
| **Стартеры чатов** (hub компании, 27 штук) | Роль потока, постоянные правила, какие файлы читать — ровно то, что нужно новому чату | Только в одном проекте. В тексте — «вставь в новый чат Claude Code». Состояние потока стартер не хранит и не должен: в лучших стартерах оно вынесено в отдельный файл-журнал («источник правды — файл, а не переписка») — это и есть образец точки возврата |
| **Методология, раздел 2, правило 3:** «закрывая сессию — короткая запись: что сделали, что в работе, где остановились» | Прямо требует точку возврата | Не сказано, куда и в каком виде писать; в `agent-rules.md` правила нет, поэтому агенты его не исполняют |
| **Методология, раздел 4:** шаблон передачи контекста в новый чат | Форма первого сообщения новому чату | Заполняет человек по памяти в момент передачи. При обрыве заполнять некому: чат, который знал состояние, недоступен |
| **Правило «результат — только файлом в репозитории»** (методология, раздел 2, правило 2) | Основа всей защиты: что записано в файл, переживает любую среду | «В репозитории» не выполняется для части рабочей папки компании (см. карту, раздел 6) |
| **Бутстрап: навыки ссылками, правила через `~/.claude/kos`** | Один исходник правил и навыков, без копий | Только для Claude Code. Про Codex и Cursor в бутстрапе и в `kos_connect.py` нет ни слова |
| **Автопамять Claude Code** | Предпочтения владельца и указатели | По стандарту факты о проекте должны жить в трёх файлах, но на деле в памяти рабочей папки 220 записей, и многие из них — факты о проекте. Другой агент их не видит |
| **Резерв канона в закрытом GitHub** | Методологии, навыки, правила переживают потерю диска | Только слой канона. Проекты внутри `D:\Knowledge-OS` в него сознательно не входят |
| **`codex_import_sync.py`** | Чинит обновление сессии Claude Code, уже импортированной в Codex | Сам факт скрипта — довод против опоры на импорт истории: в сборке 26.928 штатный импорт не дотягивал новые сообщения в уже импортированный чат |
| **Карта Knowledge-OS** (реестр проектов) | Список проектов под каноном и подключённых к нему | Нет столбцов «где копия» и «запасная среда»; репозитории рабочей папки компании в ней не значатся |

## Противоречие, которое надо решить владельцу

Карта Knowledge-OS (сверка 28.09.2026): «глобального `AGENTS.md` у Codex нет; правила канона Codex сознательно
не грузит: второе мнение должно быть независимым». С 29.09 файл `~/.codex/AGENTS.md` на машине есть — его создал
импорт Codex из `~/.claude/CLAUDE.md`, с неработающей ссылкой на правила. С тех пор Codex используется в двух
ролях: независимый проверяющий (129 запусков `exec`) и рабочий агент (17 тредов настольного приложения, 78
импортированных сессий).

Развести роли одним уровнем подключения не получится: навык `second-agent` запускает проверяющего в рабочей
папке (`cd "<рабочая папка>" && codex exec …`), значит паспорт проекта он читает так же, как рабочий агент.
С 11.10, когда импорт создал `AGENTS.md` в рабочей папке компании, это уже так. Варианты для владельца:

- правила канона — в паспорте проекта; проверяющий, которому нужна независимость от них, запускается из папки
  вне проекта, а материалы получает в промпте. Глобальный файл Codex — короткий, без правил канона;
- признать, что независимость второго мнения — это другая модель и чистый контекст задачи, а общие правила
  (секреты, персональные данные, достоверность) проверяющему не мешают; тогда правила можно грузить и глобально.

Решение — за владельцем канона; в черновике стандарта записан первый вариант.

## Чего не хватает

1. **Точки возврата.** Нет файла, который отвечает «где остановились, что дальше, что читать» и обновляется
   без участия человека. Правило есть в методологии, места и формы нет.
2. **Паспорта, который читают все три агента.** Сейчас это `CLAUDE.md` плюс самодельная копия для Codex.
3. **Правил канона у Codex и Cursor.** Работают только в Claude Code.
4. **Удалённой копии для всего, что названо «файлом в репозитории».** Журнал действий и база инцидентов
   рабочей папки, автопамять.
5. **Резервной копии настроек и истории трёх сред** с шифрованием и без токенов в открытом виде.
6. **Реестра «где что открывать».** Карта Knowledge-OS перечисляет проекты, но не говорит, в какой среде
   проект открывается и какие MCP ему нужны. Три набора MCP разошлись.
7. **Проверки готовности.** Никто не замечает, что у проекта 275 незакоммиченных файлов или что точка возврата
   устарела. По правилу канона «запрет — в коде, а не в промпте» это должна ловить команда, а не память.
8. **Репетиции.** Передача работы в другую среду ни разу не проверялась на живом проекте.

## Чего делать не надо

- Заводить вторую агентную систему поверх своей. Каркас (паспорт, журнал, инциденты, цепочка, навыки ссылками)
  уже есть и переносим; нужен один новый файл и несколько правил.
- Опираться на перенос истории чатов. Импорт Codex работает (78 сессий), но берёт 30 дней, идёт только в одну
  сторону, отдаёт переписку целиком другому поставщику, а его автообновление на этой машине уже подводило.
  История — запасной источник, а не точка возврата.
- Копировать правила в каждую среду. Копия для Codex разошлась с оригиналом за две недели.
