# Выжимка — Метрика, цели, атрибуция

Для основного агента, который пишет переносимую инструкцию «Метрика, цели и учёт заявок, которым можно верить»
(малый бизнес: услуги, онлайн-школа, магазин; реклама — Директ и ВК). Инструкцию эта выжимка не заменяет.

**Источники.** MAED 2022 (спикер Т. Зубкова), модули 46.1, 46.2, 49, 50 — тексты извлечены `kos_extract_text.py` в
`txt\46.1 … txt\50`, страница = «=== стр. N ===» в извлечённом тексте (совпадает со страницей PDF). Строков
«Адекватный Директ» 2025, урок 11 (3 транскрипта). Пресняков «Яндекс.Директ» 2025, урок 8: файлы 8.1, 8.11, 8.12,
8.13, 8.14. Покрытие — 100 % назначенного (реестр в §7). Подробные заметки с адресами — «Промежуточные заметки.md» рядом.

**Разметка.** [факт: источник, файл, стр.] — сказано в источнике (это факт о том, что утверждает курс, а не
проверенная истина); [тезис без данных] — утверждение без замера; [вывод] — мой вывод; «⚠ интерфейс» — название
кнопки или путь на дату источника, сверить с текущей справкой Яндекса.

Сокращения файлов: MAED 46.1 ф.1 = «1. УСТАНОВКА ЯНДЕКС.МЕТРИКИ.pdf», ф.2 = «2. МЕТРИКИ И KPI…», ф.3 = «3. НАСТРАИВАЕМ
И АНАЛИЗИРУЕМ ЦЕЛИ…», ф.4–9 = «Аналитика рекламного трафика…»; 46.2 ф.1 «ЧТО ЕЩЕ ПОСМОТРЕТЬ», ф.2 «КАК СДЕЛАТЬ АНАЛИЗ
САЙТА», ф.4-8 «ПРЕЗЕНТАЦИЯ», ф.9 «СЕКРЕТЫ…», «Авто» = «Автоматический отчет», «Воронка» = «Воронка продаж»; 49/50
«През.» = «Презентация.pdf». Строков ф.0 = «Установка метрики и настройка целей.txt», ф.1 / ф.2 = «1 …», «2 …».

## 1. Краткая суть

1. **Цель на заявку — условие рекламы, а не украшение.** Без цели реклама не обучается и нельзя отличить работающий
   срез от неработающего; Строков без целей не берёт проект [факт: Строков 11, ф.0; ф.1]. Звонки без коллтрекинга —
   половина результата невидима [факт: Строков 11, ф.1].
2. **Цель должна означать заявку, а не жест.** Клик по кнопке, клик по номеру и автоцель «отправка формы» дают
   ложные срабатывания: пустая форма, неудачная отправка, боты в РСЯ («достижений в 5 раз больше, чем заявок»)
   [факт: Строков 11, ф.1; Пресняков 8.1]. Надёжнее — событие по факту успешной отправки (JS/GTM) или страница
   «Спасибо»; по странице «Спасибо» источники расходятся (§3).
3. **Каждую цель проверять руками до запуска**: пройти сайт сверху вниз, выписать все действия, выполнить каждое и
   увидеть срабатывание в отладке (`_ym_debug=2`, панель Метрики) [факт: Пресняков 8.11, 8.13]. Затем сверить число
   заявок в Метрике с фактом клиента (формы + звонки) и с Директом [факт: Строков 11, ф.2].
4. **Считать людей, а не визиты и не достижения.** «Целевые посетители» вместо «Достижений цели»: один человек
   оставляет заявку + звонит + пишет [факт: MAED 46.1 ф.5, стр.2]; сравнение каналов по конверсии визитов искажено
   (визитов на человека 1,1–2,3, плавает) [факт: MAED 49 През., стр.27–30]. «Достижение любой цели» смешивает
   макро- и микроцели [факт: MAED 46.1 ф.4, стр.2].
5. **Метрика — заменитель денег.** Ценность цели и офлайн-конверсии (CSV/API по ClientID/UserID) связывают визит с
   CRM; ключевые цели Директа считают рентабельность только внутри Директа [факт: MAED 46.2 ф.4-8, стр.8, 15]. Без
   CRM канал оценивается по заявкам, а не по выручке [вывод].
6. **Атрибуция — выбор под длину цикла, и решение об отключении нельзя принимать по одной модели.** Короткий цикл —
   последний значимый переход; длинный — смотреть первый переход и ассоциированные конверсии; кампанию оценивать
   вилкой «снизу (last click) — сверху (была в цепочке хоть раз)» [факт: MAED 46.1 ф.4, стр.4–5; MAED 49 През.,
   стр.37–41]. Набор моделей Метрики в MAED устарел (§5).
7. **Вебвизор — для гипотез о сайте, а не для решений о рекламе.** Карты (скролл, клики, ссылки) статистичнее
   Вебвизора, который «подвержен искажению восприятия» [факт: Строков 11, ф.2]; Вебвизор полезен на сегменте
   «дошёл до промежуточной цели и не купил» и для поиска скликивания [факт: MAED 50 През., стр.13, 19].

## 2. Разделы по темам

### 2.1. Установка счётчика и настройки при создании

| Что | Как / зачем | Адрес |
|---|---|---|
| Создание | Счётчики → «Добавить счётчик»: имя, URL без http/https, часовой пояс ⚠ интерфейс | MAED 46.1 ф.1, стр.2; Строков 11 ф.1 |
| Вебвизор | Включать сразу при создании | Строков 11 ф.1; MAED 46.1 ф.1, стр.6 (на скриншоте) |
| Поддомены, несколько сайтов | Включить отслеживание поддоменов при необходимости; несколько URL на один счётчик → переходы между ними внутренние (не новый источник) | MAED 46.1 ф.1, стр.2 |
| Вебмастер | Привязать счётчик к Вебмастеру («быстрее индексирует» — [тезис без данных]) | MAED 46.1 ф.1, стр.2 |
| Фильтры | «Не учитывать мои визиты» — сразу; исключения по IP/URL (до 30 фильтров); фильтрация роботов на той же вкладке ⚠ интерфейс | MAED 46.1 ф.1, стр.3 |
| Тестирование при фильтре своих визитов | Свой трафик отфильтрован → цели тестировать с другого устройства или в инкогнито | MAED 46.1 ф.3, стр.12 |
| Уведомления | Оповещение о недоступности сайта | MAED 46.1 ф.1, стр.4 |
| Доступы | Редактирование/просмотр; публичная статистика не открывает фразы, «Целевой звонок», «Директ», Вебвизор, содержимое заказов | MAED 46.1 ф.1, стр.5 |
| Место кода | На все страницы; в `<head>` или в начало `<body>` — «чем выше, тем раньше грузится, тем точнее» | MAED 46.1 ф.1, стр.7; Строков 11 ф.1 |
| Конструктор (Тильда) | Номер счётчика в «Настройки сайта → Аналитика», затем **опубликовать**, иначе счётчик не встанет ⚠ интерфейс | Строков 11 ф.1 |
| Номер счётчика для Директа | Брать из кода живого сайта (просмотр кода → поиск «metr»), не со слов клиента — «может быть каша» | Строков 11 ф.1 |
| Параметры визитов/посетителей | Визит — до 1000 параметров (тариф, ID внешней системы, промокод, звонок); посетитель — постоянные признаки без ПДн (UserID, статус) | MAED 46.1 Описание, стр.1–2 |
| Альтернативный CDN | Для регионов с ограниченным доступом к Метрике; замедляет загрузку кода | MAED 46.1 Описание, стр.1 |
| Отчёт по контенту | Включить в настройках + разметка Schema.org Article; статьи < 500 знаков не учитываются, нет отказов | MAED 46.2 ф.3, стр.2, 6 |
| Электронная коммерция | Включить в настройках счётчика, контейнер `dataLayer` | Пресняков 8.14; MAED 46.2 ф.4-8, стр.6 |
| Проверка установки | 2022: `?_ym_debug=1` + консоль браузера. 2025: Настройки → «Проверить» (зелёная плашка) → «Проверить передачу данных» → сайт с `_ym_debug=2` и панель отладки ⚠ интерфейс | MAED 46.1 ф.1, стр.8; Пресняков 8.13 |
| Статус счётчика | «Зелёный, а не красный/жёлтый», переходы фиксируются | MAED 46.1 ф.3, стр.11 |

[вывод] Ни один источник не разбирает подтверждение прав на счётчик, согласие на cookies/ПДн и роботов подробнее
одного упоминания («фильтрация роботов», «наличие накрутки-роботов» в задании MAED 46.2 Описание) — пробел, закрывать
справкой.

### 2.2. Какие цели ставить и в каком порядке

**Порядок работы (собран из источников) [вывод]:**
1. Пройти сайт сверху вниз и выписать все активные действия: где (шапка/блок), сколько шагов до действия, скриншот,
   какой тег срабатывает, срабатывает ли цель, идентификатор цели, примечание [факт: Пресняков 8.11]. Проход заодно
   находит поломки сайта («Скачать прайс» не работает) [факт: там же].
2. Убрать на сайте то, что не отследить: оставить один номер под подмену коллтрекингом (кейс: два номера — половина
   звонков не видна), иметь форму заявки [факт: Строков 11 ф.1].
3. Макроцели (заявка, звонок, чат/мессенджер, оплата) → надёжным способом; микроцели — отдельно и не смешивать с
   макро в отчётах [факт: MAED 46.1 ф.4, стр.2].
4. Проверить каждую цель (§2.3), затем отдать в Директ (§2.4).

**Каталог целей с оценкой надёжности:**

| Цель | Способ | Надёжность по источникам | Адрес |
|---|---|---|---|
| Заявка — по факту успешной отправки | JS-событие `reachGoal` из кода/GTM по успешной отправке | Надёжно; нужен программист (или GTM) | Строков 11 ф.1; Пресняков 8.1 |
| Заявка — страница «Спасибо» | «Посещение страниц», URL содержит thanks/spasibo | Строков: основной способ, «эталон». Пресняков: **не советует** — страницу сохраняют и открывают повторно; на многих сайтах URL не меняется | Строков 11 ф.1; Пресняков 8.1 |
| Заявка — Тильда | JS-событие, идентификатор содержит `submitted` | Работает | Строков 11 ф.1 |
| Квиз, чат, оплата сторонним сервисом | JS-событие, идентификатор из справки сервиса (Marquiz, Jivo, Яндекс Pay/Сплит), условие «совпадает» | Работает, если сервис их отдаёт; у Jivo — автоцели | Пресняков 8.12; Строков 11 ф.1 |
| Автоцель «Отправка формы» (все формы) | Автоцель Метрики | **Ненадёжно**: ловит нажатие «Отправить» с пустой формой; в РСЯ «боты порвут», заявок в 5 раз меньше достижений | Пресняков 8.1; Строков 11 ф.1 |
| «Отправка формы» конкретной | Выбор формы на сайте | Видит только открытые формы; всплывающие не ловит | Пресняков 8.1 |
| Автоцель «Заполнение контактных данных» | Автоцель | «В основном точно срабатывает» | Строков 11 ф.1 |
| Клик по кнопке | Выбор кнопки на сайте / JS | **Не для обучения**: скликивают боты; нажал, а форма не ушла | Строков 11 ф.1; Пресняков 8.1 |
| Клик по номеру телефона | Автоцель (конкретный или все) | Срабатывает технически корректно (Пресняков), но: только мобильные, не каждый клик = звонок, в РСЯ скликивают | Пресняков 8.1, 8.11; Строков 11 ф.1 |
| Звонок | Коллтрекинг (динамическая подмена номера на визит) → интеграция с Метрикой → цель «Звонок» появляется автоматически | Надёжно; «через несколько дней» начинается передача | Строков 11 ф.1; MAED 46.2 ф.4-8, стр.10 |
| Клик по email / email-трекинг | Автоцель / разные адреса на визит | Клик — «более-менее»; email-трекинг — точно | Строков 11 ф.1; Пресняков 8.1 |
| Переход в мессенджер / соцсеть | Автоцели | «Обычно адекватно» | Пресняков 8.1 |
| Скачивание файла | Автоцель (любой/конкретный) | Работает | Пресняков 8.1 |
| Поиск по сайту | Автоцель | Только если в коде ожидаемые параметры поиска — уточнить у разработчика | Пресняков 8.1 |
| Возвращение из платёжной системы | Тип цели Метрики | Обязательна при онлайн-оплате: уход в платёжку дробит визит; сравнить с целью «оплата» — расхождение в 2–3 раза → оптимизировать по возврату | Пресняков 8.1 |
| Просмотры ≥ 3 страниц, время > 1 мин | Микроцели | «Часто не коррелирует с макроцелью»; ловит и конкурентов | Пресняков 8.1 |
| Составная цель — воронка | До 5 шагов, до 10 условий на шаге (ИЛИ), шаги строго по порядку в одном визите; шаги — URL и JS | Для воронки магазина/звонка (call_started → call_established) | MAED 46.1 ф.3, стр.5–9; MAED 46.2 «Воронка», стр.6–8; Пресняков 8.1 |
| Составная цель — «склейка» | Один шаг: заявка ИЛИ звонок ИЛИ чат | Для обучения при малом объёме («даём Яндексу больше данных») | Пресняков 8.1 |
| Негативные цели | «Закрыл окно вовлечения» | Оценка всплывающих окон/чатов | MAED 46.1 ф.3, стр.14; Описание, стр.2 |
| Офлайн-конверсия | Отдельная цель «JavaScript-событие» под загрузку | См. §2.6 | MAED 46.2 ф.4-8, стр.8 |
| Ретаргетинговые цели | Чекбокс «Ретаргетинг» — отдельная вкладка ⚠ интерфейс | | MAED 46.1 ф.3, стр.10 |

**Как называть.** Источники правил именования не дают. Есть: пометка года в названии («…2025») [факт: Пресняков
8.1]; название из справки сервиса при JS-идентификаторе [факт: Пресняков 8.12]; JS-идентификатор без `/ # ? = &` и
без слов из URL страницы [факт: MAED 46.1 ф.3, стр.4]. [вывод] Правило имён (тип — действие — место — способ)
надо задать в инструкции самим.

### 2.3. Проверка срабатывания и сверка

- **Отладка 2025:** «Проверить передачу данных» → сайт с `_ym_debug=2` → панель Метрики в правом нижнем углу:
  события `goalReach` (JS-цели), `buttonGoal` (автоцели/кнопки), ЭК-события; статус Вебвизора, записи, карт.
  Нажать каждую кнопку, отправить каждую форму, кликнуть Telegram/WhatsApp — увидеть, какая цель сработала. Минус:
  фоновые цели (время, скролл) засоряют; предпросмотр GTM нагляднее [факт: Пресняков 8.13] ⚠ интерфейс.
- **Отладка 2022:** `?_ym_debug=1` + консоль браузера (Ctrl+Shift+J) [факт: MAED 46.1 ф.1, стр.8].
- **Пустая форма:** отправить форму без данных — если цель сработала, цель брак [факт: Пресняков 8.1].
- **Через несколько минут — отчёт по цели** [факт: MAED 46.1 ф.3, стр.12].
- **Сверка с фактом при старте:** спросить клиента точное число заявок (формы и звонки) → сравнить с Метрикой → не
  сходится — разбирать цели; Метрика сходится, Директ меньше — «Источники, сводка» по цели: сколько с рекламы, с
  поиска, с прочего [факт: Строков 11 ф.2].
- **Возврат из платёжки против «оплаты»** — сверка 2–3× [факт: Пресняков 8.1].
- **Составная цель в Вебвизоре:** жёлтая = пройдена не полностью, видно шаг отвала [факт: MAED 50 През., стр.11].
- **Номер визита в Вебвизоре** — сколько визитов до решения [факт: MAED 50 През., стр.11].

### 2.4. Передача целей в Директ и обучение стратегий

- Счётчик прописывается в параметрах кампании Директа; оптимизация — в цель («Звонок», заявку) [факт: Строков 11
  ф.1].
- «Реклама требует обучения: визит с заявкой — найди ещё таких»; без цели реклама невозможна [факт: Строков 11 ф.1].
- **10 достижений цели в неделю** на стратегию [факт: Пресняков 8.1; канон: Методология Строкова §2 — то же число]
  — сверить с текущей справкой Директа.
- Мало макроконверсий → составная цель «заявка ИЛИ звонок ИЛИ чат» [факт: Пресняков 8.1].
- Не удалять цели, на которых обучена кампания (кейс: удалили цель «перешёл в канал» — РСЯ потеряла ориентир)
  [факт: Строков 11 ф.1].
- Магазин с онлайн-оплатой: если «оплата» и «возврат из платёжки» расходятся в 2–3 раза, оптимизировать по возврату
  [факт: Пресняков 8.1].
- Ключевые цели Директа влияют только на рентабельность в Директе; доход для ROI в Метрике — ценностью цели с сайта
  или из CRM, либо ЭК [факт: MAED 46.2 ф.4-8, стр.15].
- Подключить счётчик к Директу — условие CPA-стратегий [факт: MAED 46.1 ф.2, стр.25].
- «Основная работа — в Директе; Метрика — создать цели, передать и заходить для разбора сайта» [факт: Строков 11 ф.0,
  ф.2]. MAED, наоборот, строит анализ кампаний/ключей/площадок/пол-возраста в Метрике («Директ, расходы») [факт:
  MAED 46.1 ф.5–9] — §3.

### 2.5. Отчёты для рекламы (из MAED 46.1, что переносимо)

- «Директ, расходы» + «Стоимость кликов» + «Целевые посетители» по каждой цели (до 10 метрик в отчёте) → вручную
  «Всего лидов» и «Цена лида» в таблице [факт: MAED 46.1 ф.5, стр.2, 9–10] ⚠ интерфейс.
- Цена лида важнее процента конверсии: хороший % при высоком CPL — повод отключать [факт: MAED 46.1 ф.5, стр.6].
- Пороги курса (ключи < 10–20 кликов не анализировать; > 15–20 кликов, < 30 с, 0 конверсий — отключать; площадки
  > 50–70 кликов без конверсий — исключать; отказы > 35–40 %) [факт: MAED 46.1 ф.6, стр.7, 9; ф.7, стр.3, 5] —
  [тезис без данных]; в каноне пороги уже разобраны строже (Справочник порогов §1) — брать оттуда.
- Пол/возраст, устройства, города — **по каждой кампании отдельно**, в сводке по аккаунту «всё одинаково» [факт:
  MAED 46.1 ф.8, стр.2, 5; ф.9, стр.4].
- Время суток — смотреть **конверсию**, не визиты; не выключать день целиком, а плохие часы; нужен объём (3–4 месяца
  одного сезона или 1000–2000 посетителей/день) [факт: MAED 46.1 ф.8, стр.7, 10; Строков 11 ф.2].
- При уходе из отчётов Директа — **фильтр на источник** обязателен [факт: MAED 46.1 ф.8, стр.8].
- Бренд отделять: сегмент «Поисковая фраза» последнего источника, «!@бренд», до 20 условий или регулярка `~…`;
  варианты написания бренда — из выгрузки фраз за год [факт: MAED 46.2 ф.9, стр.7–13; «Авто», стр.4–5]. Продажи
  только с брендовых запросов → сайт не продаёт холодным [факт: Строков 11 ф.2].
- «yandex-direct / cpc» смешивает поиск, РСЯ, ретаргетинг → группы «Бренд / Поиск / РСЯ» [факт: MAED 49 През.,
  стр.31].
- Отчёты по расписанию — 100 % точности без семплирования, письмо получателям без доступа [факт: MAED 46.2 «Авто»,
  стр.1–3] ⚠ интерфейс.

### 2.6. Деньги: ценность цели, офлайн-конверсии, CRM, расходы, ROI

- **Офлайн-конверсии:** CSV через «Настройка → Загрузка данных» или API; идентификаторы ClientID / UserID;
  обязательные поля — идентификатор посетителя, цель, время конверсии; «увеличенный период учёта конверсий» —
  21 день вместо 16 часов по умолчанию; под загрузку — отдельная цель «JavaScript-событие» [факт: MAED 46.2 ф.4-8,
  стр.8; MAED 50 През., стр.85] ⚠ интерфейс и сроки — сверить (вероятно изменились).
- **Через сервисы без разработчика:** коннекторы для офлайн-конверсий, расходов, ЭК, звонков, установки счётчика в
  CMS [факт: MAED 46.2 ф.4-8, стр.3] — список партнёров 2022, сверить.
- **Данные CRM в профиль посетителя:** статус клиента, состояние заявки, звонки → сегменты и ретаргетинг [факт:
  MAED 46.2 ф.2, стр.13; MAED 50 През., стр.43].
- **Расходы:** разметка utm (обязателен utm_source; далее campaign/medium/term/content); Директ размечен сам;
  расходы других каналов — CSV, API или коннектор, «данные через час»; **расходы Директа в Метрике без НДС → расходы
  других каналов передавать тоже без НДС** [факт: MAED 46.2 ф.4-8, стр.14].
- **Рекламный переход по UTM:** utm_source из списка систем (vk, vkontakte, mytarget…) или utm_medium ∈ {cpc, ppc,
  paidsearch, cpv, cpa, cpp, display, cpm, banner} [факт: MAED 46.1 ф.2, стр.11] — сверить текущий список.
- **ROI:** отчёт «Источники, расходы и ROI» + метрика ROI по доходу ЭК или по цели с ценностью [факт: MAED 46.2
  ф.4-8, стр.13–16].
- **Звонки:** группа отчётов «Звонки» — качество обработки (пропущенные, ожидание), источники, детально; тема
  разговора — в метках звонка; история посетителя до звонка [факт: MAED 46.2 ф.4-8, стр.10–11; ф.2, стр.14].
- **CAC, LTV, MRR, отток — «считать с данными CRM / вручную»**, не в Метрике [факт: MAED 46.1 ф.2, стр.26, 33–35].
- **Расхождение аналитики и CRM — норма, которую надо мерить:** пример GA 629 заказов против CRM 824, выручка
  1 883 271 против 2 467 056 ₽, потерянные 195 заказов не распределить по каналам [факт: MAED 49 През., стр.30 —
  пример курса, GA].
- Каркас учёта (что собирать по каналу): источник, расход, заявки, покупки, чек, повторные покупки [факт: MAED 49
  През., стр.9].

### 2.7. Атрибуция и ассоциированные конверсии

- **Модели Метрики по MAED (2022):** первый переход, последний переход, последний значимый, последний из Директа;
  выбор при построении отчёта рядом с «точностью»; «по умолчанию — последний переход» [факт: MAED 46.1 ф.4, стр.4;
  MAED 49 През., стр.60] — **устарело/сверить** (§5).
- **Выбор:** короткий цикл («пришёл — позвонил») → последний значимый; длинный цикл с возвратами → первый переход
  при единственном рекламном канале, «первый + последний» вручную при нескольких каналах и цикле от 7 дней [факт:
  MAED 46.1 ф.4, стр.5] — [тезис без данных]. Длину цикла мерить отчётом «Время с первого визита» [факт: MAED 46.1
  ф.4, стр.6; 46.2 ф.9, стр.5].
- **Алгоритм выбора (9 вопросов):** какие конверсии, сколько касаний, разовые/регулярные покупки, новые или текущие
  клиенты, длина решения, известность бренда, объём статистики, конкуренция, сезонность → применить несколько
  моделей и посмотреть, как меняются отчёты [факт: MAED 49 През., стр.54–55]. Примеры: парикмахерская — первый
  клик; шины — последний непрямой; застройщик — линейная [там же, стр.55, «не однозначные рекомендации»].
- **Ассоциированные конверсии:** канал был в цепочке, но не последним; отключение кампаний без прямых конверсий
  роняет общее число и поднимает цену заявки [факт: MAED 49 През., стр.10–11 — тезис без данных]. Если > 90 %
  конверсий с первого визита — многоканальный анализ не нужен [там же, стр.12 — правило курса]. Отношение
  ассоциированных к последнему клику: > 1 — вспомогательный канал, < 1 — закрывающий [стр.15–16, GA].
- **Время до конверсии → окно ретаргетинга** (нет конверсий за 15 дней — исключать; пик на 7-й день — догонять)
  [факт: MAED 49 През., стр.14].
- **Оценка кампании вилкой:** снизу — last click (последний непрямой), сверху — 100 % вклада, если кампания была в
  цепочке хоть раз («top score»). Сходится снизу — усиливать; не сходится ни так ни так — отключать/перерабатывать;
  между — дорабатывать; мало данных — ждать [факт: MAED 49 През., стр.37–41]. [вывод] В Метрике: снизу — «последний
  значимый»/«последний из Директа», сверху — сегмент «визиты из кампании X были» + целевые посетители; переносимый
  приём для инструкции.
- **Нельзя сравнивать каналы на разных этапах одной моделью** (брендовый поиск против баннера) [факт: MAED 49 През.,
  стр.56].
- **Своя атрибуция по CRM:** брендовые и прямые касания с весом 0, остальным поровну; дробные продажи — норма [факт:
  MAED 49 През., стр.62–65 — пример].
- **Ошибки атрибуции:** платёжная система как источник (возврат со страницы банка = переход с сайта); тайм-аут
  визита → «прямой заход» забирает заслугу; отмена транзакции не перезаписывает канал [факт: MAED 49 През., стр.61
  — про GA]; в Метрике та же проблема — «два разных человека, один заказ» после платёжки [факт: Пресняков 8.1].
- **Когорты:** ROI кампании через месяц < 100 % — не приговор, у части покупателей решение до 5 месяцев; сравнивать
  с ROI прибыльного источника на той же неделе жизни [факт: MAED 49 През., стр.75–77]. «В Метрике когорт нет, только
  в AppMetrica» [стр.99 — сверить].

### 2.9. Электронная коммерция

- Настраивает разработчик по справке Метрики; задача маркетолога — передать справку и список событий, потом проверить
  [факт: Пресняков 8.14; MAED 46.2 ф.4-8, стр.6]. Плагины CMS — альтернатива [MAED 46.2 ф.4-8, стр.3, 6].
- Проверка: в настройках счётчика ЭК включена, контейнер `dataLayer` (или своё имя, совпадающее с кодом); в коде
  страницы `ecommerce:"dataLayer"` (Ctrl+U → поиск); `_ym_debug=2` → положить товар в корзину → в отладке событие
  add с товаром и ценой [факт: Пресняков 8.14] ⚠ интерфейс.
- События: impressions, click, detail, add, remove, purchase, промо-просмотр/клик; поля товара id, name, brand,
  category, price, quantity, variant; revenue — числом; номер цели в отдельном поле [факт: Пресняков 8.14] — сверить
  со справкой.
- Что просить отслеживать: просмотр товара, добавление в корзину (и уникальное), переход в корзину (и уникальный),
  удаление, оформление покупки [факт: Пресняков 8.14].
- Отчёты: доход по источникам/кампаниям, конверсия, транзакции, товары и разделы, средний чек [факт: MAED 50 През.,
  стр.52, 54]. Обязательные сегменты: активные; смотрели карточку; добавили в корзину; перешли в корзину; не
  завершили; завершили [стр.56].
- Ретаргетинг на «положил в корзину, не купил» через сегмент Метрики в Директе [факт: MAED 46.2 ф.9, стр.6].

## 6. Утверждения про интерфейс — сверить со справкой Яндекса

1. Путь создания счётчика: «Добавить счётчик» → вкладка «Счётчик»: имя, URL без протокола, часовой пояс, поддомены,
   несколько адресов, привязка к Вебмастеру (MAED 46.1 ф.1, стр.2; Строков 11 ф.1).
2. Вкладка «Фильтры»: «Не учитывать мои визиты», до 30 фильтров по IP/URL, фильтрация роботов (MAED 46.1 ф.1, стр.3).
3. «Уведомления» о недоступности сайта (стр.4); уровни доступа и что скрыто при публичной статистике (стр.5).
4. Альтернативный CDN (MAED 46.1 Описание, стр.1).
5. Параметры визита — до 1000 в визите (MAED 46.1 Описание, стр.2).
6. Типы целей и их названия: количество просмотров, посещение страниц, JavaScript-событие, составная, продолжительность
   визита, клик по номеру, клик по email, отправка формы (все/конкретная), переход в мессенджер, переход в соцсеть,
   скачивание файлов, поиск по сайту, клик по кнопке, возвращение из платёжной системы; бегунок «Автоцели»
   (Пресняков 8.1).
7. Составная цель: до 5 шагов, до 10 условий на шаге, логика «ИЛИ» внутри шага, только в рамках одного визита
   (MAED 46.1 ф.3, стр.5; 46.2 «Воронка», стр.7).
8. Ограничения JS-идентификатора: без `/ # ? = &` (MAED 46.1 ф.3, стр.4).
9. Чекбокс «Ретаргетинг» у цели и отдельная вкладка (MAED 46.1 ф.3, стр.10).
10. «Отправка формы» конкретной — только открытые формы; поиск по сайту — по параметрам в коде (Пресняков 8.1).
11. Проверка: «Убедитесь, что счётчик размещён» → «Проверить»; «Проверить передачу данных» → `_ym_debug=2`; события
    `goalReach`, `buttonGoal` в панели (Пресняков 8.13).
12. ЭК: включение в общих настройках, контейнер `dataLayer`, `ecommerce:"dataLayer"` в коде, имена событий и полей
    (Пресняков 8.14).
13. Тильда: «Настройки сайта → Аналитика», поле номера счётчика; JS-идентификатор `submitted` (Строков 11 ф.1).
14. Офлайн-конверсии: «Настройка → Загрузка данных», CSV, ClientID/UserID, «увеличенный период учёта конверсий»
    21 день / 16 часов, отдельная цель JS-событие (MAED 46.2 ф.4-8, стр.8).
15. Звонки: цель создаётся автоматически при интеграции коллтрекера; отчёты «Качество обработки звонков»,
    «Источники звонков», «Звонки, детально» (MAED 46.2 ф.4-8, стр.10–11).
16. «Источники, расходы и ROI»: загрузка расходов CSV/API/коннектор, «данные через час», расходы Директа без НДС
    (стр.13–14).
17. Модели атрибуции и модель по умолчанию; переключатель атрибуции рядом с «точностью» (MAED 46.1 ф.4, стр.4; 49
    През., стр.60).
18. Отчёты: «Директ, расходы», «Директ, сводка», «Директ, площадки» (нельзя добавить стоимость кликов), до 10 метрик
    в отчёте, «Время с первого визита», «Посещаемость по времени суток» (MAED 46.1 ф.3, стр.13; ф.5, стр.2; ф.7,
    стр.2; ф.8, стр.7).
19. Сегментация: условие «!@», до 20 условий, регулярные выражения с префиксом `~` (MAED 46.2 ф.9, стр.7, 13).
20. Отчёты по расписанию: иконка часов, ежедневно/понедельник/1-е число, без семплирования, получатели без доступа
    (MAED 46.2 «Авто», стр.1–2).
21. Аналитика форм: ≤ 1000 форм в день, «Взаимодействие с сайтом» для всплывающих форм (MAED 46.2 ф.2, стр.9–10).
22. Вебвизор: соцдем скрыт при < 10 посетителях; трафик +≤ 4 Кб; жёлтые цели = составная не завершена (MAED 50
    През., стр.11, 22).
23. Отчёт по контенту: Schema.org, < 500 знаков не учитывается (MAED 46.2 ф.3, стр.2, 6).
24. Публикация в Директе: счётчик в параметрах кампании; «Ключевые цели» Директа и их связь с ROI в Метрике (MAED
    46.2 ф.4-8, стр.15; Строков 11 ф.1).
