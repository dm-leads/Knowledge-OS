# Выжимка — marketingskills (Corey Haines, GitHub, 2026-11)

Источник — https://github.com/coreyhaines31/marketingskills, ветка main, коммит 1f83744 (11.11.2026), версия
пакета 2.14.12, лицензия MIT, 61 004 звезды на 17.11.2026 (факт, API GitHub). Автор — Corey Haines, у него свой
платный продукт Magister, построенный на этих навыках; это видно в тексте (раздел «Безопасность»).

**Как читалось.** Дерево — через API GitHub. 681 текстовый файл скачан по одному с raw.githubusercontent.com в
отдельную папку временного каталога сессии; ничего не клонировалось, не устанавливалось и не запускалось. Скрипты
проверки лежали в другой папке и только читали файлы. Папки `tests/` (152 файла контрактных тестов) и
`evals/triggers/` (5 наборов тестовых запросов) не скачивались: это проверки самого репозитория. Сверка с каноном,
таблица по навыкам и предложение — в [Сверке](<Сверка — marketingskills с каноном (2026-11-17).md>).

## Краткая суть

- Это не методология, а **набор промптов-навыков** под американский SaaS: Google, Meta, LinkedIn, G2, Product
  Hunt, Stripe, законы FTC, TCPA, CAN-SPAM. Российские площадки почти не упоминаются (один справочник про
  Telegram-каналы).
- Сильные стороны — **дисциплина доказательств** (наблюдено / выведено / не найдено, «не наблюдается ≠ нет»,
  MISSING вместо оценки), **устройство навыков** (короткое описание с границами, маршрутизация по справочникам,
  единый контекст-файл продукта, версии и тесты вызова) и несколько тем, которых в каноне нет: видимость в
  ИИ-ответах, ёмкость рынка, PR, мероприятия, отток подписки.
- Опасного кода и скрытых инструкций не найдено. Риски — в механике: инструкция агенту самому обновлять навыки
  через `git pull`, навыки предлагают запускать внешние пакеты и скрипты, в тексте есть реклама автора и
  платных партнёров (раздел «Безопасность»).

## 2. Безопасность

**Вердикт: есть риски, вредоносного содержимого не найдено.** Скрытых инструкций агенту, невидимого текста,
кода, который отправляет ключи или данные на чужой адрес, хуков и автозапуска не обнаружено. Риски — в механике
обновления, в предложениях запускать внешний код и в коммерческих вставках. Пока навыки не ставятся на
устройство, риска нет; при установке — пункты 1–4 закрыть до установки.

**Чем проверялось.** Скрипт по всем 681 файлу: символы нулевой ширины и управления направлением текста,
HTML-комментарии, фразы вида «ignore previous», `curl | sh`, `npx`/`npm install`/`pip install`, `postinstall`,
длинные base64, `eval`/`exec`/`child_process`, обращения к переменным окружения с ключами, `mcpServers` и `hooks`,
самообновление, все внешние адреса. Каждое срабатывание просмотрено глазами.

## 3. Суть по навыкам

Адрес — путь от корня репозитория. «Прочитан» — SKILL.md целиком; «оглавление» — описание и заголовки
(подробнее — реестр покрытия).

### Платная реклама и креатив

- **ads** (`skills/ads/SKILL.md`, прочитан). Маршрутизация по 16 справочникам под намерение; доля знания об
  аудитории в креатив против настроек таргета по площадкам (Meta 80/20, поиск Google 40/60); ретаргетинг другим
  оффером, а не тем же; четыре вида ретаргетинг-объявлений; бренд и не-бренд считать раздельно («отчёт —
  смешанный, оптимизация — по не-бренду»); масштабирование на +20 % с паузой 3–5 дней; правила аудита:
  «неизвестно ≠ провал», «не выдумывать минус-слова без отчёта по запросам», «не суммировать конверсии разных
  окон атрибуции», MISSING вместо оценки, черновик изменения с откатом. Недельная проверка
  (`references/operating-check.md`, прочитан): шесть вопросов по порядку — расход → трафик → конверсии → выгорание
  креатива → посадочная → учёт; ровно одно решение HOLD / FIX / TEST / INVESTIGATE, INVESTIGATE сильнее всех;
  каждое решение заканчивается списками «факты / гипотезы / недостающие данные»; пятничная сводка до 200 слов.
- **ad-creative** (`skills/ad-creative/SKILL.md`, прочитан). Четыре режима: с нуля, по данным, пачки по 50
  статичных концептов, стратегия креативов. «Заземлённые входы»: 10–20 лучших объявлений за 90 дней, 50–100
  отзывов, комментарии к рекламе; каждый концепт ссылается на источник; пустая папка входов — стоп, а не
  генерация. Гипотеза теста обязана уметь проиграть: метрика, сравнение, направление. Список признаков ИИ-текста.
  Страница согласования креативов для заказчика (`assets/creative-review-template.html`).
- **conversion-tracking** (`skills/conversion-tracking/SKILL.md`, первые ~60 строк). Развилка «лидогенерация /
  магазин»; восемь обязательных правил: конверсия — только по подтверждённому успеху, «тег сработал ≠ конверсия
  дошла», у каждого вывода источник (наблюдено / выведено), симптом — повод для диагноза, а не для правки,
  «причину не нашёл» — допустимый вывод, не трогать сайт и кабинет, которые не назвали в разговоре. 65 готовых
  рецептов GTM для форм и записи на встречу.
- **attribution** (`skills/attribution/SKILL.md`, прочитан). Модели и как каждая врёт; три подхода (MTA, MMM,
  инкрементальность); опрос «Откуда вы о нас узнали» в момент конверсии с вариантами и свободным полем; сверка
  источников: один источник количества (CRM), платформы не суммировать, согласие направлений вместо совпадения
  чисел; слепые зоны — прямые заходы, брендовый поиск, «тёмные» соцсети, ИИ-ответы. Своя атрибуция через
  `identify()` и передачу анонимного идентификатора во внешний сервис записи.
- **analytics** (`skills/analytics/SKILL.md`, прочитан). «Считай кодом, а не глазами», перепроверка итога вторым
  способом; окна числителя и знаменателя совпадают, когорта в незакрытом окне — «ожидает», не «провал»; UTM:
  строчные, дефис, одно написание источника, без ПДн; шаблон меток по типу партнёра (`creator`, `newsletter`);
  канал «ИИ-ассистенты» как нижняя граница.
- **ab-testing** (`skills/ab-testing/SKILL.md`, прочитан). Формула гипотезы «Because… we believe… will cause… for…
  We'll know when…»; таблица размера выборки; основная, вспомогательные и защитные метрики; элемент, который видит
  часть посетителей (видео, калькулятор), — анализ только по дошедшим до точки показа; трактовка p-value и
  доверительного интервала по заявлению ASA; программа экспериментов: ICE, журнал паттернов.
- **influencer-marketing** (оглавление; `references/telegram-channels.md` частично). Спектр «блогер ↔ амбассадор»,
  права на контент, UGC-программа, раскрытие по FTC. Справочник по Telegram: форматы «1/24, 1/48», охват =

  месяца, не пользуюсь — пауза 1–3 месяца, ушёл к конкуренту — сравнение); без тёмных паттернов, кнопка отмены

- **product-marketing** (прочитан). Один файл `.agents/product-marketing.md`, который читают все навыки перед
  работой: 14 разделов — продукт, аудитория, персоны (B2B), боли, конкуренты (прямые, вторичные, косвенные),
  отличие, возражения и антиперсоны, четыре силы переключения, язык клиента дословно, голос бренда, доказательства,

  раздел «Уроки»: одна фраза, доказательство с выборкой, где применимо, статус `active` / `watch` / `retired`;
  первый вариант агент собирает сам из репозитория и сайта.
- **customer-research** (прочитан). Три режима: разобрать имеющееся, собрать чужие публичные высказывания
  («водопои»), спросить самим. Уровни уверенности инсайта: высокий — 3+ независимых источника, без подсказки;
  минимум 5 точек на сегмент для персоны; поправки на смещение выборки (отзывы пишут крайние, тикеты — о
  проблемах); персоны без отзывов — по цепочке прокси-источников с пометкой.
- **competitor-profiling** (прочитан). Досье по одному шаблону; три слоя: наблюдено (с источником и датой) /
  выведено / следствие для нас; «не наблюдается на проверенных страницах на дату ≠ нет»; мотив не приписывать;
  сырые данные сохранять в папку с датой съёма; быстрый скан и глубокое досье.
- **competitors** (прочитан). Четыре формата страниц сравнения; честность (сильные стороны конкурента, кому он
  подходит лучше); один источник данных о конкуренте на все страницы; дисциплина доказательств и аудит
  существующих утверждений: текущее / изменилось / не подтверждается / преувеличено.
- **reverse-engineer-marketing** (прочитан частично). Хронология, а не портрет: два файла — помесячный трафик из
  одного источника и журнал датированных ходов; «ход перед скачком — кандидат в причины, не вывод»; метки
  наблюдено / выведено / не найдено; арифметика — кодом; паузы между стадиями с ценой следующей; 20+ отраслевых
  пакетов сигналов.
- **marketing-plan** (прочитан; `references/market-sizing.md` прочитан). План из 13 разделов по AARRR с
  возобновлением по файлу прогресса; ворота «размер × частота проблемы»; бюджет от цели;
  S-кривые и распределение 70/20/10. Ёмкость рынка: определение рынка одной фразой; TAM/SAM/SOM; четыре метода —
  снизу вверх, от поискового спроса, от выручки конкурентов, от доступных каналов; минимум два, расхождение больше
  ~3 раз — сломано допущение; метки уверенности; порядок силы доказательств (свои продажи → поведение рынка →
  поисковые прокси → отчёты → мнения → слабые прокси); подача: диапазон, допущения отдельно от фактов, метод,
  уверенность, одно допущение, сильнее всего меняющее ответ, и как его проверить; карта привлекательности рынка —
  10 факторов по 1–5, пороги 40 / 30 / 20.
- **marketing-loops** (прочитан). Регулярная задача агента из девяти частей: частота проверки, условие действия,
  цель, навыки, тело, самопроверка, состояние и защита от повтора, условие остановки, куда результат. Частота — по
  скорости сигнала (позиции — раз в неделю, выгорание рекламы — раз в 2–3 дня, отток — каждый день); когда не
  автоматизировать: публикация и деньги без проверки человеком, слишком редкий сигнал, отчёт, который никто не
  читает. Каталог из 60 задач.
- **marketing-council** (оглавление). Имитация совета известных маркетологов с «правилами опоры» на их книги.

## 5. Что не прочитано и почему

- 30 SKILL.md — только описание и оглавление, 336 справочников не читались. Причина — объём: 3,4 млн байт текста
  не помещаются в один проход агента. Оценки «у нас глубже / равно» по этим навыкам в Сверке опираются на
  оглавление и помечены. Кандидаты на дочитывание при встраивании — справочники, которые питают топ-10 дельты:
  `ai-seo/references/*` (14 файлов), `ads/references/audit-guardrails.md`, `marketing-loops/references/loop-guardrails.md`
  и `loop-template.md`, `sales-enablement` целиком, `public-relations/references/*`, `events/references/*`.
- `tests/`, `evals/triggers/` — не скачивались: это проверки репозитория.
- `tools/` — интеграции с американскими сервисами, для методобазы не нужны; проверены только на безопасность.
