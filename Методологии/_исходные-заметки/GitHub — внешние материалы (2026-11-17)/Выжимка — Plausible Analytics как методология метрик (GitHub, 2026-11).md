# Выжимка — Plausible Analytics как методология метрик (GitHub, 2026-11)

## Краткая суть

- Источник: репозиторий `plausible/analytics`, ветка по умолчанию, коммит `012522e4e6a4fe69b61a9d66c622be751aafd480`
  (снят 17.11.2026), и документация `plausible.io/docs`, `plausible.io/data-policy` (открыты 17.11.2026).
  Ставить Plausible не собираемся — читали только определения.
- **Посетитель** — хэш от суточной соли, User-Agent, IP и домена сайта. Соль меняется раз в сутки (в полночь UTC),
  поэтому «уникальный посетитель» уникален **только внутри суток**: за неделю один человек, заходивший пять дней,
  — пять посетителей.
- **Визит** — события одного посетителя с перерывом не больше 30 минут; порог зашит в код и не настраивается.
- **Отказ** — визит с одним просмотром и без «интерактивного» события. **Порога по времени нет** (у Метрики — 15 с).
- **Конверсия** — уникальные выполнившие цель ÷ уникальные посетители (на человека, не на визит).
- **Источник** — у визита, по первому просмотру; конверсия достаётся источнику визита, где она случилась
  (последний клик, без исключения прямых заходов).
- **Воронка** — 2–8 шагов, окно 24 часа, считается по посетителю (то есть фактически в пределах суток).
- Сами разработчики честно пишут о пределах: блокировщики режут 5–25 % посетителей, «ни один фильтр ботов не
  идеален», боты без JavaScript в счёт не попадают.

## 1. Опись и реестр

Что в репозитории относится к методологии: модули сессий и приёма событий (`lib/plausible/session/`,
`lib/plausible/ingestion/`), выражения метрик (`lib/plausible/stats/sql/`), воронки (`extra/lib/plausible/stats/funnel.ex`),
расписание соли (`config/runtime.exs`, `lib/workers/rotate_salts.ex`). Остальное — интерфейс, биллинг, авторизация,
инфраструктура — к методологии не относится и не читалось.

Статусы: **прочитан** — открыт и прочитан нужный фрагмент; **по пересказу** — прочитан через инструмент, который
отдаёт пересказ и номера строк, а не сам текст (номера строк — сверить по коммиту перед цитированием); **найден** —
найден поиском по коду, открыт фрагмент.

## 2. Определения метрик

Статус всех определений — **факт** по коду или документации на 17.11.2026; где источник — пересказ, это сказано в
реестре выше.

| Метрика | Определение у Plausible | Адрес |
|---|---|---|
| Посетитель (Unique Visitors) | число различных `user_id`; `user_id` = SipHash(соль суток; User-Agent + IP + домен + корневой домен). В пределах суток повторные визиты — один посетитель; разные дни и устройства — разные посетители | `expression.ex` ≈ 315–319, 474–478 (`uniq(user_id)`); `event.ex` ≈ 581–584; metrics-definitions |
| Визит (Visits, Sessions) | события одного `user_id` на одном сайте, пока между событием и прошлым событием визита не больше 30 минут; служебное событие вовлечённости продлевает визит, не меняя счётчиков | `cache_store.ex` стр. 94 (`diff(...) <= 30`), стр. 50–58 |
| Просмотры (Pageviews) | число событий `pageview`, включая повторные просмотры той же страницы | `expression.ex` ≈ 303–307 |
| События (Events) | все события, кроме служебного `engagement` | `expression.ex` ≈ 309–313 |
| Отказ (Bounce Rate) | доля визитов, где был **один** просмотр и **не было** события, помеченного интерактивным; события с `interactive: false` отказ не снимают. Порога времени нет. При фильтре по странице — только визиты, **начавшиеся** на ней | `cache_store.ex` стр. 141–145, 162; `expression.ex` ≈ 425–442; metrics-definitions |
| Длительность визита (Visit Duration) | время от первого до последнего события визита; визиты из одного просмотра дают 0 и **входят в среднее** | `cache_store.ex` стр. 146; `expression.ex` ≈ 480–486 |
| Просмотров на визит | просмотры ÷ визиты | `expression.ex` ≈ 488–499 |
| Время на странице (Time on Page) | активное время: скрипт шлёт событие вовлечённости при уходе со страницы или смене вкладки; время в скрытой вкладке не считается | metrics-definitions; `expression.ex` ≈ 361–421 |
| Глубина прокрутки | средний процент высоты страницы; цель по глубине — только уникальные и конверсия, без «всего» | scroll-depth |
| Вход и выход | страница первого и последнего просмотра визита; доля выхода = выходы ÷ просмотры страницы | `cache_store.ex` стр. 129–140; metrics-definitions |
| Цель | просмотр страницы или пользовательское событие; у события — свойства и выручка | goal-conversions |
| Свойства событий | до 30 пар на событие, имя до 300 знаков, значение до 2000; только строки, числа, логические; **ПДн отправлять запрещено** (имя, почта, телефон, IP, идентификатор cookie) | custom-props |
| Уникальные конверсии | посетители, выполнившие цель хотя бы раз | metrics-definitions |
| Всего конверсий | все выполнения, с повторами | metrics-definitions |
| Конверсия (Conversion Rate) | уникальные конверсии ÷ уникальные посетители, с текущими фильтрами | metrics-definitions |
| Воронка | 2–8 шагов; посетитель проходит шаги за окно 24 ч; строгая — подряд без чужих шагов, последовательная — по порядку с промежутками, гибкая — обязательны первый и последний; отсев = шаг(n−1) − шаг(n); конверсия шага — от первого шага и от предыдущего; дошедший до поздних шагов засчитан на всех ранних | `funnel.ex` стр. 7, ≈ 189, 267–280, 291–323; funnel-analysis |
| Источник (Source) | у визита: определяется по первому просмотру; UTM меняют источник только на первом просмотре нового визита; приоритет `utm_source` → `source` → `ref`, иначе домен реферера | `event.ex` ≈ 304–322; top-referrers |
| Поддерживаемые метки | `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `utm_term`, `ref`, `source`; из идентификаторов кликов (`gclid`, `gbraid`, `wbraid`, `msclkid`, `fbclid`, `twclid`) хранится **только имя**, не значение; остальные параметры адреса отбрасываются | `event.ex` ≈ 445–452; data-policy |
| Прямой трафик (Direct / None) | визит без реферера: ввод адреса, закладки, письма, мессенджеры, приложения. «Тёмный трафик» лечится UTM на всех своих ссылках | top-referrers |
| Каналы | 19 групп (Organic Search, Paid Search, Organic Social, Paid Social, Email, SMS, Referral, Direct, AI Assistants и др.); правила — по источнику и `utm_medium`, выровнены с GA | top-referrers |
| Атрибуция конверсии | последний клик: конверсия засчитывается источнику визита, в котором случилась; прямой заход тоже получает заслугу | top-referrers |

## 3. Уникальность без cookie

- Формула (data-policy): `hash(daily_salt + website_domain + ip_address + user_agent)`; в коде — SipHash
  (`event.ex` ≈ 581–584). Сырые IP и User-Agent не хранятся; версии браузера и ОС — только мажорная и минорная;
  гео — страна, регион, город.
- Соль — 16 случайных байт; новая каждую полночь по расписанию `0 0 * * *` (`config/runtime.exs`; часовой пояс
  планировщика по умолчанию UTC — **вывод**, в коде пояс не читали); в памяти — текущая и прошлая; в базе стираются
  старше 48 часов.
- Прошлая соль нужна, чтобы визит, начатый до полуночи, продолжился после неё (`register_session`, поиск сессии по
  `prev_user_id` в `cache_store.ex` стр. 29–30). **Вывод:** события после полуночи получают новый `user_id`, поэтому
  такой человек в отчёте за два дня — два посетителя.

### Что из этого следует для сравнения с Метрикой

| Ось | Plausible | Метрика ([глоссарий](https://yandex.ru/support/metrica/ru/general/glossary)) | Следствие |
|---|---|---|---|
| Кто посетитель | хэш IP + браузер на сутки | идентификатор браузера в cookie (ClientID), живёт до очистки cookie; есть UserID | за сутки близко; за неделю и месяц Plausible **завышает** посетителей тем сильнее, чем больше возвращающихся |
| Один человек за сутки сменил сеть (Wi-Fi → мобильная) | два посетителя | один (cookie тот же) | Plausible завышает у мобильной аудитории |
| Много людей за одним IP и одинаковым браузером (офис, NAT оператора) | могут слиться в одного | разные | Plausible занижает в корпоративных сетях |
| Тайм-аут визита | 30 мин, жёстко | 30 мин по умолчанию, настраивается 30–360 | при нестандартном тайм-ауте Метрики визиты несравнимы |
| Отказ | 1 просмотр и нет интерактивного события; без порога времени | ≤ 1 просмотра, **меньше 15 с** (порог настраивается) и нет события «не отказ» | у Plausible отказов **больше**: долгое чтение одной страницы — отказ |
| Длительность | от первого до последнего события; нули отказов в среднем | время от первого до последнего события визита (просмотры, клики по ссылкам, скачивания, цели) | близко по смыслу, но Метрика видит больше видов событий — длительность выше |
| Конверсия | на посетителя | «Конверсия» по умолчанию и отдельная «Конверсия на посетителя» (по справке; формула основной на странице не написана — **не подтверждено**, что она от визитов) | сравнивать только одинаковые знаменатели |
| Источник и атрибуция | источник визита, последний клик, прямые с заслугой | модель выбирается; «Последний значимый переход» не отдаёт заслугу прямым заходам | у Plausible больше конверсий у «Direct» |
| Боты | отбрасывает до записи: User-Agent, ≈ 40 800 диапазонов IP дата-центров (в README — ≈ 32 тыс.: **расхождение источников**), headless, спам-рефереры, поведение | явных роботов исключает; поведенческий фильтр стирает данные безвозвратно | разная политика — разный объём «людей» |
| Блокировщики | теряет 5–25 % без прокси (их оценка) | тоже блокируется, доля у нас не измерена | **нет данных** о потерях Метрики в наших проектах |
| Выборка | при больших объёмах — масштабирование выборки (`scale_sample`) и приближённый `uniq` | у Метрики своё семплирование | малые сегменты на выборке шумят у обоих |

## 4. Точность, боты, блокировщики — что пишут сами

- **Боты** ([bot-traffic-filtering](https://plausible.io/docs/bot-traffic-filtering)): «No filter is perfect»; новый бот
  проходит, пока его не опознали; признак бота в отчёте — почти 100 % отказов и нулевая длительность, смотреть ещё
  время на странице, прокрутку, конверсии. Низкокачественный живой трафик — не бот. Боты без JavaScript (в том числе
  краулеры ИИ) счётчик не запускают вовсе. Часть VPN и даже домашних адресов попадает под фильтр дата-центров —
  ложные срабатывания признаны.
- Заявления «в 18 раз меньше просмотров, чем в серверных логах», «GA4 засчитал ботов, мы — нет» — **их собственные
  замеры без независимой проверки**: в методику не брать.
- **Блокировщики** ([proxy](https://plausible.io/docs/proxy/introduction)): 5–25 % посетителей в зависимости от
  аудитории; лечится отдачей скрипта со своего домена. Ловушка: прокси без реального IP посетителя — фильтр ботов
  молча отбрасывает событие, а ответ сервера всё равно успешный (202). **Урок общий:** «код 200 не значит
  записано».
- **Воронки, выручка, продвинутый фильтр ботов** — только в облаке; в самостоятельной версии фильтр ботов —
  только по User-Agent и спам-реферерам (README).
- Причины отбрасывания события перечислены в коде явным списком (`event.ex`, тип `drop_reason`): спам-реферер,
  бот, IP дата-центра, IP угроз, блок-листы сайта по IP, странице, стране, хосту, ошибки записи. **Вывод:** у них
  «почему не посчитано» — объявленная классификация, а не молчаливая потеря.

## 5. Безопасность

- Читали только текстом: GitHub MCP (`get_file_contents`, поиск по коду) и WebFetch страниц `raw.githubusercontent.com`
  и `plausible.io`. Ничего не клонировали, не скачивали архивом, не устанавливали и не запускали.
- **Риск низкий.** Крупный известный проект; в README нет команд вида `curl | bash` — установка самостоятельной
  версии вынесена в отдельный репозиторий (не открывали). В `.github/` — обычные `dependabot.yml`, шаблоны задач и
  процессы CI; файлы процессов CI не читали — для чтения как текста они не опасны. Сбора ключей и инструкций,
  обращённых к агенту, в прочитанном нет.
- **Лицензия — главное ограничение:** ядро под AGPL-3.0 (изменённую версию, работающую по сети, обязаны раскрыть);
  каталог `extra/` (воронки, выручка) — закрытая лицензия: «no rights to use, distribute or otherwise exploit this
  software are granted», «for informational purposes only». Мы берём только определения и идеи, код не переносим.
- Ничего о владельце и его проектах во внешние сервисы не отправлялось: запросы содержали только адреса страниц и
  вопросы об их содержимом.

## 6. Что не проверено

- Номера строк `event.ex`, `salts.ex`, `expression.ex`, `funnel.ex` — из пересказа инструмента чтения; точные — только
  у `cache_store.ex` (прочитан целиком). Перед цитированием в каноне — открыть файл по коммиту.
- Модуль классификации источников `Plausible.Ingestion.Source` и правила каналов в коде — не открывали; каналы взяты
  из документации.
- Часовой пояс планировщика соли — вывод о поведении по умолчанию, не прочитан.
- Формула основной «Конверсии» Метрики (от визитов) — справка формулу не пишет; не подтверждено.
- Цифры точности (5–25 %, ≈ 40 800 диапазонов, 18 раз) — заявления разработчика, не проверены.
