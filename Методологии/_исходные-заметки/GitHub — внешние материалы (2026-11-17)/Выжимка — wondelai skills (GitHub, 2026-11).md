# Выжимка — wondelai skills (GitHub, 2026-11)

Источник — https://github.com/wondelai/skills, ветка main, коммит `c5265583` (13.11.2026), лицензия MIT, © 2025
Wondel.ai sp. z o.o. На 17.11.2026 — 2 721 звезда и 266 форков (факт, API GitHub). В задании стояло «≈50 навыков»;
в репозитории их **65**: 51 навык-пересказ книги или руководства и 14 метанавыков, которые ведут пользователя по
другим навыкам (факт, `CLAUDE.md` репозитория и опись ниже).

**Как читалось.** Дерево — через GitHub MCP и API GitHub. 440 текстовых файлов (все, кроме копий в `plugins/` и
ссылок в `.claude/`, `.cursor/`, `.windsurf/`, `.pi/`, `.agents/`) скачаны по одному с raw.githubusercontent.com на
закреплённом коммите в отдельную папку временного каталога сессии. Это не клон и не архив: ничего не
устанавливалось и не запускалось. Скрипты проверки лежали в другой папке, запускались с `python -I` и только читали
файлы. Копии навыков в `plugins/` (853 файла) не скачивались: по хешам из дерева git они побайтно совпадают с
исходными. Сверка с каноном, противоречия и предложение — в [Сверке](<Сверка — wondelai skills с каноном (2026-11-17).md>).

**Как читать пометки.**

- **[WS: навык, файл, раздел]** — адрес в репозитории. Всё с таким адресом — вторичный источник, пересказ книги
  третьим лицом: при встраивании в канон «сверить с книгой при первом применении».
- **[вывод]** — моё заключение, в репозитории его нет. **[вывод, по памяти о книге]** — сравнение с книгой, которую я
  в этой работе не держал в руках; это версия, пока не сверено с текстом книги.
- Числа из навыков — тезисы, если не сказано иное.

## Краткая суть

- **Это набор промптов-пересказов, а не книги.** Навыки писались по одному шаблону: принцип, шкала 0–10, разделы с
  таблицами «где применить», «шаблоны текста», частые ошибки, быстрая диагностика, ссылки на Amazon с партнёрской
  меткой. Примеры почти все — американский B2B SaaS.
- **По позиционированию** у wondelai заметно полнее, чем в уже разобранном founder-playbook: восемь справочников по
  ~2 тыс. слов — сценарий интервью «что вы использовали до нас», пять типов альтернатив, проверка «только мы»,
  цепочка «и что?», тесты сегмента, дерево выбора категории, «налог на обучение», сценарий командной сессии по
  минутам. Книга при этом пересказана с искажениями (раздел 3.3).
- **По переговорам** — один навык и один справочник на 21 приём Восса. Приёмы разговора описаны хорошо; процедуры
  подготовки (лист на одну страницу из книги), торга со стороны продавца и уступок нет; метод Акермана местами
  применён неверно (раздел 4.3).
- **По цене** — главное уже в каноне (Офферы, раздел 4а, из founder-playbook). wondelai добавляет три вопроса о
  цене, признаки негодных данных, экономическую ценность для B2B, правила уровней и смены модели оплаты.
- **Опасного кода и скрытых инструкций нет.** Риски — в механике: метанавыки предлагают агенту ставить другие
  навыки командой `npx … --global`, при клонировании 65 навыков подхватились бы автоматически и перехватили бы
  триггеры наших, индекс навыков обновляется ботом без выпуска (раздел 2).

## 3. Позиционирование — `obviously-awesome` (April Dunford, «Obviously Awesome», 2019)

Прочитаны `SKILL.md` и все восемь справочников. Соседний материал по позиционированию — справочник
`crossing-the-chasm/references/positioning.md` (формула Мура), он в разделе 3.2.

### 3.1 Что даёт навык

- **Определение.** Позиционирование — не сообщение, а **контекст**: в какую категорию клиент кладёт продукт, с чем
  сравнивает, по каким критериям судит. «Дорого» в одном контексте — «дёшево» в другом. **[WS: obviously-awesome,
  SKILL.md, Core Principle]**
- **Холст из десяти клеток.** Пять строятся по шагам: альтернативы → уникальные свойства → темы ценности → лучшие
  клиенты → категория; остальные выводятся: тренд, формулировка позиционирования, доказательства, история продажи,
  внешний заголовок. Каждый в команде заполняет холст сам; расхождение ответов — признак несогласия. **[WS: SKILL.md,
  The Positioning Canvas]**
- **Альтернативы.** Пять типов: прямые конкуренты; «смежные» инструменты, приспособленные под задачу; ручной процесс;
  нанять человека или подрядчика; ничего не делать. Источник — интервью с довольными клиентами (3–6 месяцев с
  продуктом, продлили, из 3–4 разных компаний): 12 вопросов, главные — «чем решали до нас», «если мы завтра исчезнем,
  что будете делать», «что ещё всерьёз рассматривали», «было ли решение без покупки программы», «что было хорошего в
  старом способе». Ответы группируют («Excel, Таблицы, Numbers» → «таблицы»), ранжируют по частоте, топ-3–5 — основа.
  Отдельный разбор «ничего не делать»: цена боли, срочность, цена перехода, страх риска, сколько людей должны
  согласиться. **[WS: references/competitive-alternatives.md]**
- **Уникальные свойства** — факты, а не выгоды. Два теста: «только мы…» и «можно проверить». Категории свойств шире
  функций: устройство, данные, интеграции, модель оплаты, команда, метод, сообщество, свойства компании. «Лучше на 10 %»
  — не отличие. Проверки: сайт и демо каждой альтернативы; спросить пять клиентов «это можно получить у X?»; срок, за
  который сильный конкурент повторит (меньше 6 месяцев — хрупко, 6–18 — умеренно, больше 18 — прочно); что клиенты
  называют при выигрыше и чего не хватило при проигрыше. Свойства без доказательства и запланированные «будем делать»
  в холст не идут. Пересмотр — раз в квартал и при запуске конкурента. **[WS: references/unique-attributes.md]**
- **Ценность.** Цепочка «и что?»: свойство → преимущество → ценность → стратегическая ценность, 2–4 шага; остановиться
  на шаг раньше общего «экономит время и деньги». Темы ценности: одна — «вы функция, а не продукт», 2–3 — норма,
  5+ — расфокус. На каждую тему 2–3 доказательства; тип доказательства — замер клиента, кейс, отзыв, сторонняя оценка,
  демо, бенчмарк, сертификат, пробный доступ. Иерархия: главная тема — то, что лучшие клиенты называют первым без
  подсказки. **[WS: references/value-mapping.md]**
- **Лучшие клиенты.** Признаки, по которым клиента можно узнать **до первого разговора** (отрасль, размер, роль,
  стек, событие-триггер), не психография. Порядок: топ-20 % клиентов по удержанию, скорости ценности, рекомендациям,
  длине сделки → общие признаки → проверка на худших клиентах → определение «[роль] в [тип компании] с [признаками],
  у которых [событие]». Тесты: можно собрать список из 100+ компаний; можно настроить рекламу; продавец узнаёт за
  2 минуты; под определение попадают 80 % лучших и меньше 20 % ушедших. **[WS: references/target-customers.md]**
- **Категория — три пути.** Лоб в лоб в известной категории (покупатель уже понимает, но критерии задают лидеры);
  подкатегория с уточнением — отрасль, размер, роль, способ («CRM для недвижимости»), меняет критерии оценки; новая
  категория — только если продукт правда не помещается ни в одну, с «налогом на обучение» (что это, зачем, как
  сравнивать, из какого бюджета, как объяснить начальству). Дерево выбора из трёх вопросов. Тест: понимает ли
  покупатель, что это, за 30 секунд. Признаки неверной категории: путают, сравнивают с нерелевантными, сделки длиннее
  нормы категории, используют не для того, о чём вы говорите. Смена категории — проверить, протестировать на
  разговорах и посадочных, перевести всё за 4–8 недель: «наполовину сменить хуже, чем остаться». **[WS:
  references/market-category.md]**
- **Тренд** — только поддержка; злоупотребление: позиционирование имеет смысл только из-за тренда, тренд не связан ни
  с одним свойством, тренд желаемый, а не идущий. **[WS: SKILL.md, Market Reference Points]**
- **Командная сессия.** 5–8 человек: основатель, продукт, сильный продавец, маркетинг, клиентский сервис. Подготовка
  за 1–2 недели: 10–15 интервью, сводка 20 выигранных и 20 проигранных сделок, сайты и цены конкурентов. Сессия 3 часа
  по минутам, правило «каждое мнение — с данными клиентов», спор больше 15 минут — голосование и пересмотр через
  90 дней. После — холст за 2 дня, сайт и скрипт продаж за 2–4 недели, проверка через 90 дней. **[WS:
  references/team-exercise.md]**
- **Проверка холста:** каждая тема ценности выводится из свойства; каждое свойство отвечает на слабость альтернативы;
  есть «чем мы не являемся»; позиционирование держится, если конкурент скопирует одно свойство. **[WS:
  references/positioning-canvas.md, Review Checklist]**
- **Признаки сбоя (быстрая диагностика):** в команде описывают по-разному; покупатель не понимает за 30 секунд; нельзя
  назвать три вещи, которых нет у конкурентов; не знаете, что клиент делал бы без вас; определение лучших клиентов
  нельзя использовать для поиска. **[WS: SKILL.md, Quick Diagnostic]**

### 3.2 Формула Мура — смежный инструмент

«Для [кого], кто [нужда], наш продукт — [категория], который [главная выгода]. В отличие от [альтернатива], наш
продукт [главное отличие]». Одна выгода, категория, которую покупатель уже знает. Две альтернативы сразу: **рыночная**
(как решают сейчас — подтверждает проблему) и **продуктовая** (ближайший конкурент — подтверждает категорию).
Пятиминутный тест на целевом покупателе: что, по-вашему, делает продукт; есть ли у вас эта проблема; в какую
категорию положите; с чем сравните; стали бы рассматривать. Приём «признать слабость»: настоящую и неважную для
главной нужды покупателя. Проверка: формулировка «скучна» маркетингу — значит понятна. **[WS: crossing-the-chasm,
references/positioning.md]**

## 4. Переговоры — `negotiation` (Chris Voss, «Never Split the Difference», 2016)

Прочитаны `SKILL.md` и `references/techniques.md` (21 приём).

### 4.1 Что даёт навык

- **Принцип.** Люди хотят быть понятыми и в безопасности; путь к «да» — через эмпатию и слушание, а не через логику
  и компромисс. Допущения о собеседнике — гипотезы. «Плохая сделка хуже никакой». **[WS: negotiation, SKILL.md, Core
  Principle]**
- **Приёмы разговора:** тактическая эмпатия (озвучить мир собеседника, не соглашаясь с ним); отражение — повторить
  1–3 ключевых слова вопросом и молчать; называние — «похоже, что…», «звучит так, будто…», без «я думаю, вы…», и
  пауза; калиброванные вопросы «как?» и «что?» вместо «почему?»; «Как я могу это сделать?» — отказ без слова «нет»;
  «нет»-ориентированные вопросы («Было бы неразумно…?»); извинение и пауза. **[WS: techniques.md, разделы 1–8]**
- **Аудит обвинений** — до встречи выписать всё плохое, что собеседник может думать о вас, и сказать первым.
  **[WS: SKILL.md, 5; techniques.md, 6]**
- **«Это правда» вместо «вы правы»:** пересказать позицию собеседника вместе с чувствами так, чтобы он сказал «да,
  именно так»; «вы правы» — признак, что от вас хотят отделаться. Три вида «да»: фальшивое, подтверждающее,
  обязывающее. Правило трёх: подтвердить договорённость три раза разными способами, третий — вопрос о
  выполнении («Как вы передадите это финансовому отделу?»). **[WS: techniques.md, 9–11]**
- **Справедливость:** «мы хотим только честно» — спросить «я сделал что-то нечестное?»; «это честное предложение» —
  отразить «Честное?» и спросить «как вы пришли к этой цифре?»; заранее сказать «если в какой-то момент будет
  нечестно — скажите». **[WS: techniques.md, 13]**
- **Якорь и сроки:** на крайний якорь не отвечать встречной цифрой, а спросить, как получилась; продавец начинает
  выше, покупатель ниже, мягкий якорь — диапазоном; про любой срок спрашивать «чей это срок и настоящий ли он».
  **[WS: techniques.md, 14; SKILL.md, Handling Common Situations]**
- **Метод Акермана:** цель → первое предложение 65 % цели → 85 % → 95 % → 100 %; последняя цифра неровная; к ней —
  неденежная добавка; ни одной уступки без встречной. **[WS: SKILL.md, 7; techniques.md, 15]**
- **Скрытое и кто решает:** «чёрные лебеди» — скрытые ограничения, мотивы, обстоятельства, их около трёх в каждых
  переговорах; три вида рычага — позитивный, негативный, нормативный (ценности самого собеседника); «много „я“ —
  решает не он», «много „мы“ — вероятно, ЛПР»; молчание; три стиля собеседника — аналитик, уступчивый,
  напористый. **[WS: techniques.md, 16–18, 20–21]**
- **Быстрая диагностика подготовки:** аудит обвинений, 3–5 калиброванных вопросов, лучшая альтернатива без сделки
  (BATNA) и точка ухода, цель «это правда», стиль собеседника, поиск «лебедей». **[WS: SKILL.md, Quick Diagnostic]**

### 4.2 Чего в навыке нет

- **Процедуры подготовки целиком.** Есть шесть вопросов диагностики, но нет листа подготовки на одну страницу
  (в книге — «Negotiation One Sheet»: цель, итог ситуации, ярлыки и аудит, калиброванные вопросы, неденежные
  предложения). [вывод, по памяти о книге]
- **Торга со стороны продавца и плана уступок.** Акерман описан как метод покупателя; как продавцу вести цену вниз,
  чем обменивать уступки и где предел — нет.
- **Закупок, тендеров, нескольких ЛПР** — нет.
- **«Дать собеседнику назвать цифру первым»** и **четыре способа сказать «нет»** из книги в навыке отсутствуют.
  [вывод, по памяти о книге]

## 5. Цена — `monetizing-innovation` (Ramanujam, Tacke, 2016)

Прочитаны `SKILL.md` и все пять справочников. Основа метода уже в каноне (Офферы, раздел 4а, из founder-playbook);
здесь — то, чего там нет.

- **Три вопроса о цене по порядку:** приемлемая (хорошая сделка) → дорогая (сомневаюсь, но заплачу за ценность) →
  запретительная. Здоровая цена — между приемлемой и дорогой. Узкий разрыв «приемлемо — запретительно» — товар
  воспринимают как обычный; широкий — отличие ценят или концепция непонятна. **[WS: references/wtp-conversations.md,
  The three-point price probe]**
- **Вероятность покупки 1–5** при показанной цене: считать только «5» и со скидкой, «4» — частично, 1–3 — «нет»;
  спрашивать при 2–3 ценах и смотреть, как падает доля «5». **[WS: там же, Purchase-probability scale]**
- **Вынужденный выбор:** ранжирование, 100 баллов по функциям (меньше ~5 баллов — второстепенное или
  отпугивающее), пары «A или B за одну цену», «собери пакет сам»; упрощённый конджойнт на 8–12 задачах. **[WS: там же]**
- **Признаки негодных данных:** ответы совпадают с вашей или конкурентной ценой; одинаковые ответы у разных клиентов
  (описание концепции подсказывает); отказ говорить о цене (говорите не с тем, кто платит); «всё ценно, всё честно» —
  переходить к вынужденному выбору. **[WS: там же, Red flags]**
- **B2B: экономическая ценность.** От следующей лучшей альтернативы клиента прибавить денежную ценность отличий
  (сэкономленные часы × полная стоимость часа, снижение ошибок × цена ошибки, прирост выручки × маржа). Готовность
  платить — доля этой суммы; если в интервью она **выше** расчёта, в модели не хватает драйвера ценности. **[WS: там
  же, B2B extra]**
- **Объёмы:** B2B — 15–25 интервью на сегмент, насыщение — три интервью подряд без новой логики; меньше 10 —
  только направление. B2C — 10–15 интервью для языка, затем опрос 150–300 на сегмент; конджойнт — от ~200 ответов.
  Основатель на интервью — да, вопросы о цене — не он: с основателем торгуются рефлекторно. **[WS: там же, Sample
  Sizes]** (тезисы)
- **Четыре провала с деревом диагноза:** есть ли спрос хоть по какой-то цене (нет — «нежить», критерии остановки
  записать заранее) → покупают легко, без сопротивления цене, процент выигрыша около 100 %, «смешно дёшево»
  (минивация: поднять прейскурант новым, добавить премиальный уровень) → широко и сложно, готовность платить не растёт
  с функциями (перегруз: оставить основное одного сегмента) → ценность есть, но без владельца (спрятанный самородок).
  Иначе — не провал цены, а исполнения: охват, канал, продажи; цену держать. Ежеквартальный разбор на 60 минут.
  **[WS: references/four-failures.md]**
- **Правила уровней:** проектировать средний первым; старший — 2–4 цены среднего, с настоящими «лидерами» старшего
  сегмента; младший — «попробовать лидера, а не получить целиком»; забор между уровнями — сначала ценностью, потом
  лимитами; разрыв цены объясняется одной фразой; не больше четырёх уровней; называть уровни по клиенту («Мастер —
  Бригада — Компания»), а не металлами; безопасность, приватность, выгрузка данных — во всех уровнях; понижение
  уровня не удаляет данные. **[WS: references/packaging-tiers.md]**
- **Отпугивающее** — порог «20 %+ сегмента реагируют отрицательно на оплату» (в founder-playbook порог другой: «меньше
  20 % ценят и больше 20 % не ценят»). **[WS: packaging-tiers.md, The Classification Procedure]**
- **Модель оплаты:** метрику выбрать раньше уровня цены; пять проверок метрики — растёт с ценностью, предсказуема для
  клиента, привычна, измерима обеими сторонами, не штрафует нужное поведение. Оплата по использованию — с порогами,
  предупреждениями, лимитами; смешанная (абонентская часть + использование) — «включённый объём около медианы».
  **[WS: references/monetization-models.md]**
- **Смена модели оплаты:** пересчитать 12 месяцев счетов каждого клиента по новой модели; сначала — новым клиентам;
  действующим — старые условия на 6–18 месяцев или выбор с кредитом; объявлять с ценности, не с таблицы; следить по
  когортам. **[WS: там же, Migrating Between Models]**
- **Пороги реакции до запуска:** записать метрики и пороги на 30/60/90 день и действия при них, чтобы в первую
  неделю не снижать цену в панике. **[WS: SKILL.md, 6; four-failures.md, Running a Failure Review]**
- **Распределение по уровням** «70 % средний / 20 % старший / 10 % младший» **[WS: packaging-tiers.md, 4]** — у
  founder-playbook «≤25 / ~70 / ≥10» с другим порядком. Два пересказа одной книги расходятся; ни одно не норма.
- **Расходится с правилами канона:** «якорь работает даже произвольный», «вариант-приманка существует, чтобы его
  отвергли» **[WS: SKILL.md, 6]**; «ставьте премиальный уровень первым как якорь» (если он настоящий — допустимо).
  Кейсы трёх компаний — без названий, иллюстрации.

## 6. StoryBrand — `storybrand-messaging` (Donald Miller, «Building a StoryBrand», 2017)

Прочитаны `SKILL.md` и все шесть справочников. Рамка SB7 и её разбор уже в каноне (каталог SMM, выжимка
founder-playbook, раздел 2). Новое:

- **Разговор продажи по SB7** с таймингом: проблема (5 мин) → три уровня проблемы вопросами (15) → проводник —
  эмпатия и авторитет (5) → план из трёх шагов (10) → успех и провал (5) → шаг (5); библиотека вопросов по миру
  клиента, целям, ограничениям и чувствам. **[WS: references/sales-conversations.md]**
- **Возражения: признать → расспросить → переформулировать:** «дорого — по сравнению с чем?», «надо подумать — что
  именно нужно обдумать?», «не время — что сделает время подходящим?», «надо обсудить с начальником — какие у него
  будут вопросы, могу присоединиться к звонку». **[WS: там же, Objection Handling]**
- **Цена после ценности:** «теряете 20 000 в месяц → решение даёт +8 000 → вложение 5 000». **[WS: там же, Presenting
  Price]** Это то же, что калькуляторное закрытие Хормози в каноне.
- **Шаблон отзыва-истории на видео** из шести вопросов: что было до нас → что было тяжелее всего → почему выбрали
  нас → как шла работа → какие результаты → что скажете тому, кто думает. **[WS: references/multi-channel-consistency.md,
  Testimonial Video Guide]**
- **Серия из пяти писем** (выдать обещанное → проблема и эмпатия → авторитет и кейс → план → прямой призыв),
  правило «3 полезных : 1 продающее», серия возврата неактивных. **[WS: references/email-sequences.md]**
- **Расходится с каноном:** «какие измеримые результаты вы можете пообещать» в шаблоне BrandScript **[WS:
  brand-script.md, 6]**; «100 % гарантия удовлетворения» как план-соглашение по умолчанию **[WS: SKILL.md, 4]**;
  злодей-персонаж «жаргон Уолл-стрит, созданный, чтобы вас запутать» **[WS: SKILL.md, 2]**; ориентиры писем
  (открытия 20–30 %, клики 2–5 %) — без источника, американские.

## 7. Crossing the Chasm — `crossing-the-chasm` (Geoffrey Moore, 3-е изд., 2014)

Прочитаны `SKILL.md` и восемь справочников; `b2b-saas.md` и `case-studies.md` — бегло, до примеров компаний.

- **Пять групп покупателей и пропасть** между ранними последователями (визионеры: хотят быть первыми, терпят сырое) и
  ранним большинством (прагматики: нужны отзывы равных, «целый продукт», низкий риск). Отзывы визионеров
  прагматиков пугают. Признаки: «Кто ещё из нашей отрасли пользуется?», несколько согласующих, вопросы про интеграции
  и устойчивость поставщика. **[WS: SKILL.md; references/buyer-segments.md]**
- **Выбор плацдарма — матрица:** боль ×2, возможность собрать целый продукт за 6–12 месяцев ×2, доступ к сегменту ×1,
  конкуренция ×1, сарафан внутри сегмента ×2, размер ×1 (лучший — 50–1 000 компаний; 5 000+ — слишком широко);
  35–45 из 45 — сильный кандидат. Сначала 20+ кандидатов, затем топ-3 вглубь (5+ разговоров, карта целого продукта,
  экономика), потом выбор одного. Ошибки: слишком широко, слишком узко, два плацдарма, выбор по размеру рынка, «у нас
  три клиента в трёх отраслях». **[WS: references/beachhead-selection.md]**
- **Целый продукт:** базовый → ожидаемый → расширенный → потенциальный (слои Левитта). Таблица разрывов по 12 строкам,
  для каждого — построить / партнёр / рекомендовать / принять; приоритет — «без этого не купят» × «нужно большинству»;
  разрыв, который всплыл в 3+ проигранных сделках плацдарма, — первый приоритет; правило 80 %. **[WS:
  references/whole-product.md]**
- **Следующий сегмент («кегли»):** перенос доверия отзывов ×2, перенос целого продукта ×2, усилия продаж ×1; 20–25 из
  25 — следующий, ниже 10 — это новый плацдарм. Четыре оси соседства: та же роль в другой отрасли; другая роль в той
  же отрасли; тот же сценарий в другом размере; соседний сценарий у того же покупателя. Перед расширением — доминирование
  (тезисы навыка: доля 30–50 %, 10+ отзывов, удержание 90 %+). **[WS: references/expansion.md]**
- **Для прагматиков:** кейс по шаблону (профиль → задача в цифрах → решение → результат → цитата с должностью),
  калькулятор окупаемости, где каждое допущение привязано к замеру реального клиента; цены — опубликованные уровни,
  без сюрпризов. **[WS: references/go-to-market.md]**
- **Расхождения:** «плацдарм Salesforce — inside sales в B2B-стартапах Кремниевой долины (actual)», «плацдарм Slack»
  — в книге Мура таких разборов нет, история не подтверждена [вывод]; доли групп 2,5/13,5/34/34/16 — из модели
  Роджерса, у Мура для иллюстрации. Пример Documentum — из книги [вывод, по памяти о книге].
