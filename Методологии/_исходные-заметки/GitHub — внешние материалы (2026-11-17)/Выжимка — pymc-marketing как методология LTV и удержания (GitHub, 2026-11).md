# Выжимка — pymc-marketing как методология LTV и удержания (GitHub, 2026-11)

Источник: <https://github.com/pymc-labs/pymc-marketing>, ветка `main`, прочитано 17.11.2026 как текст (GitHub MCP —
опись папок; raw.githubusercontent.com и pymc-marketing.io — содержимое). Ничего не клонировали, не ставили, не
запускали. Сверка с каноном и предложение — в [сверке](<Сверка — pymc-marketing с каноном (2026-11-17).md>).

Пометки: **[код]** — формула или правило из исходника, **[док]** — из страницы документации, **[вывод]** — мой вывод,
в источнике его нет. Цитаты — короткие, по-английски, как в источнике.

## Краткая суть

- Библиотека отвечает на три вопроса по каждому покупателю: **жив ли он** (вероятность, что ещё покупает),
  **сколько ещё купит** за горизонт, **какой будет чек**. Произведение «ожидаемые покупки × ожидаемый чек» с
  дисконтом — её «CLV». Это **будущая (остаточная) ценность покупателя от даты среза**, а не пожизненная от первой
  покупки, и **по выручке**: маржи в формуле нет **[код]**.
- Вход у всех моделей один — сводка по покупателю из журнала оплат: число **повторных** покупок, срок от первой до
  последней, «возраст» от первой покупки до даты среза, средний **повторный** чек **[код]**.
- Главная развилка — тип отношений: **договорной** (уход виден — не продлил подписку) или **недоговорной** (уход не
  виден — просто перестал покупать); и **непрерывное** или **дискретное** время покупок **[док]**.
- Ключевая идея, совпадающая с каноном: клиенты разные, поэтому **удержание когорты растёт со временем** — первыми
  уходят склонные уйти. Отсюда постоянный отток и «LTV = 1 / отток» дают заниженный хвост **[док, sBG]**.
- Проверка — прогноз на отложенном периоде против факта и сравнение распределения повторных покупок с моделью
  **[код, док]**. Минимального объёма данных документация не называет.
- MMM (вклад каналов) — линейная модель продаж с переносом эффекта рекламы (adstock) и насыщением; калибровка
  экспериментами; пример — чуть больше двух лет понедельных данных **[док]**.

## 2. Данные: RFM-сводка библиотеки

Функция `rfm_summary` **[код]** превращает журнал оплат (покупатель, дата, сумма) в строку на покупателя:

| Колонка | Определение | Ловушка |
|---|---|---|
| `frequency` (x) | число **повторных** покупок = периоды с покупкой − 1 | первая покупка не считается; несколько покупок в одном периоде (день по умолчанию) — **одна** |
| `recency` (t_x) | время от первой до **последней** покупки; у купивших один раз = 0 | это **не** давность классической RFM (время с последней покупки); давность = `T − recency` |
| `T` | «возраст»: от первой покупки до конца периода наблюдения | модель требует `T ≥ recency`; код этого не проверяет |
| `monetary_value` | средний чек **повторных** покупок; у купивших один раз = 0 | первая покупка исключена (если не задать `include_first_transaction`); суммы одного периода складываются |

- Единица времени (`time_unit`: день, неделя, месяц) задаёт и «склейку» покупок, и масштаб параметров **[код]**.
- `rfm_train_test_split` **[код]** — та же сводка на учебном отрезке плюс `test_frequency`, `test_monetary_value`,
  `test_T` на отложенном. Покупатели, впервые купившие в отложенном отрезке, выпадают. Границы отрезков округляются
  неодинаково (учебный — по периоду, отложенный — по сырой дате).
- `rfm_segments` **[код]** — классическая RFM по **квартилям** (`qcut` на 4), код из трёх цифр и пять сегментов
  по жёстким спискам кодов («Premium», «Repeat», «Top Spender», «At Risk», «Inactive»), остальное — «Other».

## 3. Модели повторных покупок

### 3.1 Выбор модели **[док, быстрый старт]**

| | Недоговорной (уход не виден) | Договорной (уход виден) |
|---|---|---|
| **Непрерывное время** (купить можно в любой момент) | BG/NBD, Pareto/NBD, модифицированная BG/NBD — интернет-магазин | (в библиотеке моделей нет; пример страницы — «время до конверсии») |
| **Дискретное время** (поводы для покупки по расписанию) | BG/BB — концерты, спортивные события | ShiftedBetaGeo (sBG) — подписки, продление договоров |

Gamma-Gamma — отдельная модель **чека**, ставится в пару к любой модели покупок.

### 3.2 BG/NBD — «умирает только сразу после покупки»

Допущения **[код, док]**:

- Пока покупатель активен, покупает со своим постоянным темпом λ (промежутки — экспоненциальные, число покупок —
  Пуассон). Темп у разных покупателей разный — гамма-распределение с параметрами r, α.
- **После каждой покупки** покупатель с вероятностью p уходит навсегда. p у разных покупателей разная —
  бета-распределение с параметрами a, b. Темп и склонность уйти независимы.
- Уход не наблюдается: о нём судят по паузе.
- Следствие: купивший один раз (x = 0) считается **живым с вероятностью 1** — уйти он «не успел» **[код]**.

Выходы и формулы **[код, `beta_geo.py`]** (x — повторные покупки, t_x — `recency`, T — возраст, t — горизонт):

- **Вероятность, что активен:**
  `P(alive) = 1 / (1 + [a / (b + x − 1)] · [(α + T) / (α + t_x)]^(r + x))`, при x = 0 — 1.
  Смысл: чем длиннее пауза `T − t_x` **относительно собственного темпа покупателя** (r + x), тем ниже P(alive).
  Частый покупатель, замолчавший на два месяца, «мертвее» редкого с той же паузой **[вывод из формулы]**.
- **Ожидаемые покупки за горизонт t:**
  `E[Y(t)] = [(a + b + x − 1) / (a − 1)] · [1 − ((α + T)/(α + T + t))^(r + x) · ₂F₁(r + x, b + x; a + b + x − 1; t/(α + T + t))] / [1 + 1{x>0} · (a/(b + x − 1)) · ((α + T)/(α + t_x))^(r + x)]`.
  Нужна гипергеометрическая функция ₂F₁ — в таблицах её нет, в Python есть (`scipy.special.hyp2f1`) **[вывод]**.
- **Ожидаемые покупки нового покупателя** за t от первой покупки:
  `[(a + b − 1)/(a − 1)] · [1 − (α/(α + t))^r · ₂F₁(r, b; a + b − 1; t/(α + t))]`.
- **Вероятность ни одной покупки** в (T, T + t] — отдельная формула через бета-функции.
- **Правдоподобие для подгонки** **[код, `distributions.py`]**:
  `ℓ = lnΓ(r+x) − lnΓ(r) + lnΓ(a+b) + lnΓ(b+x) − lnΓ(b) − lnΓ(a+b+x) + r·ln α − (r+x)·ln(α+t_x) + ln[((α+t_x)/(α+T))^(r+x) + 1{x>0}·a/(b+x−1)]`.
  Все функции есть в таблицах (`GAMMALN`), так что подогнать четыре параметра можно и «Поиском решения» **[вывод]**.
- Ковариаты (признаки покупателя, не меняющиеся во времени) — на темп и на уход отдельно **[код]**.

Толкование **[док, BG/NBD]**: на графике «P(alive) без будущих покупок» вероятность только падает, у частых
покупателей — очень быстро. Это не прогноз ухода, а «что будет, если он больше не купит».

### 3.3 Pareto/NBD — «может уйти в любой момент»

- Активен неизвестное время, затем уходит навсегда; уход возможен в любой момент, не только после покупки **[код]**;
  BG/NBD «sacrifices functionality in customer dropout estimation for better computational performance» **[док]**.
- Те же входы; дополнительно — вероятность ровно N покупок за горизонт **[код]**.
- Подгонка тяжелее: «NUTS sampling … can be quite slow» — рекомендуют безградиентный сэмплер **[док]**.
- Порог из документации: «an alive probability of .25-.30 usually indicates an at-risk or inactive customer»
  **[док]** — тезис автора примера, не норма.
- Средний чек нельзя брать ковариатой, если потом в паре стоит Gamma-Gamma **[док]**.
- На малой выборке примера автор прямо пишет о переобучении **[док]**.

### 3.4 Модифицированная BG/NBD (MBG/NBD)

Снимает допущение BG/NBD, что все купившие один раз живы: уйти можно и сразу после первой покупки (Batislam и др.,
2007) **[код]**. Нужна там, где много разовых покупателей. Вероятность «ни одной покупки» не реализована **[код]**.
Пересказ страницы быстрого старта описал MBG наоборот («assumes non-repeat customers are still active») — беру код.

### 3.5 BG/BB — дискретные поводы

Покупка возможна только в известные «окна» (событие, сезон, рассылка с поводом). У всех покупателей одинаковое число
окон T. Склонность купить в окне и склонность уйти — бета-распределения **[код]**.

### 3.6 ShiftedBetaGeo (sBG) — подписка и договоры

Допущения **[код, док]**:

- Каждый период подписчик продлевает или уходит; вероятность ухода θ постоянна **у него**, но разная у разных —
  бета-распределение (α, β).
- Когорта = начали в один период; несколько когорт подгоняются вместе, можно с признаками (сегмент, канал).
- Данные: на подписчика — последний период продления (`recency`), максимальный период когорты (`T`), когорта;
  `1 ≤ recency ≤ T`, `T ≥ 2`. Вернувшийся после отмены — новый подписчик.
- **«Retention rates increase over time as high-risk customers drop out»** **[док]** — та же мысль, что в каноне
  «LTV = 1 / churn — ложь».

Формулы **[код, `distributions.py`]**: дожитие до периода t
`S(t) = B(α, β + t) / B(α, β) = Γ(β + t)·Γ(α + β) / (Γ(β)·Γ(α + β + t))`.
Отсюда **[вывод]**:

- Удержание периода t (доля продливших из доживших до t − 1): `r(t) = S(t)/S(t−1) = (β + t − 1) / (α + β + t − 1)` —
  растёт к 1 с возрастом когорты.
- По двум первым наблюдаемым удержаниям r₁, r₂ (нужно r₂ > r₁): `α = (1 − r₁)(1 − r₂)/(r₂ − r₁)`,
  `β = r₁(1 − r₂)/(r₂ − r₁)`. Проверка: r₁ = 0,6, r₂ = 0,7 → α = 1,2, β = 1,8 → r₁ = 1,8/3 = 0,6, r₂ = 2,8/4 = 0,7.
- Хвост `S(t)` убывает примерно как `t^(−α)` — степенной закон, как кривая удержания в каноне. При α ≤ 1 сумма
  ΣS(t) (ожидаемая длительность) **бесконечна** — пожизненную ценность считать только на ограниченном горизонте.

Выходы **[код]**: удержание по периодам, вероятность активности (дожитие), ожидаемая оставшаяся длительность,
эластичность удержания.

### 3.7 Gamma-Gamma — ожидаемый чек

Допущения **[док, код]**:

- Чек покупателя колеблется вокруг его среднего; средние у покупателей разные, но **во времени не меняются**.
- Чек **не зависит от частоты** покупок; проверка в примерах — корреляция частоты и среднего чека: 0,05 и 0,11,
  порог в быстром старте — «less than 0.3» **[док]** (порог автора, не обоснован).
- Только покупатели с **хотя бы одной повторной** покупкой; суммы строго положительные **[код]**.

Формула **[код]**: `E[чек] = (p·v + p·x·z̄) / (p·x + q − 1)` — взвешенное среднее популяционного чека `p·v/(q − 1)` и
среднего чека покупателя z̄ с весом `p·x / (p·x + q − 1)`. **Чем меньше у покупателя покупок, тем сильнее его чек
тянется к среднему по базе** — защита от выводов по одной-двум покупкам. Новому покупателю — `p·v/(q − 1)`.

## 4. Как собирается «CLV» библиотеки

`customer_lifetime_value` **[код, `utils.py`]**:

`CLV = Σ по месяцам i = 1..H [ future_spend × (E[покупки к месяцу i] − E[покупки к месяцу i − 1]) / (1 + d)^i ]`

- `future_spend` — ожидаемый чек (Gamma-Gamma или свой столбец); `E[покупки]` — из модели покупок; d — **месячная**
  ставка дисконта (по умолчанию 0; при 0 — один шаг на весь горизонт); H — горизонт **всегда в месяцах**.
- **Маржи нет.** Документация: `monetary_value` может быть «profit, or revenue, or any value» **[док]** — что
  подставишь, то и получишь.
- Считается **только будущее от даты среза**; прошлые покупки и первая покупка не входят.
- Связь с каноном **[вывод]**: прогноз CLTV на покупателя = маржа первой покупки + E[повторные покупки за горизонт]
  × E[маржа повторной покупки]; LTV на привлечённого = C1 × CLTV.

## 5. Проверка модели

| Проверка | Что делает | Источник |
|---|---|---|
| Отложенный период | подгонка на первых 52 неделях, сравнение с фактом следующих 26 | **[док, быстрый старт]**; `rfm_train_test_split` **[код]** |
| Ожидаемые против фактических покупок во времени | накопленные или по периодам, с отметкой начала проверки | `plot_expected_purchases_over_time` **[код]** |
| Распределение числа повторных покупок | доли 0, 1, 2… покупок: модель против факта (до и после подгонки) | `plot_expected_purchases_ppc` **[код]** |
| Карты «частота × давность» | ожидаемые покупки и P(alive) по сетке — проверка здравым смыслом | `plot_frequency_recency_matrix`, `plot_probability_alive_matrix` **[код]** |
| Экспозиция | на каждого покупателя — линия до последней покупки и до среза | `plot_customer_exposure` **[код]** |
| Сходимость подгонки | r_hat ≈ 1, точечная оценка близка к средней по апостериорному | **[док]** — нужно только при байесовской подгонке |
| Подписка | подгонка на 8 периодах, факт остальных внутри 94 %-го интервала прогноза | **[док, sBG]** |

после фильтра «только повторные» — 1 126 **[док]**. В Pareto/NBD на малой выборке — переобучение **[док]**. В sBG
когорта из 2 периодов даёт оценку только в общей модели с другими когортами **[док]**.

## 6. Когда модели неприменимы и типовые ошибки

1. **Недоговорная модель для подписки** (и наоборот): у подписки уход виден — sBG; BG/NBD там «угадывает» то,
   что известно **[док, матрица]**.
2. **Сезонность и тренд.** Темп покупок у покупателя постоянен, признаки не меняются во времени **[код: только
   time-invariant covariates]** — сезонный бизнес даст ошибку на отложенном периоде, если он попадает в другой
   сезон **[вывод]**.
3. **Мало повторных покупок.** Gamma-Gamma их требует; BG/NBD считает всех разовых живыми — при большой доле разовых
   нужна MBG/NBD или Pareto/NBD **[док, код]**. Для товаров длительного пользования (покупка раз в много лет)
   модели повторных покупок смысла почти не имеют **[вывод]**.
4. **Выручка вместо маржи** — в формуле CLV маржи нет **[код]**.
5. **Возвраты и нулевые суммы** — Gamma-Gamma требует строго положительных сумм **[код]**; возвраты нужно погасить
   против покупок до сводки **[вывод]**.
6. **Чек зависит от частоты** — Gamma-Gamma неприменима, проверять корреляцию **[док]**.
7. **Путаница «повторные / все покупки»** и **«recency / давность»** — см. раздел 2.
8. **Слишком мелкий или крупный период** — несколько счетов одного заказа в один день склеятся (хорошо), заказы
   одной недели при недельном периоде — тоже (плохо для частых покупателей) **[код, вывод]**.
9. **Порог P(alive) «0,25–0,30»** как норма — это тезис примера **[док]**.

## 7. MMM — вклад каналов (коротко)

- **Уравнение** **[док]**: продажи_t = база + Σ β_канал · f(расход_канал,t) + Σ γ · контроль_t + шум. Тренд и события
  — контрольные переменные, сезонность — гармоники Фурье, база может меняться во времени.
- **Перенос эффекта (adstock)** **[код, док]**: реклама действует и в следующие периоды. Геометрический:
  доля α (0–1) переходит в следующий период, `l_max` — максимум запаздывания (в примере 8 недель); есть варианты с
  задержкой пика (Delayed), Вейбулла, биномиальный.
- **Насыщение** **[код, док]**: отдача от расхода убывает. Логистическое, Хилла (S-образное), Михаэлиса-Ментен,
  логарифмическое и др.; у «lam» в разных функциях **разный смысл** (крутизна или точка полунасыщения).
- **Порядок**: сначала перенос, потом насыщение **[док]**.
- **Данные** **[док]**: понедельно продажи, расход по каждому каналу, события; в примере — «a bit more than 2
  years», два канала. Минимум не назван.
- **Калибровка экспериментами** **[док, lift test]**: при одинаково меняющихся расходах каналов модель
  «cannot cleanly separate the channel responses». Эксперимент (изменение расхода, изменение продаж, ошибка замера)
  ограничивает кривую насыщения. Улучшение не гарантировано; без экспериментов — калибровка по известной цене
  целевого действия.
- **ROAS из модели — «an approximation»** **[док]**.
