# Постановка — Свой трекер позиций и выдачи

Автор: Claude по брифу Дмитрия, 03.11.2026. Источник: [Бриф чата — свой трекер позиций и выдачи](<Бриф чата — свой трекер позиций и выдачи.md>)

## Проблема

Дмитрий ведёт SEO в нескольких проектах. Позиции он снимает через Topvisor, а Rush Analytics в брифе назван
вторым сервисом того же рода. Оба берут выдачу у поставщиков и перепродают её с наценкой. Что мешает сейчас:

1. **Переплата за то, что можно взять у источника.** В режиме XML Topvisor снимает Яндекс через официальный
   Yandex Search API (так написано в его справке) и берёт за топ-100 63–90 ₽ за 1 000 проверок. Сам Яндекс в
   отложенном режиме берёт 25–30,5 ₽. В Google разрыв
   больше: у Topvisor каждая страница из 10 результатов — отдельная проверка. Конкуренты, снимок топа и сниппеты у
   Topvisor — платные надбавки, хотя приходят в том же ответе поставщика.
2. **Негибкость.** Функции перепродавцов заданы за Дмитрия: лишнее не отключить, нужного нет. Расчёты (видимость,
   средняя позиция, конкуренты) живут в их кабинете, и их нельзя связать с остальными системами канона —
   Контент-машиной, Движком роста, Ядром данных.

## Нужный результат

Свой инструмент, общий для любых проектов Дмитрия. Что увидит Дмитрий:

- **По проекту:** семантика — фразы, группы, теги, целевые страницы. Позиции в Яндексе и Google по региону
  снимаются по расписанию без участия человека, а история хранится у Дмитрия.
- **Цифры проекта, группы и страницы:** видимость, средняя позиция и медиана, доли топ-3/10/30/100. Динамика
  между любыми двумя датами: улучшились, без изменений, ухудшились.
- **Конкуренты:** кто стоит в выдаче по фразам Дмитрия, чья видимость растёт и какие страницы обходят его
  страницы. Весь топ с заголовками и сниппетами сохраняется из того же ответа, без доплаты.
- **Целевая страница:** флаг, если в выдаче стоит не та страница сайта.
- **Деньги:** цена съёма видна до запуска, есть месячный потолок, учёт расхода по проектам.
- **Потом**, не в первой версии: чем страницы конкурентов отличаются (разбор топа), нейровыдача и блоки выдачи,
  реклама, навык, возможно — MCP-сервер.

**Готово для первой версии, когда** (критерии уточнит спецификация):

1. Новый проект заводится одной командой из файла фраз, без правки кода.
2. Съём по расписанию идёт сам: Яндекс через отложенные запросы, Google — у поставщика. Цена названа до запуска,
   потолок не превышается: ночью без подтверждения система останавливается, а не тратит деньги.
3. История хранит три состояния ячейки: позиция, «не найден в глубине», «проверки не было». Ни одно не сводится
   к нулю.
4. Видимость, средняя позиция и доли топ-N на пробном проекте сходятся с ручным расчётом по той же выдаче.
5. Отчёт по конкурентам строится из сохранённого топа без дополнительных запросов.
6. Расход за месяц по проекту виден числом, и это число сходится со списаниями поставщика.

**Границы:** не заменяем Keys.so — он даёт чужую базу по всем запросам рынка, трекер даёт свой прибор по своим
фразам. Не строим веб-интерфейс как у сервисов. Перепродавать доступ не собираемся.

## Кого и какие системы касается

- **Пользователь** — Дмитрий в любом своём проекте. Агент работает через CLI, потом через навык. Рабочие проекты — среди
  будущих пользователей, но работа личная: в рабочей папке компании об инструменте не пишем.
- **Поставщики выдачи:** официальный Yandex Search API (Yandex Cloud), XMLRiver и XMLStock. Ключи — переменные
  `XML_RIVER_*`, `XML_STOCK_*` и ключ Yandex Cloud, который уже использует Контент-машина.
- **Канон, переиспользуем** (подробно — раздел 3 аналитики): из пакета `content_engine` — интерфейс выдачи
  `SerpSource`, адаптер Search API, клиент только-чтение, бюджет-гейт, учёт расхода, кэш выдачи, позиции из
  консолей, Wordstat, кластеры по выдаче. Навык `topvisor` — для разового переноса истории. Пакет `datacore` —
  образец устройства системы с кодом.
- **Рядом:** Keys.so (рынок и ИИ-ответы Алисы), Контент-машина (ей нужен топ выдачи — трекер может стать её
  источником), Движок роста (замер гипотез по позициям).
- **Реестр инструментов:** оценки XMLRiver, XMLStock и Yandex Search API как поставщиков выдачи по мере готовности.

## Ограничения

- **Деньги:** любой платный вызов — сначала число запросов и цена, потом «да» Дмитрия. В коде — бюджет-гейт и
  месячный потолок.
- **Секреты** — только по именам переменных из `C:\Users\redmi\Second Brain Secrets\.env`, значения не
  печатаются и не пишутся в файлы.
- **Установки:** ничего глобально и никаких MCP без «да» Дмитрия. На диске C мало места — тяжёлых зависимостей
  не берём.
- **Канон:** код — пакетом канона по ADR-0003, нейтральный, без имён и данных компаний. Данные проектов —
  в инстансе проекта, не в каноне. Коммит своих путей и строка в CHANGELOG; push делает Дмитрий.
- **Внешние системы** — только чтение, кроме оплаченных запросов к поставщикам выдачи.
- **Субагенты** — не больше трёх одновременно и только на чтение.
- **Достоверность:** уровни разных приборов (Topvisor, Keys.so, свой трекер, консоли) не сшиваются, изменения
  сравниваются внутри одного прибора. Каждое число — с периодом, источником и статусом.

## Открытые вопросы

Порядок — от того, что сильнее меняет работу. В скобках — вариант по умолчанию, если Дмитрий не скажет иначе.

1. **Источник Яндекса** — (официальный Search API в отложенном режиме, ночью: 25,41 ₽ за 1 000, договор с
   Яндексом, адаптер уже есть). Альтернатива — прокси того же API у XMLRiver или XMLStock: 24–28 ₽ без своего
   облака. «Живая» выдача поставщиков нужна только для колдунщиков и рекламы, и тогда — топ-10 (1 запрос).
2. **Google в первой версии** — (да, глубина топ-30, раз в неделю). Глубина 100 утраивает цену.
3. **Где живёт и чем запускается** — (локально, планировщиком Windows, хранилище — файл DuckDB или SQLite в
   папке инстанса). Альтернатива — сервер: компьютер не обязан быть включён, но нужна аренда и выкладка.
4. **Отдельный пакет или модуль Контент-машины** — (отдельный пакет `rank_tracker`, общие адаптеры выделить в
   общий модуль). Решается в спецификации, Дмитрию — выбрать, если есть предпочтение.
5. **Пробный проект** — (семантика проекта-примера из Topvisor, около нескольких тысяч фраз, данные — только в
   инстансе вне канона). Нужен ли перенос истории Topvisor — (да, один раз, отдельным прибором без сшивки).
6. **Месячный потолок трат** на съём — нет данных, нужна цифра от Дмитрия (для сценариев аналитики: от 400 до
   18 500 ₽ в месяц).
7. **Пробный платный вызов** для сверки поставщиков с Topvisor — предложение: 50 фраз × Яндекс через Search API
   отложенный (50 запросов, около 1,5 ₽) + 50 фраз × Google топ-30 у XMLRiver (150 запросов, около 3,75 ₽) +
   50 фраз × живой Яндекс топ-10 у XMLStock (50 запросов, около 1,25 ₽). Итого 250 запросов, меньше 10 ₽.
   **Не запускался, ждёт «да».**
8. **Отчёты** — (CSV и одна HTML-страница по проекту). Альтернатива — Google Таблица.

**Факты со слов Дмитрия:** нужен свой инструмент вместо Topvisor и Rush; лишние функции не нужны, нужного нет;
инструмент общий для любых проектов; состав функций из брифа; порядок «постановка → спецификация → план»; работа
личная.

**Предположения агента:** разбивка на первую версию и «потом»; варианты по умолчанию в открытых вопросах;
критерии готовности; отказ от веб-интерфейса; «Keys.so не заменяем». Ещё одно наблюдение агента: по
проекту-примеру ряд в Topvisor нерегулярный — Google не снимался почти год (чтение API, 03.11.2026). Своего
инструмента это не требует, расписание есть и в Topvisor. Но первая версия должна снимать регулярно без участия
человека. Всё это Дмитрий может поправить.

**Поправка к брифу:** оценка «1 000 проверок — около 25 ₽ у поставщика и около 125 ₽ у Topvisor» в таком виде не
подтвердилась. 25 ₽ — цена 1 000 страниц по 10 результатов, то есть топ-10. Топ-100 у поставщика — 250 ₽ в
живой выдаче или 24–30,5 ₽ через Search API. Topvisor за топ-100 Яндекса — 63–90 ₽ (раздел «Краткая суть»
аналитики).
