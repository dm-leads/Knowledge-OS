# Справочник — Семантическое ядро: проверенные приёмы и ловушки инструментов

> Поднято из проекта-примера 06.11.2026. Основание методик — внешние источники (Rush, Топвизор, Пиксель Тулс,
> Semrush); здесь — только то, что проверено на живых данных.

## Частотность

- **Массово — парсер Wordstat Keys.so,** не Yandex Search API. Search API Wordstat — одна фраза за вызов, лимит 100
  вызовов в час: 774 вызова ≈ 8 часов, а прервавшийся ночью процесс теряет прогон. Парсер Keys.so отдаёт тысячи фраз за
  минуты в рамках подписки.
- У проекта парсера Keys.so параметр `ws_types`: 0 — W, 1 — "!W", 2 — "[!W]" — заказывать сразу все три. Keys.so
  склеивает фразы с переставленными словами — ключ сопоставления: слова по алфавиту.
- Отдельный старый адрес `api.wordstat.yandex.net` не отвечает (сертификат не на это имя) — Wordstat теперь внутри
  Search API.

## Выдача и позиции

- **Search API, `groupMode`:** `GROUP_MODE_FLAT` отдаёт документы подряд без группировки по сайтам (по 7–9 страниц
  одного сайта в первой дюжине) — позиция сайта неверна. Для позиций — `GROUP_MODE_DEEP`.
- **Отложенный режим Search API** — в 14–16 раз дешевле синхронного; принимается ночью (00:00–06:00 МСК). Днём
  единичные запросы проходили, массовая отправка получила HTTP 429 почти целиком — ставить на ночь задачей.
- **Позиция из базы Keys.so и живой съём расходятся сильно** (пример: 4 против 73 в Москве по одному запросу). База —
  для кластеризации и разведки; для решений — живой съём с датой; источник позиции показывать рядом с числом.
- Keys.so `check-top` знает выдачу только запросов своей базы — для остальных добирать выдачу Search API.

## Кластеризация

- Порог пересечения топ-10 не выбирать по источникам вслепую (они расходятся: 3–4 у Топвизора, 5 у Rush для
  магазина) и не по старой разметке, расставленной правилом. Сделать ручной эталон: ~90 запросов из всех направлений
  (зёрна + соседи по выдаче), две независимые разметки «какая одна страница отвечает» (человек или модель + вторая
  модель), эталон — пары, где разметки согласны; выбрать порог по F1 пар. В проекте-примере согласие 97,4 %, лучший —
  мягкий порог 2 (для уровня «страница»), жёсткий 3 — для подгрупп текста.
- Номер кластера держать постоянным (файл «главный запрос → номер»); ручные переносы и склейки — отдельным файлом с
  причиной, применяемым при каждой пересборке; после поправок главный запрос кластера не менять — иначе теряется
  привязка заметок.

## Таблица ядра

- Источник правды — файлы проекта; таблица собирается скриптом; ручные колонки («что оптимизировать», «приоритет»,
  «заметки») и журнал задач скрипт не перезаписывает; перед каждой записью — снимок «до».
- Проверить, кто видит таблицу (доступ по ссылке) — внутренние версии и деньги туда не писать.
- Мониторинг: ежедневно — маленький набор главных широких запросов, сезона и страниц под правкой; остальное — раз в
  неделю; наборы не менять каждый день, иначе ряды несравнимы; бюджет — потолком в коде.
