# Методология — Интеграция: JTBD × Юнит-экономика

## Краткая суть

**JTBD** (Jobs To Be Done, Замесин) отвечает на вопрос «почему клиент нанимает решение»: работа → сегмент → сценарий → ценность.
**Юнит-экономика** (Красинский) отвечает на вопрос «зарабатываем ли мы на этом найме»: AMPU, AMPPU, CAC, LTV, Gross Profit.

Интеграция строится на одном ключевом тезисе: **JTBD-переменные питают все пять рычагов юнит-экономики** — и именно работа клиента, а не продуктовая фича, определяет, в каком направлении двигать метрики.

Единая воронка:

```
[Работа клиента + контекст]
         ↓
[Наём решения (выбор / переключение / пробуждение спящей работы)]
         ↓
[Активация ценности в первой сессии (aha-moment ≤ первой сессии)]
         ↓
[Конверсия в первую покупку (C1)]
         ↓
[Повторные покупки (C2+, APC, Retention)]
         ↓
[AMPU / AMPPU / LTV]
         ↓
[Gross Profit = Users × AMPU = Buyers × AMPPU]
         ↓
[Profit per User = AMPU − CPU → сходимость юнит-экономики]
```

---

## Принципы

### 1. Работа первична — метрики вторичны

«Работа первична. Всё, что мы дальше делаем, вся ценность, продукт, продажи, использование, возвращаемость — вследствие того, что мы нашли людей с важной, частотной, неудовлетворённой денежной работой.» (источник → Z-segment, [txt-1.1])

Следствие для ЮЭ: пока не выбран целевой сегмент с денежной работой, AMPPU считать преждевременно — в нём нечему расти.

### 2. Сегмент = судьба юнит-экономики

Экономическая карта сегментов (Замесин):
```
Size × AMMPPU × Extra Value × Competition
```
(источник → Z-segment, [diag-1.1])

Это прямое отображение на рычаги ЮЭ: Size → поток Users; AMMPPU → целевой AMPPU сегмента; Extra Value → потенциал среднего чека и APC; Competition → возможность удерживать CAC.

«Выбрал сегмент — выбрал судьбу.» (источник → Z-segment, [txt-1.1])

### 3. Ценность = польза − инвестиции (неточная, но рабочая формула)

```
Ценность = Польза (бенефиты) − Инвестиции (косты)
```
(источник → Z-osnovy)

Ценность загружается в голову клиента до найма. Именно воспринимаемая ценность определяет конверсию C1. В ЮЭ это тот самый параметр, который «собран» в AMPPU: «В АМПУ собраны все-все-все метрики, которые описывают некоторую ценность продукта на рынке.» (источник → K1-money, транскрипт)

### 4. Конверсия — КПД найма

«Конверсия — это КПД нашего продукта. Отношение людей, которые выполнили работу с нашим продуктом, к количеству людей с целевой работой, поданных на вход воронки.» (источник → Z-sleeping, txt)

В ЮЭ:
```
AMPU = Conversion × AMPPU
Profit per User = AMPU − Cost per User
```
(источник → K0-ampu, транскрипт)

Конверсию снижают: барьеры, непонятая ценность, ненайденный aha-moment, техническая поломка. Каждый из этих факторов — JTBD-переменная.

### 5. Привычка и спящие работы — рычаги APC и LTV

Повторные покупки (APC) определяют AMPPU. Их динамика зависит от:
- **Привычки** — физического изменения структуры мозга под важную частотную задачу (источник → Z-sleeping, txt). Чем глубже работа укоренилась в сценарии клиента, тем выше Retention и APC.
- **Ценности работы** — если продукт выполняет верхнеуровневую работу (важную, частотную), клиент возвращается. Если работа спящая — она ещё не вошла в сценарий и APC будет низким, пока тройка активирующих знаний не загружена.

В ЮЭ прямая связь retention → повторные покупки отсутствует математически, но ограничивает C2+ сверху: «Retention может ограничивать сверху конверсию второй покупки, но не более чем.» (источник → K5-cohorts, расшифровка)

### 6. Модель нелинейна — точки роста ищутся, не угадываются

«Самое главное — посмотреть пример нелинейных зависимостей в юнит-экономике, где экономика неустойчива.» (источник → K1-money, транскрипт)

Малейшее улучшение JTBD-переменной (правильный сегмент, снятый барьер, сдвинутый aha-moment) даёт кратный рост прибыли из-за операции вычитания в формуле `Profit per User = AMPU − CAC`.

## Подход

### Блок 1. JTBD — понять спрос и выбрать сегмент

**Шаг 1. Сформировать широкую гипотезу работы.**
Убрать все заужения из идеи продукта. Не «обучение сейлзов», а «обучение любых сотрудников чему угодно» (источник → Z-segment, [txt-1.1]).

**Шаг 2. Оценить рынок в деньгах.**
Рынок без денег даст красивое исследование с нулевым AMPPU. Итерировать параллельно с качественным исследованием (источник → Z-segment, алгоритм 5 этапов).

**Шаг 3. Провести качественное JTBD-исследование (итерации по 6–8 интервью).**
Рекрутировать по критерию «платит деньги за решение, связанное с широкой гипотезой работы». После каждой итерации — кластеризация в сегменты и выделение не-сегментов. Остановить, когда за последние 10 интервью ничего принципиально нового: ~80% полноты (источник → Z-segment, [txt-1.1]).

**Шаг 4. Количественная валидация сегментов.**
```
Ранжировать по: Важность × Частотность × Размер × Неудовлетворённость
```
(источник → Z-segment, [txt-1.1])

Убрать сегменты, за которые нет компетенций или ресурсов.

**Шаг 5. Акт выбора — назначить работы целевыми.**
После выбора строить граф работ ниже уровня. До выбора — не прокапывать: время интервью сгорит на нецелевых сегментах (источник → Z-segment, [txt-1.1]).

---

### Блок 2. Соединение: как JTBD-переменные двигают метрики ЮЭ

| JTBD-переменная | Метрика ЮЭ | Механизм |
|---|---|---|
| Важность и частотность работы | APC, LTV (AMPU) | Частотная, важная работа → высокая возвращаемость → высокий APC |
| Неудовлетворённость текущим решением (Четыре силы) | Conversion (C1) | Сильные «силы вперёд» снижают барьер входа → растёт C1 |
| Снятие барьеров | Conversion (C1, C2+) | Барьеры — «пожиратели ценности»; их снятие поднимает конверсию без роста CAC (источник → Z-sleeping) |
| Aha-moment в первой сессии | Activation → C1 | Чем раньше клиент понимает ценность, тем меньше дропается до первой покупки (источник → Z-sleeping) |
| Выбор сегмента (Size, денежность) | Users, AMPPU | Большой денежный сегмент → больше Users при том же CAC, выше целевой AMPPU |
| Спящие работы (тип 1) | C1, новые Users | Загрузка тройки активирующих знаний расширяет адресуемый рынок (TAM) — источник → Z-sleeping |
| Граф работ: предыдущие/следующие | AMPU через допродажи | Выход на соседние работы → рост APC или среднего чека без роста CAC |
| Привычка к текущему решению | CAC | Сильная привычка конкурента = дорогой переключатель; выгоднее идти в спящие работы или сегменты с минимальной привычкой |
| Личные работы ЛПР (B2B) | C1 в продажу | Продажа через личную мотивацию ЛПР повышает конверсию; 80% мотивации покупки B2B — личная (источник → Z-osnovy, «B2B специфика») |

---

### Блок 3. Юнит-экономика — посчитать и найти точку роста

**Базовые формулы (Красинский):**

```
AMPPU = Средний чек × Маржинальность(%) × Среднее число повторных покупок
```
(источник → K0-ampu; K1-money, транскрипт)

```
AMPU = Conversion × AMPPU
```
(источник → K0-ampu, транскрипт)

```
Gross Profit = Users × AMPU  =  Buyers × AMPPU
```
(источник → K0-ampu, транскрипт)

```
Profit per User = AMPU − Cost per User
```
(источник → K0-ampu, транскрипт)

**Три уровня сходимости (Красинский):**
1. По привлечённым пользователям: `AMPU > Cost per User`.
2. По платящим пользователям: `AMPPU > 0`.
3. Финансовая сходимость: суммарная выручка > суммарных расходов (включая фикс).
(источник → K0-ampu, транскрипт)

**Когортный расчёт APC (правильный):**
```
APC = Суммарное число платежей когорты / Размер когорты
```
(источник → K1-money, транскрипт)

Считать APC без когорт — ошибка: «100 чел. за год сделали 600 покупок → в среднем 6» — реально 90% купят 1 раз (источник → K1-money, транскрипт).

**Прогноз MAU через retention (Красинский, М5):**
```
Retention(месяц X) = Retention(месяц 1) × X^(-a)
MAU(N) = Новые_пользователи × Мультипликатор(N)
Мультипликатор(N) = 1 + R(1) + R(2) + ... + R(N−1)
```
(источник → K5-cohorts, расшифровка)

**LTV через Gross Profit когорты:**
```
LTV (когорты) = Σ Gross Profit за время жизни когорты / Число байеров когорты
```
(источник → K5-cohorts, расшифровка)

---

### Блок 4. Работа со спящими работами → расширение рынка → рост Users

Спящие работы (Замесин) — уникальный рычаг роста потока Users без прямой конкуренции:

**Тройка активирующих знаний для пробуждения:**
1. Знание, что эту работу возможно выполнить (новый способ существует).
2. Знание, что наша версия работы эффективнее прежнего способа.
3. Знание о конкретном удобном решении.
(источник → Z-sleeping, txt)

**Алгоритм:**
1. Найти людей, у которых спящая работа уже проснулась.
2. Провести JTBD-интервью: работы, квалифицирующие факторы, активирующее знание.
3. Сформировать тройку активирующих знаний.
4. Загружать тройку людям из того же сегмента на более ранних стадиях.
5. Снижать барьеры к решению и к выполнению работы в целом.
(источник → Z-sleeping, алгоритм 4.3)

**Связь с ЮЭ:** пробуждение спящей работы расширяет TAM (больше Users при том же CAC) и потенциально повышает APC (если новая работа частотная). Кейс Yango: загрузка тройки через сотрудника банка подняла конверсию в пополнение с 10% до ~65% (источник → Z-sleeping, кейс Yango).

---

### Блок 5. Aha-moment → активация → C1

Aha-moment (хамомент) — «точка, когда клиент понимает ценность продукта» (источник → Z-sleeping, txt). Если ценность отложена, клиент отваливается до C1.

**Связь с балансом воронки (Красинский):** на каждом шаге воронки, если воспринимаемая ценность < косты шага → пользователь дропается (источник → Z-sleeping, «Баланс ценность/косты»).

**Алгоритм сдвига aha-moment:**
1. Узнать, через сколько шагов клиент получает ценность.
2. Двигать aha-moment раньше: давать хотя бы часть ценности на первой сессии или даже на уровне маркетинговой коммуникации.
3. Постоянно напоминать, к какой ценности клиент идёт — на каждом шаге воронки.
(источник → Z-sleeping, алгоритм 4.2)

В ЮЭ это напрямую влияет на конверсию C1: рост C1 при неизменном CAC линейно повышает AMPU = Conversion × AMPPU.

---

### Блок 6. Четыре силы → диагностика барьеров → рост конверсии

**Четыре силы прогресса (Замесин):**
- Вперёд: воспринимаемая ценность нового решения + проблемы с текущим.
- Назад: барьеры к новому решению + привычка к текущему.
(источник → Z-sleeping, фреймворк 5.1)

**Связь с ЮЭ:** снижение барьеров повышает C1 без роста CAC. Это самое дешёвое улучшение Profit per User (формула вычитания работает в нашу пользу).

**7 условий конверсии (Замесин):**
1. Привлечён лид с целевой работой.
2. Предложена ценность выше конкурентов.
3. Лид понял ценность (язык работ).
4. Нет тревог к нашему решению.
5. Нет тревог к выполнению работы в целом.
6. Лид активировался в ценность и не дропнулся по пути.
7. Воронка технически исправна.
(источник → Z-sleeping, алгоритм 4.1)

Ни одно из условий не является фичей — все они JTBD-переменные, которые меняют C1 в формуле AMPU.

---

### Блок 7. Точка роста и нелинейность

**Алгоритм поиска точки кратного роста (Красинский):**
1. Посчитать AMPPU и CAC по текущим метрикам.
2. Проверить сходимость (AMPPU > CPU).
3. Выдвинуть гипотезы по каждому рычагу: средний чек, маржинальность, конверсия, повторные покупки, поток.
4. Оценить потенциал каждой гипотезы.
5. Порядок работы: обычно маржинальность → средний чек → конверсия → трафик.
6. После реализации — повторить цикл, точка роста сместится.
(источник → K1-money, транскрипт)

**JTBD-интерпретация точек роста:**
- Маржинальность и средний чек: зависят от того, правильно ли выбрана работа и сегмент (денежность работы).
- Конверсия: зависит от барьеров, aha-moment, понятости ценности — JTBD-переменные.
- Повторные покупки: зависят от частотности и важности работы + глубины привычки.
- Поток пользователей: зависит от размера сегмента и от пробуждения спящих работ.

## Как применять

### Последовательность для нового продукта / нового сегмента

1. **Выбрать сегмент** по экономической карте (Size × AMMPPU × Extra Value × Competition) — убедиться, что работа важная, частотная, денежная, неудовлетворённая. (источник → Z-segment)
2. **Посчитать предварительную ЮЭ** — оценить AMPPU и CAC на целевом сегменте до глубокого исследования. Если даже в лучших допущениях экономика не сходится — пивотировать сегмент.
3. **Провести JTBD-исследование** — выяснить работы, барьеры, aha-moment, граф работ. Собрать материал для всех 7 условий конверсии.
4. **Считать юнит-экономику по когортам** — не по средним. Кросс-чек: `Gross Profit (столбец) = P&L (месяц)`. (источник → K5-cohorts)
5. **Найти точку кратного роста** через JTBD-диагностику: какое условие конверсии проседает? Какие барьеры поднимают CAC?
6. **Проверять гипотезы решенческим интервью** (минимум 6 интервью на итерацию) перед реализацией в продукте. (источник → Z-sleeping, алгоритм 4.4)
7. **Для расширения рынка** — диагностировать спящие работы: есть ли сегмент, у которого работа ещё не проснулась? Загрузить тройку активирующих знаний.

### Диагностика действующего продукта

**Если конверсия C1 низкая:**
- Проверить 7 условий конверсии (Замесин).
- Провести решенческое интервью: где клиент «отваливается» по балансу ценность/косты?
- Сдвинуть aha-moment раньше.

**Если APC/LTV низкие:**
- Проверить когорту (не доверять среднему APC без когорт).
- Оценить частотность и важность работы: возможно, работа по природе своей низкочастотна — нужно выходить на соседние работы в графе.
- Проверить, не «спящая» ли это работа: клиент не выстроил ещё привычку.

**Если CAC растёт:**
- Проверить, правильный ли сегмент: возможно, конкуренты давят привычкой (Четыре силы).
- Рассмотреть спящие работы — там ниже конкуренция за внимание.
- В B2B — выяснить личные работы ЛПР и продавать через них.

**Если экономика сходится только на одном канале/когорте:**
- Строить когортный треугольник — один удачный месяц (Чёрная пятница) создаёт иллюзию сходимости. (источник → K5-cohorts, кейс интернет-магазина обуви)

### Антипаттерны интеграции

- **Считать ЮЭ до выбора сегмента** — данные ни о чём, работа не выбрана.
- **Лить трафик при плохой конверсии** — JTBD-барьеры и несдвинутый aha-moment убивают AMPU быстрее, чем растёт поток. (источник → K1-money, антипаттерн «Сначала трафик»)
- **Бороться с привычкой конкурента напрямую** — дешевле идти в спящие работы или сегменты с минимальной привычкой. (источник → Z-sleeping, стратегия 1 из Четырёх сил)
- **Галлюцинировать про работы клиентов** — нужно исследование, не проекция. (источник → Z-segment, антипаттерн 5)
- **Копировать внешние элементы успешного продукта** без понимания его JTBD-сегмента — классический карго-культ. (источник → K1-money, антипаттерн «Карго-культ»)
- **Считать APC = число месяцев подписки** — реально меньше из-за оттока; считать когортами. (источник → K0-ampu, антипаттерн 4)
- **Экстраполировать сегменты из одной страны на другую** без исследования. (источник → Z-sleeping, «Сегменты разных стран»)
