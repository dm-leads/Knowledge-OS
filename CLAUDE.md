# CLAUDE.md — Knowledge-OS

> Корневой «мозг» для Claude Code: как устроен этот рабочий каталог. Всегда в контексте при работе под
> `D:\Knowledge-OS\`. Агент поддерживает файл в актуальности при новых терминах/решениях/направлениях.

## Что это

Knowledge-OS — переносимый движок знаний (форк логики «Второго мозга Бризекс», переориентирован на Claude
Code). **Один движок (`_Движок`) — много проектов** (отдельные PARA-папки рядом).

## Раскладка

- `_Движок\Канон\` — правила (типы / имена / метаданные / ссылки / память / SSOT-DRY / Git). **SSOT канона.**
- `_Движок\Шаблоны\` — скелеты документов + манифесты + `CLAUDE.md` проекта.
- `_Движок\Каркас\` — пустое PARA-дерево для штамповки проекта.
- `_Движок\Сценарии\` — bootstrap / stamp / canonize.
- `_Движок\Исходники скиллов\` — исходники скиллов, включая общие навыки устройства (`claude-brief`,
  `second-agent`, `image-edit`, `questions` и др.). В `~/.claude/skills` стоят **ссылками** на эти папки —
  править только здесь; видят Claude Code и Cursor.
- `_Движок\Пакеты\` — исходники систем с кодом (Движок роста, дальше — Ядро данных): проекты подключают
  их ссылкой, компании получают выпуск с паспортом ([ADR-0003](<_Движок/0 — System Docs/ADR-log/0003-code-systems-source-in-canon-releases-in-projects.md>)).
- `_Движок\Инструменты\` — скрипты самого канона: `kos_release.py` (выпуск пакета в проект и его проверка),
  `kos_connect.py` (подключение любого проекта к канону).
- `_Движок\Подключение\` — то, что проекты импортируют через ссылку `.kos`: `agent-rules.md` — правила работы
  агента (ADR-0004). Имена латиницей — иначе импорт не работает.
- `_Движок\0 — System Docs\` — память движка (спецификация / ADR / CHANGELOG / BACKLOG).
- `Методологии\` — единственная библиотека методологий: Next Move Theory, юнит-экономика, AJTBD, продажи,
  платный трафик, Движок роста, Ядро данных, классические фреймворки, работа с ИИ-агентами.
- `Экосистема инструментов\` — реестр внешних инструментов: оценки, вердикты, матрица подключения.
- `<Проект>\` — каждый проект = самостоятельное PARA-дерево со своим `CLAUDE.md`. Проекты вне KOS
  подключаются ссылкой (ADR-0004) и записываются в «Карту».

## Правила (всегда)

- Правила работы агента — [`_Движок\Подключение\agent-rules.md`](<_Движок/Подключение/agent-rules.md>).
- Любой документ — по канону: тип из закрытого списка → имя `Тип — Название` → YAML-frontmatter → ссылки.
  Канон: [`_Движок\Канон\_manifest.md`](<_Движок/Канон/_manifest.md>).
- **Единый русский нейминг** (словарь префиксов — в «Стандарт — Конвенция именования»). Исключение —
  файлы для импорта в `_Движок\Подключение\` (латиница, ADR-0004).
- **SSOT/DRY:** не копировать — ссылаться.
- Менять правила канона — **только через ADR движка** (`_Движок\0 — System Docs\ADR-log\`); правка
  `agent-rules.md` — строкой в CHANGELOG движка.
- **Git:** корень — репозиторий слоя канона, резерв — личный закрытый GitHub; `git status` перед записью,
  коммит только своих путей; push — сам после блока изменений, со сканом добавленных строк на секреты и ПДн и
  с метками (`--follow-tags`) — разрешение владельца 28.09.2026 только для этого репозитория; LF. Подробно —
  [Стандарт — Git и GitLab workflow](<_Движок/Канон/Стандарт — Git и GitLab workflow.md>). Секреты вне git и чата.

## Скиллы (Claude Code)

- Все общие навыки устройства — в `_Движок\Исходники скиллов\` (одна папка — один навык), в `~/.claude/skills`
  стоят ссылками. Навыки Knowledge-OS — только с приставкой `kos-`: без неё имя совпадает с навыками Бризекса.
- `kos-create-doc` — создать документ по канону.
- `kos-doc-compliance` — привести документ/папку к канону.
- `kos-memory-check` — брифинг перед работой в живом контуре.
- `kos-migrate-to-canon` — привести чужую/хаотичную папку к канону.
- `build-plan` — план до правок (один проход или субагенты); `maker-checker` — независимая приёмка.
- `unit-economics` — юнит-экономика по Красинскому: испытания курса одной линией и постоянный формат таблицы;
  применять до первого числа, когда считают экономику, точку роста, гипотезу в деньгах или план от цели.
- Прочие: `growth-*` (шаги Движка роста), `ads-*` (Авито, ВК, Telegram, Директ), `keysso`, `topvisor`, `seo-niche-research`,
  `claude-brief`, `second-agent`, `questions`, `image-edit`, `brand-voice`, `agent-hygiene`,
  `llm-pipeline-economy`, `graphify-graph`, `anthropic-cookbook`.

## Сценарии (`_Движок\Сценарии\`)

- Настроить движок → `Бутстрап — Настройка движка Knowledge-OS.md`.
- Новый проект с нуля → `Плейбук — Развернуть новый проект.md`.
- Папка → канон → `Плейбук — Привести папку к канону.md`.
- Любой проект где угодно подключить к канону → `Плейбук — Подключить проект к канону.md` (запрос в чате
  проекта: «Подключи этот проект к Knowledge-OS по сценарию D:\Knowledge-OS\_Движок\Сценарии\Плейбук — Подключить
  проект к канону.md»).

## Реестр проектов

См. [`_Движок\Канон\Справочник — Карта Knowledge-OS.md`](<_Движок/Канон/Справочник — Карта Knowledge-OS.md>):
проекты в KOS, подключённые проекты вне KOS, выпуски систем с кодом.

## Как со мной работать

- Открывай Claude Code в `D:\Knowledge-OS\`.
- «Создай документ…» → `kos-create-doc`. «Проверь/почини…» → `kos-doc-compliance`.
  «Возвращаемся к…» → `kos-memory-check`. «Изучи папку и приведи к канону» → `kos-migrate-to-canon`.
- При новых терминах/решениях дополняю канон / этот файл / паспорт проекта, чтобы контекст не терялся между чатами.
